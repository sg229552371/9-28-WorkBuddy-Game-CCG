> 范围：`弹幕射击 Roguelike × 背包肉鸽 × 轻度搜打撤` 的全部界面布局
> 依据：`G_docs/game_design_proposal.md`（1909 行）+ 现有原型 `index.html / css/style.css / js/*.js`
> 阶段：**阶段一 布局线框（本次）→ 阶段二 视觉美化 → 阶段三 落地到原型 / Godot**
> 版本：v1 · 2026-09-28

## 一、任务梳理

### 1.1 这次到底在做什么

| 项 | 内容 |
| --- | --- |
| **交付物** | ① 布局规范文档（本文件）② 灰阶线框稿 `ui/index.html`（9 屏 + 通用层，可点击切换）③ 阶段二视觉方案骨架 |
| **不做** | 不碰现有 `js/game.js`、`js/ui.js` 等逻辑；不替换原型配色；本阶段不追求好看 |
| **判断标准** | 只看三件事：**信息放对位置了吗 / 战斗视野被挡了吗 / 关键控件够不够大够不够近** |
| **为什么先线框** | 现有原型 `style.css` 已带完整暗色主题，视觉噪音会掩盖布局问题——格子错位、按钮遮挡、状态缺失会被"看起来挺酷"糊过去。灰阶稿强制暴露结构缺陷 |

### 1.2 关键事实（来自文档，非推测）

- 目标形态：**16:9 横版**，画布基准 **1920×1080**（`index.html` canvas 即此尺寸），后续迁移 Godot 4.7.2
- 交互模型：**WASD 移动 + 鼠标只操作 UI**，玩家自动锁敌、自动攻击 → **左手在键盘、右手在鼠标，HUD 按钮必须在右手可达区**
- 界面原则：**无账号体系、无设置页**，只保留局内循环所需按钮（§2.2）
- **小地图已移除**（§16.8），不要设计方位指示
- 局内背包/武器栏：**6×4 仓储** + **4×3 武器栏（= 小队技能栏）**，仅武器栏物品生效（§9.1.0）
- 死亡界面**只能返回选关，不可原地重开**（§13.1）

### 1.3 信息密度定位

三块 UI 的密度目标完全不同，不能套同一套节奏：

| 界面 | 密度取向 | 依据 |
| --- | --- | --- |
| 局内 HUD | **极低密度、贴边、永不遮挡中央** | 弹幕射击，屏幕中央是生死区 |
| 背包 / 武器栏 | **高密度、格子系统** | 46px 格子 + 4px 缝，形状拼图是核心玩法 |
| 工匠 / 结算 / 死亡 | **中密度、可滚动、左信息右操作** | 一次性决策界面，允许占满屏 |

## 二、路由决策（设计分支与契约）

### 2.1 分支

- **主分支：product（交互产品）** — 交付物是可操作的界面与流程，不是海报或品牌物
- **产品模式：operational（操作型 / 信息扫描型）** — 用户在高认知负荷下持续读写状态，优化目标是**扫描速度与状态可读性**，不是阅读节奏
- **不选** brand/graphic 分支：本次不涉及 Logo、KV、宣传物料

### 2.2 视觉谱系（阶段二才会真正用到，此处先定方向）

| 角色 | 谱系 | 它负责回答什么 | **绝不能抄什么** |
| --- | --- | --- | --- |
| **主谱系** | 暗黑 / 流放之路系 ARPG 的 HUD 与格子背包词典 | 血条·能量条·经验条的贴边布局；格子物品的形状拼图与品质色阶 | 繁复的拟物石质边框、拥挤的技能球阵、深棕金属材质 |
| **辅助谱系** | 撤离射击（搜打撤）的"压力读数"语言 | 负重读数、超重惩罚提示、撤离读条的仪式感 | 军事写实贴图、枪械改装面板、复杂的弹药分类 |

> 两者的分歧点只有一处：**"背包是仓库"还是"背包是战力"**。本作答案是后者（武器栏才是战力），因此**武器栏必须视觉权重大于背包**——这是布局上的硬约束，不是审美选择。

### 2.3 为什么这两条谱系能共存

它们服务于同一个心理动作：**"我该带走什么、我还能撑多久"**。ARPG 提供的是"看一眼就知道装备强度"的色阶语言，撤离射击提供的是"看一眼就知道还能不能跑"的读数语言。两者不冲突，因为它们占用的屏幕位置本来就不同（背包面板 vs HUD 左下角）。

## 四、布局规范（阶段一即锁定，阶段二不再改）

### 4.1 画布与适配

```
基准画布   1920 × 1080 (16:9)
适配方式   整体 transform: scale() 等比缩放 + 居中（letterbox）
缩放公式   scale = min((vw − 48) / 1920, (vh − 96) / 1080)
最小可视   1280 × 720（scale = 0.667，46px 格子 → 30.7px，仍可点）
```

> **不采用**响应式重排。本作是固定 16:9 游戏画面，重排会破坏"弹幕区必须空白"这条硬约束。

### 4.2 栅格与间距

| 令牌 | 值 | 用途 |
| --- | --- | --- |
| `--u` | 8px | 基础单位，所有间距为 8 的倍数 |
| 安全边距 | 24px | HUD 元素距画布边缘 |
| 组内间距 | 8px | 血条与能量条、进度条与预警文字 |
| 组间间距 | 16px | 血条组与增益图标区 |
| 面板内边距 | 24px | 所有 `.panel` |
| 面板圆角 | 14px | 骨架阶段统一，阶段二再分层 |

### 4.3 关键尺寸（已在原型验证，保留为常量）

| 元素 | 尺寸 | 理由 |
| --- | --- | --- |
| 背包格子 | 46×46，gap 4 → 节距 **50px** | 6 列 = 46×6 + 4×5 + 12(内边距) = **308px** |
| 武器栏格子 | 同上 | 4 列 = **208px**，3 行 = **158px** |
| 可点击控件最小高 | **44px** | 触摸目标下限 |
| 读条圈 | ⌀88，环宽 6 | 中央下方，余光可见 |
| 面板最大宽 | 背包 1100 / 工匠 1220 / 结算 760 | 现有原型值，布局合理，沿用 |

### 4.4 层级（z-index）

```
0   游戏画布
10  局内 HUD
20  屏级界面（关卡/角色/局外/结算/死亡）
30  覆盖层（背包面板 / 工匠面板）
99  拖拽幽灵
```

### 4.5 字体与数字

| 用途 | 方案 |
| --- | --- |
| 中文正文 | `"Microsoft YaHei", "PingFang SC"` |
| **所有数值** | **等宽数字**（`font-variant-numeric: tabular-nums` 或 `Consolas`）← 血条/金币/负重每秒跳动，不等宽会左右抖动 |
| 字号阶梯 | 11 / 12 / 13 / 14 / 16 / 20 / 42（沿用原型，不新增） |
| 字距 | **恒为 0**，禁止负字距 |

## 六、三阶段执行方案

### 阶段一：布局线框（本次交付）

**产出**：`G_docs/ui/index.html`（灰阶线框，顶部工具条切换 9 屏 + 标注开关）

**做法**
1. 全部屏共用一个 1920×1080 `#stage`，等比缩放适配浏览器
2. 所有盒子：`1px dashed` 边框 + 区域编号角标 + 尺寸标注（可开关）
3. 用**方块占位**代替图标、**灰条**代替文字段落、**色阶灰**代替品质色
4. 顶部工具条可切屏、可开关标注

**验收动作**（打印出来看更准）
- [ ] 9 屏逐屏走查，每屏回答："主任务在哪？一眼能找到吗？"
- [ ] HUD 屏：把中央 1600×760 框出来，确认**无元素侵入**
- [ ] 背包屏：实际拖一件 2×3 物品，确认 6×4 / 4×3 拼图空间够用
- [ ] 确认所有可点元素 ≥ 44px
- [ ] 确认键盘 B / Tab 快捷键与右下角按钮文案一致

**停止条件**：9 屏布局全部确认无异议 → 冻结为 v1.0 布局基线

### 阶段二：视觉美化

**产出**：`ui/visual.css`（视觉令牌层，与线框 DOM 一一对应）

**顺序**（必须按此顺序，否则返工）
1. **颜色令牌**：底色 / 面板 / 描边 / 文本三级 / 品质色阶 / 状态色（危险·成功·警告）
2. **质感**：面板材质、描边、阴影、圆角分层
3. **字体**：字号字重行高按角色定稿、数字等宽
4. **图标**：格子物品图标、状态图标、Buff 图标
5. **动效**：Toast 进出、读条圈、超重脉冲、开箱飞行轨迹

**约束**
- 品质色阶**必须与现有 `q0~q3`（白/蓝/紫/金）保持映射**，不要另起一套
- 涨跌色沿用中国习惯？**不适用**——本作无股价，只有血/能量/经验/品质，用常规语义色
- 战斗区仍必须保持空白，不允许用"氛围光效"侵入中央

### 阶段三：落地

- **回写原型**：把确认后的布局与令牌合并进 `css/style.css`，由你确认后再动 `js/ui.js`
- **Godot 迁移准备**：本阶段产出的**尺寸常量 + 区域坐标表**可直接映射为 Godot 的 `Control` 锚点预设，建议同步产出 `ui/layout_tokens.json`

## 七、验收门禁（阶段二结束前逐条打勾）

**结构**
- [ ] 每个主要控件都有：默认 / 悬停 / 激活 / 选中 / 禁用 / 加载 / 成功 / 错误 / 空 / 恢复 十态
- [ ] 背包满时拾取 → 有明确失败反馈 + 宝箱留在地上可回头再捡（§6.3）
- [ ] 背包拖拽非法位置 → 格子变红，松手回原位（不是静默失败）

**反馈与恢复**
- [ ] 直接操作反馈 < 100ms
- [ ] 撤离读条：任一成员站进圈内即**自动**读条 + 受击归零 + 离开圈缓降 + 雕像保留可重读（§5.2）
- [ ] 祭坛读条离开圈 → 缓慢衰减而非归零（§4.1）——**与撤离读条行为一致**（同一判定圈组件），仅读条时长与后果不同
- [ ] 超重状态 → 左下读数转红 + 实时移速惩罚数值

**内容与文案**
- [ ] 全部面向玩家的文案为中文；术语统一（金币 / 进化结晶 / 武器模块 / 武器栏）
- [ ] 结算界面明确写出折算率 0.5 与"不开箱"（§6.4）

# 游戏设计方案：弹幕射击 Roguelike × 背包肉鸽 × 轻度搜打撤

***

## 一、核心玩法概述

**游戏定位**：**弹幕射击 Roguelike + 背包 Roguelike + 轻度搜打撤**。

本游戏融合 **弹幕射击**、**Roguelike**、**轻度搜打撤（Loot & Extract）** 与 **背包肉鸽（Backpack Roguelike）** 玩法要素：战斗以弹幕/弹道形式呈现，局内构建依靠属性卡牌与背包格子规划，风险收益博弈（死亡惩罚、撤离结算）作为轻度的压力来源，构建以"战斗爽感 + 构筑策略 + 风险博弈"为核心的循环体验。

玩家在有限地图中击杀怪物、搜刮宝箱、管理背包负重，通过随机出现的祭坛（雕像、宝箱、裂缝等）调整战局策略，最终携带战利品撤离才算带出。中途死亡将面临道具损失惩罚，玩家需要在贪婪拾取与安全撤离之间持续博弈。

***

## 二、游戏流程

### 2.1 完整流程

```
打开游戏
  │
  ▼
关卡选择界面 ──→ 点击「开始」
  │
  ▼
角色选择 ──→ 确认角色进入游戏
  │
  ▼
进入有限地图（出生在地图正中心）
  │
  ▼
四周随机刷怪（随机圆持续生成）/ 祭坛按关卡时间轴到点投放（固定指定 / 随机池，不可重叠）
  │
  ▼
击杀怪物 → 宝箱以「未开封货物」形式进入背包（占格、有重量）
  │         └→ 经验水晶 + 金币直接入账（不占格）
  │
  ▼
持续战斗 / 拾取资源 / 交互祭坛（升级获得属性卡牌资产）
  │
  ├──→ 可能触发空间裂缝 → 进入子地图 → 返回原地图（状态保留）
  │
  ▼
获得撤离点（仅 Boss 击败后于其死亡位置生成，全图仅 1 个）→ 前往雕像读条 8 秒撤离
  │
  ▼
关卡结算 → 背包内物品（含未开封宝箱）按各自固定价值 × 统一折算率 0.5 折算为进化结晶
  │         └→ 结算界面不开箱、不拖拽分配；宝箱本体不带出，只折算价值
  │         └→ 局内经验与金币一律归零、不参与折算
  │
  ▼
【若中途死亡】→ 按未保险占用格剔除70%（整件、贵小件优先）→ 关卡失败
```

### 2.2 界面按钮说明

- **界面原则**：只保留局内循环所需的按钮，**无账号体系、无设置页**

- **关卡选择界面**：展示可选关卡，点击「开始」进入角色选择

- **角色选择界面**：选择出场角色后正式进入游戏地图

## 三、地图与刷怪机制

### 3.1 地图结构

- 地图为**有限封闭地图**，四周有墙壁，非无限开放世界

- 玩家**出生在地图正中心**位置

- 地图四周会**随机刷新怪物**

### 3.2 刷怪进度机制

- 刷怪机制参考**暗黑破坏神 2 大秘境**设计

- 界面上方有**时间/怪物进度条**，用于展示当前关卡刷怪进度

- 玩家击杀怪物推进进度条，进度满后触发后续事件（如 Boss 出现等，具体规则待细化）

### 3.3 随机圆刷怪机制

> 设计原则：**圆只负责"在哪、刷什么、刷多少、多久刷一次"**——即刷怪的"最小执行单位"。什么时候刷（节奏）、刷多强（等级）、总共多少（上限），都不归圆管，归关卡层管。**BOSS（BS）不进随机圆**，由关卡层定点投放（见 3.4）；**精英怪首版改为「词缀精英」**——由普通怪按概率转化（见 16.9），同样不单独配进刷怪圆。

#### 3.3.1 三层模型

**层 1：关卡层（每关一行配置）**——决定"这一局刷怪的宏观节奏"

- 怪物等级基准（默认 = 关卡数，可单独覆盖设置）

- 精英怪 / BOSS 的**基础数量**（可被局内效果增减——邪神雕像等，**具体影响来源待定**，见 4.5）

- 全场**怪物总数上限**（性能红线，当前定 **200**，配合 15.2 的 80 角色指标）

- 引用哪些刷怪圆模板、各自的出现时机（进场即刷 / 进度阈值触发）

**层 2：刷怪圆模板层（可复用）**——决定"单个圆的行为"

- **圆的半径**（覆盖范围）

- **每波数量**（每波生成几只小怪）

- **怪物池**（小怪编号 + 权重，如 `NM0010:70 / NM0011:30`）

- **刷新间隔**（持续生成型圆：每隔几秒刷一波；一次性圆无此项）

- **触发方式**（进场即刷 / 进度条达到 X% 时激活 / 玩家靠近 Y 米时激活）

**层 3：运行时规则（代码固定，不配表）**

- 圆在地图上**随机摆放**，与祭坛一致做**不重叠检测**

- 圆内随机取点刷怪：**避开墙体**、与玩家保持**最小距离**（防止脸刷）

- 全场怪物数到达上限时，**暂停刷新**，低于上限后恢复

#### 3.3.2 怪物编号体系

- **普通小怪：NM**（Normal），如 `NM0010`

- **精英怪：ED**（Elite），如 `ED0014`——原方案为关卡层定点投放；**首版改为「词缀精英」**：普通怪按概率转化为精英（+1~2 条随机词缀、体型放大、光环标识），不单独配进刷怪圆（见 16.9）

- **BOSS：BS**（Boss），如 `BS0001`——不进随机圆，进度条满 / 时限到后在固定或随机点位投放

- 编号对应怪物配置表条目，便于配表与调试定位

> 原 `ED0014[]`、`BS00xx[]` 的"方括号数量参数"**取消**：数量表达重复且语义不明（与圆的"每波数量"、关卡层的"基础数量"三处冲突）。数量统一收口：**小怪数量 → 圆模板，精英/BOSS 数量 → 关卡层**。

## 四、祭坛系统（原场景物体系统）

### 4.1 概述

地图上随机地点刷出各类场景物体。**雕像、宝箱等场景物体统称为「祭坛」**——**战争雕像、女神雕像、宝箱、邪神雕像本质上是同一个东西**：都是同一个通用"祭坛道具"，触发时按配置**尝试执行一组效果**；不同的只是**外包装**（外观、名字、文案）。交互规则统一。**物体之间不可重叠**。所有功能均**数据驱动**，由策划配表决定具体效果，后续可灵活扩展。

- **统一实体**：游戏内只存在一种"祭坛"实体；"战争雕像/女神雕像/宝箱/邪神雕像/工匠雕像/空间裂缝"都是它在配置表里的不同行（不同外包装 + 不同效果参数）

- **效果尝试机制**：祭坛触发时，按配置的效果列表**依次尝试执行**（效果是否成功、成功后的表现由效果类型决定）

- **统一交互方式**：英雄进入祭坛的**交互圆圈**范围 → 圈内**停留 2-3 秒** → 祭坛生效（获得/使用）

  - 停留期间**离开圆圈**：读条进度**缓慢衰减、不立即归零**（衰减速度 = 积累速度 × 1.2），重新进入圆圈继续累积

  - 与撤离读条的区别：**两者的触发方式现在完全一致**（任一成员站进圈内即自动读条、离开圈缓慢衰减、受击归零）；差别只在读条时长与后果（祭坛 2-3 秒生效，撤离 8 秒完成离场）

  - 圆圈半径、停留时长由祭坛配置表配置（当前统一 2-3 秒）

- **一次性规则**：祭坛**触发生效成功后即消失**，不会一直持续存在（未触发的祭坛保留在原地）

- **配置表模板**：见 4.7（给出字段定义与示例行，策划填表即可扩展新祭坛）

### 4.2 物体功能分类

| 功能类型          | 说明                     |
| ------------- | ---------------------- |
| **一次性道具类型**   | 使用后消失，即时生效（如回血雕像）      |
| **持续时间性道具类型** | 使用后生效一段时间，到期消失（如增益雕像）  |
| **场景传送功能**    | 触发场景切换，进入/返回子地图（如空间裂缝） |

### 4.3 已定义祭坛（同一实体的不同外包装）

| 祭坛名称   | 功能类型    | 具体效果                          |
| -------- | ------- | ----------------------------- |
| **宝箱**   | 一次性道具   | 拾取后以「未开封货物」形式进入背包，占格有重量；**仅可在工匠世界开启**（见 6.3） |
| **女神雕像** | 一次性道具   | 恢复 25% 生命值                    |
| **工匠雕像** | 场景传送功能  | 进入**工匠世界**：可使用宝箱、属性卡与金币服务（细则见 4.6） |
| **战争雕像** | 持续时间性道具 | 增益池共 **4 个**增益，随机获得其中 1 个，持续 **20 秒**（增益内容见 4.4） |
| **邪神雕像** | 持续性/永久性 | 调整本局怪物数量与属性（5 种，见 4.5）        |
| **空间裂缝** | 场景传送功能  | 进入子地图，原地图状态保留，可返回（详见第五章）      |
| **后续扩展** | —       | **只需在配置表加一行**，无需新代码（见 4.7）    |

> 上表所有已定义祭坛均遵循 4.1 的**统一交互方式**：英雄进入圆圈内停留 **2-3 秒**后获得/使用（宝箱拾取、雕像触发、裂缝传送均需先完成停留）。

### 4.4 战争雕像增益池（暂定数值，可配表）

使用战争雕像时，从以下 4 个增益中**随机获得 1 个**，各持续 **20 秒**：

| 增益   | 效果              |
| ---- | --------------- |
| 狂力   | 攻击力 +30%       |
| 迅击   | 每秒攻击次数 +30%    |
| 疾风   | 移速 +30%（与负重惩罚分别结算） |
| 汲血   | 造成伤害的 15% 转化为生命恢复 |

> 战争雕像数值均为首版暂定，由增益效果表配置，后续可调。

> **生效对象（已定）**：增益**对小队全体成员生效**（队长 + 全部 AI 队友），不是只加队长——与武器栏物品、属性卡牌同属「本局共享收益」（代码 `runBonus()` 统一结算，见 16.5）。

> **触发者（已定）**：**任一小队成员**在雕像圈内读条即可触发——队长或任意 AI 队友都算数（判定取存活的全部成员，`aliveHeroes()`）。触发后效果**全队共享一份**（同一份持续时间）。
>
> 🔴 **同一判定不会被同时触发（已定）**：所有英雄都是**独立个体**，能触发所有判定；但**同一个判定同一时刻只可能有一个触发者**——判定是**单一实例**（只有一份进度、一个持有者），**两名英雄同处一个判定圈不会让进度加速**（不是每人各算一份），读条完成即**消费**该判定（雕像移除 / 进度归零），**不可能被第二个英雄重复触发**。全套判定圈（雕像 / 信标 / 工匠 NPC / 撤离点）共用同一条规则（见 13.4）。
>
> **治疗类雕像同理**：`heal` 效果**全队（存活成员）一起恢复**，不是只治队长。

> **🔴 重复触发 = 叠「等级」，不是叠份数（已定）**：重复获得**同一条** Buff 时，**叠加的是该 Buff 的等级**（`lv`：Lv1 → Lv2 → …），并**刷新持续时间**；同一条 Buff 永远只保留一份效果。
>
> - 效果值按**技能表的等级曲线**结算（`skillEntry(skillId, lv)`）——例如「狂力」Lv1 = 攻击 ×1.30、Lv10 = ×1.55、Lv99（上限）= ×3.00（完整表见 8.5 表 4c）。
> - 可由配置决定**该 Buff 是否可叠等级**：`stackable: false` 的 Buff 重复触发**只刷新时间、不升级**。
> - 等级上限 = `CFG.buffLevel.maxLv`（默认 99），每次触发提升 `stackPerTrigger`（默认 1）级。
> - HUD 图标显示**等级 + 剩余时间**（如「狂力 Lv3 · 18s」）。

### 4.5 邪神雕像（原"数值雕像"，暂定设计，可配表）

调整本局怪物压力的雕像，共 5 种，效果幅度在 **±100%** 区间内：

| 雕像     | 效果            |
| ------ | ------------- |
| 小怪数量雕像 | 小怪数量 ±100%    |
| 小怪属性雕像 | 小怪属性 ±100%    |
| 精英数量雕像 | 精英怪数量 ±100%   |
| 精英属性雕像 | 精英怪属性 ±100%   |
| BOSS 属性雕像 | BOSS 属性 ±100% |

- **触发时幅度随机**：每次触发在策划填写的区间（-100 ~ +100）内随机取值

- **效果限时**：持续时长由策划填写；**填 -1 时为永久**（持续到本局结束）

- 精英怪/BOSS 的**基础数量**由关卡配置决定，此类雕像在基础值上做增减（呼应 3.3；**能影响基础数量的手段不限于雕像，其他设定待定**）

### 4.6 工匠世界（工匠雕像功能）

- 通过工匠雕像进入的**特殊子地图**（复用空间裂缝的传送框架，原地图状态保留）

- **工匠世界内没有敌人**，是安全区，供玩家整备

- **工匠世界内可以**：

  - **使用宝箱**（开启未开封货物——这是全游戏**唯一**的开箱场景，见 6.3、6.4）

  - **使用属性卡**（应用累积的属性卡牌资产，见 8.3）

  - **消耗金币的工匠服务**：品质提升 / 洗词缀 / 购买宝箱 / 购买保险契约 / 购买武器模块 / 购买道具

- **工匠世界不含武器升级服务**：武器升级只在局外成长界面消耗进化结晶进行（见 6.6）

- **进入次数无限制**

- **返回方式**：参考空间裂缝——通过子地图框架进入/返回（返回读条机制沿用 5.2 的信标规则）

> 注意：原"工匠雕像打标（保险）"方案已废弃，由工匠世界功能替代；保险机制的局内来源需重新设计（见待细化第 13 条）。

### 4.6.1 工匠雕像投放机制（雕像池 + 限制器 + 多触发条件）

> 设计模型：**触发条件（多条并存）把「配额」投进池** → **限制器**决定配额何时、以什么频率变成地图上一座真实雕像。雕像使用后消失，池继续产出，因此**"无限次进入工匠世界"由池的持续产出保证**（与 4.6 "进入次数无限制"口径一致）。

**触发条件（配额来源，任一满足即 +1 配额，互不排斥）**：

| 触发条件 | 判定方式 | 配额 | 上限 |
| ---- | ---- | ---- | ---- |
| 首次里程碑 | 击杀数达到关卡配置的 `artisanAtKills` | +1 | 1 次 |
| 进度里程碑 | 击杀进度每 25% | +1 | 最多 3 次 |
| BOSS 击败 | BOSS 被击败后（撤离前的最后改造机会） | +1 | 1 次 |
| 精英猎杀 | 每击杀 2 只精英怪 | +1 | 最多 3 次 |
| 保底计时 | 距上次雕像出现超过 90 秒 | +1 | 可重复 |

**限制器（控节奏、防刷，不限制总次数）**：

- 场上同时**最多 1 座**工匠雕像

- 使用后**冷却 20 秒**（期间不投放，保证战斗节奏）

- **每关投放上限 6 座**（达到上限后本关不再产出）

- 配额就绪后有 **3~8 秒随机延迟**才落地（让出现时机显得随机）

- 投放点距玩家**至少 300px**（避免贴脸弹出）

### 4.7 祭坛效果配置表（示例模板，策划按行填表即可扩展；临时设定，通用备注见 13.13）

游戏内只有**一张祭坛配置表**。每一行 = 一个祭坛（外包装 + 触发后尝试的效果）。开发只实现"效果执行器"，新增祭坛不加代码。

**字段说明**：

## 五、空间裂缝与撤离机制

### 5.1 空间裂缝

- 空间裂缝为**场景传送类物体**，地图随机刷出

- 触发流程：

```
空间裂缝祭坛（A地图，圈内停留 2 秒）→ 传送到全新子地图
  → 开场冻结 3 秒（红色倒计时 3/2/1）→ 全部敌人一次性投放 → 战斗
  → （任务完成给额外宝箱 / 剩余敌人留场可继续清剿 / 返回信标随时可用）→ 返回 A 地图
```

- **开场冻结**：进入子地图后**冻结 3 秒**（`freezeTime = 3.0`）。冻结期间**玩家与所有敌人全部静止，双方均不受伤（全员无敌）**；屏幕中央显示**红色大字倒计时 3 / 2 / 1**，倒计时结束同时解冻并开始战斗。冻结期间任务限时不倒计时

- **一次性投放**：倒计时结束瞬间，把本次任务所需的**全部敌人一次性投放完毕**，之后**不再增援**（任务完成或失败都不再新增敌人）。投放数量 = 任务配置的 `spawnCount`（见下表）；投放位置在地图上的**两个投放区域**内一次性散布（原刷怪圆位置改为一次性散布中心），**避开障碍、玩家、返回信标**

- **独立精英怪**：精英（ED 编号）**随敌群一次性投放**，不再按时间间隔分批补投；数量 = `eliteBase(3) × 邪神雕像"精英数量"倍率`。裂缝子地图**不使用**"普通怪按概率转化为词缀精英"的旧机制（`riftChance = 0`，与主地图的词缀精英规则区分，见 16.9）

- 子地图内**任务**：**任务型子地图**。进入时按权重随机一个任务变体（任务**不强制**完成，返回信标始终可用）：

  | 任务 | 目标 goal | 一次性投放数 spawnCount | 限时 |
  |---|---|---|---|
  | 深入猎杀 | 击杀 20 只 | 22 | 无 |
  | 歼灭作战 | 击杀 18 只 | 20 | 75 秒 |
  | 闪电突袭 | 击杀 10 只 | 14 | 40 秒 |

  - 任务完成 → 额外刷出高价值「**任务奖励宝箱**」

  - 限时超时 → 任务失败（但敌人不消失，可继续清剿）

- **基础奖励宝箱**：子地图内累计击杀达 **12 只** → 刷出「**裂缝奖励宝箱**」雕像。因为每个任务的投放总数（22 / 20 / 14）都 ≥ 12，所以任何任务都能拿到这个宝箱

- **剩余敌人留场**：任务完成后，场上没打完的敌人**留在原地可继续击杀**（不再刷新新的，也不会清场）；玩家自行决定继续清剿还是通过返回信标离开

- **返回 A 地图的方式**：通过**返回信标**读条返回，读条 **5 秒**，**仅"受击"会打断并归零，移动不会打断**（离开读条圈进度保留、不衰减）；返回信标以场景物体形式在子地图**地上随机刷出**

- **A 地图状态保留**：离开时已杀的怪、已拾的物等信息均保留，返回时与离开时一致

- 进入的子地图为**全新地图**，非同地图的其他区域

- **子地图（子世界）家族**：目前有**工匠世界**（无敌人安全区，见 4.6）与**裂缝子地图**（任务型战斗子地图，本节）两个子世界，共用进入/返回框架；后续会扩展**新的子世界**

### 5.2 撤离点

> **首版基准（16.3 已确认）**：游戏中**没有撤离代币**。撤离点以**雕像（场景物体）**形式存在于地图上，**让小队任一成员站进雕像判定圈内**即可自动读条撤离（判定圈规则见 4.4 / 13.4）。

- 撤离点**非地图固定点位**，**仅由 Boss 击败产生**：

  - **Boss 击败生成**：击败最终 Boss 后，在 **Boss 死亡位置**生成撤离点雕像

- **一张地图内只能有 1 个撤离点**（上限 1 个，同一关卡内最多存在一个可用撤离点）

- **Boss 死亡前不会生成可用撤离点**

- 撤离成功后进入结算：**背包内物品不作为物品带出**（不进入局外永久资产），而是按**各自固定价值 × 统一折算率 0.5** 折算为**进化结晶**；**未开封宝箱同样不带出箱子本体，其固定价值同样折算为结晶**（口径见 6.5、6.6、13.11）

- **读条触发（已更新）**：**任一小队成员站进雕像判定圈内即自动读条**（队长或任意 AI 队友都算，**不需要按键**）——判定圈 = 雕像虚线圈 × `CFG.altarJudgeMul`（1.2 外扩容差）
- **离开判定圈**：圈内英雄**全部离开**后进度按判定圈通用规则**缓慢衰退**（1.2 倍速），不是瞬间清零；**移动本身不再单独打断**（与其它判定圈统一口径，见 13.4）
- **受击打断**：读条中受伤仍**立即归零**；中断后**雕像保留在原地**，重新站回圈内即可继续读
- **同一判定不会被同时触发**：撤离判定是**单一实例**（单一进度 `extractProgress` + 单一持有者 `extractHolder`）——多个英雄同处一个判定圈**不会加速**，读满 8 秒即被消费一次（见 13.4）

- **无撤离代币**：不存在代币的占格、重量、死亡掉落问题；撤离点雕像是场景物体，随关卡结束（撤离或死亡）消失

### 5.3 空间裂缝 vs 撤离点（核心区别）

| 维度           | 空间裂缝             | 撤离点            |
| ------------ | ---------------- | -------------- |
| **功能定位**     | 场景传送，进入子地图       | 撤离离场，进入结算      |
| **离开地点信息**   | **保留**（A地图状态不重置） | **不保留**（离开即结束） |
| **是否带出物品结算** | 否，物品仍在背包中        | 是，进入结算并按固定价值统一折算为结晶 |
| **可返回性**     | 可返回原地图继续         | 不可返回，关卡结束      |

> 两者功能类似但作用不同，具体关联关系**待定**。

## 六、怪物掉落与宝箱系统

### 6.1 怪物掉落规则

- 怪物**不会掉落装备/道具**

- 怪物掉落两类资源，**均不占用背包格子**：

  - **经验水晶**：用于**局内等级**提升（见 6.5），直接入账，不占格

  - **金币**（局内货币）：用于局内消费——刷新属性卡牌 / 购买武器模块 / 购买道具 / 工匠世界金币服务（见 6.6），直接入账，不占格

- 其他掉落物后续可能会扩展

### 6.2 宝箱掉落规则

- 宝箱掉落与**击杀怪物关联**（具体关联机制——击杀数量/怪物类型/进度条进度，待策划细化配表）

- 怪物难度/数量越高 → 宝箱数量与品质越高

- **宝箱品质共 5 种**：普通 → 高级 → 史诗 → 崇高 → 神级

  - **首版仅开发前 3 种**（普通、高级、史诗），崇高/神级后续版本加入

  - 品质决定占格尺寸、重量、开箱内容池（由宝箱品质表配置）

### 6.3 宝箱采集机制

- 宝箱拾取时**立即以「未开封货物」形式进入背包**

- 未开封货物**占用背包格子**，且具有**重量**，计入总负重

- **同品质未开封货物可叠加**：叠加后仅占 1 格、按数量计数，重量按数量累计

- **背包已满时的拾取规则**：若背包中存在同品质未开封货物则可叠加拾取；否则无法拾取，宝箱留在地上

- 未开封货物**不能在局内战斗中使用**；**工匠世界是唯一开箱场景**（通过工匠雕像进入，见 4.6、6.4），开出的物品按容量校验放入背包/武器栏，装不下作废

- **未开封宝箱不能撤离带出本体**——撤离时它仍在背包中（占格、计重），结算时按**固定价值 × 统一折算率 0.5 折算为进化结晶**（不带出箱子，只折算价值，见 6.4、6.5）

- 未开封货物作为背包物品参与**死亡掉落判定**与**负重计算**

### 6.4 结算折算机制（不开箱）

> **口径统一**：撤离结算界面**不再开箱、不再拖拽分配**。背包 / 武器栏内所有物品（含未开封宝箱）一律按固定价值折算为进化结晶。开箱动作**只存在于工匠世界**（见 4.6、16.4）。

- 结算界面展示玩家**携带出场的物品清单**（背包 + 武器栏，含未开封宝箱）与**折算明细**

- **折算公式**：`结晶 = Math.floor(物品固定价值 × 统一折算率 0.5)`（**2 点价值 = 1 结晶**，配置名 `CFG.settleConvert.valueRate`）

- **固定价值来源**：宝箱 = `CFG.chestQualities[].value`；装备 = 30 × 品质系数；武器模块 = 45 × 品质系数；属性卡牌资产 = 固定价值 4 / 张（见 6.6）

- **不区分物品类别**：宝箱 / 装备 / 武器模块 / 消耗品（保险契约、诅咒道具等）走同一套折算率，**没有分类比例**

- **局内经验与金币一律归零、不参与折算**（死亡时同样不折算）

- 死亡导致的损失不进入折算：只有**成功撤离**时背包内剩余物品才折算为结晶

- 宝箱内可开出的物品种类与概率由**策划配表**决定（配置名 `CFG.chestContents`），但只在工匠世界开箱时生效

### 6.5 局内/局外双等级体系

- 游戏等级分为**两种**：**局内等级**与**局外等级**

- **局内等级**：

  - 进入关卡后属于局内，局内等级从 **LV1** 开始升级

  - 通过击杀怪物获得的**经验水晶**提升

  - **局内升级直接提升自身属性**（成长曲线待细化）；**每次升级获得 1 张属性卡牌作为资产**（见 8.3，需到工匠世界使用）

- **局外等级**：

  - 角色的永久等级，跨局保留

  - 升级消耗**进化结晶**（局外货币，见 6.6）

- **等级归零规则**：**退出局内（撤离成功或死亡）时，局内等级归零**，下次进关重新从 LV1 开始

- **死亡惩罚**：局内死亡时，本局获得的**经验与金币清零**

- **撤离结算（已定，唯一口径）**：撤离成功后**背包内物品不作为物品带出**，而是按**各自固定价值 × 统一折算率 0.5**（== **2 点价值 = 1 结晶**，配置名 `CFG.settleConvert.valueRate`）折算为**进化结晶**；**未开封宝箱同样不带出箱子本体，其固定价值同样折算为结晶**；**局内经验与金币一律归零、不参与折算**（物品固定价值表见 6.6，另见 13.9、13.11）

### 6.6 货币体系（两层货币职责边界）

游戏**只有两种货币**：局外与局内各用一种，**互不混用**（本节为货币规则的唯一事实来源）。

| 货币 | 层级 | 来源 | 用途 |
| ---- | ---- | ---- | ---- |
| **进化结晶** | 局外 | **撤离成功后按「物品固定价值 × 统一折算率 0.5」折算背包/武器栏内的全部物品**（**2 点价值 = 1 结晶**，配置名 `CFG.settleConvert.valueRate`；含未开封宝箱、装备/武器模块、道具、属性卡牌资产，**不再按类别区分比例**；**局内经验与金币一律归零、不参与折算**），见下方「物品固定价值表」 | ① 角色升级（**局外等级**）；② 武器等级升级（**武器等级 = 技能等级**，同一条线）。升级入口统一在**独立局外成长界面**；武器/技能升级成本 = **120 结晶 × 1.05^(当前等级−1)**，取整到 10 |
| **金币** | 局内 | 击杀怪物直接入账（死亡清零） | ① 刷新属性卡牌；② 购买武器模块；③ 购买道具；④ 工匠世界金币服务（品质提升 / 洗词缀 / 购买宝箱 / 购买保险契约 / 购买武器模块 / 购买道具） |

- **武器升级只走局外结晶**：工匠世界**不再提供"金币升级武器"服务**。
- **属性卡牌刷新**：每局免费 2 次，之后每次消耗 **120 金币**（金币不足时无法刷新，见 8.3、13.15）。
- 金币仅为**局内货币**，**撤离成功后一律归零、不参与结晶折算**（原有的金币换算结晶规则已删除）；金币的局内获取与消费保持不变。

**物品固定价值表（结算折算唯一口径；结晶 = Σ 物品固定价值 × 0.5）**：

| 物品 | 固定价值 | 折算结晶（×0.5） |
| ---- | ---- | ---- |
| 普通宝箱 | 20 | 10 |
| 高级宝箱 | 60 | 30 |
| 史诗宝箱 | 150 | 75 |
| 神圣宝箱 | 400 | 200 |
| 神话宝箱 | 1000 | 500 |
| 装备（白/蓝/紫/金） | 30 / 54 / 96 / 180 | 15 / 27 / 48 / 90 |
| 武器模块（白/蓝/紫/金） | 45 / 81 / 144 / 270 | 22 / 40 / 72 / 135 |
| 保险契约（每份） | 60 | 30 |
| 诅咒道具 | 40 | 20 |
| 属性卡牌资产（每张） | 4 | 2 |

- **统一折算率 = 0.5**（即 **2 点价值 = 1 结晶**，配置名 `CFG.settleConvert.valueRate`）；**不再按类别使用不同比例**（原「宝箱 ×0.5 / 装备/武器模块 ×0.25 / 卡牌固定 2 结晶」三套口径全部作废）。
- **装备 / 武器模块固定价值 = 基础值 × 品质系数**；**品质系数：白 1.0 / 蓝 1.8 / 紫 3.2 / 金 6.0**（装备基础值 30、武器模块基础值 45）。
- **属性卡牌资产**每张有固定价值 **4 点**（配置名 `cardValue`），走同一折算率 → 2 结晶。
- **保险契约不再有独立折算价**（原 `crystalRefund` = 20 的设定作废）：它作为背包物品，按**固定价值 60** 走**同一**折算率 → **30 结晶**。保险契约的**死亡保护**作用不变（死亡时每份保护 1 件价值最高的物品，契约本身不参与损失）。
- **死亡时不折算**、**只有撤离成功才结算**（不变）。

## 七、死亡惩罚机制（搜打撤核心）

### 7.1 死亡掉落规则

- 玩家在关卡中途死亡时，按**未保险占用格子**剔除 **70%** 的物品

- 未开封货物、装备等所有背包物品均参与掉落判定

- **掉落优先级**：

  1. **整件物品优先掉落**（占格大的整件装备）
  2. **价值高的小件次之**（单件价值高的小型物品）

- 已保险的物品不参与掉落（**保险来源待重定**：原"工匠雕像打标"方案已由工匠世界替代，见 4.6）

- 死亡时本局**经验与金币清零**（见 6.5）；本关撤离点随关卡失败一并失去（无代币概念，见 5.2）

- 这是"搜打撤"玩法的核心逻辑——高风险高收益，死亡代价巨大

### 7.2 博弈意义

| 维度   | 冲突点                     |
| ---- | ----------------------- |
| 贪婪拾取 | 背包装满更多道具，收益更高           |
| 死亡风险 | 一旦死亡损失 70% 未保险物品，收益大幅缩水 |
| 背包负重 | 超重减速 → 战斗机动性下降 → 死亡概率上升 |
| 装箱策略 | 未开封货物占格有重量，装越多死亏越多      |

玩家需在"多带道具提高收益"与"轻装上阵降低死亡风险"之间持续权衡。

***

## 八、角色属性系统

### 8.1 通用基础属性（英雄 / 敌人 / 武器共用）

> 游戏共规划 **12 个英雄角色**，**首版开放前 6 个**。数值取向：**简单**——属性种类少、公式直白（伤害 = max(1, 攻击 − 防御)，见 13.8）。

以下属性为**通用属性池**，英雄、敌人、武器共用同一套字段定义（各实体按需取用，见 8.4）：

| 属性 | 说明 |
| ---- | ---- |
| **生命上限** | 生命值上限，归零即死亡（武器等非战斗实体可留空） |
| **防御** | 减免受到的伤害 |
| **攻击** | 影响造成的伤害（作为技能伤害的基数） |
| **能量上限** | 能量值上限；技能消耗能量，能量不足无法释放 |
| **能量恢复/秒** | 每秒恢复的能量值 |
| **移速** | 基础移动速度 |
| **重量** | 物品重量：英雄拾取的物品计入背包负重；武器自身有重量 |
| **碰撞半径** | 实体在弹幕判定中的受击圈大小（弹幕射击必需） |
| **召唤物上限** | **英雄属性**：限制**召唤类技能**（技能表 `type:"summon"`，如无人机）**同时存在的数量上限**（见 8.2、16.5） |
| **陷阱数量上限** | **英雄属性**：限制**陷阱类技能**（技能表 `type:"trap"`，如大地雷）**同时存在的数量上限**（见 8.2、16.5） |

补充建议（相对你列的清单新增 2 项）：

- **碰撞半径**：弹幕游戏的核心判定字段，没有它"弹道打没打中"无从谈起；普通小怪给小圈、精英/BOSS 给大圈
- **生命恢复/秒**：可作为可选项默认 0（不做回复），女神雕像回血已够；先留字段不启用

> **属性池可扩展**：以上为当前定稿的属性，**后续玩法可能新增新属性**（如暴击、吸血、抗性等）。新增方式与祭坛/实体一致——表里加字段即可，不影响现有结构；新属性是否加入以实际玩法需求为准。

> 🟢 **属性说明文案（26.x 新增，解决「看不出加成的是什么属性」）**：玩家在**英雄详情**里必须能看懂
> 「这条属性是什么、单位是什么、加了有什么用」。落地方式：
> - **`CFG.statNames`**（12 键）= 属性的**显示名**（`atk→攻击`、`def→防御`、`energyMax→能量上限`……）；
> - **`CFG.statDesc`**（15 条 `{name, unit, desc}`）= 每个属性的**一句话人话说明**
>   （例：`def` =「减免每次受击的固定伤害，最低仍会掉 1 点」）；
> - **`UI._statHelpHtml(keys)`** 渲染「属性名 + 量纲 + 一句说明」（弹窗专用 `sht-*` 样式类：
>   属性名金色高亮、量纲弱化小字、说明正文独立成行、虚线分隔逐条），未登记的键回落「暂无说明」而**不留空白**；
> - **展示位置（26.x 定稿，用户口径）**：属性说明**只出现在角色选择右上角 `?` 弹窗**（8.1.2）——
>   角色详情面板**不再内嵌**说明区块（同屏两份相同文案属冗余，已删）；详情面板只保留数值行。
> - 🔴 口径铁律：**属性显示名与说明只放 `CFG`（配表），UI 不得硬编码中文字符串**——后续加属性只改配表。
>
> **吸血 / 冷却系数**：这两个是**局内增益通道**（`runBonus()` 的 `add.lifesteal` / `mul.cd`），
> 不占英雄基础属性栏，但同样登记在 `CFG.statNames` / `CFG.statDesc` 里，供提示与图鉴展示。

#### 8.1.1 三大基础属性：力量 / 敏捷 / 智力（26.x 新增，✅ 已实现）

> **背景（用户原话）**：「角色也没有独立基础属性，新增 力量、敏捷、智力 3 个基础属性，希望能对技能有增益影响。」

- **英雄表新增三个基础属性** `CFG.heroes[].str / agi / int`，**按定位 + 远近战差异化**
  （近战重甲角力量高、高机动角敏捷高、辅助角智力高；12 角组合互不相同）：

  | 属性 | 派生加成（每点，`CFG.baseStats`） | 设计意图 |
  | ---- | ---- | ---- |
  | **力量 str** | 生命上限 **+6**、攻击 **+0.5** | 技能伤害 = 攻击 × 倍率 → **力量随攻击放大所有技能伤害**；近战/重甲角主堆 |
  | **敏捷 agi** | 移速 **+1.2**、技能冷却 **×(1−0.4%/点)**（下限 ×0.5） | **冷却缩减通道** → 敏捷越高技能出手越频繁；高机动角主堆 |
  | **智力 int** | 能量上限 **+2**、**技能效果强度 +1%/点** | 治疗量 / 光环幅度 / 护罩值统一 ×(1+智力×1%) → **辅助技能随智力变强**；辅助角主堆 |

- **结算点 = `computeStats()` / `companionStats()`（js/items.js）**：折算与装备、局内增益**同源**
  （英雄基础值 + 三属性折算 + 武器栏装备 + 局内增益），**队长与队友同表生效**；
  `str/agi/int` 原值也挂到属性产物上 → **属性加成积木 `scaleBy`（8.2.3）直接支持 `stat:"str"|"agi"|"int"`**。
- **只折算不写回**：折算发生在运行时，**不修改 `CFG.heroes`**（定位属性带的测试基线不受影响）。
- **冷却缩减下限 ×0.5**（`CFG.baseStats.agi.cdFloor`），防止敏捷堆到 0 冷却。
- **UI**：角色详情属性行显示「力量 X / 敏捷 Y / 智力 Z」（仅数值）；三条人话解释统一在右上角 `?` 弹窗（8.1.2）；
  `CFG.statNames` / `CFG.statDesc` 已登记三键（15 条）。

  内容 = **`CFG.statDesc` 全量属性说明**（复用 `UI._statHelpHtml`，唯一展示位——角色详情面板已不再内嵌同款区块）。
- **排版（26.x 优化）**：标题行「📖 属性说明」+ 逐条行式布局——属性名金色高亮（`sht-name`）、
  量纲弱化小字（`sht-unit`）、说明正文独立成行浅灰（`sht-desc`），虚线分隔、末行无分隔线；可滚动，深色主题。
- 再点一次关闭；浮窗不挤占面板布局。

> 🔴 **召唤物上限 / 陷阱数量上限的口径（已定）**：二者都是**英雄属性**（写在英雄表里，见 8.5 表 1），作用是**限制"该类型技能"的上限**——
>
> - **实际上限 = min(技能锚点数量, 英雄该属性)**：技能等级只决定"**想召几架 / 想布几颗**"，英雄属性决定"**最多几架 / 最多几颗**"（例：召唤师上限 6，所以 AT113 满级锚点 6 架能拉满；其它英雄上限 2，同样的技能最多 2 架）。
> - **走完整属性管线**（与能量上限同源）：`英雄基础值 + 武器栏装备 + 局内增益（属性卡 / 雕像 Buff）`，所以策划后续加"+召唤物上限"的词条/卡牌/增益**零代码生效**（`computeStats()` / `companionStats()` → `unitLimitOf()`）。

> 单局节奏参考：能量上限 100、恢复 10/秒 → 每 10 秒攒够一次技能，形成"普攻填充 + 技能爆发"的简单循环。

### 8.2 技能系统（数据驱动：普攻与技能统一）

> **核心原则：普攻也是技能**。"普攻"只是众多技能**种类**中的一种（普攻有很多种：单发直线、散射、环绕、近战挥砍……），不存在独立的"普攻系统"。全部**数据驱动**：技能效果由效果积木 + 参数构成，与祭坛（4.7）、实体（8.5）同构，加新技能 = 表里加一行，零代码。

**技能表 = 单表 + `cat` 字段分类**（详见 8.5 表 4；4 类只是同一张表按 `cat` 过滤出的视图，**不再物理拆成 4 张表**）：

| `cat` 取值 | 装内容 | 举例 |
| ---- | ---- | ---- |
| `active` **主动技能** | 主动释放的攻击/实用技能，**普攻也在其中** | 散弹枪普攻、BOSS 弹幕 |
| `passive` **被动技能** | 常驻生效的加成 | 防御 +300%（道具附加）、移速 +10% |
| `buff` **增益状态** | 限时 Buff | 战争雕像 4 增益（见 4.4）、狂力 |
| `debuff` **减益状态** | 限时 Debuff | 敌人施加的减速/灼烧 |

> **为什么是单表 + `cat`**：4 类的字段同构（都需要 ID / 名称 / 效果积木 / 参数 / 等级成长），拆成 4 张物理表只会让同一套字段维护 4 遍；参考 Path of Exile 的技能宝石体系，本质也是一张技能表靠 tag 区分。**策划导出时按 `cat` 过滤，即得到 4 张视图表**（分类由 `CFG.skillCat` 承载，单表本体为 `CFG.skills`）。

> **参考 Path of Exile（流放之路）的技能石 + 辅助石体系**：技能可自由组合、**强度由等级曲线决定**。

> **技能等级上限 100 级，成长曲线公式驱动**（配置参数化，不再是手写等级表）：**普攻伤害每级 +4%（线性）**、**技能效果每级 +6%（线性）**。**技能无品质维度**——强度只由 100 级曲线决定，不做白/蓝/紫/金（属性卡牌的 4 档品质见 8.3，两者不要混淆）。

> **「技能配置表」已落地**（`CFG.skills` 单表 + `cat`，1~100 级公式 / 锚点插值，见 8.2.1）；待策划填入的是各技能的最终平衡数值。

**每把武器 = 若干主动技能条目的载体**（当前默认 1 普攻 + 1 技能，结构支持扩展）：

| 条目 | 示例（XXX武器） | 说明 |
| ---- | ---- | ---- |
| 普攻条目 | CD 1.5 秒，不耗能量 | 基础输出手段，无消耗 |
| 技能条目 | CD 2.0 秒，消耗能量 100 | 爆发手段，受能量上限约束 |

**武器等级 ↔ 技能等级**：

- **武器等级 = 技能等级**：二者是**同一条线**，武器升级时其携带的技能条目等级同步提升

- **升级方式（已定）**：在**独立局外成长界面**消耗**进化结晶**升级；**上限 100 级**，成长曲线公式驱动——**普攻伤害每级 +4%（线性）**、**技能效果每级 +6%（线性）**；升级成本 = **120 结晶 × 1.05^(当前等级−1)**，取整到 10（例：1→2 级 120、2→3 级 130）（见 6.6、13.1）

- 技能效果按等级代入**公式曲线 / 锚点插值**计算（数据驱动，参数可配；接口 `skillEntry(skillId, lv)`），不再逐级手写等级表（填法见下方"技能等级效果怎么填"）

**武器栏（= 小队技能栏）词条标签 → 技能效果**：

- **术语映射**：**技能石 = 主动技能**（**绑定在武器上**）、**辅助石 = 武器模块**（= 流放之路的辅助石；旧称「技能辅助石 / 装备模块 / 模组」，代码 `module`）——完整对照见 16.5

- 武器栏中的物品可带有**词条标签**（词缀），词条**影响全队武器技能的效果**（如：弹道 +1、CD −10%、弹速 +20%）

- 🔴 **对小队全体成员生效**：同一件武器模块按**各成员自己武器的技能标签**过滤后分别结算，**等级各走自己的武器等级**；连接与套装效果全队共享（见 16.5）

- 词条本质是挂在技能上的**属性修改器**（复用 13.7 体系），修改的对象是技能参数而非角色属性

- 词条来源与池子**待定**（可来自武器模块、开箱等）

**技能等级效果怎么填（三级填法：策划最多填 5 行，不填 100 行）**：

- **① 公式驱动（连续值）**：伤害 / CD / 弹速 / 范围 / 生命 等**连续量**，只填 **LV1 基础值 + 每级成长率**两个数——
  `LVn = 基础值 × (1 + 成长率 × (n − 1))`；默认**普攻每级 +4%、技能每级 +6%**（线性，见 `CFG.weaponLevel`），单个技能可用自己的 `growth` 字段覆盖默认成长率。

- **② 锚点插值（整数离散值）**：弹道数量 / 召唤数量 / 穿透 / 弹射次数 等**只能取整数的量**，只填 **3~5 行关键等级锚点**（如 LV1 / 25 / 60 / 100），程序在相邻锚点区间内**线性插值**后取整——
  - **锚点值全为整数 → 向下取整**；**锚点含小数 → 保留两位小数**。
  - 示例：`弹道数量` 锚点表 `{LV1:1, LV25:2, LV60:3, LV100:4}` → LV40 落在 LV25~LV60 区间，插值 `2 + (3−2) × (40−25)/(60−25) ≈ 2.43` → **取整 2 发**；LV60 命中锚点 → **3 发**。
  - **一张 3~5 行锚点表覆盖 1~100 级全程有效**——不再有"只覆盖前 5 级的数组表"。

- **③ 分段公式（非线性）**：先强后弱 / 阈值跃变，按**等级区间**给不同成长率（如 1–30 级 +8%/级、31–100 级 +4%/级）。

> 三级填法对应代码接口 `skillEntry(skillId, lv)`：传入技能 ID 与等级，由程序按上述规则查出 / 算出该级全部效果参数。
>
> **26.x 属性加成积木 `scaleBy`**：技能条目可声明 `scaleBy: { stat, pct }`，结算时
> `效果值 = 技能锚点固定值 + 施法者属性 × pct × 等级系数`（等级系数 = `1 + (lv − 1) × CFG.skillScaleBy.levelGrowth`）。
> 首个样板 = **AT120「嘲讽战吼」**（`type: "taunt"`）：半径内敌人强制攻击施法者 D 秒，半径走 `scaleBy`（以防御换算），绑定在防御定位英雄的武器技能上；怪物加 `tauntedBy / tauntT` 字段，嘲讽者倒下或超时即回落最近目标。

**技能同样适用于敌人**：怪物的攻击行为也是技能条目（普攻/技能/被动），**由策划在敌人配置表中配置技能列表**（见 8.5 表 2），精英与 BOSS 通常各配 1-2 个。

- **不排除其他道具给局内敌人添加技能**：如"防御力 +300%"的被动技能等——道具效果即向指定敌人**动态附加技能/属性修改器**（来源与触发方式待定，见待细化 #35/#36）

### 8.2.1 后续开发重点：技能系统（长期规划）

- **后续开发重点在技能系统**，设定参考 **《Path of Exile（流放之路）》** 的**技能石 + 辅助石**体系（技能可自由组合、**强度由等级曲线决定**）。

- 🔴 **术语映射（已定）**：**技能石 = 主动技能**（**绑定在武器上**、**武器等级 = 技能等级**）；**辅助石 = 武器模块**（= 流放之路的辅助石；旧称「技能辅助石 / 装备模块 / 模组」，代码 `module`）；**技能栏多槽 = 局内武器栏（4×3 网格）**，栏内物品（辅助石改技能 / 装备改属性）**对小队全体成员生效**。详细对照见 16.5。

- **技能配置表 ✅已落地**：`CFG.skills` 单表 + `cat` 分类，1~100 级**公式 + 锚点插值**（`skillEntry`），四类视图见 8.5 表 4a-4d。

- **DIY 组合 ✅部分落地**：**武器（技能石）提供技能 + 武器栏辅助石按标签修正**这套组合已实现（含辅助石 1~9 级、连接效果、套装效果）；**尚未落地的是技能石（武器）物品化**——即武器能否作为战利品掉落/被替换（见 16.5、第十二章待细化）。

- 需要一张**技能配置表**（`CFG.skills`），采用**单表 + `cat` 分类**（`CFG.skillCat`），字段方向如下（具体表结构待细化）：

| 字段方向 | 说明 |
| ---- | ---- |
| 技能 ID | 唯一编号 |
| `cat` 分类 | **`active` 主动（含普攻）/ `passive` 被动 / `buff` 增益 / `debuff` 减益**（4 类为同一张表的筛选视图，见 8.5 表 4a-4d） |
| 基础值 | LV1 基准（伤害系数、弹道参数、CD、能量消耗、生命等） |
| 每级成长率 `growth` | 连续值的每级成长率（默认普攻 +4% / 技能 +6%，线性；单个技能可覆盖，见 8.2） |
| 锚点表 `anchors` | **整数离散值**（弹道数量 / 召唤数量 / 穿透 / 弹射次数等）只填 3~5 行等级锚点，程序区间线性插值取整（见 8.2） |
| 效果积木 | 复用现有积木（伤害、弹道、加防、减速……），策划只填数字 |
| 可镶嵌的辅助/修正词条 | 可挂载的修改器（弹道 +1、CD −10%、弹速 +20% 等，见 8.2 词条标签） |
| 等级成长 | 上限 **100 级**，公式 / 锚点插值驱动（普攻伤害每级 +4%、技能效果每级 +6%，线性）；**技能无品质维度**，强度只由等级曲线决定 |

> **填表成本**：连续值只需 LV1 基础值 + 每级成长率两个数；整数离散值只需 3~5 行锚点——**策划最多填 5 行，不填 100 行**（填法见 8.2、8.5 表 4）。

> **敌人技能同表**：怪物技能条目（AT201~AT205）也进这张表（`cat` 仍为 `active`，靠 `ai` 字段标注服务于哪种怪物行为），敌人攻击参数从技能表取（见 8.5 表 2、表 4e）。

### 8.2.2 近战引擎（`type:"melee"`，26.x 新增）

> **近战不是「射程很短的远程」**——它是**独立的效果积木**，不产生飞行物。

- **判定方式**：`SkillSystem.castMelee()` 做**身周扇形即时判定**（当帧结算，无弹体）：
  命中条件 = `距离 ≤ reach + 目标半径` **且** `与施法者朝向的夹角 ≤ meleeArc/2`。
  - 贴身重合（`d ≤ 1`）时**跳过角度剔除**，避免零向量抖动误判。
  - 伤害走同一个 `damageMonster()`（`killer = caster`）→ **吸血归属、逐角色统计天然正确**。
- **配置**：技能表加 `type:"melee"` + `reach`（触及距离，如 78）+ `meleeArc`（张角，如 1.75 rad ≈ 100°）
  + `dmgMul`（如 1.35，**高于远程普攻基准 1.0**，体现「贴身换取更高单次伤害」）。
- **手感取向**：近战 = **必须贴身 / 单次伤害更高 / 出手更快**，代价是**被弹幕惩罚更重**。
- **表现**：沿朝向撒一串火花（`spawnBurst`）+ 命中音效，无弹体。
- **技能表基准项**：`AT121 近战挥砍`（`cd 0.62 / dmgMul 1.35 / reach 78 / meleeArc 1.75`）。

### 8.2.3 属性成长积木 `scaleBy`（技能吃角色属性，26.x 新增）

> **设计意图**：让技能数值**随角色成长而变强**，使「同一个技能装在不同角色身上手感不同」，
> 也是「一角色一技能但是否可给他人用」的平衡阀。

- **公式**：`最终值 = 锚点固定值 + (角色属性 × pct) × 等级系数`
  - 等级系数来自 `CFG.skillScaleBy.levelGrowth`（当前 `0.06`）——技能等级越高，属性收益越大。
  - 产物写到 `sk.scaleByAdd`，由技能执行器消费（治疗量 / 光环幅度 / 护罩值 / 判定半径……）。
  - **未声明 `scaleBy` 的技能 = 原样返回（零足迹）**，不产生任何额外计算。
- **填法**：技能表加 `scaleBy: { stat: "def", pct: 0.02 }`（`stat` 取 8.1 属性池里的键）。
- **当前 4 个用户**：

  | 技能 | 缩放属性 | 效果 | 设计理由 |
  | ---- | ---- | ---- | ---- |
  | `AT120 嘲讽战吼` | **防御** | 嘲讽半径 | 越肉嘲讽范围越大，符合「防御近战」的幻想 |
  | `AT122 生命脉冲` | **攻击** | 治疗量 | 医疗兵越强治疗越多，鼓励堆攻击 |
  | `AT123 鼓舞光环` | **防御** | 增益幅度 | 圣歌者站得越稳、鼓舞越强 |
  | `AT124 灵能护罩` | **能量上限** | 护罩值 | 能量上限成为「灵能储量」的新用法 |

- **用户原始示例（已落地）**：「防御近战高防高血低攻，技能为嘲讽，嘲讽半径 = 固定数值 + 防御力%」。

### 8.2.4 技能施加的临时增益（`pushRunBuff`，26.x 新增）

- **场景**：辅助技能给全队上短期增益（鼓舞光环、灵能护罩），这类增益**不属于战争雕像 Buff**
  （没有技能 ID、不进雕像池），需要独立通道。
- **实现**：`SkillSystem.pushRunBuff(id, stat, mul, duration)` 写入 `G.run.buffs`，
  记录 `{id, stat, mul, remain}`；`runBonus()` 按 `stat` 分发到 `mul`（atk/spd/cdMul）或 `add`（def/lifesteal）。
- 🔴 **同 `id` 只保留一份**：重复施放 = **刷新时长**，**不叠加、不叠乘**（防止无限叠乘导致数值爆炸）。
- **`def` 走平坦通道**（`runBonus().add.def`），与装备/卡牌的防御加成同源，
  因此**队长 `computeStats()` 与队友 `companionStats()` 同时生效**。
- 当前 3 条：`圣咏鼓舞`（atk ×）｜`圣咏迅捷`（spd ×）｜`灵能护罩`（def +）。

### 8.3 属性卡牌系统（局内构筑核心）

- 打怪升级获取资产；**局内升级获得属性卡牌（作为资产累积，类似金币计数），不会立即生效**

- **属性卡牌共 4 个品质**：**白 → 蓝 → 紫 → 金**（品质越高加成越强，掉落权重由配表决定）

- **属性卡牌只在工匠世界内使用生效**（工匠世界没有敌人，可安全操作；具体使用时的加成选择方式——4 选 1 还是直接应用——待定）

- 卡牌效果为**强化角色属性**（攻击/防御/移速/生命/攻速/弹道数量等，具体卡池待细化）

- **卡牌池规则**：由**属性卡牌池**统一管理；**同属性的卡牌不能同时出现**（池内去重——同一属性已有卡牌时，抽卡/刷新不再出现该属性的新卡）

- **卡牌刷新按钮**：使用时可刷新候选卡牌；**刷新次数来源已定**——**每局免费 2 次，之后每次消耗 120 金币**（金币不足时无法刷新，见待细化 #37、13.15）

- 卡牌加成跟随**属性修改器**体系（见 13.7），叠加进本局属性

- 🔴 **生效对象 = 小队全体成员（已定）**：卡牌生效后**对队长 + 全部 AI 队友同时生效**，不是只加队长——与武器栏物品、战争雕像增益同属「本局共享收益」（代码 `runBonus()` 统一结算，队长 `computeStats()` 与队友 `companionStats()` 同源读取，见 16.5）

  - **加算项**（攻击 / 生命 / 防御 / 移速）：全队共享
  - **乘算项**（攻速·冷却缩减）：全队共享（队友的普攻与主动技能冷却同步缩短）
  - **弹道数量**：全队共享（走词条标签路径 `tagCalc`，队长与队友各自武器按标签过滤）
  - **吸血**：全队生效，但**归属发射者、各自回自己的血**——队友打出的伤害回队友自己的生命，不回队长
  - **能量回复 / 能量上限**：全队共享，且**对每个成员都有实际意义**——每个成员（队长与队友）都有**自己的能量池**，队友释放主动技能 = 冷却好 **且** 自己能量足够（见 16.5）

- **使用限制**：属性卡只能在**工匠世界**中使用，局内战斗进行中无法使用任何卡牌/宝箱/强化物品（见 9.1.1）

- 已获得的卡牌加成随局内等级一起，**退出局内时失效**

### 8.4 实体统一模型：英雄、敌人、武器是同一类东西（直觉验证）

你的直觉成立，证明方式与祭坛（4.7）完全相同——**如果一张表能同时装下三者，它们就是同一类东西**：

| 维度 | 英雄 | 敌人 | 武器 |
| ---- | ---- | ---- | ---- |
| 基础属性（8.1 属性池） | ✅ 全取 | ✅ 全取 | ⬜ 只取重量、技能相关 |
| 技能（普攻 + 技能，8.2） | ✅ 由装备武器提供 | ✅ 自带（怪物攻击） | ✅ 自身就是技能载体 |
| 外包装（名字/外观） | ✅ | ✅ | ✅ |
| 阵营 | 玩家方 | 敌方 | 继承持有者 |
| 有 AI | 否（玩家操控） | **是（唯一区别之一）** | 否 |
| 可拾取（进背包） | 否 | 否 | **是（唯一区别之二）** |

**结论**：三者的差异只有三个"开关字段"——**阵营、是否有 AI、是否可拾取**。其余全是同一套字段的不同取值：

- **英雄** = 实体 + 玩家阵营 + 无 AI + 可装备武器
- **敌人** = 实体 + 敌方阵营 + 有 AI + 自带技能
- **武器** = 实体 + 无 AI + 可拾取 + 普攻/技能条目（生命、防御等战斗属性留空）

**收益**：和祭坛一样，以后加新英雄/新怪/新武器都只是**表里加一行，零代码**；普攻、技能、属性修改器、死亡判定全部复用同一套代码。

> **注意区分"模型统一"与"表格分合"**：8.4 说的是**程序底层数据结构统一**（一套实体逻辑）；8.5 说的是**策划维护时分表**（英雄表/敌人表/武器表各自独立）。两者不矛盾——分表填、统一加载，兼得维护性与复用性。

**等级效果怎么填（三级填法：策划最多填 5 行，不填 100 行）**：

- **① 公式驱动（连续值）**：伤害 / CD / 弹速 / 范围 / 生命 等**连续量**，只填 **LV1 基础值 + 每级成长率**两个数——
  `LVn = 基础值 × (1 + 成长率 × (n − 1))`；默认**普攻每级 +4%、技能每级 +6%**（线性，见 `CFG.weaponLevel`），单个技能可用自己的 `growth` 字段覆盖默认成长率。

- **② 锚点插值（整数离散值）**：弹道数量 / 召唤数量 / 穿透 / 弹射次数 等**只能取整数的量**，只填 **3~5 行关键等级锚点**（如 LV1 / 25 / 60 / 100），程序在相邻锚点区间内**线性插值**后取整——
  - **锚点值全为整数 → 向下取整**；**锚点含小数 → 保留两位小数**。
  - 示例：`弹道数量` 锚点表 `{LV1:1, LV25:2, LV60:3, LV100:4}` → LV40 落在 LV25~LV60 区间，插值 `2 + (3−2) × (40−25)/(60−25) ≈ 2.43` → **取整 2 发**；LV60 命中锚点 → **3 发**。
  - **一张 3~5 行锚点表覆盖 1~100 级全程有效**——不再有"只覆盖前 5 级的数组表"。

- **③ 分段公式（非线性）**：先强后弱 / 阈值跃变，按**等级区间**给不同成长率（如 1–30 级 +8%/级、31–100 级 +4%/级）。

> 三级填法对应代码接口 `skillEntry(skillId, lv)`：传入技能 ID 与等级，由程序按上述规则查出 / 算出该级全部效果参数。
>
> **26.x 属性加成积木 `scaleBy`**：技能条目可声明 `scaleBy: { stat, pct }`，结算时
> `效果值 = 技能锚点固定值 + 施法者属性 × pct × 等级系数`（等级系数 = `1 + (lv − 1) × CFG.skillScaleBy.levelGrowth`）。
> 首个样板 = **AT120「嘲讽战吼」**（`type: "taunt"`）：半径内敌人强制攻击施法者 D 秒，半径走 `scaleBy`（以防御换算），绑定在防御定位英雄的武器技能上；怪物加 `tauntedBy / tauntT` 字段，嘲讽者倒下或超时即回落最近目标。

## 九、背包系统（背包肉鸽核心）

### 9.1 背包格子机制

- 背包采用**网格化格子设计**（类似 Backpack Hero / 冰原孤岛）

- 装备物品占用不同形状与大小的格子区域

- 背包**格子总数与品质**影响可携带物品的总量与类型上限

- **未开封货物（宝箱）** 同样占用格子且具有重量，**仅可在工匠世界开启**，撤离时不能带出本体、只折算价值；同品质可叠加（见 6.3、6.4）

- **经验水晶、金币** 不占用背包格子，直接入账

### 9.1.0 局内背包（仓储）与武器栏（装配）的核心区别

> 这是**背包肉鸽的核心规则**，也是本作相对经典背包肉鸽的关键改动：

- **武器栏中的物品才会产生影响**（属性加成、技能效果、词条标签生效）——装配区

- 🔴 **武器栏 = 小队的技能栏（多槽）**：栏内物品**对小队全体成员生效**（队长 + 全部 AI 队友）——**武器模块改技能**（按各成员自己武器的标签过滤、等级各走各自武器等级）、**装备改属性**（全队共享）；**局内增益（属性卡牌 / 战争雕像 Buff）同样全队共享**（见 8.2、8.3、4.4、16.5）

- **局内背包（仓储背包）中的物品不影响武器或技能**，只是"携带的货物"——仓储区

- 玩家必须把物品从**背包搬进武器栏**才能获得效果——搬什么、搬多少、怎么摆，就是核心决策

**这个设计同时解决三个问题**：

1. **强化背包肉鸽核心**：装配决策（背包 → 武器栏）成为持续的玩法，而非只在上阵时选一次
2. **新增搜打撤元素**：局内背包本质是**战利品仓**——搜刮的货物放这里，撤离时带出
3. **解决网格不够 / 无暂存的问题**：经典背包肉鸽中"格子满了只能扔"，现在新拾取物先进仓储背包暂存，玩家可从容规划何时换装、带什么撤离

> 一句话：**武器栏 = 战斗力，背包 = 战利品 + 暂存区**。两者重量联动计入总负重（见 9.3）。

### 9.1.1 局内背包管理交互

- 局内支持对背包/武器栏物品的**丢弃、整理、替换**操作

  - **丢弃**：将物品移出背包，地上生成可拾取的掉落物（是否可被再次拾取待定）

  - **整理**：一键整理背包内物品的摆放位置（重量不变，仅重排格子）

  - **替换**：拖拽新物品到已占用位置时，与旧物品交换（旧物品回到手中/地上）

- 所有操作**实时重新计算总重量**，触发/解除超重状态

- **局内战斗进行中**：**无法使用宝箱、强化物品、属性卡**，也无法进行背包管理操作；**属性卡牌的唯一使用窗口是工匠世界**（见 8.3）

### 9.2 重量与阈值系统

- 每件拾取物品具有**重量属性**

- 背包内物品总重量存在一个**阈值：100**

- 总重量**未超过阈值**时：无惩罚，玩家正常移动

- 总重量**超过阈值**后：开始影响玩家角色，**移动速度降低**

- 超重程度越高，速度惩罚越大，**最慢保留 20% 基础移速**

- **惩罚曲线（首版定为线性递减，可配表）**：

  - 移速系数 = max(**20%**, 1 − **80%** × (总重量 − 阈值 100) ÷ 100)

  - 即：超重后每超出 1 点负重扣 0.8% 移速，总重量达到 **200** 时降到最低 20%

  - 示例：负重 150 → 保留 60% 移速；负重 200 及以上 → 保留 20% 移速

### 9.3 武器栏联动（= 小队技能栏）

- 武器栏同样采用格子化机制，**是小队的技能栏**：栏内**武器模块对小队全体成员生效**（见 8.2、16.5）

- **只有武器栏中的物品才产生效果**：**属性加成（装备）与技能修正（武器模块）**均在此生效，且**对小队全体成员生效**；背包内物品无任何战斗效果（见 8.2、16.5）

- 武器栏内物品的重量与主背包**联动计算**，共同计入总重量

- 玩家在背包与武器栏之间统一规划负重

### 9.4 取舍博弈

| 维度     | 冲突点                   |
| ------ | --------------------- |
| 拾取更多装备 | 提升战力/收益，但增加重量         |
| 超重惩罚   | 移动变慢，战斗机动性下降，死亡风险上升   |
| 背包空间规划 | 格子摆放策略影响能携带多少物品       |
| 死亡风险   | 背包装越多，死亡时损失 70% 的代价越大 |

## 十、武器系统

### 10.1 专属绑定武器（= 技能石）

- 每个角色**开局即绑定专属武器**（即其**技能石**，见 16.5），定义角色的基础战斗风格（速射/散射/穿透/弹射/召唤/陷阱等）

- 🔴 **三方一对一硬绑（已定）**：**英雄 → 武器 → 主动技能**。英雄绑定武器（`CFG.heroes[].weapon`，8 英雄 ↔ 8 武器严格一对一）、武器绑定主动技能（`CFG.weapons[].skills.skill`）；**武器不可丢弃 / 更换**，**技能石（主动技能）不做独立物品形态**。玩家的主动技能由所用英雄唯一决定（见 16.5、8.2）。

- 武器本身**不可丢弃、不可替换**——**武器等级（= 技能等级）在局外用结晶升级**，是深度成长线（见 6.6、8.2）。

### 10.2 武器栏格子机制（= 小队技能栏）

- 武器栏采用与背包类似的**格子化摆放机制**（背包肉鸽风格），是小队共用的**多槽技能栏**

- **武器栏是小队战斗力的唯一来源区**：属性、技能、词条标签只有在此才生效（见 9.1.0）

- 栏内物品**对小队全体成员生效**：**武器模块**按各成员自己武器的技能标签过滤、等级各走各自的武器等级；**装备（属性件）**的生命/攻击/防御/移速/能量加成全队共享（见 8.2、16.5）
- **局内增益同样全队共享**：属性卡牌（8.3）与战争雕像 Buff（4.4）的加算/乘算加成对队长 + 全部队友生效，吸血归属发射者各自独立（见 16.5）

- 武器配件、**武器模块**、**词条标签**、弹药等以不同形状格子形式嵌入武器栏；**词条标签会影响全队武器技能的效果**（见 8.2、16.5）

- 通过合理摆放提升武器效能，格子规划本身成为策略玩法的一部分

### 13.2 地图生成系统

**职责**：生成有限封闭地图，管理怪物刷新点（随机圆）与祭坛刷新点。

**核心功能**：

1. **地图生成**：根据关卡配置生成矩形/不规则封闭区域，四周墙壁不可穿越
2. **出生点**：玩家固定在地图几何中心出生
3. **刷新点管理**：

   - 怪物刷新点：地图边缘区域随机选取

   - 祭坛刷新点：全地图随机选取，需做**不重叠检测**（碰撞检测）
4. **空间裂缝子地图生成**：当玩家进入空间裂缝时，生成全新子地图实例，原地图挂起保留状态

**数据需求**：

| 数据项     | 类型             | 说明             |
| ------- | -------------- | -------------- |
| 地图尺寸    | Width × Height | 从关卡配置表读取       |
| 墙壁定义    | 坐标集合           | 封闭边界           |
| 刷新点列表   | List\<Vector2> | 可用刷新坐标         |
| 怪物配置表   | Table          | 怪物类型、数量、刷新间隔   |
| 祭坛配置表 | Table          | 祭坛类型、刷新概率、上限数量 |

**关键接口**：

- `MapManager.GenerateMap(LevelConfig)` — 生成地图

- `MapManager.GetSpawnPoint(SpawnType)` — 获取可用刷新点（含不重叠校验）

- `MapManager.SaveState()` / `RestoreState()` — 空间裂缝场景的保存/恢复

### 13.3 怪物系统

**职责**：管理怪物刷新、AI 行为、死亡掉落。

**核心功能**：

1. **刷怪管理**：

   - **随机圆生成机制**（见 3.3）：刷怪圆模板（半径/每波数量/怪物池/刷新间隔/触发方式）+ 关卡层（等级、精英/BOSS 基础数量、全场怪物上限）三层模型

   - **怪物编号**：普通 `NMxxxx`、精英 `EDxxxx`、BOSS `BSxxxx`，对应怪物配置表条目；**BOSS 由关卡层投放、不进随机圆**；**精英怪首版以「词缀精英」形式实现（普通怪按概率转化，见 16.9）**；裂缝子地图例外——精英（ED 编号）随敌群一次性投放（见 5.1）

   - **精英怪/BOSS 基础数量**由关卡配置表决定，可被局内效果增减（邪神雕像等，**来源待定**，见 4.5）

2. **怪物 AI**：基础行为（追击、攻击、巡逻），弹幕射击定位下怪物的**弹幕攻击模式**待细化
3. **死亡掉落**：

   - 掉落金币（自动入账）

   - 掉落宝箱（生成场景物体，玩家拾取后进背包）

   - 掉落物后续可扩展

   - **掉落物停留时长可配**（`CFG.pickup`）：金币 / 结晶默认 **永不消失**（`life = -1`）、经验宝石 30 秒；同屏数量超上限（`maxPickups`，建议 200）时把**最旧的自动磁吸结算**（不吃掉价值）

### 13.4 祭坛系统（原场景物体系统）

**职责**：管理地图上随机刷出的祭坛。**游戏内只有一种通用"祭坛"实体**，战争雕像/女神雕像/宝箱/邪神雕像/工匠雕像/空间裂缝都是它在配置表中的不同行（不同外包装 + 不同效果参数），统一处理交互与效果执行。

**核心功能**：

1. **祭坛刷出**：从祭坛效果配置表按刷新权重随机选取行，在不重叠的位置生成
2. **交互处理**：英雄进入祭坛的**交互圆圈**范围 → 圈内**停留 2-3 秒** → 停留完成触发效果（停留期间离开圆圈则进度**缓慢衰减、不归零**，衰减速度 = 积累速度 × 1.2，重新进入继续累积）
2.1 🔴 **判定圈统一规则（已定，全套交互共用同一实现 `judgeChannel`）**：

   - **任一英雄都可触发**：**所有英雄都是独立个体**，判定不区分"只有队长能触发"——**任一小队成员**（队长或任意 AI 队友）在判定圈内都能推进判定
   - **同一判定不可同时触发**：判定是**单一实例**——只有**一份进度**、**一个持有者**（`holder`）；两名英雄同处一个判定圈**不会让进度加速**（不是每人各算一份），也**不会各自触发一次**
   - **完成即消费**：读条读满立刻结算并**把判定本身消费掉**（雕像/祭坛从地图移除、进度归零），因此**不可能被第二个英雄重复触发**
   - **离开即衰退**：圈内英雄**全部离开**后进度按 1.2 倍速缓慢衰退（不是瞬间清零，可回来接着读）；**受击**仍立即归零
   - **判定半径**：绘制半径 × `CFG.altarJudgeMul`（1.2，外扩 20% 容差）
   - **适用对象**：祭坛/雕像、空间裂缝返回信标（此例 `decay = 0`，离开圈进度**保留**）、工匠世界 NPC 与返回出口、**撤离点雕像**（见 4.4、5.2、5.1、4.6）
3. **效果执行（效果积木机制）**：触发后按该行配置的**效果列表依次尝试执行**；效果类型即"积木"（恢复生命/随机增益/给予宝箱/调整怪物/场景传送等），由程序实现效果库，策划只在表中组合与填参；**触发成功后祭坛消失**（一次性，不会持续存在）
4. **数据驱动**：新增祭坛 = 配置表加一行，**零代码扩展**

**效果类型枚举（效果积木库）**：

```
恢复生命   → 即时回血，执行后祭坛销毁
随机增益   → 附加 Buff，祭坛销毁，效果到期自动移除
给予宝箱   → 生成未开封货物进入背包（走背包容量/叠加校验）
调整怪物   → 修改怪物数量/属性（限时，-1 为永久）
场景传送   → 触发场景切换（工匠世界/裂缝子地图共用此积木）
后续扩展   → 程序向效果库新增积木，即可被任意祭坛组合
```

**已定义物体清单**：

| 物体   | 功能类型 | 效果        | 参数         |
| ---- | ---- | --------- | ---------- |
| 宝箱   | 一次性  | 进背包为未开封货物 | 品质、占格尺寸、重量 |
| 女神雕像 | 一次性  | 恢复25%生命   | 恢复比例       |
| 工匠雕像 | 场景传送 | 进入工匠世界（可使用宝箱/属性卡/金币服务，无武器升级） | 工匠世界配置、返回方式（见 4.6） |
| 战争雕像 | 持续时间 | 随机获得 4 增益池中 1 个，持续 20 秒 | 增益池（狂力/迅击/疾风/汲血，见 4.4） |
| 邪神雕像 | 持续性/永久性 | 调整怪物数量/属性（±100%） | 5 种雕像、幅度区间（见 4.5） |
| 空间裂缝 | 场景传送 | 进入子地图     | 子地图配置、返回方式 |

**数据需求**：

| 数据项    | 类型    | 说明                |
| ------ | ----- | ----------------- |
| 祭坛配置表  | Table | 祭坛ID、类型、效果参数、刷新概率、交互圆圈半径、停留时长（当前统一 2-3 秒） |
| 增益效果表  | Table | 战争雕像可用增益列表（狂力/迅击/疾风/汲血，见 4.4） |
| 子地图配置表 | Table | 空间裂缝进入的子地图配置      |

**关键接口**：

- `SceneObjectManager.SpawnObject(ObjectConfig, Vector2 pos)` — 在指定位置生成物体

- `SceneObjectManager.Interact(Player player)` — 进入圆圈后开始 2-3 秒停留读条，读条完成触发效果

### 13.5 背包系统

**职责**：管理背包网格（仓储区）、物品摆放、重量计算、死亡掉落判定。

**核心规则（背包肉鸽核心，见 9.1.0）**：**只有武器栏中的物品影响英雄属性与技能；背包物品仅作仓储/战利品，无任何战斗效果**。背包系统与武器系统的加成计算严格分离，仅在重量汇总时联动。

**核心功能**：

1. **网格管理**：

   - 背包为二维网格，固定尺寸 **6×4**（24 格）

   - 每件物品有形状定义（占用的格子集合，如 2×3、1×1、L 形等）

   - 物品放入时需校验：格子空闲 + 形状匹配 + 不越界

   - 支持拖拽摆放；首版物品形状固定，不支持旋转
2. **物品管理**：

   - 普通装备：占格、有重量

   - 未开封货物（宝箱）：占格、有重量、局内不可开启；**同品质可叠加**（1 格计数，重量按数量累计）

   - 经验水晶/金币：不占格，直接入账
3. **局内管理交互**：

   - 支持**丢弃**（生成地上掉落物）、**整理**（重排格子）、**替换**（拖拽交换）

   - 拾取宝箱时：背包满且无同品质可叠 → 无法拾取，宝箱留地上
4. **重量计算**：

   - 实时计算背包 + 武器栏所有物品总重量

   - 对比阈值，超阈值触发移速惩罚

   - 惩罚曲线：线性递减，移速系数 = max(20%, 1 − 80% × (重量 − 100) ÷ 100)
5. **死亡掉落判定**：

   - 死亡时按未保险占用格子剔除 70%

   - 掉落优先级：整件物品优先 → 价值高的小件次之

   - 已保险物品不参与掉落

**数据需求**：

| 数据项    | 类型     | 说明            |
| ------ | ------ | ------------- |
| 背包尺寸   | 6×4    | 网格行列数         |
| 物品形状定义 | 格子坐标集合 | 每件物品的占格形状     |
| 物品重量   | float  | 每件物品的重量值      |
| 物品叠加数  | int    | 可叠加物品（同品质宝箱）的当前数量与单格堆叠上限 |
| 物品价值   | int    | 用于死亡掉落优先级判定   |
| 重量阈值   | float  | 触发移速惩罚的临界值（当前定为 100） |
| 惩罚曲线   | 公式/表   | 超重比例 → 移速降低比例（下限：保留 20% 基础移速） |
| 保险标记   | bool   | 物品是否已保险       |

**关键接口**：

- `Backpack.TryPlaceItem(Item, Vector2 gridPos, Rotation)` — 尝试放入物品（校验+放置）

- `Backpack.RemoveItem(Item)` — 移除物品

- `Backpack.GetTotalWeight()` — 计算总重量

- `Backpack.CheckOverweight(float threshold)` — 超重判定

- `Backpack.CalculateDeathPenalty()` — 死亡掉落计算（返回需剔除的物品列表）

- `Backpack.IsOccupied(Vector2 gridPos)` — 格子是否被占用

- `Backpack.DropItem(Item)` — 丢弃物品（生成地上掉落物）

- `Backpack.SortItems()` — 一键整理

- `Backpack.TryStackItem(Item)` — 尝试叠加到同品质未开封货物

### 13.8 战斗系统

**职责**：处理攻击判定、伤害计算、死亡触发。

**核心功能**：

1. **攻击判定（弹幕射击）**：玩家攻击以**弹道/弹幕**形式呈现，命中判定为**弹道与目标的碰撞检测**；怪物攻击同样以弹幕形式表现（敌人弹幕模式待细化）；性能目标见 15.2（每秒 100 弹道）
2. **伤害计算**：实际伤害 = **max(1, 攻击 − 防御)**，即防御最多将伤害减免至 1 点保底
3. **攻击频率**：由**技能 CD** 决定攻击间隔（普攻/技能各自独立 CD，见 8.2）；能量不足时技能无法释放，普攻无消耗
4. **能量循环**：能量按"能量恢复/秒"回复，技能消耗能量——形成"普攻填充 + 技能爆发"循环
5. **死亡处理**：怪物死亡 → 掉落 + 进度条推进；玩家死亡 → 触发死亡惩罚

**关键接口**：

- `CombatSystem.ProcessAttack(Attacker, Target)` — 处理一次攻击

- `CombatSystem.CheckHit(Vector2 origin, float range, float angle)` — 命中判定

- `CombatSystem.CalculateDamage(float attack, float defense)` — 伤害计算

- `CombatSystem.OnMonsterDeath(Monster)` — 怪物死亡处理

- `CombatSystem.OnPlayerDeath()` — 玩家死亡处理

### 13.9 撤离系统

**职责**：管理撤离点获取、读条撤离、撤离打断。

**核心功能**：

1. **撤离点生成**：**仅由最终 Boss 击败触发**——在 **Boss 死亡位置生成撤离点雕像**；**一张地图内只能有 1 个撤离点**；**Boss 死亡前不生成**
2. **撤离激活**：玩家**前往撤离点雕像**，在雕像附近触发，开始读条
3. **读条管理**：撤离读条 **8 秒**；**任一小队成员在判定圈内即自动推进**（无需按键）；**圈内英雄全部离开** → 进度缓慢衰退（1.2 倍速）；**受击立即归零**；雕像保留，重新站回圈内即可继续读（判定圈统一规则见 13.4）
4. **撤离结果**：成功 → **背包内物品不作为物品带出**，而是**按各自固定价值 × 统一折算率 0.5 折算为进化结晶**（**2 点价值 = 1 结晶**；含未开封宝箱、装备/武器模块、道具、属性卡牌资产；**局内经验与金币一律归零、不参与折算**，固定价值表见 6.6，另见 6.5、13.11）；中断 → 继续游戏（雕像仍在）；**无撤离代币**（见 5.2）

**关键接口**：

- `ExtractSystem.SpawnExtractionStatue(Vector2 pos)` — 在指定位置生成撤离点雕像

- `ExtractSystem.StartChanneling(Player)` — 进入雕像判定圈，开始读条

- `ExtractSystem.InterruptChanneling()` — 打断读条（受击/移动触发）

- `ExtractSystem.OnExtractSuccess()` — 撤离成功，进入结算

### 13.10 空间裂缝系统

**职责**：管理场景传送、原地图状态保存/恢复、子地图加载/卸载。

**核心功能**：

1. **裂缝交互**：玩家进入空间裂缝祭坛的交互圆圈**停留 2 秒** → 触发传送
2. **原地图状态保存**：序列化当前地图所有状态（已杀怪物、已拾物品、剩余物体、进度条等）
3. **子地图加载与开场冻结**：生成全新子地图实例，玩家传送进入；进入后**冻结 3 秒**（`freezeTime = 3.0`），玩家与所有敌人全部静止、双方均不受伤（全员无敌），屏幕中央显示红色大字倒计时 3 / 2 / 1，倒计时结束同时解冻并开始战斗；冻结期间任务限时不倒计时
4. **一次性投放**：冻结结束瞬间，按任务配置的 `spawnCount` 把本次任务所需的**全部敌人（含精英 ED 编号）一次性投放完毕**，之后不再增援；投放位置在两个投放区域内散布，避开障碍、玩家、返回信标
5. **任务变体与奖励**：进入时按权重随机任务变体（深入猎杀 / 歼灭作战 / 闪电突袭，见 5.1）；任务完成刷出「任务奖励宝箱」，累计击杀 12 只刷出「裂缝奖励宝箱」；限时超时任务失败但敌人不消失；剩余敌人留场可继续清剿
6. **返回机制**：子地图内通过**返回信标**读条 **5 秒**返回（**仅受击打断归零，移动不打断**）→ 恢复原地图状态 → 玩家传送回原位置
7. **状态隔离**：子地图与原地图的背包/角色属性共享，但地图状态独立

**关键接口**：

- `RiftSystem.EnterRift(Player, RiftConfig)` — 进入空间裂缝

- `RiftSystem.SaveOriginMapState()` — 保存原地图状态

- `RiftSystem.LoadSubMap(SubMapConfig)` — 加载子地图

- `RiftSystem.StartFreeze(freezeTime)` — 开场冻结（3 秒全员无敌静止 + 红色倒计时）

- `RiftSystem.DeployAllEnemies(spawnCount, eliteCount)` — 冻结结束时一次性投放全部敌人（不再增援）

- `RiftSystem.ReturnToOriginMap()` — 返回原地图

- `RiftSystem.RestoreOriginMapState()` — 恢复原地图状态

### 13.11 结算系统

**职责**：撤离成功后汇总带出物品、按统一口径折算为进化结晶、展示收益。**本系统不承担开箱职责**——开箱只发生在工匠世界（见 4.6、16.4）。

**核心功能**：

1. **物品清点**：汇总撤离时背包 + 武器栏内的全部物品（含未开封宝箱）
2. **统一折算**：对每件物品执行 `Math.floor(固定价值 × 0.5)` 并累加为进化结晶——**宝箱 / 装备 / 武器模块 / 道具 / 卡牌同一套折算率**，不再按类别区分比例
3. **卡片资产折算**：属性卡牌资产按固定价值 4 / 张参与同一折算
4. **归零项**：局内经验与金币一律归零、**不参与折算**
5. **收益展示**：结算界面展示折算明细（宝箱 / 装备与武器模块 / 道具 / 卡牌 → 结晶 分项 + 合计）与带出物品清单

**明确不做**（与旧稿的区别）：

- ❌ 结算界面**不开箱**、不生成开箱结果
- ❌ 结算界面**无拖拽分配**、无容量校验（该逻辑只在工匠世界开箱时存在）
- ❌ 未开封宝箱**不带出本体**，只折算价值

**关键接口**：

- `SettlementSystem.CalcConvert(Run)` — 遍历背包 + 武器栏，按固定价值 × 折算率累加（对应 `calcSettleConvert`）

- `SettlementSystem.CrystalsFor(Item)` — 单件物品折算 `Math.floor(value × valueRate)`

- `SettlementSystem.FinalizeRewards()` — 汇总收益并写入局外存档

## 十五、技术方案与单局时长

### 15.1 技术方案

- **游戏形态**：多端游戏，**横版**画面，分辨率 **16:9，1920×1080**

- **开发路线**：

  - **后期**：正式开发使用 **Godot 4.7.2**

### 15.2 性能预估（每秒渲染目标）

| ----- | ---- |
| 弹道    | 100 个 |
| 特效    | 80 个 |
| 角色（含怪物） | 80 个 |

> 弹幕射击玩法的核心性能压力在弹道与特效，原型阶段即需按此指标验证 HTML 方案的可行性上限。

### 15.4 关卡与赛季结构

- **共 99 个关卡**

- 完成全部 99 关后进入**赛季玩法**：目前定位为**无限地图玩法**，具体规则待细化；**首版暂缓**（见 16.7）

### 15.5 技术调研结论（HTML 原型 → Godot 4.7.2 迁移）

**HTML 阶段选型建议**：

- **渲染框架：PixiJS 8**（纯渲染性能优先，适配弹幕射击）+ DOM 实现 UI/背包/卡牌界面；若需要内置场景管理/输入/音频等完整 2D 引擎能力，备选 Phaser 4

- 渲染后端：**WebGPU 优先、WebGL 兜底**（`navigator.gpu` 特性检测）

**性能优化关键技术（按优先级）**：

1. **空间哈希网格碰撞**：把弹道×怪物的 O(n²) 判定降到约 O(n)——同类 Web 弹幕游戏实测 1000 弹道 + 200 怪物时，暴力判定需 20 万次/帧，空间哈希后降至数百次；本项目"每秒 100 弹道 + 80 角色"的目标在此方案下有充足余量
2. **对象池**：敌人、弹道、拾取物、特效**分池管理**（混池会出诡异 bug），避免每帧创建/销毁对象触发 GC 卡顿。**HTML 阶段暂缓**（见 16.7）——对象池解决的是 JS 的 GC 抖动问题，迁到 Godot 后该问题的性质不同（Godot 用引用计数 + 引擎自带批处理），需按引擎特性重新设计，收益不可平移
3. **零 GC 写法**：哈希键用整数（比字符串键快 3-10 倍）、预分配桶数组、typed array 存储热点数据
4. **按碰撞组分层哈希**："玩家弹道 vs 怪物"、"怪物弹幕 vs 玩家"分表，避免弹道间互检
5. **绘制批次化**：纹理图集合并，批次控制在 100 次/帧以内；数据驱动（关卡/刷怪/祭坛全部 JSON 配表）

**迁移 Godot 的架构建议**：

- HTML 原型阶段就把**业务逻辑与渲染解耦**（纯 TS 核心循环 + 渲染适配层），不深度绑定框架 API（如 Phaser 的 Scene/Group）——迁移时只需替换渲染层，逻辑平移
- 对应关系：JSON 配表 → Godot **Resource（.tres）**；事件总线 → Godot **信号（Signal）**；全局管理器 → **Autoload 单例**；各子系统 → 独立 **Scene**
- Godot 4 的 2D 管线是强项（像素完美、内置 TileMap/物理/导航），2D 弹幕类项目迁移成本低；工程上注意：目录按功能划分（gameplay/world/ui）、信号命名统一、避免巨型 Autoload

> 结论：**PixiJS 8 + 对象池 + 空间哈希**的技术栈可满足首版性能指标，且以"逻辑/渲染分离 + 全配表驱动"的架构编写原型，可将后期迁移 Godot 4.7.2 的成本降到最低。

## 十七、Boss 设计：弹幕范式与阶段结构

> 本章为 2026-09-29 调研（弹幕射击 / 肉鸽 Boss 设计范式）后的设计成果，用于替换首版「3 个 Boss 机制雷同」的过渡实现。
> 🔴 **核心结论：Boss 之间的差异必须来自「机制范式」，而不是数值。** 只调 `cd / radius / dmgMul` 的三只 Boss，打起来是同一只。

### 17.1 现状诊断（改造前）

| 项 | 现状 | 问题 |
| --- | --- | --- |
| Boss 数量 | 3 个（BS0001~BS0003） | 铺满 10 关不够分 |
| 行为 | 只有 4 件事：追玩家 / 定时圆形 AOE（预警→爆炸）/ 定时召唤小怪 / 接触伤害 | **完全不发弹幕** |
| 差异 | AT207/208/209 仅数值不同 | **三只 Boss 打起来一模一样** |
| 阶段 | 无 | 血条掉光前没有任何节奏变化 |
| 电报 | 只有一个红圈（`warnTime`） | 表现语言单薄，玩家无法从"形状"预判"招式" |

**结论**：当前 Boss 本质是"血多的精英怪"，不符合弹幕射击品类的预期。

### 17.2 调研结论（弹幕射击 / 肉鸽 Boss 设计范式）

#### 17.2.1 弹幕模式 8 大范式

| # | 范式 | 视觉特征 | 常见变体 | 难度旋钮 | 本项目用途 |
| --- | --- | --- | --- | --- | --- |
| 1 | **放射 Radial** | 360° 均匀扩散，像烟花/涟漪 | 逐发偏角、多圈、奇偶交错 | 弹数 / 角度 / 速度 | 教学关 Boss 基础招；其它招式的"底噪" |
| 2 | **螺旋 Spiral** | 边转边射，弹数少但视觉强 | 单/多臂、顺逆交叉、速度差分层 | 臂数 / 每发偏角 / 转速 | 中段 Boss 主招（视觉招牌） |
| 3 | **扇形 Fan** | 单向扇形，攻击意图明确 | 宽扇/窄密扇、围绕玩家位置展开 | 扇角 / 弹数 / 密度 | 压制型 Boss（逼走位） |
| 4 | **瞄准 Aimed** | 直指玩家当前位置 | 直瞄 / 散射瞄 / 连射瞄 / **预判瞄** | 频率 / 预判系数 | 全套 Boss 的"黏人"底招 |
| 5 | **波/幕 Waves** | 正弦波、帘幕、瀑布推进 | 相位差多层、往返摆 | 波幅 / 波长 / 行距 | 冲锋型 Boss 的落地冲击环 |
| 6 | **网格 Grids** | 规则排布，缝隙可读 | 正网格 / 斜移菱形 / 滚动网格 | 行距 / 列距 / 滚动速度 | 阵地战 Boss（考耐心与读缝） |
| 7 | **花形 Floral** | 对称花瓣，适合"符卡"演出 | 5/6/8 瓣、多层花、旋转花 | 瓣数 / 层数 / 旋转 | 关底 Boss 的招牌技（视觉高潮） |
| 8 | **激光 Laser** | 持续光束，需持续位移躲避 | 单/多束、旋转、扫描、交叉 | 束数 / 转速 / 预热 | 高段 Boss（全新实体，见 17.6） |

> 通用规律：**同一种范式，只要改「弹数 / 角度 / 速度」三个旋钮就能覆盖很大难度区间**——这意味着 8 个发射器足以撑起 10 关的招式池，不需要为每关写新逻辑。

#### 17.2.2 六条设计原则（业界共识，逐条落到本项目）

1. **电报（Telegraph）与可读性**：每个攻击都必须有**清晰的前摇提示**；玩家的失败应当来自"操作失误"而不是"看不懂"。⚠️ 反面教材是"毫无征兆的瞬杀"。
2. **攻击多样性**：招式要考不同能力——反应（弹速）、走位（扇形/激光）、空间规划（网格/波）、资源管理（续航）。**禁止三招同源**。
3. **阶段递进**：分阶段要**加新机制**，而不是只加血加攻（"懒设计"）。阶段转换本身就是玩家的心理里程碑。
4. **公平与反制**：每一招都要有解法（缝隙 / 位移 / 反制窗口），且解法要**在战斗中可读**，不能靠攻略才知道。
5. **主题一致**：Boss 的弹幕应当"讲得出它是什么"（如冰系 Boss 的弹幕会**冻结后散开**）。本项目落法：**招式名 + 弹幕形状与 Boss 主题绑定**（技能表 `name` 即面向玩家的招式名）。
6. **难度可调**：所有招式通过"弹数 / 角度 / 速度"三旋钮配表，不写死。

#### 17.2.3 三阶段结构（推荐骨架）

| 阶段 | 血量段 | 作用 | 设计要点 |
| --- | --- | --- | --- |
| **① 教学（Lesson）** | 100%~66% | 让玩家读懂"这只 Boss 的语言" | 只用 1~2 种基础范式，节奏慢、预警长，给足学习窗口 |
| **② 变奏（Twist）** | 66%~33% | 打破第一阶段的肌肉记忆 | 引入新范式或**组合**（如"放射 + 瞄准"双层），场地出现变化/召唤 |
| **③ 压测（Pressure）** | 33%~0% | 高压检验 | 提速 / 减预警 / 招式混编，但**只remix已教过的机制**，不引入全新规则 |

> 转换规则：阶段切换时 Boss **短暂无敌 + 停手 1.0~1.5 秒**（给玩家喘息与读招时间）；不采用"清屏+全屏弹"这类无预警惩罚。

#### 17.2.4 业界案例 → 本项目映射

| 案例 | 做法 | 本项目落地 |
| --- | --- | --- |
| **《Hades》渐进式设计** | Boss 招式**继承本关杂兵/陷阱机制**，降低学习成本、强化连贯；后续 Boss 复用前作 Boss 招式并强化 | **Boss 招式 = 本关怪物技能的"升级版"**（关卡 `circles` 的怪池决定 Boss 招式的"母题"），最终 Boss 混编前面出现过的机制 |
| **《Risk of Rain》** | Boss 随等级/时间缩放；"加倍难度神龛"用风险换奖励 | 已有：`monsterLevel` 缩放 + **邪神雕像「BOSS 属性」变体**（风险换收益，见 4.5） |
| **《东方 Project》符卡** | 每招有**名字**、有**主题**、有**时限**；弹幕即角色性格 | 技能表条目 `name` = 招式名（HUD 可显示）；Boss 主题（邪神/树母/吞噬者）决定弹幕色与形状语言 |

### 17.3 设计基准（护栏，先定死再填表）

| 护栏 | 取值 | 理由 |
| --- | --- | --- |
| **电报颜色语言** | 红=范围爆炸 ｜ 橙=冲锋/践踏 ｜ 青=激光 ｜ 紫=召唤 ｜ 白=弹幕预警 | 玩家学一次，全 Boss 通用（原则 1） |
| **弹幕性能预算** | Boss **≤ 40 发/秒**；玩家小队 ≈ 20 发/秒；小怪 ≈ 20 发/秒；**合计 < 100 目标** | 15.2 性能红线是每秒 100 弹道，需留余量 |
| **同屏弹幕存量** | Boss 弹幕同屏 ≤ 260 发（超出时新招式排队/降密度） | 防"弹幕墙糊屏"，也保护帧率 |
| **单场时长** | **60~90 秒**（阶段各约 25 秒） | 撤离玩法节奏：Boss 战是"撤离前的门槛"，不宜过长 |
| **可躲性** | 每招必须有缝隙或位移解法；**禁止无预警全屏伤害** | 原则 4 |
| **可退性** | Boss 战不锁地图，玩家可拉开距离重整（Boss 不脱离追击，但受地图尺寸限制） | 搜打撤品类的容错 |
| **阶段转换** | Boss 无敌 + 停手 1.0~1.5 秒，**不清屏** | 避免"刚要赢被打断"的挫败 |

**代码契约（后续加 Boss 只改表、不改逻辑）**

1. **Boss 配招写在怪物表**：`CFG.monsters[BSxxxx].phases = [{ hp, skills: ["ATxxx"] }, ...]`。
   ⚠️ 与 17.6 原稿的偏差：原稿写「`phases` 放技能表 + 技能条目带 `phase` 字段」，落地改为**放怪物表**——「这只 Boss 分几段血、每段用什么招式池」是该 Boss 的**配招**，与 `skillList` 同源；技能条目只描述**招式本身**（形状 + 数值），从而可被多只 Boss 复用（`AT212` 就被 BS0001 与 BS0003 共用）。
   `phases[0].hp` 必须为 `1.0`（满血即生效），`hp` 严格递减。`skillList[0]` 仍是**基础行为技能**（AT207~209：圆形 AOE + 召唤），`skillList[1..]` 是弹幕招式，由 `phases` 编池。
2. **发射必须过护栏**：`PatternSystem.emit(w, m, p, aimAng, spinAng)` 内部查「本 Boss 每秒额度（滑动窗口，用 `m.bossClock` 而非全局时间）+ 同屏存量（只统计 `b.owner === m`）」，超限按**等间隔抽取**裁剪（形状保持对称，而不是砍尾巴），返回**实际发射数**。
3. **电报 = 白圈先亮、到点才发**：`warnTime > 0` 的招式先进入 `patternWarnT` 倒计时（渲染白充能圈 / 扇面），归零才 `bossFire()`；`warnTime = 0`（螺旋类持续招）冷却一到直接连发，不逐发电报。
4. **加新 Boss 的"六件套"**：怪物表一行（含 `phases` / `patternCd`）+ N 条技能表条目（带 `pattern`）。数值只需满足 `每发弹数 ÷ cd ≤ bulletBudget`，护栏会自动兜底。
5. **弹幕寿命**：慢弹幕必须给 `life`（缺省取 `CFG.boss.bulletLife = 6s`），否则 `Bullet` 默认 2.2s 会在半场凭空消失。

## 十六、首版范围与已确认决策（当前开发基准）

> 本章记录讨论后确认的首版方向。若本章与前文的长期规划存在差异，首版开发优先遵循本章；前文内容保留作为后续扩展参考。

### 16.1 首版目标

首版使用 **HTML + PixiJS** 验证单局核心循环，不追求完整内容量。首版暂定范围：

- 1 个角色
- 1 张有限封闭地图
- 3 种普通怪
- 1 个最终 Boss
- 1 个工匠世界
- 3 种宝箱品质/样式：普通、高级、史诗
- 背包网格与武器栏网格
- 装备与武器模块
- Boss 生成撤离点并完成撤离
- 死亡损失规则
- 单局目标时长约 5 分钟，后续根据试玩调整

### 16.2 战斗与地图

- 游戏采用俯视角 2D，玩家使用 `WASD` 进行八方向移动。
- 鼠标主要用于界面、背包和拖拽操作，不控制角色朝向。
- 玩家自动锁定**屏幕内距离最近的敌人**。
- 首版自动攻击为单发直线子弹；子弹朝发射时目标所在位置飞行，不自动追踪。
- 普通怪从地图边缘持续刷新。
- 三类普通怪按击杀进度逐步解锁：近战追击怪、远程攻击怪、冲锋怪。
- 击杀进度达到目标，或战斗时间达到上限，先到者触发 Boss 阶段。
- Boss 出现后继续刷新少量更强的普通怪，直到 Boss 被击败。
- Boss 为混合型：平时追击玩家，定期释放以自身为中心的圆形范围爆炸；范围攻击需要有清晰预警区。
- 首版地图包含少量固定内部障碍物；Boss 的圆形范围攻击不被障碍物阻挡。

### 16.3 Boss 与撤离

- Boss 死亡后，停止刷怪。
- 撤离点**仅由 Boss 击败产生**：Boss 死亡位置生成撤离点雕像，**一张地图内只能有 1 个撤离点**。
- 游戏中没有撤离代币。
- 玩家必须前往撤离点雕像，在附近完成 8 秒读条。
- 撤离读条：**任一小队成员站进雕像圈内即自动读条 8 秒**（不需要按键）；**离开判定圈**进度缓慢衰退、**受击归零**；雕像保留可反复重读。
- 撤离成功后进入结算，背包和武器栏中的装备、武器模块均可保留。
- Boss 死亡前不会生成可用撤离点。

### 16.4 工匠世界与开箱

- 工匠雕像由**雕像池 + 限制器 + 多触发条件**机制投放（详见 4.6.1）：触发条件把配额投入池，限制器决定配额何时落地为地图上的一座真实雕像。
- **工匠雕像生效后消失**：使用雕像进入工匠世界后，该雕像立即从地图上移除；池继续产出新雕像。
- 工匠雕像生成位置随机，且不得与障碍物或其他场景物体重叠，投放点距玩家**至少 300px**。
- 玩家通过工匠雕像进入工匠世界；进入后主地图状态保留。
- **工匠子世界可无限次进入**，不限制总次数。
- 工匠世界为无敌人安全区。
- 工匠世界内有工匠 NPC。玩家靠近 NPC 并交互后弹出开箱 UI。
- UI 展示三种宝箱样式、品质和当前数量；玩家逐个选择宝箱并点击下方“开启”按钮。
- 开箱结果播放宝箱开启表现，并以飞行动画进入待分配区域。
- 玩家将装备拖拽到背包或武器栏，进行格子校验；首版物品形状固定、不可旋转，装备不会自动占用格子。
- 暂不显示具体掉落概率，仅显示宝箱品质和数量。
- 无法放入背包或武器栏的装备可以放弃，放弃后不保留。
- 工匠世界内设置固定返回出口；玩家靠近后完成返回读条，移动会中断并归零。
- 返回主地图后原地图状态保持不变；**可再次进入工匠世界**（由雕像池持续产出新雕像保证，见 4.6.1）。
- 主地图不能开箱；**未开封宝箱不能直接撤离带出本体**——它仍在背包中（占格、计重），撤离结算时按**固定价值 × 统一折算率 0.5 折算为进化结晶**（带不走箱子本体，但箱子价值会变成结晶，见 6.5、6.6）。
- 工匠世界提供消耗**金币**的服务：品质提升 / 洗词缀 / 购买宝箱 / 购买保险契约 / 购买武器模块 / 购买道具；**不含武器升级**（武器升级只在局外成长界面消耗进化结晶进行，见 6.6）。

### 16.5 技能石、武器模块（= 辅助石）与武器栏（= 小队技能栏）

> **术语映射（与代码一一对应；只换外包装名称、不改结构）**
>
> | 流放之路术语 | 本项目游戏内名称 | 代码标识 |
> | ---- | ---- | ---- |
> | 技能石（主动技能载体） | **主动技能**——游戏内称「**技能石**」，**绑定在武器上** | `CFG.skills`（`cat:"active"`、`kind:"skill"`）+ 绑定于 `CFG.weapons[].skills.skill` |
> | 技能石等级 | **武器等级 = 技能等级**（1~100） | `Meta.weaponLv` / `weaponLevelEntry(lv)` |
> | 辅助石 | **武器模块**（旧称「技能辅助石 / 装备模块 / 模组」） | `CFG.moduleDefs`（`kind: "module"`） |
> | 辅助石插槽 = 多槽技能栏 | **局内武器栏（4×3 网格）** | `G.run.weaponInv` |
> | 技能最终效果 | 等级曲线 × 词条 × 连接/套装 | `skillEntry` / `tagCalc` / `resolveSkill` |

- **技能石 = 主动技能（绑定武器）**：主动技能条目（技能表 `kind:"skill"`）就是「技能石」，它**绑定在武器上**（`CFG.weapons[].skills.skill`）；**武器等级 = 技能等级**，二者是同一条线（见 8.2）。
- **辅助石 = 武器模块**：即流放之路的辅助石，**游戏内统一叫「武器模块」**（旧称「技能辅助石 / 装备模块 / 模组」）；代码标识符仍为 `module`（只换外包装，不动结构）。
- **技能石（主动技能）来源 = 武器（不做独立物品）**：主动技能**随英雄的专属武器绑定**——**英雄绑定武器、武器绑定主动技能**，一对一硬绑（见 10.1）；不存在「开出技能石 → 装到武器上 / 替换武器自带技能」的路径。
- **武器模块来源**：**宝箱开出为主**（各品质宝箱内容池均含武器模块定义），**工匠世界金币购买为补充**（金币服务之一，见 6.6）。
- **武器栏就是小队的技能栏（多槽）**：物品以形状格子嵌入武器栏，**放进去才提供战斗效果**；放在普通背包只占格并计入重量，**不提供任何战斗效果**。
- 🔴 **武器栏内的物品与局内增益均对小队全体成员生效**（队长 + 全部 AI 队友），不是只对队长生效。三类来源各自的生效方式：

  | 来源 | 作用对象 | 全队生效规则 |
  | ---- | ---- | ---- |
  | **武器模块** | 技能 | 按**各成员自己武器的技能标签**过滤后分别结算；**等级各自独立**（各按自己的武器等级）；**连接/套装效果全队共享** |
  | **装备（属性件）** | 角色属性 | 生命 / 攻击 / 防御 / 移速 / **能量上限 / 能量回复**加成**全队共享**（队长 `computeStats()`、队友 `companionStats()`） |
  | **局内增益**（属性卡牌 8.3 / 战争雕像 Buff 4.4） | 角色属性、技能 | 加算项（攻击 / 生命 / 防御 / 移速 / 能量）与乘算项（攻速冷却 / 移速倍率）**全队共享**；吸血**归属发射者、各自回自己的血** |

- **统一结算入口**：`runBonus()`（`js/game.js`）汇总属性卡牌 + 战争雕像 Buff，分 `add`（加算）/ `mul`（乘算）两个通道返回，队长与队友共用，结算式为 `最终值 = (基础值 + 武器栏装备 + add) × mul`。
- **唯一的口径例外**：`弹道数量` 卡走词条标签路径（`tagCalc`），不进入属性面板。
- **Buff 按「等级」结算**（4.4）：`G.run.buffs` 里每条增益只保留一份，记 `{ skillId, lv, remain }`；效果值由 `skillEntry(skillId, lv)` 的等级曲线给出（重复触发叠的是**等级**）。旧写法「`{id, stat, mul}` 直接读数」已废止。
- 🔴 **能量池：每个成员各一套**（队友是独立个体，不是队长的附属）——`能量上限 / 能量回复` 对队长与队友**都有实际意义**：队友技能释放条件 = **冷却好 且 自己的能量足够**，释放后**扣自己的能量**；各自按 `regen` 恢复（`companionStats(c).energyMax / .regen`）。
- 🔴 **产物池：每个成员各自独立**（召唤物 / 陷阱都记 `owner = 召唤者`）——`G.run.drones` / `G.run.traps` 是**全队共用的容器**，但**计数与上限按成员隔离**：
  - 召唤物：队友再次施放**只补满自己那一队**，不会顶掉队长或其他成员的无人机；无人机**谁的技能就随谁**——**环绕自己的召唤者**，子弹带 `owner` → 吸血回召唤者自己的血。
  - **召唤者倒下不回收**（已定）：无人机**留在场上继续作战**（只是改为跟随队长以免乱飘），陷阱**留在原地**照常等敌人入圈引爆；两者都不因召唤者阵亡而消失或转移归属。
  - 陷阱：`数量上限` 按成员各自计，超限**只回收自己名下**最旧的一颗。
  - 🔴 **数量上限 = min(技能锚点数量, 英雄「召唤物上限 / 陷阱数量上限」属性)**：技能等级决定"想召几架"，**英雄属性**决定"最多几架"（召唤师 6 / 陷阱师 3 / 其它英雄 2 与 1，见 8.1、8.5 表 1）；该属性走完整属性管线（英雄基础值 + 武器栏装备 + 局内增益），`unitCap()` 统一结算。
- **吸血归属**：子弹记录发射者（`Bullet.owner`），命中时由**发射者自己回血**——队友的输出回队友、队长的输出回队长，互不串味（`applyLifesteal()`）。
- 🔴 **判定圈：任一英雄可触发、但同一判定不可同时触发**（已定，全套交互统一走 `judgeChannel`）：所有英雄都是**独立个体**，**任一小队成员**（队长或任意 AI 队友）站进判定圈都能推进该判定；但同一判定是**单一实例**（一份进度 + 一个持有者），**多人同圈不加速**、读满即**消费**（雕像移除 / 进度归零），**不会被第二个英雄重复触发**；离开圈进度按 1.2 倍速缓慢衰退（裂缝返回信标例外：`decay = 0`，离开即保留）。**撤离点雕像同样适用**——任一成员站进圈内即自动读条 8 秒（不需要按键）（见 13.4、4.4、5.2）。

- **队友是全战斗单位**：AI 队友与队长走**同一套技能系统**——自动普攻 + **释放自己的主动技能（技能石）**，**各自有独立能量池**（各自恢复、各自扣费），按各自技能冷却与能量施放（不做队长的附属；可用 `CFG.team.aiSkill` 关闭）。队友的普攻/技能数值同样吃各自的武器等级、各自武器的标签与武器栏辅助石。
- 武器栏中的辅助石**不需要与武器或其他辅助石相邻**；放入即生效，位置只影响摆放空间（**连接效果除外**，见下）；首版不支持旋转。
- 词缀**不绑定具体技能 ID**，而是匹配武器暴露的技能标签，例如：`弹道数量`、`冷却`、`弹速`、`范围`、`穿透`、`弹射次数`、`伤害`、`召唤物`、`陷阱`。
- 词缀支持两种修改方式：加算与乘算。
- 同一标签的多个词缀统一先合并加算，再合并乘算；计算结果不受辅助石摆放顺序影响。
- 通用计算形式为：`最终值 = (基础值 + 加算总和) × 乘算总和`。
- 离散值和连续值的最小值、最大值、取整规则由标签配置（`CFG.affixTags`），避免叠加产生异常。
- **辅助石等级（1~9 级）** ✅已实现：相同辅助石拖拽合并 → 等级 +1；主词缀有效值 = 基础值 × (1 + (等级−1) × 0.15)；每 3 级为一个阶段（共 3 阶段），逐阶段解锁「强化·技能伤害 / 技能冷却 / 技能范围」附加词缀（配置 `CFG.moduleLevel`）。
- **连接效果** ✅已实现：武器栏内**边相邻且同品质**的辅助石，每对提供 **+3% 技能伤害**（`CFG.moduleLevel.linkBonus`）——几何摆放带来的构建收益。
- **套装效果** ✅已实现：同系列辅助石在武器栏内集齐 N 件触发词缀强化（首版 3 套、均 2 件触发——弹道套装 / 冷却套装 / 增幅套装，见 `CFG.moduleSets`）。
- 首版**仍暂不制作**：随机词缀组合（同一辅助石随机出不同词缀）。

### 16.6 死亡与物品损失

- 专属武器和基础装备不掉落。
- 死亡时，背包中未保护的已开出装备和武器模块，随机损失其总价值约 70% 的整件物品。
- 损失判定暂不采用“占格优先、价值优先”的复杂排序。
- 同一堆宝箱视为一个物品。
- 未开封宝箱在死亡时全部损失，不参与已开出装备的 70% 随机损失规则。
- **未开封宝箱不能撤离带出本体**，但其价值不作废：它作为背包物品，撤离结算时按**固定价值 × 统一折算率 0.5 折算为进化结晶**；若在工匠世界中开启并将结果放入背包或武器栏，结果物品同样按各自固定价值参与同一折算。

> | ---- | ---- | ---- |
> | 输出 | **高**（基准 1.0） | 少量附加，专注清场 |
> | 防御 | **低**（约 0.5~0.7） | 护盾 / 减伤 / 控场 |
> | 恢复 | **低**（约 0.4~0.6） | 治疗 / 回复队友 |

### 19.10.2 获取流程（升级 4 选 1）

**触发点**：`gainExp(v)` 的升级 `while` 循环内（`js/game.js:1927` 附近）。每升 1 级 → 生成 1 次 4 选 1。

**流程**：

1. **升级结算**（既有）：`r.lv++`、`expNext` 重算、`baseStatGain` 全队属性成长、飘字/toast —— **保持不动**。
2. **生成候选（🔴 全队混抽，20.0 修订）**：**遍历全队每个英雄**，各自取池 `CFG.modulePool.perHero[hid]`
   （未列出回落 `CFG.modulePool.default`），各自跑「满级过滤」（该英雄已满 9 级的模块剔除）后，
   **汇总成一个全队候选池** → 再按 `CFG.modulePool.weights` 加权抽 `CFG.levelUp.choiceCount`（=4）个。
   - 🔴 **谁升级不重要**：候选来源是**全队池**，不是升级者一个人的池——升级 = 一次「给全队某位置补强」的机会。
   - 🔴 **4 格已满的队友整体排除**：该英雄 `heroModules[hid]` 无空槽 → **完全不生成他的候选**（避免选了装不上）。
   - 🔴 **每个候选必须带 `heroId` 归属**，UI 显示「**该模块属于哪个队友**」，玩家据此决策。
   - `CFG.levelUp.allowDuplicateOffer = true` → 允许同一模块重复入选（便于快速堆层）。
3. **池过滤（方案 2）**：候选生成前**先剔除各英雄已满级（lv ≥ 9）的模块 ID**；剩余 ID 才参与加权抽取。
4. **兜底**：**全队**过滤后可用 ID 数 = 0（所有人模块都满级 / 所有人 4 格已满）→
   **改出「属性小包 4 选 1」**（见 19.10.4）。
5. **弹窗**：调 `UI.onLevelUpChoice(candidates, onPick, meta)`（契约见 19.10.6），**游戏暂停**（不加倒计时）。
6. **入槽**：玩家点选 → 回调 `onPick(idx)` → 按 19.10.3 规则写入 **`G.run.heroModules[cand.heroId]`**
   （🔴 **候选所属英雄**，不是升级者！）→ `recomputeWeapon()` → **恢复**。
7. **多级连升**：一次 `gainExp` 触发 N 级 → **排队逐个弹**（`modulePoolState.queue`），第 1 个结算完才弹第 2 个，全部完成才恢复。

### 19.10.3 入槽规则（三选一 + 槽满策略）

| 持有状态 | 规则 |
| ---- | ---- |
| **未持有该模块 且 有空槽** | 找**第一个空槽**放入，`lv = 1`，`defId = 候选 defId`。 |
| **已持有该模块 且 `lv < 9`** | `lv += CFG.moduleSlot.stackLevelUp`（=1），**复用 `CFG.moduleLevel` 阶段词缀结算**（`moduleStage` / `moduleEffValue` 沿用，不新增一套）。 |
| **已满级（`lv = 9`）** | **不出现在候选池**（19.10.2 第 3 步过滤）。 |
| **未持有 且 4 槽全满** | 见下方**槽满策略**。 |

> 🔴 **槽满策略（本代理拍板）= 「禁止选取置灰」（不自动替换）**。
>
> **理由**：
> 1. **避免玩家无感知地丢模块**。自动替换会在玩家点选瞬间静默销毁一个已投入 4~9 级的模块（可能还是核心 build），
>    是不可逆的负反馈；置灰则把「弃哪个」的决定权交还玩家，符合本作「背包/构筑管理」的核心乐趣。
> 2. **实现更简单且无隐藏状态**。自动替换需定义「最旧槽」口径（按放入时序？按 `lv` 最低？按 `defId` 排序？），
>    每种口径都会和后续「槽拖拽整理」功能打架；置灰只需读一次「是否有空槽」。
> 3. **与 19.9 方案 7（暂停弹窗）契合**：弹窗期间玩家可切到背包管理界面（19.9 方案 3 的三段横排）**手动弃槽**，
>    或直接选其他候选。UI 上对「槽满且未持有的候选」标 🔒 并附文案「槽位已满，需先弃用一个模块」。
>
> ⚠️ **置灰的判定边界**：只有「未持有 + 无空槽」才置灰；「已持有 + lv<9」的候选**永不置灰**（可继续叠层）。
> 若 4 个候选**全部**被置灰 → 不允许出现（池过滤已保证至少 1 个可叠层 ID；若极端情况下全置灰，则整个弹窗降级为「属性小包 4 选 1」）。

### 19.10.4 兜底：属性小包 4 选 1（数值案）

当**该英雄全部模块满级**（过滤后候选为空）时，弹窗改出「属性小包」：从下表 4 项**选 1**，数值进 `CFG.levelUp.statPack`。

| 选项 | 效果 | 数值（⚠️ **暂定，可调**） |
| ---- | ---- | ---- |
| 强攻包 | `atk` | **+3** |
| 坚韧包 | `hpMax` / `hp` | **+15** |
| 铁壁包 | `def` | **+1** |
| 疾行包 | `spd` | **+8** |

- **配置落点**：`CFG.levelUp.statPack = [{ id, name, stat, value } × 4]`；`G.run.statPackGain`（累计，供 `computeStats` / `companionStats` 读取）。
- **拟数理由**：以「模块满级 ≈ 一局中后期」为基准，
  - `atk +3` 相对单发技能基础伤害（数十量级）≈ 5%~8%，与一张白卡（`baseStatGain.atk 1.5`）的 2 倍，作为「满级后仍能变强」的保底增益**略高于常规升级**但不失控；
  - `hp +15` = 2.5× 常规升级 `hp 6`，抵一次小怪集火；
  - `def +1` / `spd +8` 与现有装备件（`G004` def+3、`G003` spd+25）同量级，**取小值**避免移速溢出。
  - 四者**互斥选择**（选 1），保证「满级后仍有克制取舍」，而非无脑平推。
- **生效通道**：并入 `runBonus().add`（全队生效），**不进 `tagCalc`**（它不是武器词条）。
- **卡面显示（21.21）**：升级 4 选 1 的属性小包卡须把 `stat` 渲染成**中文属性名**——
  主 desc = 「**属性名 +N**」（如「攻击 +3」，数值仍走 `lu-num` 高亮），
  另补一行小字说明 = 「**全队<属性名>提升 N 点**」。属性名优先读 `CFG.statNames`
  （`{ atk:"攻击", hp:"生命", def:"防御", spd:"速度" }`），缺失时 UI 回落内置映射（容错）。
  ⚠️ 旧实现只显示「+3」，看不出加的是什么属性（已修）。

### 19.10.5 生效路径（heroModules 如何汇入现有体系）

**现状**：`tagCalc(tag, forSkill)`（`js/game.js:414`）遍历 `G.run.weaponInv.items` 里 `kind === "module"` 的物品，读 `it.affix` + `moduleEffValue(it)` + 阶段词缀。

**迁移方案（🔴 本节拍板）**：

1. **`tagCalc` 新增读取源 `heroModules` 汇总**，读取顺序 = **先 `weaponInv` 旧模块（兼容期）→ 再 `heroModules` 汇总**。
   两段结果按**同一「先加算后乘算」管线合并**（`flat` 累加、`mul` 连乘），与既有口径一致。
2. **heroModules 汇入口径**：
   - 遍历 **全部存活/在场英雄**（`G.heroDef` + `G.run.companions[].heroDef`）的 `heroModules[hid]`；
   - 每个非空槽 `{defId, lv}` → 查 `CFG.moduleDefs[defId]` → 取 `affix{tag, mode, vals}`；
   - 主词缀有效值复用 `moduleEffValue({affix:{value: vals[q]}, lv})`（**`q` 取槽内品质**）；
   - 阶段词缀复用 `moduleStage(lv)` + `CFG.moduleLevel.stageAffixes`（`forSkill` 时才计，与现有一致）。
3. **`weaponInv` 旧模块路径保留兼容**：`kind === "module"` 物品**在第 3 步仍可存在于 `weaponInv`**（旧存档/旧流程），
   `tagCalc` 照常读取，**直到第 4 步（芯片系统）结束、确认无旧模块来源后再物理删除**。
   ⚠️ 删除时机必须与「宝箱/商店不再产模块」（`CFG.chestContents` 已移除 M*）**同时**，否则会出现「能拿到模块但无处生效」。

### 19.11.2 生成器 `makeChip(defId, q)`

```
makeChip(defId, q):
  - 数值芯片：从 CFG.chips.valuePool 找 defId → { name, tag, mode, vals }
      value = vals[q]
      → { kind:"chip", defId, q, lv:1, shape: CFG.chips.shapes.value, value, affix:{tag,mode,value} }
  - 行为芯片：从 CFG.chips.behaviorPool 找 defId → { name, behavior, vals }
      value = vals[q]
      → { kind:"chip", defId, q, lv:1, shape: CFG.chips.shapes.behavior, value, behavior }
  - 品质色：UI 侧读 CFG.itemQualities[q].color（物品不存色，与既有物品一致）
```

- **`defId` 前缀约定**：`C_V_*` = 数值芯片，`C_B_*` = 行为芯片（决定走哪条生成分支）。
- 品质 `q` 决定生成哪类：`q ∈ {0,1}` → 数值；`q ∈ {2,3}` → 行为（`CFG.chips.qualityMode`）。

### 19.11.8 芯片与背包重量的关系

🔴 **本节拍板：芯片计入负重**（与其余物品一致）。

| 项 | 数值（⚠️ **暂定，可调**） | 理由 |
| ---- | ---- | ---- |
| 数值芯片重量 | `q + 1`（白 1 / 蓝 2 / 紫 3 / 金 4） | 品质越高越重，提供"带不带高价值芯片"的取舍。 |
| 行为芯片重量 | `(q + 1) × 2`（紫 6 / 金 8） | 行为芯片占格更大（2×1）、更稀有，重量翻倍强化取舍。 |

  ② 与搜刮背包共用一套重量规则（本作核心是「搜打撤」的**取舍**），芯片不该有特权；
  ③ 数值保守（满背包 30 格全金数值芯片 = 120 重量），确保**极端构筑会明显变慢**但不至于寸步难行。
- ⚠️ 若实测手感过重，**先调 `CFG.chips.weightMul`（新增全局系数）**，不要单体改每个芯片。

## 19.12 行为芯片积木（✅ 已实现，`chip_behavior_test` 48 条锁定）

### 19.12.1 四种行为的数据契约

统一字段：`behavior = { type, value }`（`value` 来自 `CFG.chips.behaviorPool[].vals[q]`，见下表）。

| type | 中文 | `value` 语义（`vals[q]`） | 注入点 | 数据通路 |
| ---- | ---- | ---- | ---- | ---- |
| `bounce` | 折射 | 命中后**弹射次数** N（`vals = [1,1,2,2]`） | **bullet 命中后**（`Bullet` 命中回调） | 命中未消亡时，取附近新目标 → 改变 `bullet` 速度方向并续命，剩余弹射次数 -1（**复用现有 `bounce` 字段链路**）。 |
| `burn` | 燃蚀 | 每秒**灼烧伤害** N（`vals = [3,5,8,12]`），持续 3 秒 | **bullet 命中后** | 给被命中怪物挂 `m.burn = {dps, remain}`；`Monster.update` 扣血 + 渲染火色描边。 |
| `split` | 裂变 | 击杀后**分裂小弹**数量 N（`vals = [1,1,2,3]`） | **敌人死亡时**（`onMonsterKilled` / `damageMonster` 致死分支） | 死亡怪物位置生成 N 枚继承部分属性的小弹（`owner` 沿用击杀弹 owner）。 |
| `chain` | 链锁 | 命中后**传导目标数** N（`vals = [1,1,2,2]`） | **bullet 命中后** | 命中后向 N 个最近敌人发射瞬结（闪电/线段）并结算伤害；**链锁标记**防止无限链。 |

- 🔴 **`value` 取 max 不叠乘**（同 type 多枚芯片）：与 19.11.5 一致。
- **四种行为与 `CFG.chips.behaviorPool` 一一对应**：`C_B_BOUNCE`→bounce / `C_B_BURN`→burn / `C_B_SPLIT`→split / `C_B_CHAIN`→chain。

### 19.12.2 注入点（`SkillSystem` / `Bullet` / `Monster`）

| 行为 | 需要接入的函数 | 需读取的字段 |
| ---- | ---- | ---- |
| `bounce` | `Bullet` 命中处理（现有 `bounce` 计数） | `bullet.behavior.value`（剩余次数） |
| `burn` | `damageMonster` / `Monster.update` | `monster.burn = {dps, remain}` |
| `split` | `damageMonster` 致死分支 / `onMonsterKilled` | `killer` 弹的 `behavior.value` + `owner` |
| `chain` | `Bullet` 命中处理 + 索敌（`nearestMonster`） | `bullet.behavior.value` + 已链集合 |

- ⚠️ **`LaserBeam`（17.7 已实现）走弹幕吞噬路径，不在本规格范围**；行为芯片**只挂 bullet 类技能**，召唤/陷阱是否挂载**待定**。

### 19.12.3 ✅ 验收断言清单（`chip_behavior_test.js`，未来锁定行为）

1. `behavior` 字段从 `resolveSkill` 结果**透传到实际生成的 `Bullet` 实例**。
2. `bounce`：命中 1 个目标后 `bullet` 转向并继续存在，剩余次数按 `value` 递减；次数耗尽后消亡。
3. `burn`：命中后怪物获得 `burn.remain ≈ 3s`，每帧按 `dps` 扣血；`remain` 归零后停止扣血。
4. `burn` 的 `dps` 与 `vals[q]` 一致（4 档分别 3/5/8/12）。
5. `split`：击杀怪物后场上新增 `value` 枚小弹，`owner` 与击杀弹一致。
6. `split` 的小弹**不再触发 `split`**（防止无限分裂，需显式护栏）。
7. `chain`：命中后向最近 N 个敌人传导伤害，目标数 ≤ `value`。
8. `chain` 不重复链接同一敌人（链锁标记生效）。
9. 同 type 多枚芯片 → 生效 `value` = **max**（非叠乘）。
10. **无**行为芯片时，bullet / monster / onKill 行为与接入前**完全一致**（回归护栏，等价性断言）。

> 目标：解决「AI 回答/思考越来越慢」的工程根因，且**零功能回归**。

## 零、问题诊断（实测数据）

| 指标 | 现状 | 问题 |
|---|---|---|
| `js/game.js` | **5509 行 / 296KB** 单文件 | 每次改动整读 → 上下文爆 |
| 核心 5 文件 | 12,544 行 / 728KB | 改 3 个文件即 ~700KB 上下文 |
| `run_tests.sh` 门禁 | 60 测试 / 50.7 秒 | 每轮跑 2~3 次 = 2 分钟 |
| 测试代码 | 16,943 行（1.35× 业务代码） | 体积超过业务代码本身 |
| `/workspace` 截图 | 31 张 / 16MB | 图片 token 消耗极高（用户要求保留） |
| dev_guide | 1043 行 | 每次恢复上下文全读 |

**根因三条**：① 单文件过大导致「整读」不可避免；② 无文件地图，每次靠 grep 摸索；③ 无归档机制，历史与现状混放。

## 一、重构目标（可量化）

| 指标 | 现状 | 目标 |
|---|---|---|
| 最大单文件 | 5509 行 | **≤ 1200 行** |

| 门禁耗时 | 50.7s | **≤ 25s**（分套件 + 可 --quick）|
| 单次改动平均读取量 | ~700KB | **≤ 150KB**（靠文件地图定位）|

**硬约束：零功能回归** —— 门禁 2661 断言必须保持全绿，线上表现不变。

## 二、拆分方案

### 2.1 game.js（5509 行）→ 5 个文件

| 新文件 | 内容 | 预估行数 | 来源行段 |
|---|---|---|---|
| `js/game.js` | 保留：世界/实体核心/主循环骨架 | ~1100 | 保留 World/Monster/Player/Bullet 类 |
| `js/items.js` | 物品/装备/背包/芯片构造与计算 | ~900 | 26~520 行（Inventory/makeChest/affix/computeWeapon 等）|
| `js/combat.js` | 战斗结算/伤害/技能解析/特效 | ~1200 | damageMonster/explode/FX/Laser/行为芯片 |
| `js/modes.js` | 关卡机制/毒圈/赛季/无尽入口 | ~900 | 4330~5509 行（毒圈/赛季/深渊门/无尽流程）|
| `js/render.js` | 渲染（render/renderWorld/renderCity）| ~1200 | 3509~3940 行 + renderWorld |

⚠️ **拆分铁律**：
- **纯物理搬移**，不改一行逻辑（降低风险）
- 每个新文件顶部写「文件职责 + 依赖方向」注释
- **加载顺序**必须与拆分前一致（全局脚本无模块化，靠 index.html 顺序）
- 拆分后立即全量门禁 + e2e 验证

### 2.2 其他文件

|---|---|---|

### 2.3 测试分层（解决门禁 50 秒）

- `run_tests.sh` 拆为 **4 套件**：
  - `core`（核心逻辑，~15 测试，~10s）
  - `ui`（UI/布局，~20 测试，~15s）
  - `feature`（玩法系统，~15 测试，~15s）
  - `perf`（性能/压测，~10 测试，~10s）
- 新增 `run_tests.sh --quick` = 只跑 core + 冒烟（~12s），日常开发用
- **全量门禁仍是交付前必跑**（口径不变：exit=0 且 bad=0）

## 三、文件地图机制（长期防慢）

### 3.1 新建 `AGENTS.md`（项目根，新会话第一份要读的文件）

内容结构（控制在 **150 行内**）：
```
1. 项目速览（一句话定位 + 技术栈 + 铁律清单）→ 5 行
2. 文件地图（每个 js 文件：职责 / 行数 / 关键符号）→ 表格，~20 行
3. 加载顺序（index.html 脚本序，改动须知）→ ~10 行
4. 常用定位表（「我要改 X → 去 Y 文件的 Z 区块」）→ ~30 行
5. 门禁与验收流程（命令 + 口径）→ ~10 行
6. 血泪坑索引（指向 dev_guide 10.3，不重复内容）→ ~5 行
```

- ✅ 每个 js 文件**顶部维护符号索引注释**（函数名 + 行号 + 一句话）

## 五、风险与对策

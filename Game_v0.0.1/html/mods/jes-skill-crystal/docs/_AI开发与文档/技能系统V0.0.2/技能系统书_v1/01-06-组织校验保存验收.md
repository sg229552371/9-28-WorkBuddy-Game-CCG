# 第 13 章　技能组织

〔2026-10-18 第1轮〕本章目标是让作者在十二个角色、每角色多个技能和共享水晶池之间可靠定位同一份定义，而不是把文件夹名字当作归属、把搜索结果当作装备许可。

## 13.1 组织单位与身份

| 对象 | 主键 | 可变内容 | 不可混同 |
|---|---|---|---|
| 单份技能定义 | `skill_id` | 名称、描述、参数、标签、版本 | 不等于某次施放，也不等于场上实例 |
| 角色 | `meta.role` 引用角色登记标识 | 角色显示名由角色登记提供 | 不以中文名反推角色标识 |
| 水晶池成员 | 水晶类定义的 `skill_id` | 池成员关系及适配说明 | 入池不代表对全部技能生效 |
| 积木实例卡 | `bricks[i].brick_id` | 经授权的参数覆盖 | 积木目录标识不是技能主键 |
| 修饰器 | `params.modifiers[i].modifier_id` | 对应权限与叠加配置 | 物品类别不直接决定运行时作用域 |
| 施放与效果体 | 运行时生成的标识 | 运行期间状态 | 不写回目录，不参与技能重命名 |

〔推荐默认〕身份创建后保持稳定；修改中文名称只影响展示，不能连带改 `skill_id`。同一技能修数值使用自身版本递增；为了同时保留两种可装配定义才创建新标识。禁止把“第一版、第二版”的显示文字当成唯一标识，因为导出、复制和检索必须在没有界面语言的情况下工作。

技能身份、归属和可用范围分开处理。角色归属说明谁拥有这份定义，技能池说明它在哪里被发现，适配关系说明某个水晶能修改哪些已暴露字段。跨角色水晶应归属 `common`，不能为了出现在不同角色页面而复制十二份相同定义。角色页可以引用同一水晶主键，运行时仍只加载一份定义。

## 13.2 ID 命名与解析

命名格式严格为 `<role>_<category>_<name>[_<variant>]`。`role` 是登记角色标识或 `common`；`category` 只能是 `active`、`passive`、`crystal`、`relic`。`name` 为小写 snake_case 短名；`variant` 可选，表示并存变体，不承担版本号职责。

| 情形 | 合法示例或处理 | 组织含义 |
|---|---|---|
| 角色技能石 | `pyro_active_flame_lance` | pyro 归属、主动技能类别 |
| 共享水晶 | `common_crystal_split` | common 归属、水晶类别 |
| 共享遗物 | `common_relic_soul_chain` | common 归属、遗物类别 |
| 并存变体 | `pyro_active_flame_lance_wide` | 与原定义具有不同主键 |
| 仅数值修订 | 保留 `pyro_active_flame_lance` | 递增 `meta.version` |
| 缺角色前缀 | 拒绝 `relic_soul_chain` | 冻结约定示例与格式不符，登记未决问题 |

〔推荐默认〕编辑器用独立的角色、类别、短名、变体输入框生成完整 ID；保存后这些组成项保存在 `meta` 内并与主键互校。由于短名本身允许下划线，不能只按最后一个下划线推断变体。导入旧 ID 时先用已登记角色前缀和类别识别，短名与变体不能无歧义分离时，把剩余部分作为短名、变体留空，展示解释并等待导入确认，不凭末尾数字猜版本。

ID 不允许空格、大写、中文、连续下划线或首尾下划线。角色标识若含下划线，以角色登记表做最长合法前缀匹配，再核对 `meta.role`，不能写死角色名长度。碰撞检查覆盖活动库和被现有定义引用的归档身份；删除文件不等于立即释放身份。重命名属于引用迁移事务，必须列出所有引用方并整体校验，不能只改当前文件名后宣称完成。

## 13.3 归属、池与标签

〔推荐默认〕`meta.role`、`meta.category` 是单值；`meta.pools[]`、`meta.tags[]` 是去重集合；`meta.name` 为中文显示名。池标识引用项目登记，池数量与每角色技能数量均不设固定上限。初始验收数据使用十二个角色，但界面不得写十二个分支，也不得把第十三个登记角色视为错误。

| 维度 | 作者填写 | 运行时用途 | 检索展示 |
|---|---|---|---|
| 归属角色 | 登记角色或 common | 提供归属信息，不自行跨技能授权 | 角色分面、共享分面 |
| 类别 | 四种冻结类别之一 | 选择对应定义形态 | 类别分面、分组计数 |
| 技能池 | 零到多个登记池 | 被相应系统读取，非修饰器权限 | 池名、成员数、孤立成员提示 |
| 语义标签 | 登记标签集合 | `tagged` 作用域显式匹配 | 标签交集、并集及排除 |
| 编辑备注 | `meta.design_notes` | 不参与逻辑 | 全文检索可选，不作为默认标签 |
| 适配结果 | 校验器计算，不手写 | 不取代装载时复核 | 可用、不可用、待补配置及原因 |

标签不是任意中文备注。新增标签应先登记语义，展示中文别名与稳定键；修改别名不改稳定键。标签直接影响 `tagged` 匹配，因此批量增删标签属于逻辑相关变更，要显示受影响修饰器，而不是按纯文案修改免除回归。池成员变化只改变发现范围，不能自动打开权限、添加行为或重设继承。

水晶适配面板同时检查字段存在、权限允许、作用域匹配与取值范围。技能没有分裂行为时，“分裂数量增加”的水晶显示不适配，不能因名字包含分裂而自动增加行为。已经配置该行为但字段未暴露，也应明确显示“字段未开放”，不可与“未找到技能”混成一个空列表。

## 13.4 十二角色、多技能和水晶池的索引

〔推荐默认〕建立从定义内容可重建的索引：主键到完整定义、角色到主键集合、类别到集合、池到集合、标签到集合，以及显示名称和短名的文本索引。索引是缓存，不新增 CFG 顶层键。重建时任何非法定义进入错误清单，不能无声跳过后把缺项当成搜索成功。

检索逻辑为不同分面之间取交集，同一分面的多个选择默认取并集；标签提供显式“全部满足”开关。界面必须把当前组合写成可读查询摘要。例如“角色为 pyro 或 common；类别为 crystal；位于当前水晶池；具有 fire 标签”与“只看 pyro 自有技能”是两个不同查询，不能暗中合并。

| 作者任务 | 查询入口 | 必须返回的内容 |
|---|---|---|
| 查看某角色全部技能 | 角色分面，不限制池 | 每份定义的 ID、类别、版本和状态 |
| 给某技能找水晶 | 选技能后打开适配检索 | 水晶池成员及逐项适配原因 |
| 找共享定义 | 归属 common | 不因当前角色过滤而消失的共享条目 |
| 找同标签跨角色技能 | 标签分面加多角色选择 | 合并去重后的定义，不复制结果行 |
| 精确定位引用 | 完整 `skill_id` | 唯一结果或明确不存在，不模糊替代 |
| 查遗漏 | 无池成员、无标签、未完成登记筛选 | 设计遗漏清单，不与空库混淆 |

查询结果默认按稳定主键排序；按中文名排序时相同名称以主键破同分。分页、滚动加载和筛选切换不改变查询全集。结果应显示总匹配数、当前显示数和被过滤数量，避免把前一页误认为全部结果。修改定义后索引与库快照整体切换，不能出现列表已经改名而详情仍指向旧版本的中间态。

最小硬指标验收使用登记表中全部十二个角色，每个角色至少两份主动技能定义，另有共享水晶池和一个角色限制水晶池。分别按角色、类别、池、标签和精确 ID 查询，并取并集核对源定义集合。增加第三份角色技能及一个新池后不修改检索逻辑仍能找到；移除池成员后精确 ID 仍能找到定义，只是不再出现于该池查询。

## 13.5 搜索、复制、归档与引用保护

复制分为“复制为新定义”和“基于现版编辑”。前者必须生成新的合法 ID、清空旧发布状态并记录来源，后者保留身份并产生新技能版本。〔推荐默认〕复制来源写 `meta.copied_from`，只供追溯，不成为运行时父实例引用。复制不继承调试记录、运行时实例标识或某次施放的种子状态。

复制弹窗列出三类引用：仍指向共享目录的外部引用、随副本保留的定义内引用、需要作者选择的跨技能引用。不能把所有字符串批量替换成新 ID，因为表现资源名、玩家文字和修饰器标识的生命周期不同。复制后先做引用解析，再运行完整校验；若只复制成功但无法装载，应保留编辑草稿并提示尚未形成可保存 CFG。

归档只改变编辑可见状态，不静默删除仍被引用的定义。默认搜索隐藏归档条目，但精确 ID 和反向引用页面仍可访问。真正移除需先列出池、模板、派生引用、触发产出与测试用例的依赖；存在强引用时阻止移除。该功能不涉及多人联网协作，文件被外部改变时仅做版本冲突提示和本地重载。

## 13.6 技能版本与 Schema 版本

`schema_version` 表达文件结构和解释规则，当前固定字符串 `"0.1"`；`meta.version` 表达同一技能定义内容的修订，两者独立。〔推荐默认〕技能版本使用三段数字字符串，初版 `0.1.0`；数值或逻辑修改递增技能版本，只有结构解释发生变化才进入 Schema 迁移。文档版本 v0.1 又是第三个概念，不能拿文档版本覆盖存档结构版本。

预览必须显示自己实际加载的技能版本，而不是编辑框里尚未保存的版本号。旧回放绑定旧内容指纹；当前库中同 ID 已更新时，界面提示版本不一致，不能悄悄用新版本运行再说回放失真。一个技能的历史版本不增加水晶池成员数量，池以身份引用当前已选版本，历史浏览需显式切换。

# 第 14 章　校验规则表

〔2026-10-18 第1轮〕校验不是给表单涂红，而是阻止作者把运行时不能解释或违反契约的定义保存成可执行 CFG。运行时仍保留防御性检查，编辑器通过不等于运行时可以删除保护。

## 14.1 校验入口、定位与严重度

校验分为填写中、整卡、装配组合、保存前、加载前和预览契约探针六个入口。填写中只检查已提交控件值，避免输入负号的中间态刷屏；保存前必须对规范化后的完整定义和全部依赖再校验一次。装配组合检查不能只看单个修饰器，因为多个合法覆盖合并后仍可能越界或互相冲突。

| 严重度 | 对保存的影响 | 对预览的影响 | 作者可做什么 |
|---|---|---|---|
| 阻止保存 | 不生成可执行 CFG，不覆盖上一份有效定义 | 仅允许浏览字段和旧版预览，不能运行坏草稿 | 修改字段、取消本次提交、保留内存草稿 |
| 警告 | 可保存，必须在提交摘要可见 | 可以运行，但提示相关风险 | 修正或留下设计说明，不隐藏规则 |
| 提示 | 不阻止 | 不阻止 | 了解默认值和实际生效口径 |

每条诊断携带规则 ID、文案 ID、实际字段路径、当前值、预期约束和相关字段。路径缺失时定位到应存在的槽位；数组项错误定位到具体项。并发重新校验时诊断绑定草稿修订号，旧结果不得覆盖新结果。相同字段有类型错误时先报告类型错误，依赖该值的范围检查暂缓，避免一个字符串造成几十条伪错误。

本表路径均以第 16 章字段落点为准。`bricks[i].default_cfg` 中出现相同逻辑字段时，应用同一规则并报告该处的真实路径；若错误由 `params` 覆盖引起则定位覆盖值，同时关联默认值。禁止只报规范化内存里的地址，作者必须能回到保存文件中的原因位置。

## 14.6 从契约反推的完整性账本

固定行为不允许作者配置，仍必须在保存前得到正向证据。〔推荐默认〕积木目录登记时执行契约探针，保存时按积木内容指纹、运行时版本和启用能力检查对应探针凭据；新积木、修改过的积木或新增组合没有凭据时执行预览沙盒探针。探针失败使用 V-079 定位到引入该能力的积木卡，而不是要求作者去修改引擎内部顺序。

| 契约约束 | 前置静态校验 | 不可配置行为的探针断言 |
|---|---|---|
| 只有两个事件；结算记录只读 | V-019、032、060 | 不产生第三种事件，不修改已写记录 |

# 第 15 章　报错文案

〔2026-10-18 第1轮〕文案必须回答“哪里错、为什么不能接受、下一步改哪里”，不只写失败。规则 ID 服务追踪，字段路径服务定位，文案服务理解；三者不能互相代替。

## 15.1 展示与占位规则

同一规则可以复用一个模板，但必须传入不同的实际字段。策划视图默认显示中文字段名、当前值、修改建议，展开后显示完整 Schema 路径和依据；程序视图同时显示规则 ID、文案 ID、实际类型和相关引用。两个视图使用同一份诊断，不能一个说警告、另一个说错误。

占位内容作为纯文本插入，不执行表达式，不解释为 Markdown 链接或脚本。引用 ID、路径、输入值长度超出界面可展示范围时，界面截断但详情可复制完整值。缺失值显示“未填写”，空数组显示“空列表”，两者不能都渲染为空白。中文字段名未登记时回退到完整路径，不能显示未定义。

## 15.3 多错误、建议与无障碍定位

多个字段不合法时按阻止保存、警告、提示排序，同严重度按章节表单顺序和数组下标排序，最后以规则 ID 破同分。不得按异步返回顺序乱跳。点击一条诊断应展开折叠区、定位字段、保持旁边的契约说明可见；若字段位于积木默认值，先显示“错误来自默认卡”而不是自动把默认值复制到覆盖区。

自动修复只允许无语义变化的操作，例如去除标签集合重复项；修复前显示差异并允许取消。版本迁移、载体替换、修改派生入口、增加权限、改变预算不能作为“一键修复全部”默默执行。错误提示中的示例值只供解释，不能自动填成最终数值。对可修复结构错误与运行时契约失败，按钮文案应分别为“定位填写项”和“查看探针差异”。

同一问题经规范化影响多个输出字段时，先定位作者实际输入，再展示关联结果，不能把展开出的十个后果当成十个独立错误。相反，不同修饰器分别越权时必须分别报告，不能因为文案相同合并丢掉来源。复制诊断时带上版本、规则和路径，避免评审收到一张截图后无法知道对应哪份定义。

# 第 16 章　保存与版本

〔2026-10-18 第1轮〕完成判定不是“导出了一段 YAML”，而是导出的 CFG 与编辑器校验使用同一结构定义，能被相同版本运行时加载，重开后参数、权限和引用含义不丢失。本章冻结七键骨架，子字段作为本稿明确提案交给 Schema 合并方，不声称仓库已有完整 Schema 实现。

## 16.1 七个顶层键与三层数据

| 顶层键 | 保存类型 | 保存内容 | 不允许混入 |
|---|---|---|---|
| `schema_version` | string | 当前结构版本 `"0.1"` | 数值 0.1、技能版本、文档版本 |
| `skill_id` | string | 第13章完整主键 | 运行时实例编号 |
| `meta` | object | 归属、标签、版本、作者及设计说明 | 施放时的实时战斗状态 |
| `bricks` | array | 每项严格为十二字段积木登记卡实例 | 临时第十三个卡字段 |
| `params` | object | 逻辑参数、覆盖、暴露和触发定义 | 不可配置的内部工序 |
| `presentation` | object | fx、sfx、anim、trail、camera、damage_number、status_icon 七段 | 反向修改逻辑的回调 |
| `runtime_hints` | object | 已登记非功能性提示 | 掩藏逻辑参数和安全上限 |

编辑态有选择、光标、折叠、撤销栈；定义态有七键 CFG；运行态有 `instance_id`、`seq`、`origin`、`snapshot`、`state` 和日志。三者分离。编辑器的脏标记不写进技能，运行时结果不回灌 `params`，导出时也不能把整个调试面板序列化成第八个键。

〔推荐默认〕单文件采用 UTF-8 YAML，禁止重复键、自定义执行标签和不能展开为普通值的引用结构。布尔必须是真布尔，空集合明确写空集合；缺省与 null 不等价，未登记允许 null 的字段拒收 null。所有数字必须有限，逻辑时间以整数 tick 保存。编辑器可以提供秒数输入，但换算后只提交 tick 值，并在界面展示采用的项目频率与向上取整结果。

以下子字段落点均为〔推荐默认〕，其字段语义优先采用主书稿已有词表；仅目录组织和编辑支撑字段为新增提案。参数章如果已登记同一语义不同路径，评审必须选定唯一落点再合书，不能让保存器写一种、校验器读另一种。本稿内部一律按此表，不用未登记的路径简称替代。

| 路径 | 内容与类型 | 约束及默认 |
|---|---|---|
| `meta.role`、`meta.category` | string、enum | 与 skill_id 一致，必填 |
| `meta.short_name`、`meta.variant` | string、string | 短名必填，变体可空；不从最后下划线猜测 |
| `meta.name`、`meta.author`、`meta.version` | string | 显示名、执笔信息、技能自身版本 |
| `meta.tags[]`、`meta.pools[]` | string 引用集合 | 去重，引用登记目录 |
| `meta.design_notes`、`meta.copied_from` | string、可选技能引用 | 设计说明、复制来源，非运行时父引用 |

修饰器接口六个字段之外不暗加 `value` 等孤立字段。〔推荐默认〕`stack_rule` 保存结构化运算登记，包含运算种类和操作数；具体表示需参数章与 Schema 共同收口。校验时先检查其运算种类，再核对操作数单位和目标类型。未登记运算不能以字符串表达式执行；多个 set 的挂载次序来自运行时装配输入，不由文件键排序决定。

〔推荐默认〕本阶段 `scope=tagged` 使用该物品定义的 `meta.tags[]` 作为匹配集合，至少命中一个登记标签；界面显式标为“作用域标签”。这是为冻结六字段接口提供的临时明确落点，不宣称主书稿已规定标签选择器。若一个物品的多个修饰器需要不同标签集合，本稿不假装已支持，应交评审选择登记表达方式；不能往六字段接口偷偷增加自定义字段。

份定义与事件载荷不是同一结构。配置 `params.parts[i]` 定义产生何种份及输入数值；`evaded`、`final_amount`、`any_reduced_to_zero`、`killed` 是运行结果，不作为策划预填值保存。若导入文件把这些结果写在份定义中，按未知字段拒收。条件可以按 `hit_settled.parts[].type` 过滤，但不能访问其中不存在的 `final_amount`。

## 16.3 积木默认值、覆盖与确定性展开

每项 `bricks[i]` 仍严格包含 brick_id、name、tagline、carrier、summary、default_cfg、author_params、locked_params、relic_params、presentation、player_text、status。`default_cfg` 是可被运行时读取的 CFG 片段，不把中文概述当执行内容。所有默认片段展开后须经过同一 Schema，不允许“登记卡默认值绕过校验”。

〔推荐默认〕通用 `params` 字段提供设计卡级配置，`brick_overrides` 提供具体卡覆盖；一个逻辑叶字段只能有一个最终权威赋值来源。按“登记默认→通用适用覆盖→指定卡覆盖”展开，覆盖前先检查锁定声明。两张卡映射到同一个能力槽而没有组合规则时拒绝装载，不以数组后者悄悄覆盖前者。不同效果体的半径不能因为字段同名被合并成一个数值。

数组默认整体替换，不隐式拼接；引用列表是否可并集合并必须在参数登记显式声明。深层对象按登记叶字段覆盖，不能递归接受任意键。默认值来源、覆盖来源和最终值均在界面可查；保存的是作者定义，预览加载的是规范化展开结果，两者之间保留路径来源表，用于把错误定位回真实输入。

积木目录更新不得自动改变已保存定义。本稿保存完整登记卡实例，故旧存档继续保留当时 default_cfg。作者选择更新目录卡后先看差异，包括默认参数、锁定字段、暴露字段和表现引用，再整体校验并递增技能版本。不能只更新中文说明却在背后换掉逻辑默认值，也不能凭同一个 brick_id 宣称内容完全相同。

| snapshot_layers、snapshot_fields | 快照观察器读取结构及参数登记依据 | L3 修改技能字段，不混进属性快照 |
| input_buffer | 项目级输入策略与预览夹具引用 | 不在单技能重复发明窗口语义 |
| modifier | params.modifiers | 三权限、作用域、继承和固定运算顺序 |
| card_extra_fields | params 同名字段及 triggers 对应字段 | 不丢弃召唤上限、冷却和触发标识 |
| collision_priority_reference | 积木契约校验依据 | 不开放内部碰撞工序排序器 |
| budget_rule、runtime | 固定行为探针及项目配置引用 | 非功能提示不改逻辑顺序和清理语义 |

附录 B 的 `same_tick_spawn_hits_next_tick` 不能机械解释成所有生成物都延后一 tick。第 36 章和第 14 章区分出手创建与派生创建，本稿按该区别验收。载体冻结约定中的 `instant` 也不能不经说明直接写入运行时；本稿使用 `none` 表示瞬时载体，并保留 `self` 位移跟随判定体。两处冲突列入末尾，不改共享文件。

## 16.5 保存事务与失败保护

保存按钮先检查身份，再解析依赖，展开默认及覆盖，执行结构和语义校验，最后提交单份定义。提交期间使用打开时的版本与内容指纹作为基线，基线已变化就停止，不覆盖外部更新。成功后更新目录索引、当前文件版本和脏标记；任何一步失败，旧持久化内容仍可加载，界面保留作者输入并指出失败阶段。

〔推荐默认〕正式实现使用具备原子替换语义的存储服务，具体落盘机制由后续实现任务确定；本次规格撰写不创建任何辅助文件。保存后以实际持久化内容重新解析并比对规范化值，不能只相信按钮回调返回成功。写入成功但重读失败时标为“保存完整性失败”，不得自动清除草稿或显示通过验收。

编辑器可保留未通过校验的内存草稿，但草稿不是可执行 CFG。若未来提供草稿持久化，应由项目编辑态存储规格定义，与技能目录隔离；本章不增加草稿文件格式。导出、另存和批量操作都必须调用同一校验入口，不能出现普通保存拒绝而导出按钮放行的旁路。

## 16.6 版本不匹配与迁移策略

| 输入版本状态 | 打开方式 | 保存方式 | 原文件保护 |
|---|---|---|---|
| 当前支持版本 | 正常编辑 | 全量校验后保存 | 基线冲突检测 |
| 已知旧版且有完整迁移链 | 先只读展示，生成内存迁移预览 | 确认迁移差异后以新版本提交 | 迁移提交前原内容不变 |
| 已知旧版但链缺一段 | 只读，展示缺失边 | 阻止保存为当前版 | 不做猜测性补键 |
| 比当前更新的版本 | 只读查看可解析原文 | 阻止降级覆盖 | 不删除未知字段 |
| 版本缺失 | 标为未识别结构 | 仅在明确导入适配器识别后迁移 | 不直接填当前版本 |
| 版本合法但语义冲突 | 只读并列差异 | 阻止认证与迁移提交 | 不以类型正确掩盖行为变化 |

迁移按版本边逐步执行，每条边声明前置条件、字段变换、默认补入、丢失信息和行为影响。没有跨越某版本的登记边，就不能把版本字符串直接改成当前值。迁移预览必须给出源路径、目标路径、旧值、新值和理由；自动补入默认值也要可见。对于载体名称、计数单位、输入缓冲语义等会影响行为的差异，迁移必须要求对应契约测试重新通过。

〔推荐默认〕同一源内容重复迁移得到相同规范化结果；已经是目标版本时再次迁移不再改动。保留技能身份，递增技能自身版本，并在设计说明追加迁移来源和原因。迁移不重置修饰器权限、不扩大标签作用域、不把未知事件改成 hit、不把非法时间截断为零。无法无损解释的字段必须阻止提交，不能删掉它以后称迁移成功。

对于未带版本但形似附录 B 的 YAML，编辑器识别为“契约摘要而非技能定义”，不执行技能导入。对于旧载体 `instant` 的输入，仅当导入适配器明确证明它表示瞬时无载体且不存在需要 `self` 的位移语义时，才可建议映射 `none`；本稿不把这个映射注册为普遍事实。所有未知状态保留原文供评审，而不是进入可运行库。

## 16.7 保存格式完成判定

同一字段登记应驱动控件、校验器、序列化器、加载器和错误定位；不得分别维护五份不同默认值。完成判定包括七键严格一致、十二字段卡严格一致、七表现段严格一致、每个可填叶字段在 Schema 中有类型和范围、每条校验能定位到保存字段、往返不丢值、运行时加载无隐式修复。规范化前后允许键排序变化，不允许数组语义顺序和引用含义变化。

本稿提供的是接口提案和验收标准，不是最终 Schema 文件。评审合书时必须把本稿推荐子字段与第 5、9 章登记逐项对照；若未完成合并，应将“CFG Schema 一致”保持未验收状态。不能仅因顶层七个名字一致就勾选整个硬指标，也不能用本稿自己定义的字段去证明已有运行时已经支持。

# 第 17 章　预览与试算

〔2026-10-18 第1轮〕预览的可信度来自加载同一份 CFG、执行同一运行时契约和保留输入证据，不来自把伤害公式在界面上再写一遍。“预览里看到的就是运行时跑出来的”指逻辑结果同源，不承诺装饰粒子的每个像素完全一致。

## 17.1 三种视图和运行凭据

| 视图 | 输入 | 输出 | 不允许冒充 |
|---|---|---|---|
| 配置试算 | 展开的参数、修饰器与字段范围 | 当前值、来源、夹取前后值、理论请求数量 | 不能冒充真实命中结果 |
| 逻辑预览 | 已校验 CFG、场景夹具、种子、输入序列 | hit、vanish、结算记录、状态观察 | 不能由动画回调补发结果 |
| 表现预览 | 同一逻辑运行结果和表现配置 | 图形、声音、动画、数字、图标 | 不能反写命中、伤害或目标顺序 |

〔推荐默认〕每次逻辑预览建立只读凭据，至少展示技能 ID、技能版本、Schema 版本、CFG 内容指纹、依赖内容指纹、运行时版本、场景夹具标识、逻辑种子和输入摘要。这些是预览会话元信息，不追加到七键技能定义。未保存草稿也可预览，但必须先规范化并标“草稿”，正式验证时重新加载实际持久化内容。

参数改动使当前凭据过期，界面保留旧结果供比较但添加醒目标记，不自动换标题伪装新结果。只改表现时可以复用已记录的逻辑流做表现查看，但新的完整验收仍须证明逻辑流未受影响。涉及角色属性、目标防御、装配、项目预算或运行时版本的变化，都属于新运行条件，不能只用相同种子宣称可直接比对。

## 17.2 snapshot、当前值与 live 的显示差异

| 面板列 | 数据含义 | 更新时机 | 交互限制 |
|---|---|---|---|
| 基准定义 | 技能配置和角色基础数据 | 配置版本改变 | 可回到编辑器修改，不改正在运行实例 |
| 当前施法者属性 | 当前角色受永久与临时增益影响的属性 | 世界状态变化 | 不是旧实例的快照 |
| 出手快照 snapshot | 出手瞬间冻结的属性 | 实例取得快照时 | 只读，不随拾取遗物重算 |
| 实例 params | 生成时确定的技能参数 | 实例生成；合法 live 更新 | 展示来源和权限，不直接拖动绕过管线 |
| 目标当前状态 | 结算时目标防御、受治疗等 | 每次结算读取 | 不混进施法者快照 |
| live 变更记录 | 双向许可的数字变化 | 下一次合法重算起 | 只影响现在以后，不改历史轨迹与 hit |

D-44 与 D-62 的关键不是“所有值都冻结”，而是施法者侧出手快照与目标侧结算时状态分开。持续区域每跳读取旧快照，不因当前攻击提高而回溯变强；目标新获得减免或受治疗降低可以影响之后结算。界面必须同时展示这两条来源，不用一个“实时伤害”数字掩盖其中一层。

附录 B 的快照分层显示为来源说明：基础与等级、永久成长、局内临时增益进入快照；水晶遗物修饰技能字段，不以同名攻击加成暗塞快照。字段观察器展示 name、unit、source_layer、live_override_allowed、rounding，未知字段不得凭示例补入正式表。某个字段名出现在示例列表，不等于已获实时修改权限。

示例只用于验收：治疗实例出手后、命中前施法者攻击增加，同时目标获得受治疗降低。预览中旧实例名义治疗量保持出手快照口径，实际恢复量按目标当前状态及缺失生命计算；不能把名义量与实际量相等当作通过。治疗派生护盾若按名义量计算，也不能误用受缺血上限截断后的恢复量。

## 17.3 战斗中替换与新旧实例对照

装配试验提供按 tick 安排的替换输入，而不是直接编辑场上实例字段。替换在 tick 开始、任何出手前整批应用；同一批次中不能看见半套旧装配半套新装配。旧修饰器对之后生成的实例失效，新修饰器从基准值重算。旧实例 params、snapshot 和行为保持原状，只有另外满足 live 双向声明的合法数字修改才能走实时通路。

| 试验操作 | 左侧旧实例 | 右侧新实例 | 预览必须指出 |
|---|---|---|---|
| 移除数值水晶 | 已冻结值不回滚 | 不再应用旧数值修饰 | 替换 tick 与实例 spawn_tick |
| 加入行为遗物 | 不得到新行为 | 按新定义生成 | add_behavior 不包含 live 权限 |
| 合法 live 数字变化 | 从下一次重算起使用新值 | 按当前配置生成 | 历史命中与已走路径不改 |
| 公共冷却内再次换装 | 不变 | 不产生半完成配置 | 整个操作被拒绝及剩余冷却 |
| 替换为空 | 旧实例不变 | 对应修饰不再加入 | 空槽也是替换语义 |

对于缩短剩余寿命、改变半径等 live 改动，界面只能展示目标字段登记允许的具体语义；没有定义“仅延长剩余”还是“允许缩短”的字段不得自行试验成通用功能。观察值缺少来源时标为未解析，而不是显示零。快照的不可变性与实例参数的受限可变性必须在视觉上分区，防止作者以为“实时”开关覆盖所有字段。

## 17.4 结算、数量和时间轴

时间轴至少显示施放请求、进入前摇、实际出手点、实例创建、首个可判定 tick、候选接触、hit、vanish、回收以及被动触发处理段。前四项作为观察标记，不新增技能事件。计数面板分别统计出手次数、实例创建数、候选接触数、hit 数、份数、派生请求数及被拒绝数，不以一个“攻击次数”概括。

选择一条 hit 时展示全部份的 part_index、evaded、type、final_amount，以及 any_reduced_to_zero 和 killed。选择 hit_settled 时仅展示它真正提供的字段，不能把事件载荷复制进去冒充冻结记录。全闪避没有 hit，观察器应通过独立记录和候选接触视图说明发生了什么，而不是合成一条零伤害 hit 方便画图。

暂停冻结逻辑 tick；单步推进一个完整 tick；慢动作只改变真实时间中推进 tick 的频率。渲染可以插值，逻辑结算顺序不能随拖动时间轴变化。回看历史优先读日志；需要重新执行时从固定初态重放输入，而不是把场上位置手动倒回去。一个派生瞬时实例的创建时刻和首次判定时刻应同时显示，避免只看寿命为零推断同 tick 命中。

## 17.5 可信预览的差分验收

相同规范化 CFG 在编辑器沙盒与正式运行入口分别加载，使用相同依赖、初态、逻辑种子和输入。比对事件与结算记录的种类、顺序、tick、目标、份结果及来源链，并保留首个差异位置。实例标识若由运行域前缀生成，比较前仅允许有声明的等价重编号，不能删除 seq 或打乱事件顺序后比较总伤害。

关闭动画、换低细节表现、静音、修改镜头、隐藏调试面板后重跑，逻辑轨迹应一致。只有纯表现预算压力改变时可比较逻辑不变；真正拒绝或清理判定派生体时，应该出现相应逻辑差异和 debug_record，不能仍要求全轨迹相同。本稿不把“所有预算变化都无影响”当成承诺，也不据此新增性能门槛。

预览中的安全保护必须与运行时相同，不能为了画面完整临时取消代数上限、防霰弹、召唤上限或公共装配冷却。需要展示未截断的理论数量时放在配置试算区，并标明不是实际运行结果。一个有意触发预算截断的案例可以通过规则验收，但不能以被截断后的结果证明技能设计已经合理。

# 第 18 章　模板库与批量

〔2026-10-18 第1轮〕本章属于后续阶段能力，首版可只提供受控复制与逐项提交，但模板实例化后必须走相同 Schema、权限和保存校验。不能把“来自模板”当作有效性证明。

## 18.1 模板内容与实例化

〔推荐默认〕模板是带参数占位和说明的编辑器预设，不是新的运行时类别。模板来源、说明、可填项、锁定项、适用角色或类别和依赖版本由编辑器模板目录管理；实例化后输出仍是七键技能 CFG。模板不得携带某次施放的实例标识、运行快照和历史随机抽取状态。

| 模板操作 | 必须展示 | 必须保留的约束 |
|---|---|---|
| 新建自模板 | 将生成的 ID、归属、待填参数 | 不沿用原技能主键 |
| 应用表现预设 | 七表现段的改动差异 | 不改 params、不增订阅权限 |
| 应用逻辑预设 | 积木、命中策略、暴露范围差异 | 新增能力重新校验 |
| 更新模板版本 | 当前实例与新模板的逐字段差异 | 不自动覆盖已发布定义 |
| 复制到其他角色 | 归属、池、标签及引用变化 | common 引用不无故复制 |

模板占位尚未填完时，只能停留在编辑草稿，不能把占位字符串当合法数字保存。模板中锁定的字段与积木锁定字段取更严格者，模板不能解除积木约束。作者解开一个模板锁只表示放弃模板一致性，不代表获得修改运行时固定策略的权限。

## 18.2 批量编辑事务

批量动作先冻结目标集合，展示目标数量与精确 ID 清单，再指定允许修改的已登记路径。搜索页面的当前页不等于全部结果；必须明确操作当前勾选项还是查询全集。执行期间查询索引变化不追加新目标，避免作者以为只改一个角色却把新入池定义也卷进去。

〔推荐默认〕整批先生成内存变更集，对每份定义做静态校验，并对跨定义引用和组合关系做整体验证；默认整批成功或整批不提交。若后续提供跳过失败项模式，必须显式选择并生成成功、失败、未处理三栏摘要，不允许静默跳过。取消操作恢复到提交前，不依赖把乘法倒除回原值。

批量允许同字段同类型的替换或范围内调值，不允许对任意字符串做全库正则替换。重命名、标签作用域变化和积木更新需要独立预览，因为它们影响引用或逻辑范围。批量只改玩家文字时也要检查三句限制与行为一致性；不能因为“不碰伤害”就省略所有校验。

## 18.3 模板与批量验收边界

至少验证一个有效模板实例化、一个缺必填字段的模板拒收、一次跨十二角色的合法标签批改、一次中间定义失效导致整批不提交、一次外部版本变化导致冲突停止。验证关注定义完整性，不以大批量操作耗时作为技能文档验收指标。

所有模板默认值都应标示来源。模板推荐的示例半径、数量和冷却不是最终数值；首次实例化时可以保留示例，但必须在设计说明标清用途。模板目录新增条目不修改程序分支，只增加登记数据。候选模板可以供设计讨论，但不能绕过积木 `status` 的可运行门禁。

# 第 19 章　调试与回放

〔2026-10-18 第1轮〕本章属于后续阶段的完整界面化能力。首版可以没有完善的回放库，但第 17、20 章所需固定种子、固定输入、逐次比对入口不能推迟。调试面板是观察工具，不是新的逻辑订阅方。

## 19.1 种子回放界面

| 区域 | 必备内容 | 操作约束 |
|---|---|---|
| 条件栏 | CFG 与依赖指纹、运行时版本、夹具、种子 | 修改任一条件产生新运行，不覆盖旧证据 |
| 输入轴 | 按 tick 排列的施放、移动、换装、控制及清理输入 | 同 tick 输入保持记录顺序 |
| 运行控制 | 从初态运行、暂停、单 tick、重新运行 | 不用渲染帧作为步进单位 |
| 日志轴 | 事件、结算记录、调试记录分栏 | 三类记录不得混为一种事件 |
| 差异窗 | 首个不同 tick、字段和值 | 不只显示最终总伤害差异 |
| 导航栏 | skill_id、cast_id、instance_id、trigger_id 关联 | 使用实际存在字段，不臆造记录关联 |

回放的最小输入不只是一个种子。还需要初始角色属性、目标状态、装配内容、项目规则版本、场景位置和外部输入顺序。缺一项时应标“条件不完整，不能认证确定性”，而不是尝试自动猜测当前项目状态。回放使用旧技能内容时必须明确隔离，不能把它重新注册为当前库版本。

〔推荐默认〕回放包由项目测试或调试存储负责，不嵌入技能 CFG，不在本次任务新建回放文件。存储格式未来登记时须区分逻辑种子与表现种子，并记录逻辑 RNG 抽取用途，禁止让粒子抖动消耗逻辑随机流。确定性承诺限于主书稿所述单机运行边界，不扩成跨平台位级一致或联网同步保证。

## 19.2 debug_record 专用面板

| kind | 显示重点 | 可跳转位置 | 禁止行为 |
|---|---|---|---|
| `budget_drop` | tick、detail、可用的预算类别与关联标识 | cast_budget 或项目预算配置入口 | 不触发补弹，不向正式 UI 注入丢弃提示 |
| `proc_blocked` | 来源标记、深度或冷却对应的 detail | trigger_id 所在规则 | 不自动解除自链限制 |
| `gen_limit` | 派生请求与上限 | max_generation 或派生规则 | 不自动增加代数以让预览完整 |

冻结载荷至少有 kind、detail、tick；其他字段只有记录实际提供时才显示。不能因为面板希望展示父实例，就要求所有 debug_record 伪造 parent_ref。关联缺失时显示“此记录未提供”，可用 tick 辅助筛选但不能把同 tick 第一条 hit 自动认作原因。

调试面板可以聚合计数、筛选原因、导航配置，不能把聚合结果送回游戏逻辑。正式伤害数字的合计只来自 hit 和 hit_settled；关闭调试采集或过滤预算记录后，合计仍正确。记录被截断或环形缓冲覆盖时必须显示证据不完整，不能把空结果理解为从未发生预算拒绝。

## 19.3 事件链与差异定位

来源链视图按 origin_skill、origin_cast_id、chain_depth、proc_mask 展示祖先关系，generation 单独显示。每次派生与被动触发都推进因果深度，不能用 generation 代替它。根实例的 parent_ref 为空；被动触发没有某个父实例直接引用时，只展示实际来源链，不制造父子边以满足树形界面。

点击失败的预览用例应先定位第一个分歧，再展示前后相关记录和输入。比如预期全闪避但出现 hit，应先看候选接触及逐份判定，不从总伤害不同直接推断减免公式错误。比如遗物少触发一次，先查看记录过滤、proc_mask、深度、内置冷却和预算，不默认认为随机失灵。

差分过滤只能隐藏显示，不能改变判定通过与否。允许忽略纯表现资源句柄等非逻辑字段，但必须列出忽略名单。不能忽略 tick、seq、target_id、份结果、来源链或拒绝原因来获得通过。重新排序日志后结果相同不证明 FIFO 正确，比较对象必须保留原始顺序。

## 19.4 回放的操作安全

回放默认运行在隔离沙盒，结束后不把角色属性、装配、冷却和死亡状态写回正在编辑的项目会话。重放过程中禁止热换 CFG；若作者选择测试新版本，则建立对照运行而不是继续旧轨迹。关闭窗口可以停止模拟，但不能把中断运行标成成功结束。

出现失败时保留条件摘要、首差异和相关日志，不自动修改技能去迎合当前实现。测试期望来自主书稿验收表；若发现原表冲突，登记未决问题交评审，不把两种预期都设成允许。回放界面最终应帮助复现问题，而不是提供“忽略全部差异”的快捷通过方式。

# 第 20 章　编辑器自身验收

〔2026-10-18 第1轮〕验收对象是从设计卡输入到 CFG 保存，再到同一运行时复现的整条链。表单能打开、按钮能点、预览能播放都不是完成判定。文档本身的静态校验与未来编辑器实现验收分开报告，本轮不冒称后者已通过。

## 20.1 端到端流程与交付证据

| 步骤 | 操作 | 期望 | 证据 |
|---|---|---|---|
| 填卡 | 从已登记积木创建技能，填写归属、参数、暴露和文字 | 字段单位清楚，锁定项不可改 | 完整设计卡及路径表 |
| 即时校验 | 注入一个非法值再修复 | 报错指向准确字段，修复后旧诊断消失 | V 与 E 编号、实际路径 |
| 整卡校验 | 解析积木、引用、修饰器和表现 | 无阻止保存项，警告可解释 | 校验摘要与依赖指纹 |
| 保存 | 提交并重新加载 | 七键结构一致，版本正确，值无损 | 持久化内容与规范化差异 |
| 预览 | 固定初态、输入和种子运行 | 输出符合对应契约例子 | 事件、结算和调试分栏轨迹 |
| 正式复现 | 从持久化 CFG 在正式入口运行同一夹具 | 逻辑轨迹与预览一致 | 首差异检查结果 |
| 重跑 | 同输入同种子再次运行 | 结果逐次一致 | 两次运行凭据和比较报告 |
| 人审核 | WorkBuddy 核对规则覆盖，用户拍板主观取舍 | 未决项不被伪装为确认 | 审核结论与未通过项 |

验收例子的输入必须非空且能走到目标分支。验证“没有非法事件”时，同时证明至少发生过一次正常 hit 或合法清理；验证“某标签能找到技能”时，先给出预计主键集合，再比较实际结果，不能对空集合执行全部成立判断。失败用例需要证明拒绝原因正确，而不只是按钮没有响应。

每项证据绑定版本和内容指纹。重新保存以后旧测试证据仍可供历史查看，但不能自动贴到新版本上。字段无变化的重复保存不生成假修订；规范化结果变化却沿用同一技能版本时必须阻止覆盖。界面任何绿色通过状态都应能展开到具体用例，不能仅由“未收到异常”推导。

## 20.6 本稿交付与实现验收的分界

本次交付只完成章节草案和文档静态检查。清单的空框不是遗漏，而是留给未来实现与评审填写的证据入口。文档校验能够证明章节数、引用小节、编号关联、保存骨架和术语使用的一致性，不能证明编辑器已经运行，也不能证明推荐子字段已被全书 Schema 接纳。

实际实现时遵循规格先行与测试驱动：先选一条上述例子写失败测试，确认失败原因是功能未实现，再实现最小行为并回归。每一轮只推进明确用例，不能先完成整个编辑器再倒推测试期望。人工审核重点是期望是否忠于契约、失败是否真被触发、改动是否越界，而不是单看测试数量。

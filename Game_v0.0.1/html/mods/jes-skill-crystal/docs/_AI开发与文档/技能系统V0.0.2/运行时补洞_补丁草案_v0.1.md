# 第33C章　非伤害案例三：增益与减益（共鸣印记）

> **一句话结论：**同一次出手给友方施加增益、给敌方施加减益；施加由瞬时效果体结算，持续属性由附着效果体保存，有限叠层共用计时，到期撤销贡献，驱散走 purge。所有数值均为测试示例，不是最终平衡表。〔2026-10-18 第1轮〕

## 33C.1 设计卡（八栏，示例数值）

| 栏位 | 内容 |
|---|---|
| **1 基础信息** | `skill_id=common_active_resonant_marks`；技能石；意图为强化队友后续攻击、让敌人承受更多伤害；标签为增益、减益；状态〔推荐默认〕 |
| **2 施法者闭环** | 索敌同时确定一个合法友方 T 和一个合法敌方 E，各按距离、再按目标编号定序；友方允许自身，`include_self=true`；前摇零，X=1，冷却60 tick，从实际出手起算。一侧无目标只省略该侧，不复制另一侧；两侧均无目标则不进入施放 |
| **3 效果体** | 出手创建 G（友方施加体）与 C（敌方施加体），各 `carrier=none`、`lifetime_ticks=0`，固定顺序先 G 后 C。首次有效施加分别形成 B（增益）和 D（减益），`carrier=attached`，`anchor_target_id` 指向各自受益／受害目标；寿命240 tick，无运动、无周期跳，不进空间分桶。两种状态均需单独驱散、叠层与来源管理，满足6.6升格条件 |
| **4 命中与伤害份** | G 只有 `type=buff`，C 只有 `type=debuff`；两者 `per_target_limit=1`，无重复间隔，无伤害份。G 不判闪避；C 判闪避并检查 `immune_debuff`。有效施加时 `final_amount` 表示本次合并后的有效总层数，不是伤害，也不是本次净增层数；B、D 只保存持续贡献，不重复发挂载 hit |
| **5 派生** | G／C 的有效 hit：若对应份未闪避且 `final_amount>0`，首次创建 B／D，`generation=1`、`parent_ref` 指向施加体；目标显式取该 hit 的 `target_id`，覆盖默认排除命中目标规则。已存在同组实例则依 `restack_rule` 合并，不再创建第二个存活状态。G／C 的 vanish 不派生；B／D 不配置任何 hit 或 vanish 派生 |
| **6 终止原因** | G／C 为 `instant_end`；B／D 自然到期为 `expired`；驱散、宿主阵亡、场景清理为 purge。完整表见33C.3；不使用未冻结原因码 |
| **7 修饰器接口** | 暴露 `params.buff_strength`、`params.debuff_strength`、`params.lifetime_ticks`、`params.max_stacks`，均只允许 `mutate_number`，`scope=own_skill`；前两者为非负比例，寿命与上限为正整数。示例值依次0.1、0.2、240、3。不暴露实时修改、阵营、免疫标记、来源键与计时规则；不默认授予 `add_behavior` |
| **8 被动触发挂点** | 允许 `cast_started`、`hit_settled`；后者必须按份 `type=buff/debuff` 与目标过滤。本卡不产生 `damage_taken`，不定义“状态到期记录”；被动不得订阅 hit、vanish 或 `debug_record` |
| **玩家文字** | 强化一名队友的攻击，并给一名敌人留下易伤印记。重复施放可以叠加效果，达到上限后只续时。印记可被驱散，消失后不再强化后续攻击。 |
| **积木优先自查** | 施法者闭环＋瞬时施加＋附着效果体＋既有有限叠层足以表达，不新增积木。以下参数为本卡声明，不扩展 instance 顶层词表 |

| 挂载 | G／C的hit在阶段④施加，B／D创建时即挂载；不再命中、不进空间接触，只推进寿命 | D-98、D-106 |

| 属性 | B每层攻击+10%，进入宿主以后出手快照，不改已发攻击；D每层受伤+20%，命中时读取。均从基准重算，不逐tick连乘 | D-44、D-62、D-67 |

# 第33D章　非伤害案例四：召唤（守望灵）

> **一句话结论：**召唤动作生成一个长期独立效果体，其中包含召唤物自己的施法者闭环；所有者负责归属与同时存活上限，不能代替召唤物成为后续攻击的施法者。召唤上限替换与全局预算拒绝是两种不同操作。〔2026-10-18 第1轮〕

## 33D.1 设计卡（八栏，示例数值）

| 栏位 | 内容 |
|---|---|
| **1 基础信息** | `skill_id=common_active_watch_spirit`；技能石；指定可用空位，召唤守望灵协助攻击；标签为召唤；状态〔推荐默认〕；所有者记 O |
| **2 施法者闭环** | O 确定空位→前摇零→X=1→冷却120 tick；实际出手生成 S。S 从创建后的下一 tick 起推进自己的闭环：找最近有效敌人→前摇零→X=1→冷却120 tick。每个 S 单独计时，不能共享 O 的冷却 |
| **3 效果体** | S 为 `independent`，寿命600 tick，`owner_id=O`、`bind_owner=true`、同类 `summon_cap=2`；S 的创建来源 `caster_id=O`。其自身出手创建 P，P 为 `independent`、寿命90 tick、直线飞行；P 的 `caster_id=S`。S 是可受伤单位，不以身体碰撞造成攻击 |
| **4 命中与伤害份** | 召唤空位不适用闪避，不凭空制造“召唤命中敌人”的 hit。P：`per_target_limit=1`、`max_hits=1`，一份示例物理伤害20；命中后 `hit_end`，未命中寿命结束 `expired`。S 受击按通常逐份结算；防御状态不与 O 共用 |
| **5 派生** | S 与 P 均无 hit／vanish 派生。P 是 S 新一次施放的根实例，不是 S 的命中派生；`generation=0`、`parent_ref` 为空；`origin_skill` 沿用召唤技能，`origin_cast_id` 为本次 S 施放新建，根 `chain_depth=0`，后续若扩展派生仍按第20章递增 |
| **6 终止原因** | S 寿命到期为 `expired`；被击杀、上限替换、绑定所有者死亡、场景卸载均按阵亡／清理的 purge 路径；P 为 `hit_end` 或 `expired`。不给 S 增加“死亡原因码”或“退场攻击”，见33D.3 |
| **7 修饰器接口** | 暴露 `params.summon_cap`、`params.lifetime_ticks`、`params.damage`，只允许 `mutate_number`；上限与寿命为正整数、伤害为非负数。本卡不开放 `bind_owner`、来源链、免疫标记、出生推进时点与实时修改。召唤物有效继承集合仅纳入显式 `inheritable=true` 且目标字段合法的修饰器 |
| **8 被动触发挂点** | O 施放及 S 自己进入前摇时可各有 `cast_started`，按 `caster_id` 区分；P 的结算允许 `hit_settled`，受伤侧仅实际扣血大于零时有 `damage_taken`。不订阅 `debug_record`，不把 purge 变成触发来源 |
| **玩家文字** | 在指定位置召唤守望灵，守望灵会自行攻击附近敌人。达到召唤上限时，新守望灵替换最早召出的同类。默认在召唤者阵亡后离场，但已经发出的攻击仍会继续。 |
| **积木优先自查** | 既有召唤模板和独立闭环可表达，无新增积木；示例上限只服务测试，不是内容数量硬上限 |

## 34.1 运行时失败行为

> 故障必须在最小明确边界内停止，不能崩溃整局、把错误数值猜成合法值，或无限排队等待预算。下面每种失败只选定一种行为，均为〔推荐默认〕；“记录错误”不等于“游戏逻辑订阅错误”。〔2026-10-18 第1轮〕

### 34.1.1 五种失败的唯一选择

| 决策 | 失败输入 | 三选一裁定 | 失败范围和行为 | 诊断与恢复 |
|---|---|---|---|---|
| D-108 | 请求的 `skill_id` 在当前合法技能集合中不存在 | **跳过并写 debug_record**〔推荐默认〕 | 拒绝本次施放请求，不进入索敌／前摇，不生成 `cast_started`，不创建实例，不扣该次冷却，不改其他技能 | `kind=config_error`，`detail` 标明未知技能与请求的原始ID。当前集合保持不变；只有新请求在新合法集合中解析成功才可执行 |
| D-109 | 必填字段类型错，如把 `params.lifetime_ticks` 的整数写成字符串 | **跳过并写 debug_record**〔推荐默认〕 | 装载时拒绝该技能候选定义，不接受半份配置；不得把字符串转整数、负值改零或用任意默认值掩盖错误。运行中异常候选同样不能覆盖当前合法定义 | `kind=config_error`，记录路径、期望类型、实际类型及候选版本。先修正并重新校验，再接纳；其他无依赖的合法技能继续 |

### 34.1.2 检查顺序与副作用边界

| 边界 | 固定工序与约束 |
|---|---|
| 配置接纳 | 版本→类型→引用→修饰器目标／权限；同阶段错误按Schema路径稳定排序。未通过候选不得污染活动参数、快照、白名单或来源 |

### 34.1.3 配置位置、记录格式与可观察性

策略放在 `params.runtime_failure`，作者锁定，不暴露给水晶／遗物；字段 `unknown_skill`、`invalid_field_type`、`unknown_modifier_target`、`budget_exhausted` 均取 `skip_with_debug_record`，`schema_version_mismatch` 取 `degrade`。不增加CFG顶层键，不放进非功能性 `runtime_hints`。

坏CFG不能提供自己的失败策略：使用当前已验证公共CFG，启动时使用随版本发布的已验证默认配置。本版不开放崩溃选项；变更策略须重新登记。

外壳保持 `debug_record{kind,detail,tick}`。`config_error` 仅用于配置／引用错误；`detail` 为含错误类别、身份、路径、期望／实际值及处置的调试文本，不新增载荷字段、不作为逻辑分支键、不冒用预算或被动拦截码。

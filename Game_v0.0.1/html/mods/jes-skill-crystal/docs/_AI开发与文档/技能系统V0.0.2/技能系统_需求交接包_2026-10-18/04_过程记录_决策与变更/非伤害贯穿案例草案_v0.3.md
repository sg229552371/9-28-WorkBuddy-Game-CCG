# 案例 N1：治疗链 + 护盾（庇护祷言 `ward_prayer`）

> **一句话**：单体治疗命中后，派生一个挂在同一目标上的护盾效果体；护盾额度被来袭伤害打光则 `hit_end`，到期则 `expired`。本案例用来检验治疗/护盾在 D-05、D-44、D-70、D-16b 之间有没有缝。

## N1.1 设计卡（沿用 24.4 栏位）

| 栏位 | 内容 |
|---|---|
| **基础信息** | `skill_id=ward_prayer`；玩家主动；选射程内友方单体（`include_self=true`，22.9）；冷却 360 tick（示例）；类别：治疗 + 护盾；状态：**推荐默认 / 待用户确认** |
| **施法者闭环** | 索敌（友方）→ 前摇 24 tick（示例）→ 出手×1（X=1）→ 冷却 → 回索敌。出手瞬间创建治疗体 H，施法者随即自由 |
| **效果体 H：治疗** | 载体 `none`（无载体瞬时实例，22.3）；寿命 0；对选定友方目标做一次接触；`per_target_limit=1` |
| **效果体 S：护盾** | 载体 `none`（挂在目标上，22.4）；寿命 300 tick（示例）；`restack_rule`=刷新单例（19.3 增益默认为有限叠层，护盾按 22.4 声明为刷新单例）；额度 = `shield_ratio × 治疗量快照`，`shield_ratio=0.5`（示例）；**S 是效果体而非纯状态**，理由见 N1.3 的 F-06 四判据对照 |
| **命中与伤害份** | H：part0 `type=heal` 60（示例，= 攻击力快照 × 系数）；有益份不判闪避（22.10 候选 B，D-58）。S：一次挂载 hit，part0 `type=shield`，`final_amount`=额度 30（示例） |
| **派生** | H：`hit` → 派生 S（第1代，`parent_ref=H`）。**显式声明：S 的目标 = 触发该 hit 的目标**（覆盖 D-16b「派生体默认排除刚触发该 hit 的目标」，否则护盾会挂到别人身上）。H：`vanish(instant_end)` 无派生。S：`vanish(expired)` 无派生；`vanish(hit_end)`（额度打光）本技能声明无派生（候选：可接“护盾破裂冲击波”，由修饰器 `add_behavior` 接入，不在本卡） |
| **终止原因表** | H：`instant_end`。S：`expired`（300 tick 到期）、`hit_end`（额度打光）、`interrupted`（本技能不使用）。清场/超限丢弃按 `purge`：不发 vanish、不派生、不写结算记录 |
| **修饰器接口** | 暴露：`heal_amount`、`shield_ratio`、`shield_duration_ticks`。水晶可 `mutate_number`；“护盾打光后对周围敌人击退”属新行为，须遗物 `add_behavior`；本卡不暴露 live 字段 |
| **被动触发挂点** | 允许订阅：`hit_settled`（按份 `type=heal` / `shield` 过滤）。不得订阅 `hit` / `vanish` / `debug_record` |
| **玩家文字** | 为一名队友恢复生命，并为其披上一层护盾。护盾会吸收伤害，持续一段时间。 |
| **依赖的规则** | 第4–5章、第6章（6.4 结算记录、6.6 升格）、第7章（派生与 D-16b）、第11章（D-05、11.5 入口）、第14章、第18章（D-44）、第19章（刷新）、第22章（22.3/22.4/22.10） |

### Q2　D-44 快照：治疗量取什么时点？

| 项 | 草案规则 |
|---|---|
| 治疗量（名义） | 施法者属性（攻击力、治疗强度）**出手时快照**进 H 的 `snapshot`，命中后不随施法者变化（D-44，已有文本） |
| 目标侧因素（治疗削减、受治疗加成） | **命中时**取目标当前状态（与“目标实时”口径一致，D-62） |
| 溢出 | 超出生命上限部分不计入治疗份的 `final_amount`（22.3） |
| 护盾额度基数 | S 从父 H 的 `snapshot` 复制（18.1 派生体规则）。**额度取“名义治疗量 × 比例”，不取 `final_amount`**——否则满血目标得到 0 护盾。备选：取 `final_amount`（鼓励在残血时使用，但满血时护盾失效，体验差）。**2026-10-18 第二轮：已登记为 D-95（推荐默认）** |
| 施法者在 H 与 S 之间阵亡 | H 是无载体瞬时实例，同 tick 完成；S 不依附施法者（载体 `none` 挂目标），**不受 D-14a 阵亡清场影响**；额度来自快照，不回读施法者 |

### Q3　护盾吸收是否走 hit 结算记录？

现有文本：22.4“吸收发生在伤害份减免之后、扣血之前（顺序细节见第11章）”；11.5 原把“护甲/护盾/吸血参与顺序”列为**入口位置、细节见第26章候选**。**2026-10-18 第二轮：主书稿已按 D-96（推荐默认）统一 11.5 与 22.4 的吸收顺序，下表为 D-96 的口径来源，已收入主书稿，不再是草案空白**：

| 对象 | 口径（D-96 推荐默认） |
|---|---|
| 来袭伤害 hit | 成立与否、`parts[]`、`final_amount` **不受护盾影响**（`final_amount` = 减免后、吸收前）。被吸收的伤害仍使该 hit 成立 |
| `hit_settled.total` | = 吸收前的伤害合计。理由：“造成伤害时”类遗物应以攻击方产出的伤害为准，护盾是防守方的事 |
| `damage_taken.total` | = **实际扣血量**（吸收后）。完全被吸收则 total=0，按 D-70 **不写** `damage_taken`，只写 `hit_settled` |
| 护盾额度 | 在 S 实例上做内部扣减，**不产生新事件、不产生新结算记录**；额度到 0 的 tick 末，S 以 `vanish(hit_end)` 终止（至多一条，D-15） |
| `any_reduced_to_zero` | **2026-10-18 第二轮（U-2 已统一）**：主书稿 11.2 为准——只看份的 `final_amount` 是否为 0，护盾吸收属结算后行为，**不改变该标记**（`reduced` 不含吸收）；22.4 措辞已对齐。原“主书稿内部不一致”已消除 |
| 同 tick 多条伤害 hit 争一个护盾 | 按 `seq` 顺序依次扣额度（14.3），额度不足时后到者承担剩余部分；与 D-09 确定性一致 |

### Q4　`healing_taken` 是否需要新结算记录？

| 评估项 | 结论 |
|---|---|
| 现状能否表达“被治疗时触发”类遗物 | 治疗 hit 同样写 `hit_settled`（22.2-3）。遗物订阅 `hit_settled`，`condition` 写 `target_id==持有者` 且 份 `type=heal`，即可表达。**现有积木够用**，前提：`hit_settled` 载荷需能按份 `type` 过滤（21.4 已声明 `condition` 含按份 `type` 过滤；**2026-10-18 第二轮（U-3 已统一）：主书稿 6.4/21.2 已给 `hit_settled` 补份级 `parts[]{part_index,type}`，两处口径一致**） |
| 为何仍列为候选 | `damage_taken` 是“受击侧”记录（6.4 产生者=受击侧），带 `target_id`/`total`/`origin`，使“受伤时”类触发不必按目标过滤。治疗没有对称物，遗物作者要自己写 `target_id==持有者`；且“实际回复量（扣除溢出）”在 `hit_settled.total` 里是否扣溢出，书中未明写 |
| **新积木候选 NB-01**：`healing_taken{target_id, total, origin}` | **本草案建议：暂不新增**。先补齐 `hit_settled` 的份类型载荷（U-3，主书稿已补）与 `total` 对治疗是否扣溢出的口径；若压测（T6）发现 ≥2 个技能/遗物必须靠它，再转正。决策编号：**尚未登记**（保持「候选」，转正时再分配新编号，不占 D-95…D-103）；与 D-94 一致，表现层需要份级信息时扩展 `hit_settled`，不新增事件 |

### NB-02　状态承载型效果体的挂载时点（新积木候选，2026-10-18 第二轮已登记为 D-98，推荐默认）

D-71：非瞬时派生体**创建 tick 不判定，spawn_tick+1 起**。S 是非瞬时派生体，且它的“挂载”是一次 hit，因此：

| 候选 | 规则 | 后果 |
|---|---|---|
| A　照 D-71 办理 | H 命中 tick 创建 S，S 在 +1 tick 才挂载 | 有 1 tick 空窗：同 tick 的后续伤害不被吸收；若挂载失败，S 成为无人挂载的空实例，白占 300 tick 预算（D-90 之后无敌不再是失败原因，但其他失败情形仍可能出现） |
| B　载体 `none` 的状态型派生体在创建 tick 即挂载 | 理由：载体 `none` 没有空间判定，D-71 的“下一 tick 才判定”针对的是空间接触（防同帧爆量，F-09） | 无空窗；挂载失败的空实例由 `lifetime` 自然回收；需要给 D-71 补一句适用范围 |
| **推荐（已登记 D-98）** | **B**：状态型派生体的挂载不属于 D-71 所禁止的“判定”，创建 tick 即可挂载；空实例由 `lifetime` 自然回收，不新增原因码。主书稿落点 20.2 末注、22.2-5；不改 D-71 原文 | 推荐默认（原问题 U-4 已按此处理） |

# 案例 N2：控制类（震地冲击 `shock_slam`：眩晕 + 击退）

> **一句话**：一次瞬时范围命中，同一条 hit 内含伤害份、眩晕份、击退份。本案例检验：眩晕是状态还是效果体（F-06）、控制递减（F-23）、“眩晕时位移与施放全部禁止”如何在不加事件的前提下建模（D-06/D-13）。

## N2.1 设计卡

| **施法者闭环** | 索敌 → 前摇 18 tick（示例）→ 出手×1（X=1）→ 冷却 → 回索敌 |

## N2.2 F-06 四判据：眩晕是状态还是效果体？

| 判据（6.6） | 对“眩晕”的判断 |
|---|---|
| 周期触发伤害 | 否 |
| 到期需派生新实例 | 否（本卡）；若有“眩晕结束时爆发”遗物，则是 |
| 需被清场、刷新、叠加、单独修改 | **取决于内容**：本卡的眩晕需要“刷新”（22.8 默认刷新单例）。**只刷新时长字段**，用状态字段 `stun_until_tick` 即可表达；**只有出现“净化/驱散控制”类技能，才需要对眩晕单独 `purge`** |
| 需独立预算与来源链 | 否：每目标至多一个眩晕，数量受目标数约束；眩晕自身不派生 |
| **草案裁定** | **默认不升格**：眩晕 = 目标身上的状态字段 `control{type, until_tick}`，到期**不发任何 vanish/事件**（6.5、6.6 末段）。**升格触发条件**（任一满足即升格，2026-10-18 第二轮已登记 D-99，推荐默认）：(a) 内容里存在净化/驱散；(b) 有“眩晕到期/被净化时派生”的设计；(c) 需要被修饰器单独改（如“眩晕期间受伤增加”做成可驱散增益）。升格后走 `vanish(expired)` / `purge` 与 15 章预算，归 P2，且每目标每类控制至多一个实例 |
| 为何不一开始就全部升格 | 控制命中频繁（每次 hit 一个实例），升格会放大实例预算压力；而它又**不能被预算丢弃**（丢弃会改变结算结果，违背 T-15-7）。状态化可规避此矛盾 |

## N2.3 控制递减（F-23）候选

| 候选 | 规则 | 对“眩晕”的影响 | 评价 |
|---|---|---|---|
| A 不引入（现状） | 同类控制刷新单例，不递减 | 玩家可连锁眩晕目标 | 规则最短；Boss 需靠免疫标签挡 |
| B 全局递减 | 同类控制在窗口 W tick 内再次命中，时长 ×0.5、×0.25、再次为 0（示例） | 所有目标都递减 | 防锁死；但小怪也递减，削弱控制流构筑 |
| **C 目标标签递减（草案推荐）** | 仅目标带 `control_dr=true`（Boss/精英）才递减；窗口 W=300 tick、系数 0.5（均示例） | 小怪不递减；Boss 递减 | 兼顾构筑爽感与 Boss 不可锁死 |

递减的落点：**作为步骤 3 的“减免”**——算入控制份的 `final_amount`（命中时目标侧状态，D-44/D-62）；减到 0 时按 D-05 “免疫”同口径：份减免为 0、hit 仍成立、`any_reduced_to_zero=true`。递减计数是目标侧状态，不是效果体，不新增事件。

F-23 本身仍是「待用户确认」，本草案不改其状态。2026-10-18 第二轮：候选 C 已登记为 D-100（推荐默认候选；主书稿正文未采用，F-23 仍待用户确认）。

**刷新规则（2026-10-18 第二轮，U-5/D-101 已统一）**：D-46 与 19.3 写“刷新 = 重置为新施放的满寿命，不取较大值”，对控制而言会让“剩余 50 tick 的眩晕被一个 20 tick 的眩晕刷新为 20 tick”。主书稿的处理：**控制类刷新默认仍沿用 D-46**；需要“取剩余与新值较大者”时，由设计卡在 `restack_rule` 显式声明 `keep_longer`（D-101，推荐默认），不再把“取较大者”写成控制类的默认例外。

## N2.4 与 D-06/D-13 的交互：“眩晕期间位移与施放全部禁止”怎么建模

**现状**：D-06（已确认）管的是“**位移状态**期间不能施放”；D-13 原写“排队请求不保留”（2026-10-18 第二轮：已被 D-93 取代）；22.8 写“眩晕令闭环**暂停**、定身只阻止位移、沉默只阻止施放”。这三种“禁止”目前散在不同位置，没有统一的门。

**草案建模（不新增事件、不新增第三类记录）：**

| 要素 | 草案规则（2026-10-18 第二轮：已登记 D-102，推荐默认候选） |
|---|---|
| 行动锁 | 目标身上控制状态带锁集合：`stun={cast, move}`、`silence={cast}`、`root={move}`。锁是**状态读取**，不是事件 |
| 施放门 | 闭环“新索敌/前摇能否开始”的门条件由“不在位移状态（D-06/D-13）”扩展为“不在位移状态**且**无 `cast` 锁”。**同一道门，不另起一套机制**。位移技能的出手要进入位移状态，必须先过此门；因此眩晕中不能冲刺 |
| 位移门 | 自身位移（冲刺）受 `move` 锁阻止；受迫位移（击退）不受 `move` 锁阻止（被击退者本来就在被动移动） |
| 排队请求 | **2026-10-18 第二轮：原“沿用 D-13 不保留”作废，改由 D-93（输入缓冲窗口，推荐默认）取代**：门关闭期间收到的施放请求进入短缓冲窗口（推荐 10–15 tick），窗口内门开即执行，过期丢弃（对应 F-05，已修订）；缓冲由输入层持有，技能系统不持有队列 |
| 正在进行的前摇 | **2026-10-18 第二轮（U-6 已统一，主书稿 22.8）**：眩晕与打断分属两种机制。**眩晕 = 闭环暂停**（保留排队出手点语义），眩晕结束恢复闭环，其间不触发打断流程；**眩晕中若被打断则按打断处理**（D-10/D-12：前摇终止、剩余出手点作废、零出手不耗冷却、已生成独立实例继续）。原草案“取打断”的裁定作废，不再要求改述 22.8 |
| 正在位移 | 眩晕/击退命中处于位移状态的目标：位移状态结束，其跟随判定体 `vanish(interrupted)`，默认不派生（D-11；22.7/22.8）；设计卡可声明“位移中免疫击退”（22.7） |
| 击退是否产生“位移状态” | **不产生**。D-18：位移状态是施法者**出手**进入的状态；击退是目标的受迫位移，不套 D-06。若希望“被击退期间不能施放”，在同一 hit 中带 `stun` 份（本卡已如此），而不是给击退偷偷加锁 |
| 同 tick 阵亡 + 眩晕/打断并存 | 沿用 D-69.15（阵亡优先于打断，`purge`），不另立规则 |
| 冷却 | 其他技能冷却照常流逝（4.7-3 同口径）；被眩晕不退还不缩短已在走的冷却 |

这个建模对应新积木候选 **NB-03「行动锁门」**，已登记为 D-102（推荐默认候选）；**是否并入 D-13、是否转为正文规则**，仍待评审与用户确认。

## 1. 系统定位

### 1.1 一句话定位

**技能会自动施放，玩家通过装配模块水晶，改变技能的战斗方式与视觉表现。**

### 1.2 参考体系映射（POE ↔ 本项目）

| POE | 本项目 |
|---|---|
| 技能宝石（Skill Gem） | 技能（初始技能 / 稀有技能） |
| 辅助宝石（Support Gem） | 模块水晶 |
| 宝石等级（1~20） | 水晶等级表（上限=表长，看策划配置） |
| 宝石品质（quality） | 水晶品质字段（档数不限） |
| 插槽+链接（4L/5L/6L） | **4 个水晶槽（=乘区天然硬封顶）** |
| 天赋树+装备（Increased） | 属性 / 装备 / 芯片 / 标签加成（同区加算） |
| 辅助宝石（More） | 水晶数值（逐颗独立乘区） |
| 辅助只影响被链接的技能 | 水晶只影响所属技能池的技能 |

### 1.3 设计目标（沿用 v0.2）

| 目标 | 具体要求 |
|---|---|
| 策略性 | 四个槽位带来明确取舍，不同水晶对应不同战斗场景 |
| 视觉表达 | 每颗重要机制水晶都带来可见变化：轨迹、数量、范围、持续区域、触发时机 |
| 易上手 | 玩家先理解"这颗水晶改变了什么"，再逐步理解组合 |
| 可扩展 | 新技能拥有自己的水晶池；新水晶不改全局规则；**档数/上限/种类全部由表决定** |
| 可读性 | 同一套组合在不同槽位中结果相同，不依赖隐藏装配顺序 |

### 1.4 数据驱动约束（本系统最高优先级）

- 水晶颗数、等级上限、品质档数、标签集合、互斥关系、获取权重——**全部是配置表字段**。
- 代码侧只有一个**通用水晶解释器**：读 `effect` 机制标识 + `lv` 等级表数值执行，不认识任何具体水晶。
- 同类功能共用一套代码；只有当一套代码过于繁琐时才拆分为 N 个单元。

## 2. 核心名词

### 2.1 技能

**英雄初始拥有 1 个技能（无普攻设定）**；局内有概率通过**雕像**获得 1 个稀有技能（概率与细节待定）。

技能 = 一套完整的自动战斗行为：何时施放、选择什么目标、以什么形态产生效果、何时结算、产生什么视觉反馈。技能准备完毕后自动寻找有效目标并施放；玩家**可走位，走位就是主要操作**。

### 2.2 模块水晶

改变技能行为的**独立实体**。水晶有**多个颜色**（视觉体系由作者补图说明），不同颜色 = 不同水晶。

一颗水晶只表达一个核心变化（贯穿/分裂/爆破/余焰/环绕/扩域……），拥有自己的**等级表**（§4）。

### 2.3 水晶槽

**每英雄 4 个水晶槽，开局全部开放，共享作用于该英雄全部已拥有技能**（初始技能 + 稀有技能）。

- 四个槽规则相同，不设类型限制。
- 槽位顺序不影响结果。
- 装上后**局内不可卸载**，只能通过同名合并升级（§5）。
- 4 个槽是数值膨胀的天然硬封顶（=POE 链接数上限，§7.3）。

### 2.4 技能专属水晶池

每个技能拥有独立的水晶池；**水晶归属技能池，只影响所属技能**。

- 火球的水晶围绕火球展开；雷链的水晶围绕跳跃与电击展开。
- 4 槽里混装两个技能的水晶时，每颗水晶只作用于自己所属的技能。
- 英雄未拥有某技能时，其水晶不出现在任何获取途径。

## 3. 数据表设计（数据驱动核心 · 提案待评审）

> 结构参考 POE 技能宝石/辅助宝石的数据组织。以下字段名为提案，评审后可调整；**原则是：策划填表即产新水晶，不改代码**。

### 3.1 技能表（扩展现有 CFG 技能表）

```js
"SK_FIREBALL": {
  name: "火球",
  kind: "active",             // active=初始技能 / rare=稀有技能
  tags: ["魔法", "投射物"],    // 基础标签（§8）
  base: { ... },              // 基础行为定义（发射/索敌/冷却…，沿用现有技能积木）
  crystalPool: ["CR_PIERCE", "CR_SPLIT", "CR_BLAST", "CR_EMBER",
                "CR_FAN", "CR_HOMING", "CR_WIDEN", "CR_ORBIT"],
  lv: { dmg: [...] },         // 技能自身等级表（沿用现有 lv 表机制）
}
```

### 3.2 水晶定义表 `CFG.crystalDefs`

```js
"CR_PIERCE": {
  name: "贯穿",
  color: "red",               // 颜色（视觉体系待作者补图后细化）
  quality: 1,                 // 品质字段（档数不限，代码通用读取）
  pool: "SK_FIREBALL",        // 所属技能池
  effect: "pierce",           // 机制标识（通用解释器按此分发，不硬编码水晶名）
  target: "main",             // 作用对象：main=主效果 / derived=派生 / all
  trigger: "none",            // 触发时机：none/hit/firstHit/vanish/kill…
  addTags: [],                // 装配后追加到技能的标签
  conflicts: [],              // 互斥水晶 id 列表（形态类互斥在此声明）
  hidden: false,              // 面板是否隐藏本水晶带来的标签（策划开关）
  weakWith: ["CR_ORBIT"],     // 低收益组合提示（不禁止，只提示）
  lv: {                       // 等级表：上限=表长，不写死
    1: { count: 2, more: 0 },
    2: { count: 3, more: 0 },
    3: { count: 4, more: 0.10 },
  },
  text: "火球命中敌人后继续飞行，最多额外穿透{count}名敌人。同一枚火球不会重复命中同一目标。",
}
```

### 3.3 字段约定

| 字段 | 说明 |
|---|---|
| `effect` | 机制标识。解释器内置一批通用机制（pierce/split/blast/ember/fan/homing/orbit/widen/数值more…），新机制才加代码 |
| `lv` | 等级表。键=等级，值=该级数值与效果参数；**等级上限=表的最大键**，策划加一行即扩上限 |
| `more` | 该级 More 独立乘区数值（§7.3）；纯机制水晶为 0，不占乘区 |
| `quality` | 品质字段。**档数不限**，UI 颜色/权重按品质表查表渲染 |
| `hidden` | 为 true 时，该水晶带来的标签与变化不在面板外显（内部照常结算） |
| `conflicts` | 互斥。装上冲突水晶时弹提示（§5.3） |
| `weakWith` | 可同时生效但收益低的组合，面板给"效果较弱"提示，不暗中吞掉玩家选择 |

## 4. 水晶升级

- **重复获得同名水晶 = 自动合并升级，不占新槽。**
- 升级效果由**该水晶自己的 `lv` 等级表**定义——可以是数值成长，也可以是机制变化（如 lv3 追加 More、lv2 改变触发条件），**不是单纯的数值叠加**。
- **等级上限 = 等级表长度，看策划表配置，代码禁止写死。**
- 该英雄全部已拥有技能的水晶全满级后，4 选 1 弹窗改出属性小包（沿用现状）。

## 5. 装配规则

### 5.1 开放与锁定

- 四槽**开局全部开放**。
- 水晶装上后**本局（run）内不可卸载**，只能通过同名合并升级。换 build 的代价 = 下一局重新规划。

### 5.2 装配确认弹窗（强制）

装配即承诺，必须强确认：

> **装配「贯穿」？**
> 装入后本局不可卸下，只能升级。
> 〔装配〕 〔取消〕

（呼应 10-09 构思稿的"拾取时确认弹窗"。）

### 5.3 互斥与低收益提示

- 互斥（`conflicts`）：**"「追踪」和「环绕」都改变火球的运动方式，二者只能选择一个。"**
- 低收益（`weakWith`）：**"当前组合可以同时生效，但「贯穿」对环绕形态的帮助较小。"**
- 不允许悄悄吞掉玩家的选择，也不允许暗中补偿数值。

### 5.4 施法快照

已开始的一次施放沿用**发起时**的配置与数值快照；升级水晶只影响之后的施放。已发出的火球不会中途变环绕体，已留下的火场不因升级立即变化。

## 6. 组合规则（沿用 v0.2 §4 定案）

### 6.1 默认组合原则

1. 四颗水晶同时作用于同一次施放。
2. 槽位顺序不参与计算。
3. 互不冲突的水晶可同时装备。
4. 改变同一核心形态的水晶互斥（`conflicts` 声明）。
5. 派生效果默认不触发事件型水晶（§6.2）。
6. 一颗水晶已完成的加成，不被同一条规则重复计算。

### 6.2 主效果与派生效果

- **主效果**：本次施放直接产生的基础效果（含扇射多发）。
- **派生效果**：主效果在命中/消失等事件中额外产生的效果（小火球、爆炸、火场）。属于原技能，不算新施法。

> **命中、首次命中、消失等事件型水晶，只由主效果触发；派生效果不再触发这些水晶。直接适用的强化，仍可作用于派生效果。**

允许主火球同时分裂+爆破+留火场；不默认开放"小火球再爆炸"的连续联动。某水晶自身可设计有限连锁，但必须写明次数、伤害、结束条件。

### 6.3 伤害继承与重复命中

- 派生伤害起点 = 主效果在**外部加成前**的基准 × 继承比例，再对派生应用一次匹配的标签加成。**禁止双重计入**。
- 普通飞行弹对同一敌人只命中一次；贯穿增加可命中的不同敌人数。
- 环绕等可重复接触的攻击必须写明每个目标的受伤间隔。
- 持续区域必须写明伤害间隔、持续时间、重叠规则。
- 直击与爆炸分别结算；爆炸可再次伤害刚被直击的敌人。
- 同一枚主火球消失只触发一次消失事件。

### 6.4 核心形态唯一

**一个技能同时只有一个核心形态。** 形态类水晶（追踪/环绕等重写主效果运动方式的）互斥；不存在"多形态并存"。

### 6.5 持续区域重叠

同一技能产生的同类持续区域重叠时，对同一目标只保留最高一份持续伤害；各区域保留自己的位置与剩余时间。

### 6.6 统一结算顺序（内部规范，不展示给玩家）

1. 确定核心形态 → 2. 主效果数量 → 3. 移动/索敌/碰撞 → 4. 事件判定 → 5. 派生效果 → 6. 范围/持续/数值强化 → 7. 表现反馈。

## 7. 数值模型（POE 正统 · 零标注成本）

### 7.1 伤害类型

**仅 2 个基础类：物理、魔法。** 其他类型（火、流血等）**待定**（§14 备忘）。**无元素转换机制**。

### 7.2 核心规则

> **水晶 = More（每颗独立乘区）；其余一切来源 = Increased（同一个加算区）。**

不需要给任何词缀逐条标注"提高/更多"——按来源自动分轨，完全符合数据驱动。

### 7.3 完整公式

```
最终伤害 = 基准（技能 lv 表）× 形态修正（如扇射单发系数）
         × (1 + Σ[属性 + 装备 + 芯片 + 标签加成 + 环境])   ← Increased 加算区
         × (1+水晶A.more) × (1+水晶B.more) × (1+水晶C.more) × (1+水晶D.more)   ← 水晶独立乘区（≤4 个）
         × 暴击 × 敌方修正
```

- **4 槽 = 乘区硬封顶**：4 颗 30% More = 1.3⁴ ≈ 2.86×，水晶种类再多也炸不了。
- **机制水晶 more=0**：不占乘区；纯数值水晶才进乘区。
- **水晶数值按 More 口径设计**：每颗 20~40% 是 POE 验证过的舒适区，不宜给到 100%+。
- Increased 区（属性/装备/芯片/标签）同区加算 → 堆单一来源边际递减，天然逼分散投资。

### 7.4 派生继承

派生效果伤害 = 主效果基准（含形态修正，不含外部加成）× 继承比例 → 再应用一次匹配标签加成。禁止双重计入。

### 7.5 施法快照

一次施放发起时锁定全部乘区数值（§5.4）。

## 8. 标签系统

### 8.1 标签分层

- **基础伤害类**：物理、魔法（仅这 2 个）。
- **行为/形态类**：投射物、范围、持续、追踪、环绕、控制……（需要被外部系统识别时才新增）。
- **标签与技能的水晶池表格关联**：装配后技能的标签 = 基础标签 + Σ 各水晶 `addTags` 动态汇总。

### 8.2 外显控制

- `hidden: true` 的水晶：其带来的标签与变化**不在面板外显**（内部照常结算）——策划用于藏组合惊喜或简化面板。
- 面板显示技能整体标签；详细作用对象在详情页可查。

### 8.3 作用对象（沿用 v0.2 §6.3）

- "持续伤害提高"只提火场，不提直击。
- "范围半径增加"扩大爆炸与火场，不扩大碰撞体积。
- "投射物伤害提高"提火球与小火球，不自动提爆炸。
- "魔法伤害提高"作用于当前所有魔法类效果（主+派生）。

### 8.4 装配后变化摘要（面板固定显示）

> **火球 → 扇射火球**
> **新增：首次命中分裂、消失爆炸**
> **适用标签：魔法、投射物、范围**

## 9. 品质

### 9.1 字段化

品质 = 水晶表 `quality` 字段 + 品质定义表（名称/颜色/获取权重）。**档数不限**——策划在品质表加一行即扩展，代码通用查表渲染，100+ 档无压力。

### 9.2 设计口径

- **高品质 = 机制更独特 + 有适用条件或机会成本，不等于无条件数值更强。**
- 高品质更稀有、更有视觉记忆点；低品质水晶始终保有特定用途。
- 代价不必写成负面词条——水晶改变了技能更擅长解决的问题，即已构成取舍。

## 11. 迁移映射（武器模块 → 模块水晶）

## 13. 火球试点（沿用 v0.2 §9，标签口径已修订）

> 试点目的：验证文案、组合逻辑、视觉表达。**标签统一改用"魔法"**（原"火焰"）。

**基础技能·火球**：自动向攻击范围内目标发射一枚火球，命中造成魔法伤害并消失。标签：**魔法、投射物**。

**候选水晶 8 颗**（机制沿用 v0.2 §9.2）：贯穿 / 扇射 / 追踪 / 分裂 / 爆破 / 余焰 / 扩域 / 环绕。

- 贯穿作用于"本技能的火球"（主+小火球），不扩大爆炸/火场。
- 分裂与爆破/余焰可同装，默认只有主火球触发；小火球不再触发。
- 环绕×追踪互斥（核心形态冲突）。
- 环绕×贯穿可同装但低收益 → `weakWith` 提示。
- 扇射×分裂可同装：每枚主火球首次命中各自分裂。

**组合示例**（穿行清线 / 地面覆盖 / 近身环绕）沿用 v0.2 §9.3 全文，文案中"火焰"改"魔法"。

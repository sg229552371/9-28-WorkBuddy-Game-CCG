# 技能时序规范：两个主体、两条时间轴

技能时序**不能用单条链**描述（例如 A施法前→B施法时→C攻击中→D攻击结束→冷却）。
必须拆成两条**相互独立**的时间轴。

## 技能流程层一 · 施法者相位（每英雄一条，是**闭环**）

索敌决定 → 起手·前摇（可选）→ 出手 → 冷却 →（回索敌）

- **索敌决定**：找目标 + 判冷却门 + 判无目标策略 —— `skill-scheduler.js:28 _castPolicy`、`tick :168`
- **起手·前摇**：可选读条，读条未满不施放 —— `castTimeFor :119`、读条段 `:211-217`
  （机制已完整接线，但绝大多数技能 castTime=0，唯一非 0 = SK_SHOCKWAVE → 实际近乎无前摇）
- **出手**：创建主效果实例，是**瞬时事件** —— `skill-runtime.js` 单步第③段 `:406`
- **冷却**：下次可施放前的等待。环绕类 = max(冷却, 持续时间)，不是单纯冷却 —— `cooldownFor :52`、`intervalFor :95-108`

## 技能流程层二 · 效果体生命周期（0~N 个实例，每个各走一遍）

生成 → 存活·运动 → 命中 0~N 次 → 终止 → 派生 → 回收

- **命中是事件（瞬时），不是状态**。飞行是过程 —— 两者不能同居一格
- 派生创建**新实例**后，**递归回「生成」再走一遍** → 层二是**递归链**，不是直线
- 终止路径中**不发消失事件者不进入派生**（例：英雄阵亡强制清场，不发 vanish、不派生）
- 实现真源：`skill-runtime.js:383 _updateHeroStep`，单步十段；⑨ 派生必须先于 ⑩ 回收（硬约束）

## 术语纪律（最易错，务必遵守）

- 「效果体生命周期**产生** 0~N 个事件」——**不能**说「生命周期 = 一个事件」
- 「派生段**由事件驱动**」——事件被消费后才长出新实例
- 事件只有两种：**hit / vanish**；「触发一个事件」= 入队（`SkillEvents.emit` ≡ `enqueue`）
- **事件 ≠ 生命周期**：事件是**点**，生命周期是**容器**。类比：实例是演员，事件是他说的台词，台词可以零句，但演员仍活过一生
- 还要区分第三样东西：**`request`**（调度器产生的施放请求，属层一，不是 `SkillEvents`）

## 口语线性版（保留原骨架的最小修正）

索敌 → 起手（可选前摇）→ 出手 → ［载体存活期：运动 ＋ 0~N 次命中 → 终止 → 派生 → 回收］→ 冷却 → 回索敌

### 0.3 术语与口径（本文档内统一）

- **定位**：`CFG.heroRoles` 三值 `output`（输出）/ `defense`（防御）/ `aux`（辅助）。三者**都有伤害**，差异在「伤害倍率 + 附加效果」（`js/config.js:1690~1692`）。
- **专属武器**：`CFG.heroes[].weapon` → `CFG.weapons[wid]`，创建时绑定、不可更换（`js/config.js:1267`；设计书 887）。
- **绑定技能**：`CFG.skillSystem.initialSkillBindings[heroId].skillId` → `CFG.skillSystem.skillDefs[skillId]`（`js/config.js:2858~2875`）。旧表 `CFG.weapons[wid].skills.skill`（AT 编号）为**迁移基准**，二者净效果等价（`js/config.js:3118~3130`）。
- **风格带**：`hero_roster_test.js:140~144` 定义的按定位的 `hp/def/atk` 区间，12 角必须落在其定位带内。

### 1.4 实测纠偏：退役字段仍被二次消费（隐性张力）

- `CFG.skillResource.mode = "cooldown"`（`js/config.js:1717~1720`）已**宣告能量池退役**：技能只受冷却约束，不再检查 `energyMax / energyRegen`。
- **但实测**：12 角**仍各自携带** `energyMax / energyRegen` 差值与半径（§1.1 表），且：
  1. `SK_PSYSHIELD` 的附加效果以 `energyMax` 为加成源：`effect: { kind:"barrier", …, scaleStat:"energyMax", scalePct:0.008 }`（`js/config.js:3382`）。
  2. `CFG.baseStats.int.energyMax = 2`（`js/config.js:777`）→ 智力折算**仍向 `energyMax` 加值**（`js/config.js:764` 文案「每点 +2 能量上限」）。
  3. `hero_kit_test.js:329~330` 六6 仍在断言「智力 +10 → 能量上限 +20」；`hero_roster_test.js:202~203` 七1 快照仍在锁定 `energyMax`。
- **结论（已证实）**：`energyMax` 处于「**技能门槛已退役、但技能 scaling 与属性折算仍在消费**」的中间态 —— 这正是 §1.3 之外的另一处「定位/字段口径不一致」，须在落库清单与待裁决项中处理。

## 2. 差异化设计（12 条，逐角一条）

### 2.1 设计原则（本轮新增的收口口径）

1. **一角色一钩子**：每个角色必须有**唯一**的机制钩子（与其余 11 人不重叠），玩家凭一句话即可记住其玩法。
2. **三定位内互补**：同一 `role` 的 4 名角色之间要有"正/反面"张力（如输出=单体 vs 多弹道 vs 穿透 vs 重爆），而非同质换皮。
3. **三定位三通道**：output = 直接伤害通道；defense = 承伤/控场通道；aux = 团队增益通道（治疗 / 增益 / 护盾 / 召唤四细分，`js/config.js:1700`）。
4. **数值落地进 `CFG` 表**：本节所有新增描述性/倾向性字段一律以数据驱动结构表达（见 §4），**数值不进逻辑**。
5. **物理序与 group 不变**：不改 `CFG.heroes` 物理序（坑 13），不改 `byHero` 分组（`hero_roster_test.js:51~53` 锁定）。

## 3. 首版 6 角建议

### 3.2 推荐名单（三定位各 2，且每定位 1 远 1 近）

> ✅ **已采纳（2026-10-13 本轮落库，见 D025）**：本推荐的**首版 6 角名单**（H001 / H006 / H004 / H005 / H010 / H012，三定位各 2、每定位远/近各 1）已写入 `CFG.starterHeroIds` 并**接线**（`isHeroUnlocked`）；**Q1 已采纳**。

> **推荐首版 6 角 = H001 猎手（output·远）/ H006 重炮手（output·近）/ H004 弹射手（defense·远）/ H005 快枪手（defense·近）/ H010 医疗兵（aux·远）/ H012 灵能者（aux·近）**

| 定位 | 远程代表 | 近战代表 | 为何选它 |
| ---- | ---- | ---- | ---- |

### 3.3 推荐理由（每条一句）

1. **三定位齐备**：2/2/2 覆盖 output/defense/aux，修复现状"首发无 aux"的缺口（§3.1）。
2. **每定位远近各一**：延续 `hero_roster_test.js:151~156` 五2 的"每定位同时有远程与近战"原则，让首发玩家在同一定位内即有远近两种手感。
3. **操作难度梯度**：H001（低·基准）→ H004/H010（低-中·站位/支援）→ H006/H012（中·慢速重炮/护罩时机）→ H005（高·机动拉扯），构成 1→3 的难度爬坡。
4. **技能形态覆盖最广**：6 角涵盖直射点爆 / 重爆 / 弹幕墙 / 多弹道 / 治疗 / 护罩六种形态，可一次性验证新路径 `skillDefs` 的投射物 + 范围 + 附加效果三条主通道。
5. **改动面可控**：无需改动任何战斗数值与技能定义，仅需新增一个"首发名单"数据字段（见 §4-B），物理序、`byHero`、武器/技能绑定全部不动。

### 3.4 备选（若不接受改动首发机制）

- **备选 B（零机制改动）**：沿用 H001~H006，**接受首版无 aux**。代价 = 三定位体验不完整、aux 的四条专属技能（`SK_DRONESWARM/SK_LIFEPULSE/SK_WARSONG/SK_PSYSHIELD`）在首版不可达。
- **备选 C（折中）**：首发 = H001~H005 + **H010**（仅把第 6 个换成医疗兵，2/2/... 不齐，但至少引入 aux）。仍需"首发名单"数据字段，因 H010 不在前 6。

## 3. 核心规则速查（以 v0.5 为准，逐条可回查）

### 3.1 玩家规则（v0.5 §1）
- **技能来源 = 武器绑定的唯一初始主动技能**（v0.5 §1 + 22.2 拍板）；真源 `CFG.skillSystem.initialSkillBindings[heroId]`。
- **无普攻**：`CFG.basicAttack.removed = true`（条目保留供敌人复用，英雄侧发射路径关闭）。
- **稀有技能**：局内由**雕像最多获得 1 个**（`rareSkillPool` + `RP_STATUE`）；已拥有后再次触发 → 转其他奖励。
- **每英雄 4 个共享水晶槽，开局全开**；两个技能（初始 + 稀有）共享这 4 颗。
- 每颗水晶**分别判断两个技能**，符合的都强化。
- 水晶装配后**本局不可卸载/替换**；同 `crystalId` 重复获得 → 升级，不新增槽。
- **等级上限 = 等级数组长度**；品质由定义固定。
- 水晶来自**升级 4 选 1**；**商店/宝箱不出水晶**。
- 满槽只出「已装且未满级」的合法升级，其余位置补属性奖励；**不生成废选项**。

### 3.2 技能运行（v0.5 §2）
- 技能定义：施放条件 / 索敌 / 冷却 / 效果图；**两技能独立计时，互不阻塞**。
- 默认索敌 = 范围内最近有效敌人，距离相同按**稳定目标 ID**。
- **无目标保持就绪、不消耗冷却**；**环绕类允许无目标施放**。
- 同时就绪按**稳定技能 ID** 执行。
- **一次施放锁定**构建 / 进攻属性 / 水晶等级 / 派生配置；升级只影响后续施放。
- 环绕：有效施放间隔 = `max(冷却, 环绕持续时间)`；自然到期先处理再生成新批。

### 3.3 适用 / 冲突 / 不可拆保护（v0.5 §3）
- **标签说明「是什么」，能力说明「能做什么」**；投射物标签**不自动**代表可贯穿/追踪/分裂。
- 装配或升级先**模拟完整新组合**，须满足：① 新水晶至少对一个已有技能有**实际收益**；② 每颗已装水晶**仍至少对一技能有收益**；③ 无互斥、无无界事件链、参数与预算合法。
- 保护按**完整已拥有技能组**判断，不按单节点；全部失效 → 禁止该候选（`EXISTING_CRYSTAL_INACTIVE`）。
- 互斥 = **资源组 + 技能作用域**（首批：追踪与环绕争用主运动资源）。

### 3.4 编译流程（v0.5 §4 / 合同 §8）
```
基础图 → 主形态 → 数量与分布 → 派生模板展开 → 节点参数与伤害修正 → 校验 → 冻结构建
```
- 结构操作只读**已完成阶段**的图；**禁止靠自身新增能力过前置检查**；**禁循环依赖**。
- 同阶段同字段只用已声明合并算子：`add | multiply | min | max | exclusive`；
  `exclusive` 多来源即冲突。
- **先按稳定 operationId 排序再归并** → 槽位排列不改变结果。
- 输出逐水晶逐技能 `applied / inactive / conflict` + 命中节点 + 参数前后值 + 原因。

### 3.5 伤害与命中（v0.5 §5 / 合同 §10，**冻结**）
```
伤害 = 原始基准 × 形态系数 × 派生比例 × (1 + 匹配外部 Increased 总和)
       × Π(各独立水晶 More) × 暴击倍率 × 敌方修正
```
- **水晶 = More 独立乘区（≤4 颗）**；属性/装备/遗迹秘宝/标签 = **Increased 同区加算**。
- 每个修改器对同一节点**只应用一次**。
- **派生引用未经外部加成的原始基准**（不复制父节点最终伤害）。
- 命中额度（五类，冻结）：

| 类型 | 额度键 | 说明 |
|---|---|---|
| 主飞行弹 | `castId + 主直击组 + targetId` | 一次施放一次 |
| 分裂子弹 | `castId + 派生模板组 + targetId` | **出生目标排除** |
| 爆炸 | `castId + 爆炸模板组 + targetId` | 可与直击各一次 |
| 环绕 | `ownerId + skillId + 接触模板组 + targetId` | 共享 `nextAllowedHitTime` |
| 持续区域 | `ownerId + skillId + 区域模板组` | 取**有效最高 DPS**，共享结算时钟 |

- 持续伤害**默认不暴击**；瞬时命中每次独立暴击。

### 3.6 事件与派生（v0.5 §6）
- 主效果 = 施放直接创建（含扇射多发）；派生 = 命中/消失产生，**不算新施法**。
- **默认只有主效果触发事件水晶**；首批**不开放二层事件联动**。
- 事件字段：`castId / ownerId / skillId / effectId / parentId / templateId / operationId / targetId / depth / simulationTime / endReason`。
- 处理顺序：合法伤害 → 首次命中事件 → 贯穿与结束判断 → 消失事件。
- **自然消失可派生；批次替换 / 场景清理 / 离局 / 强制回收不可派生**。
- 每实例「首次伤害命中」与「消失」**各只发一次**。

### 3.7 首批 8 颗机制水晶 + 1 通用增幅（v0.5 §7）

| 水晶 | 改变 | 适用与限制 |
|---|---|---|
| 贯穿 | 增加额外贯穿目标数 | 具备贯穿计数的飞行弹；不改环绕接触 |
| 扇射 | 增加主效果数量、降低单体系数 | 支持数量分布的主生成器；不增分裂数量 |
| 追踪 | 主飞行弹持续转向 | 支持转向的主飞行弹；**与环绕互斥** |
| 分裂 | 首次命中产生小弹 | 主投射物；小弹不再触发事件水晶 |
| 爆破 | 自然消失产生瞬时范围伤害 | 有位置的消失事件；不由清理触发 |
| 余焰 | 自然消失产生持续区域 | 不另加瞬时伤害；重叠按最高 DPS |
| 扩域 | 扩大最终图伤害范围半径 | 爆炸/火场；**不改**弹体/扇角/索敌/环绕距离 |
| 环绕 | 主弹改为围绕英雄的接触实体 | **与追踪互斥**；一批共享目标间隔 |
| 奥术增幅 | 通用魔法伤害 More | **测试定义**，证明跨能力共享，不扩大正式承诺 |

### 3.8 获取与升级（v0.5 §8）
```
合并获取池 → 按 ID 去重 → 新装/升级分类 → 完整组合模拟 → 权重抽取 → 属性兜底 → 确认并原子提交
```
- 两池同 ID 权重默认取 **max**（不自动相加）。
- 升级不占新槽；满级移出候选；非法新装**不以灰色废选项占位**。
- 奖励生成时保存候选与随机状态；**取消不改变结果**；`rewardId` 只能兑现一次。

### 3.9 数据 / 程序边界（v0.5 §9）
- 配置表：`skillDefs / effectTemplates / crystalDefs / qualityDefs / rewardPools / rewardPolicies / supportGroupRules / hitPolicies / stackPolicies / eventPolicies / budgetPolicies / migrationMaps / localization`。
- **已有能力内新增技能/水晶只改配置**；**新底层机制才加通用执行器**。
- **禁止按具体技能/水晶 ID 或名称决定战斗行为**；配置**不允许嵌入任意脚本/eval/路径**。
- 单位：秒 / 度 / 世界距离 / 概率 0~1 / 数量非负整数 / 倍率 1=原值；**禁止 NaN、Infinity、隐式字符串转数值**。

## 8. 22.x 关键血泪（改技能系统前必读）

1. **字段名必须冻结到「取值词表级」**——W6 的 8 个缺陷中 5 个源于「词表未冻结」（`cooldown` vs `cd`、`maxRange` vs `range`、`requiresTarget` vs `allowNoTarget`）。**症状：静默降级，门禁全绿但行为错**。
2. **测试桩对着「合成契约」断言 = 假绿**：`skill_scheduler_test` 桩内字段名与实现一致 → 恒绿；真源是 `CFG.skillSystem`。**新自检必须直读真实配置**（`skill_rule_binding_test`）。
3. **节点参数必须包进 `parameters` 子对象**——平铺在等级行上读不到 → 伤害恒 0。
4. **`_cloneNode` 等级行参数只并入主节点**；否则爆炸被主弹参数污染（radius=8 的"爆炸"）。
5. **派生请求不能只带 `templateId`**——会错配主节点（爆破变成又一发主弹）。必须 `操作→节点→事件→精确 nodeId`。
6. **帧率一致性测试能抓到"每帧施放"**——坐标冷却字段名错误时，施放数随帧率线性爆炸（720/1440/2880）。**别删这条测试**。
7. **测试 PASS 文案不能含英文 `error` / `FAIL`**（门禁 `grep -ci` 会误判 `bad=1`）。
8. **恒真断言 / 空真断言**是本项目高频坑（`every` 对空数组恒 true）；写断言先问「它可能恒真吗」。
9. **「装好但未启用」的系统里，硬编码默认值是真缺口的温床**——W1 的 `level: 1` 在 `enabled:false` 时**门禁全绿、零影响**，一旦启用就「技能永不成长」。**判定方法**：搜 `level: 1` / `= 1` 这类**占位默认值**，问「它在启用后还成立吗」。启用批次必须**逐个把占位值换成真源**（本批 W1 修等级，W3 修数值）。
10. **分工边界要写进注释**：**整合层（`skill-playtest.js`）是全项目唯一允许读局外存档 `Meta` 的地方**，三个技能模块（config/compiler/reward）保持**纯函数**（只读入参）。好处：无头沙箱里 `Meta` 不存在 → 自动回落默认值 → **既有测试零改动**（30 条新断言里有 6 条专门守这条）。
11. **给「已存在的界面」加新渲染分支时，旧分支必须**逐字不改**，并且**用旧测试的隐式契约去反推约束**。W2 实例：`endless_hud_test` 七2/七3 断言 `row.children[0]` 是 `.ps-icon`、`row.children[1]` 是 `.ps-info`（**顺序**被隐式锁死），而 `ui_v2_test` 有 42 处依赖 `.ps-slot` ×4。→ 结论：新路径（`A X X X X A`）另起一套排布 `[英雄名][A][XXXX][A]`，旧路径把原 append 顺序原样保留；水晶槽**外层仍用 `.ps-slot`**，只额外挂 `crystal-slot`。**「新 class 前缀 + 保留旧 class」比「替换旧 class」安全一个数量级。**
12. **异步化（弹窗代替自动生效）必须留同步降级通道**。W2 把「踩雕像自动授予稀有技能」改成「弹窗选择」——如果无条件异步，`skill_playtest_test` ⑪ 段（同步断言「踩完就有 2 个技能」）必红。**解法：探测 `UI.showChoice` 是否可用，不可用就走原同步自动授予**；无头沙箱没加载 `js/ui.js` → 自动落回旧行为 → **旧测试零改动**。这条与第 10 条同源：**整合层对运行环境做能力探测，而不是要求环境适配代码**。
13. **`CFG` 里同一个名字可能是数组也可能是映射**。W2 的 `crystalQualityOf` 写成 `qualityDefs[qid]`，而真源是**数组**（`qualityDefs: [ {id, rank, color}, ... ]`）→ 取到 `undefined` → 品质色静默变 `null`（界面不报错、只是变灰）。**症状：门禁全绿、单测全绿，只有「颜色不对」**。→ 读配置前先确认容器形态（数组按 `id` 查、映射按键取），**两种都兼容**。写新测试时断言「取到的颜色 === 配表里的颜色」这种**关系**，而不是写死具体色值。

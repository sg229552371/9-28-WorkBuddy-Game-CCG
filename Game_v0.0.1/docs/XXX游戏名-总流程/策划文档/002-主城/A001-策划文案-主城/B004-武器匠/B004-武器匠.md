## 一、这个功能是干什么的

**一句话**：花结晶，把**武器**（连带武器上的技能）从 1 级往上强化，最高 100 级。

**和强化导师的区别（最容易搞混的一点）**：

| | 强化导师（B003） | 武器匠（B004） |
|---|---|---|
| 花结晶升谁 | 升**英雄这个人** | 升**武器这件东西** |
| 升一次影响 | 这个英雄更强 | 这把武器更强，用它的时候技能也更强 |
| 最高多少级 | 46 级 | 100 级 |
| 认人的颜色 | 紫 ✦ | 金 ⚔ |

> 太奶奶注意：**这两个面板长得非常像**（都是一行一个东西、一个等级、一个按钮）。玩家第一次进来十有八九会搞混。所以 NPC 的颜色必须拉开，紫的升人，金的升武器。

**为什么要有这个**：英雄等级是「底子」，武器等级是「招数」。玩家攒了钱，这两件事要分开决定——先补底子还是先补招数，这是一个选择，有选择才有琢磨。

## 三、点「强化」以后发生什么

```
玩家走进金色 ⚔ 圈 → 面板自动弹出（右边）
   ↓
① 玩家看中一件武器，把鼠标移到「强化 ◆150」上         0 秒
   ↓
② 点下去                                            0 秒
   ↓
③ 系统算一遍强化价格                                 瞬间
   ↓
④ 检查结晶够不够                                     瞬间
   ↓
⑤ 够 → 扣结晶，这件武器等级 +1                        瞬间
   ↓
⑥ 左上角档案卡结晶数字变小                            瞬间
   ↓
⑦ 面板整个重画：等级 +1，下一级价格变贵               瞬间
```

**耗时**：**小于 0.1 秒**。

### 3.1 价格是怎么算的（说人话版）

> 这一节给开发看。太奶奶只要知道结论：**越强化越贵，而且是越往后贵得越快。**

| 规则 | 说人话 |
|---|---|
| 起步价 | 1 级强化花一个「基础价」 |
| 每升一级 | 按一个固定的倍数往上乘（这个倍数很小，比如每次多 5%） |
| 最后一步 | 把结果**向上取整到一个整数倍**（比如取整到 10 的倍数） |

**公式（只在括号里给开发看）**：
`价格 = ceil(基础价 × 倍率^(当前等级-1) ÷ 取整单位) × 取整单位`
—— 出处：`city_visual.gd` 第 397~401 行；`基础价`、`倍率`、`取整单位` 三个参数读 `cfg/weaponLevel.json` 的第 6~8 行（分别是 120、1.05、10）。

> **不许在文档里抄死「3 级要 133」这种数字。** 只要有人调了倍率，文档立刻变成假话。文档只说「价格由谁算、参数在哪」。

## 四、各种状态

### 4.1 NPC 圈

| 状态 | 什么时候 | 样子 |
|---|---|---|
| **常态** | 玩家不在圈里 | 金色虚线圆，透明度 70% |
| **悬停 / 靠近** | 走进 76 像素内 | 圈变实，面板弹出 |
| **按下** | 无 | 圈不是按钮 |
| **禁用** | 不会 | 永远在 |

### 4.2 强化按钮

| 状态 | 什么时候 | 样子 |
|---|---|---|
| **常态** | 没满级、钱够 | 亮按钮「强化 ◆150」 |
| **悬停** | 鼠标移上去 | 提亮，变手形 |
| **按下** | 按住 | 压暗 |
| **禁用（满级）** | 已到 100 级 | 灰底灰字「已满级」，点不动 |
| **结晶不足** | 钱不够 | **看起来还是能点，点了没反应**，只在后台记一条警告（第 407~409 行）。**这是问题** |

> **注意一个不一样的地方**：武器匠在检查钱之前会**先算一遍价格**（第 406 行），所以「价格」和「扣的钱」永远一致，这是个细节做得好的地方。而强化导师那边是靠 `hero_growth.gd` 自己判断，两边逻辑不统一——**不影响玩家，但开发要知道这两块不是一套代码**。

## 六、异常情况怎么处理

| 情况 | 处理 | 玩家看到什么 |
|---|---|---|
| 结晶不够 | 不扣钱、不升级，后台记日志（第 407~409 行） | 现在：什么也不发生（要改：按钮抖 + 提示） |
| 已到 100 级 | 按钮变「已满级」禁用（第 387~389 行） | 灰按钮 |
| 武器表里一件武器都没有 | 面板只剩标题和横线 | 空面板。**这是配置坏了，要弹一句提示** |
| 武器等级数据缺失 | 按 1 级算（第 378 行「至少当作 1 级」） | 显示 Lv.1 |
| `weaponLevel` 配置缺字段 | 用缺省值：基础价 100、倍率 1.0、取整 1（第 398~400 行） | 每级都是 100，玩家会觉得「价格不涨很奇怪」 |
| 倍率配成小于 1（比如 0.9） | 价格越强化越便宜 | 玩家能刷出无限便宜的强化。**必须在配置校验里拦住** |
| 连点 | 每一下独立结算，会连升多级 | 允许（见第十节） |

## 七、这个功能不许干的事

| ❌ 不许 | 为什么 |
|---|---|
| 和强化导师共用一个按钮 | 两个功能的成本、上限、作用完全不同，共用一个按钮一定会出两种错 |
| 弹确认框 | 主城不设确认框 |
| 只改「武器等级」不改「技能强度」 | 副标题写了「武器 / 技能等级」，玩家会期待技能也变强。**如果技能没跟着变强，副标题就得改** |
| 显示「攻击力 +5%」这种百分比 | 太奶奶看不懂百分比。要么写「攻击 +12 点」，要么什么都别写 |
| 强化成功后关面板 | 玩家通常要连着强化好几级 |
| 满级后还显示成本 | 「已满级」就够了，不要再写「强化 ◆9999」 |
| 一件武器升到 100 级要花一辈子 | 100 级是上限，但从中期（约 30 小时）的角度看，应该能在合理时间内摸到高等级。这个要调平衡，不是这里定 |
| 让玩家以为「强化了就能带进下一局」以外的效果 | 这里只强化「专属武器」本身，不做临时装备 |

## 八、和其他文档的约定

| 对象 | 约定 |
|---|---|
| 输入 | 走进圈 + 点「强化 ◆N」 |
| 输出 | 武器等级 +1，扣结晶，通知档案卡刷新（第 413 行） |
| 依赖 1 | `cfg/weapons.json` 提供武器名单和名字 |
| 依赖 2 | `cfg/weaponLevel.json` 提供 `maxLv`（最高等级）、`costBase`（基础价）、`costGrowth`（每级倍率）、`costRound`（取整单位） |
| 依赖 3 | 武器上还写了 `basicMulPerLv`（每级普攻加成）和 `skillMulPerLv`（每级技能加成）——**这两个数值的战斗效果由 `005-战斗` 负责，主城只管加等级** |
| 和 `B003-强化导师` | 结构相同，颜色必须不同；两边不能共用同一个「钱不够」的提示逻辑（现在就是两套） |
| 和 `B002-档案卡` | 强化成功必须让结晶数字变化 |

## 一、这个功能是干什么的

**一句话**：主城的第二道门，通往「没有尽头的深渊」——**但现在走进去，什么也不会发生。**

**设计上它应该是什么**：游戏后期，玩家把毕业关打穿了，主城就多出一扇门。这扇门后面没有「第 N 关」，只有一直往下、越来越难、算不清第几层。**这是给「玩不够」的玩家的出口**，也是整款游戏「后期毕业关 + 无限模式并存」里的那个「无限模式」。

**为什么放在主城**：因为它是**长期目标**。玩家每次路过它都会想「等我再强一点就去」。这种「看得见但还不敢进」的门，本身就是动力。

**现在的实际状态（必须先说清）**：圈画出来了，读条也能走完，2 秒一到——**没有任何反应**。玩家会认为是自己没站对，站在那里反复试。

### 2.2 和出征门的对比（这是玩家真正要分清的）

## 三、走进去以后发生什么（现在的真实流程）

```
玩家走进橙红 !! 圈
   ↓
① 圈变实，圈外出现金色读条环              0 秒
   ↓
② 玩家站着数 2 秒                          2 秒
   （中途出圈 → 读条清零）
   ↓
③ 读条满 → 主城广播一条消息「我要进深渊」  瞬间
   ↓
④ 主城里记一下「这个圈已经触发过了」       瞬间
   ↓
⑤ ……                                       ← 什么都没有
   ↓
玩家仍然站在圈里，什么也没发生
```

**耗时**：**读条 2 秒 → 然后无限等待**。

> ⚠️ **这是主城里最伤人的一个 bug。** 出征门的读条满之后会弹选关屏，玩家的预期已经被训练成「数满 2 秒 = 有事发生」。深渊门数满 2 秒什么都不发生，玩家的第一反应不是「这功能没做」，而是「**我是不是站歪了**」，然后站在原地反复进出，浪费好几分钟。

### 3.1 为什么没反应（开发看）

读条完成时，代码会往事件总线发一条消息 `enter_abyss`（第 160 行）。**但整个项目里没有任何一处接收这条消息。** 全项目搜 `enter_abyss`，只有发出的一处，没有接收的一处。

| 环节 | 状态 |
|---|---|
| 发出消息 | ✅ 有（第 160 行） |
| 接收消息 | ❌ **没有** |
| 打开深渊关卡 | ❌ 没有 |

**要接的不是一个按钮，是一条完整的链路**：深渊模式本身（无尽关卡、层数、掉落）也得先存在，门才有地方可去。

## 四、各种状态

### 4.1 圈

| 状态 | 什么时候 | 样子 |
|---|---|---|
| **常态** | 不在圈里 | 橙红虚线圆，70% 透明 |
| **悬停 / 靠近** | 走进 84 像素内 | 圈变实，读条环开始 |
| **按下 / 读条中** | 读条计时进行中 | 金色读条环从 12 点方向长 |
| **禁用（配置层面）** | `abyssPortal.ready` 设成 `false`，或者整段配置删掉 | **圈完全不出现**（代码第 72 行只建 `ready` 为真的门） |
| **禁用（实际状态）** | **现在就是这一种** | 圈看起来完全正常、能读条，**但走完什么也没有** |
| **已触发** | 读完一次还没走出去 | 再站多久都不会再触发（第 152~156 行） |

> **注意那个「禁用」**：代码支持「不显示这扇门」，只要把配置里的 `ready` 改成 `false`。**这是一个现成的开关，改一个字就能让门消失。**

### 4.2 关于 `ready = true` 这件事

配置里 `ready` 写的是 `true`（`cfg/city.json` 第 90 行）。这个字段的实际意思是「**门要在主城里显示出来**」——所以它确实显示了。

**但「显示」不等于「能用」。** `ready` 是「画不画」，不是「通不通」。这两个意思被同一个字段承担了，所以现在出现了一种最糟的组合：**门画出来了，路没修通。**

## 五、声音 / 反馈

| 时机 | 现在有没有 | 建议 |
|---|---|---|
| 踩进圈 | ❌ 没有 | 一声低沉、偏暗的「嗡」（30%）。**深渊的声音应该比出征门更低更闷** |
| 读条中 | ❌ 没有 | 一段往上爬的暗色呼吸音（2 秒），音调比出征门低 |
| 读条满 | ❌ 没有 | 一声「咕——」（像石头落水）60%，然后——**下面必须有东西发生** |
| 读条走完却什么都没发生 | ❌ 没有 | **这一条不是缺音效，是缺功能** |
| 走出圈中断 | ❌ 没有 | 轻轻的「噗」（20%） |

> 现在一条音效都没有。但**音效能掩盖的问题只是「没有反馈」，掩不住「点了没反应」**——这是两回事。

## 六、异常情况怎么处理

| 情况 | 处理 | 玩家看到什么 |
|---|---|---|
| **读条走完，深渊没接上** | **现在：什么都不做** | 玩家一动不动地等，以为卡了 |
| 读条途中走开 | 计时清零，环消失 | 环没了，重来 |
| 读完在圈里继续站 | 不重复触发 | 无感（除非他一直在等，那他永远等不到） |
| 配置里整段删掉 | 门不出现 | 干干净净什么都没有 |
| 配置里 `ready` 改成 `false` | 门不出现 | 同上 |
| 玩家分不清出征门和深渊门 | 位置、颜色、符号都不同 | 一般不会搞错 |
| 读条 2 秒内玩家手动关游戏 | 正常退出 | — |

## 七、这个功能不许干的事

| ❌ 不许 | 为什么 |
|---|---|
| 读条走完什么都不发生 | **现在就是这样。** 这是全主城最伤人的一处 |
| 读条走完弹一句「暂无内容」 | 比没反应好一点，但一个「能做却做不了」的门，比一扇门都没有更让人失望 |
| 和出征门同色同符号 | 玩家会走错门 |
| 在深渊里也按「打死 Boss 就算赢」 | 无尽模式的本意是「没有终点」，规则不能照搬。**具体规则归深渊自己的文档** |
| 深渊里死掉也「保住局外等级」以外的东西 | 全局规则是「死了丢掉本局所有东西、局外等级保住」。**深渊不能破这条规矩**，除非太奶奶另定 |
| 一开局就把这扇门亮出来勾引新手 | 新手第一次进主城时，这扇门应该是**暗的或者关着的**，别让他第一次就走进一个 30 秒必死的坑 |
| 让玩家以为「进去就有好东西」 | 深渊应该写清楚「越深越难，没有底」 |

## 八、和其他文档的约定

| 对象 | 约定 |
|---|---|
| 输入 | 走进圈（距离 < 84 像素），不需要点击 |
| 输出 | 发出一条「我要进深渊」的消息（第 160 行） |
| **依赖（缺）** | **必须有东西接这条消息**，把玩家送进深渊模式。现在没有 |
| **依赖（缺）** | 深渊模式本身（层数、难度、掉落）要先存在 |
| 和 `B001-出征传送门` | 两扇门**读条时长一样（都是 2 秒）**，行为结构也一样。区分全靠颜色/符号/位置 |
| 和「后期毕业关」 | 设计上这两样同时开放。**先做毕业关，再做无限模式**，这是已经定了的顺序 |
| 和全局规则 | 死了丢本局所有东西、局外等级保住。**这条在深渊里也必须成立**，否则玩家会去深渊刷等级 |

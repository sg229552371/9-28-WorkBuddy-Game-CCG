## 一、这个功能是干什么的

**一句话**：屏幕最上边一条金色长条，杀够怪金条就涨满，涨满自动出 Boss——玩家一眼就知道「还差多少」。

**对太奶奶级玩家的意义**：打怪的时候最怕不知道打到哪了。有了这条金条，不用认字也能看出「哦，快满了」。这是全屏唯一一个**光看颜色变化就该看懂**的元素。

**它是怎么算数的**：金条长度 = 本局击杀数 ÷ 本关目标数。第 1 关目标是 60 只（`cfg/levels.json` 第 1 关 `progressGoal=60`），杀 30 只金条就一半。

## 三、怎么变化

### 3.1 金条怎么涨

| 触发 | 变化 | 有没有动画 |
|---|---|---|
| 打死任意一只怪 | 金条按 1/目标 的比例往前长一格 | 没有过渡，**一跳一格** |
| 达到目标数 | 涨满，然后立刻出 Boss | 没有「满了」的闪光 |
| 一局没打满就死 | 金条停在半路，但马上盖结算面板，玩家看不到 | — |
| 进 Boss 战以后继续杀怪 | 金条**继续涨但已经超出 100%**，代码会把它卡在 100% | 卡死不涨 |

### 3.2 白字怎么变

| 优先级 | 条件 | 显示 | 代码 |
|---|---|---|---|
| 1（最高） | 冻结中 | `全场冻结中 · …` | 第 701~702 行 |
| 2 | 死了 | `阵亡` | 第 703~704 行 |
| 3 | 暂停 | `已暂停` | 第 705~706 行 |
| 4（默认） | 其他 | 击杀进度 + 剩余时间 | 第 698~700 行 |

> 优先级的意思是「同时满足时显示最上面那条」。比如暂停的时候又死了，显示「阵亡」——这个顺序是对的。

### 3.3 每种数值从哪来
| 数字 | 来源 | 第 1 关 | 第 99 关 |
|---|---|---|---|
| 分子（已击杀） | 本局实际杀掉的怪 | 从 0 涨到 60 | 从 0 涨到 2336 |
| 分母（目标） | `cfg/levels.json` 的 `progressGoal` | 60 | 2336 |
| 剩余秒数 | `timeLimit` 减去「没冻结、没暂停的实战时间」 | 180 秒 | 1200 秒 |

> **重要**：剩余秒数**不会因为你暂停而减少**，也不会计入开局的 3 秒冻结。玩家 Esc 想多久都行，不打折。

## 四、各种状态

| 状态 | 什么样 | 什么时候 |
|---|---|---|
| **常态** | 黑壳 + 金条涨到一半左右 + 白字 `击败精英 32 / 60 (剩余 96s)` | 正常打怪 |
| **快满** | 金条超过 3/4，看着「差一点点」 | 代码里**没有单独表现**，只是金色更长 |
| **满** | 金条顶到最大 416 | 打满目标数，出 Boss |
| **冻结** | 白字变 `全场冻结中 · 准备战斗 2.4s`，金条不动 | 开局前 3 秒（`cfg/levelFreeze.json` `freezeTime=3`） |
| **暂停** | 白字变 `已暂停`，金条不动 | 按 Esc |
| **阵亡** | 白字变 `阵亡` | 血量归零那一帧到结算面板弹出 |
| **隐藏** | 从不隐藏 | 四个状态都显示，没有「隐藏」态 |

> 太奶奶注意：**它永远不会消失**。好处是你随时知道进度；坏处是结算面板、升级面板弹出来的时候，它还在背后亮着，有点抢戏。

## 五、声音 / 反馈

| 时机 | 现在有没有 | 应该怎么样 |
|---|---|---|
| 杀掉一只怪，金条涨一格 | 没有专门音效 | 不需要。杀怪本身有打击反馈就够了，涨条再响会吵 |
| 金条涨满 | **没有** | 该有一次明显反馈：条闪一下白光 + 一声闷响，告诉玩家「Boss 来了」 |
| 出 Boss | 没有（`EventBus.boss_spawned` 有信号，但 HUD 侧没接） | Boss 出场应该有专属提示，见 B003 的「波次」项 |

**给太奶奶的大白话**：现在金条是「哑巴」的，涨满了也没有任何声音或闪光，全靠玩家自己盯着看。这是要补的。

## 六、异常情况

| 情况 | 现在会怎样 | 玩家看到什么 | 该怎样 |
|---|---|---|---|
| 关卡目标是 0（`progressGoal=0`） | 代码直接不涨，比例固定 0 | 金条永远是空的 | 这种情况应该整条隐藏，而不是给个空壳 |
| 一局超过时间限制还没打满 | 代码**照样出 Boss**（时间到也算触发） | 金条没满但 Boss 出来了，玩家懵 | 白字应该说「时间到，Boss 强袭」 |
| 杀怪数超过目标（比如 61/60） | 金条卡在 100%，文字显示 `61 / 60` | 文字超过目标，像 bug | 文字也该卡在 `60 / 60` |
| 打死 Boss 以后继续杀怪 | 金条不动，文字继续涨 | 文字 `80 / 60` | 出 Boss 后文字应换成「Boss 战」或「去找撤离点」 |
| 暂停时按 G 切换自动战斗 | 文字不变（还显示「已暂停」） | 无声无息 | 可接受，不用改 |
| 结算面板弹出后 | 金条还在，白字显示「阵亡」或最后一个进度 | 两层字叠在一起 | 结算时应当把 HUD 整层藏起来 |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 金条按「血量」或「时间」涨 | 玩家会以为「时间到了就赢」，跟设计冲突 |
| 金条涨满了没有任何提示 | 玩家不知道 Boss 什么时候来，会被吓一跳 |
| 文字写「击败精英」但实际算所有怪 | 说话不算数，玩家会觉得游戏在骗他 |
| 时间到直接判输 | 已经定死了：时间到是「Boss 强袭」，不是输 |
| 金条上的数字用小数（比如 53.3%） | 太奶奶看着费劲，用整数 |
| 金条挡住地图正中间的怪 | 420×14 在顶部，打怪时怪可能在正上方被挡住——这也是为什么条这么细 |
| 暂停时金条还在涨 | 暂停就是暂停 |

## 八、和其他文档的约定

| 项目 | 内容 |
|---|---|
| **输入**（谁给它数据） | 逻辑层 `combat.kills`（本局击杀数）、`combat.progress_goal`（目标）、`combat.time_limit`（时限）、`combat.run_time`（实战秒数）、`combat.freeze_time`（冻结剩余秒） |
| **输出**（它告诉谁） | 不告诉任何人，纯展示。出 Boss 由逻辑层自己判断（`combat.gd` 第 255~258 行），跟本屏无关 |
| **依赖** | `cfg/levels.json` 每关的 `progressGoal` / `timeLimit` |
| **和 B007 的关系** | Boss 死后，本条的「剩余秒数」还有意义吗？建议 Boss 死后白字改成「撤离点已出现」，与 B007 左中文字呼应 |
| **和 006-结算 的关系** | 结算面板弹出后本条应隐藏（现在没有） |

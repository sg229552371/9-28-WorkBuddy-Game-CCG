## 一、这个功能是干什么的

**一句话**：左下角一行字 `负重 0 / 100`，告诉玩家身上背了多少东西；背得太重，人就走得慢。

**为什么要有这个东西**：这一局捡到的装备、宝石都背在身上，越背越重。设计上这是「核心难点是舍不得走」的一部分——捡得越多越贪，走得越慢越容易死。

**但它现在只有一行数字，没有条**。玩家必须**读数字 + 记住上限 100 + 心算**，才知道自己是不是快超了。太奶奶级玩家根本读不出这个信息。

### 2.2 上限从哪来

| 项目 | 数值 | 出处 |
|---|---|---|
| 负重上限 | **100** | `cfg/weight.json` `threshold=100`，`battle.gd` 第 50~54 行读入 |
| 读不到配置时 | 回退 100 | 同上 |

> 太奶奶注意：**「100」不是背包满了的线，是「开始变慢」的线**。超过 100 还能继续捡、还能继续走，只是越背越慢。这也是为什么它必须是个「条」——只有条才能表达「还在涨，但已经越过去了」。

## 三、怎么变化

### 3.1 数字怎么涨

| 情况 | 涨多少 | 代码 |
|---|---|---|
| 捡起一个宝箱里的装备 | 按装备自己的重量，**缺省 5** | `battle.gd` 第 348~349 行，读 `gearDefs` 里的 `weight` |
| 捡水晶 | **不涨** | 水晶不计重 |
| 拾取地上的零散物品 | 目前没接 | — |
| 丢掉装备 | **不会降** | 代码只有 `add_weight`，没有「减重」 |

> **这里有个真相**：负重只涨不跌。捡到的装备放进背包，重量就永久背着；就算你从背包里把装备扔了，重量也不会掉。所以一局只能越背越重。

### 3.2 重了会怎样（这是关键）

| 当前重量 | 移动速度 | 大白话 |
|---|---|---|
| ≤ 100 | **100%**（原速） | 没事 |
| 110 | 约 92% | 几乎感觉不到 |
| 125 | 约 80% | 有一点点慢 |
| 150 | 60% | 明显慢了 |
| 200 | 20%（最低） | 走路像在趟水 |
| 超过 200 | 还是 20% | 再重也不会更慢 |

**公式（给程序看，太奶奶不用管）**：超过 100 以后，每多 100 点重量，速度减 0.8 倍（配置 `slope=0.8`、`divisor=100`）；最低降到 20%（配置 `minFactor=0.2`）。

> 也就是说：**最多慢到原来的五分之一，永远不会停死**。这是定死的「轻微变慢」口径——虽然从 100% 掉到 20% 其实已经很慢了，但至少不会变成「定在地上」。

### 3.3 什么时候变亮 / 变色| 情况 | 现在的表现 | 应该有 |
|---|---|---|
| 正常背 | 米色字 | 米色字 |
| 超过 100（开始变慢） | **没有任何变化**，数字照常米色 | 数字变黄 + 出一行提示 |
| 接近 200（最慢） | **没有任何变化** | 数字变红 + 抖动 |

> **这是这一块最大的问题**：玩家唯一能察觉「我变慢了」的方式是**自己感觉走路变慢**。而手感一变慢，玩家的第一反应是「是不是游戏卡了」，不会想到「哦我背太重了」。

## 五、声音 / 反馈

| 时机 | 现在 | 应该 |
|---|---|---|
| 捡起装备 | 无 | 一声「咚」的闷响（越来越沉的暗示） |
| 刚超过 100 | 无 | **该有**：一声金属闷响 + 数字从米变黄 + 左中信息行出一句「太重了，走得慢了」 |
| 接近 200 | 无 | 走路带出「呼…呼…」的喘气声（很直观） |
| 掉回 100 以下 | 不会发生 | — |

**给太奶奶的大白话**：现在这块**完全不出声**。玩家越背越重，程序一声不吭，人变慢了也没人告诉他为什么。

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 超重了只是数字变大，不做任何提醒 | 「轻微变慢」必须让玩家知道**为什么**变慢 |
| 超重就完全不能动 | 已经定死了：只是变慢 |
| 背包里扔东西负重还不掉 | 玩家会觉得「扔了也没用，那我扔它干嘛」——要么就别做扔，要么扔了要减重 |
| 用「负重」这个词不解释 | 太奶奶不认识「负重」，要能看懂「背了多少」 |
| 用红色一直显示 | 红 = 危险，只在真超重时才红 |
| 把负重塞进右上角资源里 | 右上已经两行了，再塞看不清 |

## 八、和其他文档的约定

| 项目 | 内容 |
|---|---|
| **输入** | `combat.weight`（当前重量，`add_weight` 累加）、`weight_limit`（上限，读 `cfg/weight.json` `threshold`）、`combat.weight_factor()`（算速度和读条时长） |
| **输出** | 纯展示。玩家**没法**在战斗里操作负重 |
| **和 B007 的关系** | 负重还会**拉长撤离读条**：背包越重，站圈要站越久。`cfg/extract.json` `weightThreshold=100`、`weightSlopePer100=0.25`、`weightTimeScaleMax=2`，最重时读条从 8 秒拉到 16 秒。这是「舍不得走」的第二个惩罚，一定要在 B007 里同步说明 |
| **和背包（Tab）的关系** | 装备进包就计重（`battle.gd` 第 348~349 行）；背包界面里扔东西**不减重**，这是个漏洞 |
| **和 `cfg/weight.json` 的关系** | 这个文件只管**减速**；`cfg/extract.json` 里的那几个 weight 开头的键只管**拉长读条**。两个配置文件名一样但意思不同，容易搞混 |

## 十、太奶奶要定的事

| 问题 | 选项 |
|---|---|
| **一、负重怎么显示才好懂？** | (A) **在数字下面加一条横条**：米黄→黄→红三段变色，超了变红闪（最直观）　(B) 保持一行数字，**只在超重时弹一句红字**（不占地方）　(C) 把数字改成「背包 37% 满」加减号（更像血条，但要改字） |
| **二、背太重了怎么惩罚？** 现在的口径是「轻微变慢」，但实测能慢到只剩两成速度 | (A) **就按现在这样**，慢到五分之一（极限惩罚，逼玩家取舍）　(B) 改温和，最多慢到一半（不那么折磨人）　(C) 慢一点 + 撤离读条也不拉长（只留一个惩罚，别叠加） |
| **三、背包里扔掉装备，重量要不要减？** | (A) **要减**（扔了就轻，说得通）　(B) 不减（这一局的重量是你「曾经捡过」的总和，更残酷）　(C) 不做「扔」这个功能（省事） |

## 一、这个功能是干什么的

**一句话**：打死 Boss 以后，Boss 倒下的地方出现一个金色大圈，玩家走进圈里站着，站够 8 秒就撤离成功——这一局捡到的东西全部带回家。

**对太奶奶级玩家的意义**：这是这一局唯一「见好就收」的机会。设计上核心难点是「舍不得走」，这个圈就是那个「取舍时刻」的实体。圈一亮，玩家心里就该响起一句话：「要不要现在就走？」

**它同时负责两件事**

| 事 | 在哪看 |
|---|---|
| 圈在哪、读条到哪了 | 地图上的金色大圈 + 绿色进度弧 |
| 还差几秒、要不要进去 | 屏幕左中那行青字 |

## 二、界面长什么样

### 2.1 地图上的金色大圈

| 项目 | 数值 | 说明 |

| 圆环粗细 | **4** 像素 | — |
| 圆心 | 一个金色实心小圆，半径 **12** 像素 | 看着像一根插在地上的柱子 |
| 代码 | `battle.gd` 第 825~829 行 | — |

### 2.2 绿色读条弧（最重要）

| 项目 | 数值 | 说明 |
|---|---|---|
| 位置 | 金色大圈**外面再外扩 10 像素**，也就是半径 110（按实际判定 120 算，站在 120 内都算「在圈里」） | 一圈套一圈 |
| 颜色 | 亮绿 `rgb(0.4, 1.0, 0.5)` | — |
| 粗细 | **6** 像素（比金圈更粗） | 故意更粗，因为这是「进度」 |
| 形状 | 从**正上方**开始，顺时针长出一段弧 | 12 点钟方向起画 |
| 进度 | 弧长 = 已读秒数 ÷ 8 秒 | 站满 8 秒就是整圈 |
| 站圈外 | 弧**不会消失，会缩回去** | 退出圈以后读条倒退 |
| 代码 | `battle.gd` 第 830~834 行 | — |

     │   ╭───────╮   │

### 2.3 屏幕左中那行青字

| 项目 | 数值 |
|---|---|
| 位置 | 距屏幕左 16 像素，距屏幕顶 **120** 像素 |
| 字号 | 20 |
| 颜色 | 冰蓝 `rgb(0.75, 0.95, 1.0)` 即 `#BFF2FF` |
| 描边 | 6 像素黑边 |
| 行数 | 可能**多行**（撤离、裂隙、无尽三条提示会堆在一起） |
| 代码 | `battle.gd` 第 531~534 行、第 735~744 行 |

**文字内容一共只有三种**

| 情况 | 显示 | 例子 |
|---|---|---|
| 圈刚出现，人还没进圈 | `撤离点已出现（读条 Ns）：进圈读条撤离` | `撤离点已出现（读条 8s）：进圈读条撤离` |
| 人在圈里读条 | `撤离点已出现（读条 Ns）（读条中 Y%）` | `撤离点已出现（读条 10s）（读条中 62%）` |
| 人退出圈 | 回到第一种文字，但弧已经缩回去了 | — |

> **「读条 Ns」这个 N 是会变的**：它不一定是 8。背包越重，N 越大（见第三节）。

## 三、怎么变化

### 3.1 完整流程（带时间）

| 步 | 什么时候 | 发生什么 | 耗时 |
|---|---|---|---|
| ① | 开局 | 没有圈，左中没有任何撤离提示 | — |
| ② | 击杀数达到目标 **或** 时间用完 | Boss 出场 | 立刻 |
| ③ | Boss 血量归零 | **Boss 原地变成撤离点**，同时掉一个 Boss 宝箱 | 立刻（`combat.gd` 第 955~963 行） |
| ④ | 同一帧 | 左中青字出现「撤离点已出现（读条 8s）：进圈读条撤离」 | 立刻 |
| ⑤ | 玩家走进圈 | 绿弧开始长，同时**开始刷压力波**（每 2.5 秒一波） | 8 秒（背包重则更久） |
| ⑥ | 绿弧长满一整圈 | 撤离成功 → 发结算信号 → 弹结算面板 | 立刻 |
| ⑦ | 中途退出圈 | 绿弧按每秒 1.2 秒的速度倒退 | — |
| ⑧ | 读条途中死了 | **撤离点消散**（`cfg/extract.json` 的 `note` 原文），弹阵亡结算 | 立刻 |

### 3.2 读条要多久（负重会拉长）

| 背包重量 | 读条时长 | 站圈时间 |
|---|---|---|
| ≤ 100 | **8 秒** | 好走 |
| 125 | 9 秒 | — |
| 150 | 10 秒 | — |
| 200 | 12 秒 | — |
| ≥ 300 | **16 秒**（封顶 2 倍） | 又慢又久，很煎熬 |

**规则**：`cfg/extract.json` 里 `weightThreshold=100`、`weightSlopePer100=0.25`、`weightTimeScaleMax=2`。大白话：**每超重 100，站圈时间 +25%，最多翻倍**。

> **注意一个容易搞错的地方**：左中那行字里的「读条 Ns」显示的是**已经算上负重的实际时长**（第 739 行 `channel_seconds(combat.weight)`），所以背包重的时候玩家会看到「读条 12s」。这是对的，别以为是 bug。

### 3.3 读条期间会怎样

| 事 | 细节 | 出处 |
|---|---|---|
| 刷怪压力 | 只在**人站在圈里**时刷，退出圈不刷 | `combat.gd` 第 318~323 行 |
| 刷几波 | 每 2.5 秒一波 | `cfg/extract.json` `waveInterval=2.5` |
| 每波几只 | 第 1 波 2 只，之后每波多 1 只 | `waveSizeBase=2`、`waveSizeGrowth=1` |
| 会不会出精英 | 每只 **8%** 概率是精英 | `waveEliteChance=0.08` |
| 从哪出来 | 圈外 **420** 像素的圆周上 | `waveSpawnRadius=420` |
| 谁在读条 | **只有队长一个人**能读，队员站圈里不算 | `extract_point.gd` 第 61~66 行 |
| 三个人一起站会更快吗 | **不会**。代码明确「同圈多人只选首位存活英雄，不按人数加速」 | 同上 |

> **压力波的意思**：你站在圈里的每一秒，都有一群怪从四面八方冲过来。所以这 8 秒不是「等」，是「扛」。

### 3.4 什么算赢（这块是硬骨头）

现在代码里的真相：

| 说法 | 在哪 | 实际效果 |
|---|---|---|
| 设计口径 | 全局设计：「**打死 Boss 就算赢**」 | —— |
| 程序实现 | Boss 死了只是**生成撤离点**，赢的信号要等你**站够 8 秒**才发（`combat.gd` 第 326~328 行 `_settle("extract")`） | 站不满不算赢 |
| 配置备注 | `cfg/extract.json` `note="死亡时撤离点雕像消散"` | 只描述了「死了圈会消失」 |

**所以现状是**：**打死 Boss 不算赢，站够圈才算赢**。玩家打死了 Boss，如果死在读条里，结局是「阵亡」——东西全丢。

> 这跟设计说的「打死 Boss 就算赢」是**直接矛盾**的。太奶奶必须拍板（见第十节第一题）。在拍板之前，文档口径统一按「程序现状」写：**站够圈才算撤离成功**。

## 四、各种状态

| 状态 | 什么样 | 什么时候 |
|---|---|---|
| **未出现（常态）** | 地图上没有圈，左中没有提示 | Boss 死之前，占这一局绝大部分时间 |
| **已出现，没进圈** | 地图上金色大圈 + 中心金点，绿弧不出现；左中青字「撤离点已出现（读条 8s）：进圈读条撤离」 | Boss 死后，玩家还没进去 |
| **读条中** | 绿弧从 12 点方向慢慢长；青字带「（读条中 62%）」；四周不断有怪冲过来 | 玩家站圈里 |
| **读条倒退** | 绿弧往回缩；青字回到「进圈读条撤离」 | 玩家跑出圈 |
| **完成** | 弧长满，立刻弹结算面板 | 站满 |
| **消散（死亡）** | 圈消失，弹「战斗结算（阵亡）」 | 读条时死亡 |
| **隐藏** | 没有「隐藏」这个状态，要么没出现，要么在 | — |

> **缺一个很重要的状态**：现在没有「读条快满」的强调。最后 2 秒和第一秒看起来一模一样，玩家不知道「再撑一下就好了」。这是打击「舍不得走」张力的地方。

## 五、声音 / 反馈

| 时机 | 现在 | 应该 |
|---|---|---|
| Boss 倒下 → 圈出现 | 无 | **必须响**：一声悠长的钟声/号角，配文字「撤离点已出现」从下往上滑入（1 秒） |
| 玩家进圈 | 无 | 一声「嗡」的低鸣开始，持续到读条结束（像引擎发动） |
| 读条过程中 | 无 | 每秒一声「滴」的节拍，越到后面越急 |
| 玩家出圈 | 无 | 「嗡」声骤停 + 一声短促「嚓」 |
| 读条满 | 无 | 一声长鸣 + 白光亮一下 |
| 读条死亡 | 无 | 一声「啪」的碎裂 |

**给太奶奶的大白话**：这整块现在是**完全静音的**。Boss 死了你不知道该去哪，进了圈不知道自己在读，读满了不知道赢了。全靠看那个绿色小弧——而绿弧在满屏怪里只有 6 像素粗。

## 六、异常情况

| 情况 | 现在会怎样 | 玩家看到什么 | 该怎样 |
|---|---|---|---|
| Boss 死在地图边角 | 圈跟着出现在边角，可能贴墙 | 站不进去一半 | 圈应做「离墙至少一个半径」的钳制 |
| 圈和墙重叠 | 玩家可能被墙卡在圈外 | 明明贴着圈却读不了 | 同上 |
| 三人都在圈里 | 只认队长 | 正常（其他两人白站） | 文案上要说清「只有队长算」 |
| 读条期间按 Esc | 暂停，读条也停 | 正常，但玩家可以靠暂停「稳住」 | 是否允许要定（见第十节） |
| 读条期间开背包 | 读条**继续走**（面板不暂停世界） | 玩家可能在翻包时被摸黑打死 | 应该暂停（跟 B008 保持一致） |
| 读条期间按 F 开无尽 | 代码有防护：Boss 一死就进撤离流，无尽不会再开 | 正常 | ✅ |
| 时间到没打满，出 Boss 后又死 | 跟正常死一样 | 圈消失 | 正常 |
| 圈出了但玩家去捡宝箱 | 圈一直在，不会消失 | 玩家有时间到处跑 | 这是「舍不得走」的来源，是对的 |
| 撤离点和宝箱重叠 | 会叠在一起 | 看不清 | 建议宝箱自动往外挪一点 |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 读条时人出圈了，进度还保留 | 那样就能「进进出出刷进度」，游戏失去意义。必须倒退 |
| 三个人站圈里读得更快 | 已经定死了：只认队长一人 |
| 读条时停止刷怪 | 那样读条变成纯等待，没有压力，「舍不得走」就没了 |
| 圈固定出现在地图中心 | 玩家会觉得「反正有个地方」，失去「Boss 死在哪就在哪撤」的紧张 |
| 用红色画圈 | 红 = 危险。这是「回家」的机会，应该用金色 |
| 绿弧太细看不见 | 现在 6 像素，在弹幕里几乎看不见，是最该加粗的地方 |
| 读条满了不弹结算、还要玩家自己点 | 到点就该自动结束 |
| 读条期间按 Esc 把读条也暂停掉（如果允许），就要防止玩家靠反复暂停刷时间 | 要么不允许暂停，要么暂停也照走 |

## 八、和其他文档的约定

| 项目 | 内容 |
|---|---|
| **输入** | `combat.extract_point`（圈对象，含位置、半径、进度）、`combat.weight`（拉长读条）、`cfg/extract.json` |
| **输出** | 站满 → `EventBus.run_settled` 的 `winner` 为 `"extract"` → B008/006 弹结算 |
| **和 B005 的关系** | 负重既让人走慢，又把读条拉长。**两个惩罚叠加**，是「舍不得走」的核心设计，但也很可能过狠（总纲拍板项） |
| **和 B001 的关系** | Boss 出现以后，顶部条的文字应该从「击败精英 X/Y」换成撤离相关提示，现在没换 |
| **和 B002/B003 的关系** | 无关，不显示撤离信息 |
| **和 006-结算 的关系** | **最大的矛盾点**：撤离成功也会走「战斗结算（阵亡）」那个面板（`battle.gd` 第 154 行→第 238 行），标题写死「阵亡」 |
| **和 004-选人 的关系** | 队伍人数影响读条是否有意义（多人不加速），但不影响能否撤离 |
| **和 `cfg/extract.json` note 的关系** | `note="死亡时撤离点雕像消散"` 只是描述，不是规则，不能拿它当胜负判据 |

## 十、太奶奶要定的事

| 问题 | 选项 |
|---|---|
| **一、一局到底怎么算赢？** 现在设计说「打死 Boss 就算赢」，程序是「站够 8 秒才算赢」 | (A) **打死 Boss 就赢**，撤离点只是演出（最爽，但「舍不得走」没了）　(B) **站够 8 秒才算赢**（现在程序的做法，最紧张）　(C) **打死 Boss 先存一份「保底」，撤离成功再翻倍**（两条都满足，但玩家要理解两套规则） |
| **二、读条的时候按 Esc 暂停，读条要不要也停？** | (A) **停**（玩家能喘气，但可能被利用）　(B) **不停，照走**（更紧张，但玩家会觉得不公平）　(C) 干脆读条期间禁用 Esc（最干净） |
| **三、负重让读条变长，这个惩罚保留吗？** 负重已经让人走慢了，再拉长读条是双重惩罚 | (A) **保留**（贪心就该付出代价）　(B) **去掉**，读条永远 8 秒（只留「走得慢」一个惩罚）　(C) 保留但要提示清楚：青字加一句「背太重，要多站 4 秒」 |

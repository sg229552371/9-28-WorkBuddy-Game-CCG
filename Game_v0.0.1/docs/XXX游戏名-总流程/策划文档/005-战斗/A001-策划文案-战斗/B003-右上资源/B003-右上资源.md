## 一、这个功能是干什么的

**一句话**：屏幕右上角立着一个超大号的 `Lv 1`，下面两行金色小字写这一局赚了多少金币、多少经验、地上还有几个宝箱、打到第几波、场上还有几只怪。

**对太奶奶级玩家的意义**：这是「这一局战果」的总账。打怪捡钱有没有意义，全看右上角数字有没有涨——数字涨得越快，玩家越舍不得走，这正是我们想要的「舍不得走」心态。

## 二、界面长什么样

### 2.1 等级大字（`Lv 1`）

| 项目 | 数值 |
|---|---|
| 位置 | 屏幕右上角，往左退 16 像素，距屏幕顶 6 像素 |
| 字号 | **34**（全屏 HUD 里最大） |
| 颜色 | 冷白 `rgb(0.95, 0.98, 1.0)` 即 `#F2FAFF` |
| 描边 | 6 像素黑边 |
| 对齐 | 右对齐（数字往左长，右边永远贴边） |
| 内容 | `Lv 1`（中间有一个空格） |
| 代码 | 第 517~523 行、第 715 行 |

> 为什么这么大：这是玩家一局里最在意的数字。升级 = 变强 = 能打更久 = 能捡更多。所以给它 34 号，比血还大（血是 24 号）。

### 2.2 金币经验两行（金色小字）

| 项目 | 数值 |
|---|---|
| 位置 | 屏幕右上角，往左退 16 像素，距屏幕顶 **48** 像素（正好在大字下面） |
| 字号 | 18 |
| 颜色 | 亮金 `rgb(1.0, 0.88, 0.45)` 即 `#FFE073` |
| 描边 | 6 像素黑边 |
| 对齐 | 右对齐 |
| 行数 | **两行**（第一行金币经验，第二行宝箱波次场上怪） |
| 代码 | 第 524~530 行、第 716~718 行 |

**两行的具体内容**

| 行 | 内容 | 例子 |
|---|---|---|
| 第一行 | `✦金币 N · ✦经验 N` | `✦金币 42 · ✦经验 137` |
| 第二行 | `宝箱 N · 波次 N · 场上怪 N` | `宝箱 2 · 波次 7 · 场上怪 15` |

> **`✦` 星号是什么**：就是个小星星符号，用来当图标。太奶奶习惯把它当「钱」看就行。

## 三、怎么变化

### 3.1 五个数字怎么涨

| 数字 | 什么时候涨 | 每只怪涨多少 | 来源 |
|---|---|---|---|
| 等级 `Lv` | 经验够下一级就升 | 看总经验 | `combat.player_lv` |
| 金币 | 杀怪 | +2（普通怪） | 怪身上配的 `coin` 字段 |
| 经验 | 杀怪 | +3（普通怪） | 怪身上配的 `exp` 字段 |
| 宝箱 | 地上出现宝箱 / 捡走宝贝 | 精英和 Boss 必掉一个 | `combat.chests.size()` |
| 波次 | 每 2.5 秒刷一波 | +1 | `combat.wave_index` |
| 场上怪 | 实时 | 刷怪涨、清怪掉 | `combat.monsters.size()` |

> **金币和经验每只怪固定 +2 / +3 吗？** 不是。代码是从怪自己的配置里读的（`combat.gd` 第 952~954 行），不同怪给的不一样，精英给更多。上面的 2 和 3 是普通怪的典型值。

### 3.2 什么时候变亮 / 变灭

| 情况 | 表现 | 说明 |
|---|---|---|
| 捡到宝箱 | 宝箱数 +1，但**没有闪光** | 没有任何「捡到了」的反馈 |
| 升级 | `Lv` 数字直接跳，**没有放大、没有闪** | 太安静了，玩家可能都没注意自己升级了 |
| 金币暴涨 | 数字跟着涨，**没有飘字** | 打 Boss 给一大笔时看不出来 |
| 暂停 / 冻结 | **照常显示，数值不变** | 正常 |
| 阵亡 | 数值停在死前那一刻 | 正常，结算面板会重复一遍 |

### 3.3 「波次」到底是什么

**大白话**：游戏每 2.5 秒往场上「放一批」怪，放一次波次 +1（`cfg/extract.json` `waveInterval=2.5`）。它**不是**「打到第几关」的意思，只是「刷了几批」。

> 太奶奶注意：这个数字对玩家**没什么用**。玩家真正关心的是「还剩多少怪」「打到哪了」——那由 B001 顶部条负责。所以「波次」这个数可以留也可以去掉。

## 四、各种状态

| 状态 | 什么样 | 什么时候 |
|---|---|---|
| **常态** | `Lv 7` + 两行金色小字 | 全程 |
| **升级（特殊）** | `Lv` 数字变成 `Lv 8`，**没有其他表现** | 经验够了那一帧 |
| **警告** | 无。这块没有「危险」概念 | — |
| **隐藏** | 从不隐藏 | — |

> **这块没有任何「警告」态**。金币经验是「好事」，越多越好，不存在报警。但也因此，**升级这一刻没有被强调**——这是它最大的问题：全屏最重要的数字变了，你却看不出来。

## 五、声音 / 反馈

| 时机 | 现在 | 应该 |
|---|---|---|
| 升级 | 无 | **该有**：一声「叮 — 咚」的上扬音 + `Lv` 大字放大 1.3 倍再弹回，约 0.3 秒 |
| 捡到金币 | 无 | 轻微「叮」一声（连续捡会吵，需要限流，每 0.2 秒最多响一次） |
| 捡到宝箱 | 无 | 一声更亮的「叮当」，跟金币区分开 |
| 打 Boss 掉落一大笔 | 无 | 数字旁边飘一个「+300」往上飞 |

**给太奶奶的大白话**：右上角现在是**纯数字，不会说话**。玩家升了级、捡了钱，全靠自己瞟一眼。这跟「爽快割草」的手感是违背的——割草游戏最爽的就是「数字狂涨 + 声音叮叮响」。

## 六、异常情况

| 情况 | 现在会怎样 | 玩家看到什么 | 该怎样 |
|---|---|---|---|
| 金币涨到四位数 | 数字变长，往左顶 | 可能碰到中间的怪 | 超过四位数改写成 `1.2k` |
| 等级到 46 级满级 | 数字继续涨（代码没有封顶判断） | `Lv 47` | 满级应显示 `Lv MAX` |
| 三名英雄 | 只有**队长**的等级在涨 | 队员等级看不见 | 需要另做队员等级（见第十节） |
| 场上怪超过 100 只 | `场上怪 127` | 数字正常 | ✅ |
| 宝箱没被捡，存在地上 | 宝箱数一直显示，不消失 | `宝箱 3` 一直挂着 | 正常，但建议超过 2 个时数字变亮提醒 |
| 结算面板弹出 | 数字还在，压在结算下面 | 叠字 | 结算时整层隐藏 |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 升级时没有任何视觉变化 | 最重要的时刻不能静悄悄 |
| 数字用小数（`✦金币 42.5`） | 金币不给半个 |
| 把「经验」当「离升级还差多少」用 | 这里写的是**本局总赚**，跟升级进度是两码事，不能混 |
| 用红字显示金币 | 红 = 危险，钱用金色 |
| 在右上角硬塞更多项（负重、时间、裂隙进度） | 挤成一片谁都看不清，负重有专门的 B005 |
| 大字 `Lv` 让玩家误以为是「账号等级」 | 这是本局等级，回城就没了；真正的长期等级在主城 |

## 八、和其他文档的约定

| 项目 | 内容 |
|---|---|
| **输入** | `combat.player_lv`、`combat.coin_gained`、`combat.exp_gained`、`combat.chests.size()`、`combat.wave_index`、`combat.monsters.size()` |
| **输出** | 纯展示 |
| **和 B002 的关系** | 等级和经验在左上（B002）也有一份，**重复**。建议删除左上的等级经验，只保留在右上 |
| **和 006-结算 的关系** | 结算面板的 6 行数据（击杀/波次/金币/经验/暴击/技能）就是这块的「期末成绩单」，所以本块可以视作「实时成绩单」 |
| **和局外养成的关系** | 本局金币和经验**会落档**（`battle.gd` 第 228~229 行 `arch["coins"]`、`arch["exp"]`），也就是说这些东西死了也留一半（具体规则归 `006-结算` 定） |
| **等级上限** | 设计口径局内满级 **46 级**；当前配置 `cfg/levelUp.json` 的 `curve.maxLv` 写的是 99，需要统一（进总纲待办） |

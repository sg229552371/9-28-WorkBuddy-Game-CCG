## 一、这一屏是干什么的

**一句话**：玩家想关掉游戏的时候，先问他一句「真要退出吗」，确认了才真的关。

**为什么要单独做一份 007**：001 那份只讲「在主菜单上点了一次退出按钮」，那是整个游戏里最简单的一种退出。但玩家会在**任何地方**想退出：打到一半、卡在选关、马上要过关。这些地方的退出，规则完全不一样，有的安全、有的一按就丢一局。

**太奶奶怎么理解**：就像坐飞机，出舱门只有一扇，但你要先看看自己现在是在候机厅还是在天上。**在候机厅随时能走；在空中不能开门。**

**三条设计底线**

| 底线 | 具体做法 | 现实情况 |
|---|---|---|
| 手滑不能关游戏 | 默认动作永远是「不退出」 | ❌ 现在没有「默认动作」这个概念，全靠玩家点 |
| 关之前说清后果 | 如果这一局会丢，必须提前说 | ❌ 现在一个字都不提 |
| 关了就真关 | 不能留后台进程 | ✅ `get_tree().quit()` 是干净的 |

## 三、和 `001-主菜单/B004-退出游戏` 的分工（重要，避免重复维护）

**这是同一件事，但视角不同。**

| | `001/B004-退出游戏` | `007-退出`（本屏） |
|---|---|---|
| 管什么 | **主菜单上那一次点击**：按钮在哪、点了之后弹什么、弹窗长什么样 | **整个游戏所有地方的退出**：每个屏能不能退、退了丢什么、确认怎么问 |
| 读者 | 看主菜单的人 | 看整体流程的人 |
| 会不会变 | 主菜单不改，它就不改 | 每加一个屏，这里要加一行 |
| 谁是真源 | 弹窗的**长相**（尺寸、颜色、文案）以 `001/B004` 为准 | 退出的**规则**（哪里能退、丢不丢东西）以本屏为准 |
| 内容量 | 1 个功能 | 1 份总纲 + 2 个功能 |

**为了避免两份文档打架，约定三条：**

| 编号 | 规则 |
|---|---|
| 分-1 | **弹窗长相**（宽高、颜色、字号）只在 `001/B004` 写一次，本屏只引用不重复 |
| 分-2 | **退出口径**（哪些屏能退、退出丢什么）只在 `007` 写一次，`001/B004` 只写结论「主菜单退出安全，详见 007」 |
| 分-3 | 任何一边改了，另一边**只加一句指向**，不抄全文 |

> **给太奶奶的比喻**：001/B004 是「家里大门怎么装」，007 是「整栋楼哪几扇门能出、哪扇门出去是悬崖」。

### 3.1 两份文档现在的真实差异（已发现，必须对齐）

| 项目 | `001/B004` 写的 | 代码实际 | 谁对 |

## 五、能做和不能做的事

### 5.1 各个屏能不能退出（这是本屏的核心表）

| 屏 | 玩家怎么退 | 退出会不会丢东西 | 现状 |
|---|---|---|---|
| 主菜单 | 点「退出游戏」→ 确认屏 | 不会丢（主菜单不改数据） | ✅ 有路 |
| 主城 | 只能点窗口 × | 不会丢（回城时已存档） | ❌ 没有游戏内的退出按钮 |
| 选关 / 选人 | 只能点窗口 × | 不会丢（还没开打） | ❌ 没有 |
| 战斗中 | 按 Esc 只是暂停（`battle.gd` 第 395~397 行） | — | 🟡 暂停了但屏上**没有任何「退出」入口** |
| 战斗中 | 点窗口 × | **这一局全丢**（本局收获没有存档） | ❌ 而且**不会问一句** |
| 结算屏 | 只能点「返回主城」「回主菜单」 | **不会丢**（钱和星级已经落档，`flow_root.gd` 第 183~186 行在弹屏之前就写完了） | ✅ 安全 |

> **最要紧的一句**：**战斗中直接关窗口，这一局捡的东西全没了，而且游戏一句话都不说**。这是本屏最大的洞。

### 5.2 ✅ 能做的

| 玩家动作 | 结果 | 依据 |
|---|---|---|
| 主菜单点「退出游戏」 | 切到退出确认屏 | 第 326 行 |
| 确认屏点「确认退出」 | 程序结束 | 第 557 行 |
| 确认屏点「返回首页」 | 回主菜单 | 第 560 行 |

| 战斗中按 Esc | 暂停 / 继续（**不是退出**） | `battle.gd` 第 396 行 |
| 任何地方点窗口 × | 程序结束，**不询问** | 引擎默认 |

### 5.3 ❌ 不能做的（现在是错的 / 缺失的）

| 情况 | 应该怎样 | 现在实际 |
|---|---|---|
| 按 Esc 关掉确认框 | 回主菜单（安全） | **没绑定，按了完全没反应** |
| 按回车 | 应该是「继续」，不能直接关游戏 | **没绑定** |
| 点黑幕空白处 | 关掉确认框，回主菜单 | 没有黑幕，也没绑定 |
| 按钮文字 | 「退出」/「继续」 | 「确认退出」/「返回首页」——「返回首页」让人以为回到网站首页 |

| 战斗中退出 | 应该问一句「这局会丢，确定吗」 | **不问**，点 × 直接没 |
| 战斗中能不能在游戏里退出 | 应该有入口 | **完全没有**，玩家只能点 × |
| 主城/选关/选人退出 | 应该有入口 | **完全没有** |
| 默认焦点 | 应该落在「继续」上 | 没有焦点概念，`_make_button()` 没设 `focus_mode` 相关处理 |
| 退出前检查存档 | 应该 `commit` 一次再退 | 没做（好在主菜单退出时不需要） |

## 六、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 谁能弹出这个确认屏 | 现在只有 `screen-main`（第 17 行允许去 `screen-goodbye`） |
| 从确认屏能去哪 | 第 21 行：`["screen-main", "quit"]` —— 只允许回主菜单，或者退出 |
| 「quit」是真实去处吗 | **不是**。`_screens` 里没有叫 `quit` 的屏（第 202~214 行建的 8 个屏里没有它）。这是流转表里写了一个空中楼阁，实际退出走的是 `get_tree().quit()` 直接调用，不走流转 |
| 退出怎么执行 | 第 557 行 `get_tree().quit()` —— Godot 引擎的标准退出，**会正常结束进程、不留在后台** |
| 退出会不会清存档 | **不会**。这个函数只调 `quit()`，一行存档代码都没有 |
| 和存档的关系 | 主菜单退出时，所有数据在「回主城」时就 `commit` 过了；结算屏退出时，数据在弹屏前已经 `commit`（`006` 的 `B003` 第五节）；战斗中直接关窗口时，`battle.gd` 第 221~234 行 `_save_on_death()` **不会执行**（那个只在死亡/撤离时调） |
| 和 `002-主城` 的关系 | 主城现在没有退出按钮。要加的话，加到哪个位置由主城总纲定，行为按本屏 `B001` |
| 和 `005-战斗` 的关系 | 战斗里 Esc 是暂停（`battle.gd` 第 395~397 行），**暂停界面里目前没有「退出游戏」选项**。要不要加，见第十节 |
| 和 `006-结算` 的关系 | 结算屏上直接退出**是安全的**（数据早已入账）。所以结算屏可以不设退出入口 |
| 和 `001/B004` 的关系 | 见本文件第三节的分工约定 |

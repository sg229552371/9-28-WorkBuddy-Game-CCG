## 一、这个功能是干什么的

**一句话**：玩家说要退出，先弹一句「真要退出吗」，他点「确认」才真的关，点「继续」就当什么都没发生。

**为什么要多问这一句**：关游戏是不可撤销的。玩家可能手滑、可能想点别的按钮点歪了。**问一句的成本是一秒，不问的代价是玩家一肚子火。**

**太奶奶怎么理解**：就像关煤气灶，拧到底之前会「咔」一下提醒你「真要关吗」。

**现在的问题一句话**：这个「框」其实不是一个框 —— 点「退出游戏」以后，**主菜单整个从屏幕上消失了**，换成一整屏文字加两个按钮。玩家的感觉是「跳到另一页了」，不是「被问了一句」。

## 三、点击后发生什么

### 3.1 走到这个屏

| 步 | 发生什么 | 耗时 | 代码 |
|---|---|---|---|
| ① | 玩家在主菜单点「退出游戏」 | — | 第 325~326 行 |
| ② | 检查流转是否合法：`screen-main` 允许去 `screen-goodbye` | 立即 | 第 17 行、第 122~124 行 |
| ③ | 主菜单隐藏，退出屏显示 | 立即，同一帧 | 第 134~138 行 |

**没有淡入、没有黑幕渐显、没有声音。** 玩家看到的是「唰」地一下整页换掉。

### 3.2 点「确认退出」

| 步 | 发生什么 | 耗时 | 代码 |
|---|---|---|---|
| ① | 调用 Godot 引擎的 `quit()` | 1 帧后生效 | 第 557 行 |
| ② | 引擎正常退出：关窗口、释放资源、进程结束 | 通常几十毫秒 | 引擎行为 |
| ③ | 不留后台进程 | — | ✅ |

> **说明**：这个函数**只调了 quit，没做任何存档动作**。在这条路径上是安全的（主菜单不改任何数据），但如果哪天把退出按钮加到主城/战斗里，**必须补一句存档**。

### 3.3 点「返回首页」

| 步 | 发生什么 | 耗时 | 代码 |
|---|---|---|---|
| ① | 切回主菜单屏 | 立即 | 第 560 行 |
| ② | 主菜单显示，退出屏隐藏 | 同一帧 | 第 134~138 行 |

> 「返回首页」这个词有点歧义。玩家可能理解成「回到网站首页」「退出到桌面」。**实际它是「算我不退了，回去吧」。**

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 不问就关游戏 | 手滑的玩家会疯 |
| 默认按钮是「退出」 | 玩家一激动按回车，游戏就没了。**默认必须是「继续」** |
| 用「返回首页」的说法 | 「首页」在中国玩家的语境里更像个网站。要写「继续」或「返回」 |
| 把退出框做成整屏换页 | 玩家会以为游戏已经关了或者卡了。要有黑幕、要能看见背后的画面 |
| 退出框上有关不掉的按钮 | 两个按钮都必须能点 |
| 退出时清空存档 | 绝对不能。存档必须留着 |
| 退出后留后台进程 | 玩家在任务管理器看到「还有个游戏」，会以为中病毒 |
| 退出框里放广告、评分引导、「你确定要走吗」的挽留话术 | 恶心人 |
| 退出框里放「恢复默认设置」「删除存档」这类别的按钮 | 退出就是退出，别混进别的事 |
| 用「Are you sure?」英文 | 太奶奶看不懂 |
| 加 3 秒倒计时才能退出 | 玩家会骂 |

## 八、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 输入 | 无（不依赖任何数据） |
| 输出 1 | `quit`（程序结束）—— 第 557 行 |
| 输出 2 | `screen-main`（回主菜单）—— 第 560 行 |

| 前置 | 玩家必须在主菜单，点了「退出游戏」 |
| 和 `B002-关闭方式` 的关系 | Esc / 回车 / 点空白 归 `B002` 管，本文件只管两个按钮 |
| 和 `001/B004` 的关系 | **弹窗长相（宽高、颜色、字号）以 `001/B004` 为准**；代码现状和它不一致的地方见本文件 2.3。`007` 总纲分-1 已定这条规矩 |
| 和 `006-结算` 的关系 | 结算屏不设退出入口（数据早已入账，玩家点「返回主城」就行） |
| 和存档的关系 | 这条路径**不改存档**。以后若在别处复用这个屏，必须先补存档 |
| 和 `002-主城` 的关系 | 如果主城要加退出按钮，直接复用这个屏；但主城的退出**应该在退出前 `commit` 一次** |
| 和 `005-战斗` 的关系 | 战斗里没有退出入口，Esc 只是暂停（`battle.gd` 第 395~397 行），不走这个屏 |

## 十、太奶奶要定的事

> **✅ 2026-10-27 定稿**：退出框按设计稿执行——420×200 居中弹窗 + 60% 黑幕 +「退出 / 继续」左右并排 + Esc / 回车 / 点空白 / ✕ 等同「继续」+ 默认焦点在「继续」（总图 v1.1）。下列问题中与定稿冲突的按定稿为准，其余仍待拍板。

| 问题 | 选项 |
|---|---|
| **一、两个按钮谁在左谁在右？** | (A) **「继续」在左、「退出」在右**（左手先碰到安全的，Windows 的习惯）　(B) 「退出」在左、「继续」在右（和现在设计稿一致）　(C) 上下排，「继续」在上 |
| **二、「退出」按钮用什么颜色？** | (A) **红色**，危险操作要显眼（最保险，但和全游戏金色调不搭）　(B) 金色，和主色调统一（好看，但不够警示）　(C) 灰色，低调（最不显眼，反而不容易误点） |
| **三、退出框上要不要加一句「进度已保存」？** | (A) **要**，写「你的进度已保存，下次可从主城继续」（让玩家放心）　(B) 不要，多了字反而乱　(C) 只写「进度已保存」四个字 |

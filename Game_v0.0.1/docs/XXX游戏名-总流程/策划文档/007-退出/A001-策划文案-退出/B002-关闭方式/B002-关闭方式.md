# B002-关闭方式

> 父级：`007-退出`　｜　版本 v1.0　｜　2026-10-26
> 对应代码：`flow_root.gd`（退出屏 `_build_goodbye()` 第 549~562 行、确认按钮第 556~557 行、返回按钮第 559~560 行、输入处理：**整个文件里没有 `_input()` 也没有 `_unhandled_input()`**）、`battle.gd`（战斗内 Esc `_unhandled_input()` 第 391~397 行）

---

## 一、这个功能是干什么的

**一句话**：把所有能「关掉游戏」的路都数一遍，一条条说清：怎么按、会不会问、会不会丢东西。

**为什么要专门写一份**：玩家关游戏的花样很多 —— 点按钮、按 Esc、按回车、点窗口右上角那个 ×、直接按 Alt+F4。**每一条路的安全程度都不一样**。现在游戏里只有一条路问了一句，其余的全是一条道走到黑。

**太奶奶怎么理解**：就是一栋楼所有的出口。正门出去有人问你一句，后门出去直接到马路上，窗户跳出去会摔。

---

## 二、界面长什么样

「关闭方式」本身不是一个界面，它是「按了什么之后发生什么」。所以这里列的是**每种方式对应的屏幕状态**。

| 编号 | 关闭方式 | 屏幕上看到什么 | 按了以后 |
|---|---|---|---|
| 关-1 | 主菜单点「退出游戏」→ 点「确认退出」 | 退出确认屏（整屏，见 `B001`） | 程序结束 |
| 关-2 | 主菜单点「退出游戏」→ 点「返回首页」 | 同上 | 回主菜单 |
| 关-3 | 退出确认屏按 Esc | 退出确认屏 | **没有任何反应** |
| 关-4 | 退出确认屏按回车 | 退出确认屏 | **没有任何反应** |
| 关-5 | 退出确认屏点空白处 | 退出确认屏（没有黑幕可点） | **没有反应** |
| 关-6 | 点窗口右上角 × | 当前屏 | 程序结束，**不问** |
| 关-7 | 战斗中按 Esc | 战斗画面 + 「已暂停」提示 | **暂停**，不退出 |
| 关-8 | 战斗中再按一次 Esc | 战斗画面 | 继续战斗 |
| 关-9 | 战斗中点窗口 × | 战斗画面 | 程序结束，**这一局全丢，不问** |
| 关-10 | 主城 / 选关 / 选人 点窗口 × | 当前屏 | 程序结束（这些地方数据已存，安全） |
| 关-11 | 系统层面 Alt+F4（Windows） | 当前屏 | 由系统/引擎处理，**游戏拦不住** |

### 2.1 现在唯一的「问一句」长什么样

只有关-1 / 关-2 这条路上会出现确认屏，它的长相见 `B001-退出确认` 第二节。这里只强调一点：

> **它不是弹窗，是整屏换页。** 玩家点了「退出游戏」以后，主菜单整个消失，屏幕上只剩一句话两个按钮。所以「Esc 关掉这个框」这件事在视觉上会变成「切回主菜单」，玩家分不清是「Esc 生效了」还是「我又点了一次」。

### 2.2 战斗里的 Esc 长什么样

| 项目 | 说明 | 代码 |
|---|---|---|
| 按 Esc 后 | 画面停住（世界不再更新），顶部显示「已暂停」 | `battle.gd` 第 396 行、第 418~424 行 |
| 画面变暗吗 | **不变暗**，也没有遮罩 | — |
| 有没有「继续」「退出」按钮 | **一个都没有** | — |
| 再按一次 Esc | 继续战斗 | 第 396 行 `paused = not paused` |
| 暂停时能不能退出游戏 | **不能**，只能点窗口 × | — |

> **这是最要紧的一句**：玩家在战斗中按 Esc 以为能退出，结果只是画面停住了。**他找不到任何「退出游戏」的按钮**，最后只能去点窗口右上角的 ×。而 × 是不问的。

### 3.2 关-2：主菜单 → 确认 → 返回

| 步 | 发生什么 | 代码 |

### 3.3 关-3 / 关-4 / 关-5：键盘和空白

| 方式 | 现在实际发生什么 | 原因 |
|---|---|---|
| Esc | **什么都没发生** | `flow_root.gd` 整个文件没有 `_input()` 或 `_unhandled_input()` 函数 |
| 回车 | **什么都没发生** | 同上 |
| 点空白 | **什么都没发生** | 没有黑幕节点，也没有遮罩接收点击 |

> **这里要特别澄清一个谣言般的误解**：「按 Esc 会不会直接关游戏？」—— **不会**，因为根本没绑定。真正危险的是**按 Esc 什么都不发生**：玩家以为游戏卡死了，开始乱按、乱点。

### 3.4 关-6 / 关-9 / 关-10：窗口 ×

| 屏 | 点 × 以后 | 数据安全吗 |

| 选关 / 选人 | 程序结束 | ✅ 安全（还没开打） |

| 结算屏 | 程序结束 | ✅ 安全（结晶和星级在弹屏前就 `commit` 了，`flow_root.gd` 第 183~186 行） |

### 3.5 关-7 / 关-8：战斗内 Esc

| 步 | 发生什么 | 代码 |

| ② | `paused` 取反，同时告诉全局状态「现在是菜单态/游戏态」 | 第 396~397 行 |

## 四、各种状态

「关闭方式」的状态，其实就是「玩家现在在哪」× 「他按了什么」。

| 玩家在哪 | 点窗口 × | 按 Esc | 按回车 | 界面上有没有退出按钮 |
|---|---|---|---|---|
| 主菜单 | 关，不问 | 无反应 | 无反应 | ✅ 有「退出游戏」 |
| 退出确认屏 | 关，不问 | **无反应** | **无反应** | ✅ 有「确认退出」 |
| 主城 | 关，不问 | 无反应 | 无反应 | ❌ 没有 |
| 选关 | 关，不问 | 无反应 | 无反应 | ❌ 没有 |
| 选人 | 关，不问 | 无反应 | 无反应 | ❌ 没有 |
| 战斗中 | **关，这一局全丢** | 暂停 / 继续 | 无反应 | ❌ 没有 |
| 战斗暂停中 | **关，这一局全丢** | 继续战斗 | 无反应 | ❌ 没有 |
| 结算屏 | 关，安全 | 无反应 | 无反应 | ❌ 没有（有「返回主城」） |

**规律**：**只有主菜单那一条路是有「问」的，其余全靠窗口 ×**。而窗口 × 是引擎默认行为，游戏代码里一行都没管。

## 六、异常情况

| 情况 | 应该 | 现在 |
|---|---|---|
| 玩家在战斗中狂按 Esc | 应该在暂停和继续之间稳稳切换，不能乱 | ✅ `paused = not paused`，稳定 |
| 玩家在战斗中按 Esc 后以为退出了，去点 × | 应该有个「退出游戏」按钮拦住他 | ❌ 没有，玩家真的就点了 × 丢了这一局 |
| 玩家在升级弹窗（4 选 1）开着时按 Esc | 应该不响应（弹窗优先） | 🟡 弹窗期间主循环第 413~417 行提前 return，但 **Esc 仍然会翻转 `paused`**，可能造成暂停和升级弹窗打架 |
| 玩家在背包装备面板（Tab）里按 Esc | 应该先关背包 | 🟡 **没有处理**，Esc 直接切暂停 |
| 玩家在结算屏按 Esc | 无反应，可以接受 | ✅（不误操作是好事） |
| 玩家连点 × 两次 | 只关一次 | ✅ 第一次就结束了 |
| 关闭时正在写存档 | 可能写坏 | 🟡 主菜单退出不涉及；战斗中点 × 时那次写入根本没发生，所以不会写坏，但会丢数据 |
| Alt+F4 / 强制结束进程 | 游戏拦不住 | 🟡 这是操作系统行为，任何游戏都拦不住 |
| 笔记本合盖 | 游戏挂起，不退出 | ✅ 正常 |
| 游戏窗口失去焦点 | 战斗**不会自动暂停** | 🟡 玩家切出去聊天，回来发现被打死了 |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 按 Esc 直接关游戏 | 玩家在战斗里按 Esc 是想暂停，不是想退出。一刀切关掉等于随机杀人 |
| 按 Esc 什么都不发生 | 现在就是这样。玩家会以为游戏卡死 |
| 回车默认触发「确认退出」 | 玩家一激动按回车，游戏就没了。**回车必须等同「继续」** |
| 战斗中点窗口 × 直接关、不问 | 玩家打 20 分钟，一秒钟全丢，还不知情 |
| 战斗中没有任何游戏内退出入口 | 逼玩家去点 ×，这是把最危险的路留成唯一的路 |
| 退出框没有黑幕、点空白关不掉 | 玩家已经养成「点旁边就取消」的习惯，点不动会更烦躁 |
| 关闭时清空存档 | 绝对不能 |
| 关闭后留后台进程 | 玩家在任务管理器看到会以为中病毒 |
| 关闭前弹一堆「你确定吗」「真的确定吗」 | 问一次够了，不要连环问 |
| 关闭时加倒计时 / 广告 / 评分 | 恶心人 |
| 把窗口 × 的行为从引擎默认改成别的 | 不要绕开系统的关窗口约定，玩家会以为游戏卡死 |
| 在战斗还没结束就让 Esc 直接退出到主菜单 | 那这一局的东西算成功还是丢掉？必须问一句，不能默认 |

## 八、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 输入 | 玩家的按键（Esc / 回车）、鼠标点击、窗口关闭事件 |
| 输出 | `quit`（进程结束） / `screen-main`（回主菜单） / 暂停状态切换 |
| 依赖 1 | `flow_root.gd` 的流转表：`screen-goodbye` 只能回 `screen-main`（第 21 行） |
| 依赖 2 | `battle.gd` 的 Esc 处理（第 391~397 行），**和 flow_root 是两套互不知情的输入处理** |
| 前置 | 玩家在某个具体屏上 |
| 和 `B001-退出确认` 的关系 | `B001` 管那个框的两个按钮；本文件管**除了那两个按钮以外的所有关闭方式**，以及每个屏能不能关 |
| 和 `001/B004` 的关系 | `001/B004` 第三节列了「Esc / 回车 / 点黑幕 = 继续」四条，但**代码一条都没做**。本文件是这四条的完整落地口径，`001/B004` 只留一句指向本文件 |
| 和 `002-主城` 的关系 | 主城点 × 是安全的。如果以后加退出按钮，按 `B001` 的框来，**退出前必须 `commit`** |
| 和 `005-战斗` 的关系 | 战斗里 Esc 是暂停（第 395~397 行），本文件不改这个定义。但**暂停界面必须加一个「退出游戏」选项**，否则玩家只能点 × |
| 和 `006-结算` 的关系 | 结算屏点 × 是安全的（数据已入账）。所以结算屏可以不设退出按钮 |
| 和存档的关系 | 只有「战斗中退出」需要存一次档（存档现有的 `_save_on_death()` 可以复用，但它现在只在死亡/撤离时调） |
| 和 `cfg/settings.json` 的关系 | 如果以后要支持「自定义 Esc 键」，改配置不要改代码。现在代码是写死 `KEY_ESCAPE`（`battle.gd` 第 395 行） |

## 十、太奶奶要定的事

| 问题 | 选项 |
|---|---|
| **一、战斗中想退出，怎么办？** | (A) **按 Esc 弹出暂停菜单，里面有「继续 / 退出游戏」，点退出再问一句**（最标准，玩家一定会用）　(B) 按 Esc 直接回主菜单并结算（快，但容易误触）　(C) 什么都不加，禁止战斗中退出（最安全，但玩家会去点 ×） |
| **二、点窗口右上角那个 × 要不要拦一下？** | (A) **要拦**：战斗中弹「这局会全丢，确定吗」（麻烦但保命）　(B) 不拦，引擎默认（省事，但会丢局）　(C) 只拦战斗，别的屏直接关（折中） |
| **三、主城 / 选关 / 选人 要不要能退出？** | (A) **右上角放一个小「退出」图标**，点了才弹确认（一致，但多一个元素）　(B) 都不加，只能用窗口 ×（省事）　(C) 只加在暂停菜单里，平时不显示（最干净） |

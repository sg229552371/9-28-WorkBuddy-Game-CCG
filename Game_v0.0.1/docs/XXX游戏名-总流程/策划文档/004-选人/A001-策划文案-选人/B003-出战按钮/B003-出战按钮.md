## 一、这个功能是干什么的

**一句话**：这一屏的「出发」按钮。它写着现在带了几个人，点下去就真的进战斗。

**它是整条流程的最后一个确认点。** 主城 → 选关 → **选人 → 点它 → 打**。玩家点下去以后，就没有回头路了（进去之后只能打赢或打死，不能中途退出回主城——那是结算的事）。

**为什么它的文字要带数字**：`开始出战 (2/3)` 这句话同时回答了两个问题：「我现在带了几个」和「最多能带几个」。玩家不用去数卡片上的金边。**这个数字是这一屏最重要的反馈。**

**和整款游戏的关系**：按下去的那一刻，队伍名单就被交出去了。名单第一个是队长，其余跟着队长走。全局已定——死了丢光本局捡到的东西，所以这个按钮在心理上是一道门槛，**必须让玩家清楚知道「我带了谁」才敢按**。

## 三、点击后发生什么

### 3.1 一个人都没选时

| 步骤 | 发生什么 | 玩家看到什么 | 耗时 |
|---|---|---|---|
| ① | 玩家点按钮 | **按钮是灰的，点不动**（第 1005 行禁用） | 0 |
| ② | 什么都没发生 | 没变化 | — |
| ③ | （代码里还有一层保险：真被调用到也会直接返回，第 1009~1011 行） | — | — |

> 也就是说，**没选人时这个按钮是完全点不动的**，不会弹「请先选人」。这是好事（少烦人），但缺点是新玩家可能盯着灰按钮不知道该怎么办。建议在灰按钮旁边或按钮上写一句「先选 1~3 个英雄」（见第十节第 1 题）。

### 3.2 选了 1~3 个人后

| 步骤 | 发生什么 | 玩家看到什么 | 耗时 |
|---|---|---|---|
| ① | 玩家点按钮 | 按钮有系统默认按下效果 | 0 |
| ② | 检查队伍不为空 → 通过 | 没变化 | 眨眼都不到 |
| ③ | 把队伍**第一个人**记成「本局队长」 | 没变化 | 同上 |
| ④ | 把整个队伍名单记进全局状态（按点击顺序） | 没变化 | 同上 |
| ⑤ | 广播「队伍已确认」 | 没变化 | 同上 |
| ⑥ | 整个界面隐藏 | 画面开始消失 | 立刻 |
| ⑦ | 屏幕状态先记成「结算」（这是给回来时用的） | 玩家看不到 | 立刻 |
| ⑧ | 加载战斗场景 | **一段加载时间**（取决于战斗场景大小） | 正常一两秒；低配可能更久 |
| ⑨ | 进入战斗 | 看到战斗画面 | — |

> **期间没有任何「准备好，3、2、1」的倒数**。点下去就开始加载。

### 3.3 数字是怎么变的

| 玩家动作 | 按钮文字 |
|---|---|
| 刚进屏 | 开始出战 (0/3)（灰、点不动） |
| 点第 1 个英雄 | 开始出战 (1/3)（亮、能点） |
| 点第 2 个 | 开始出战 (2/3) |
| 点第 3 个 | 开始出战 (3/3) |
| 取消一个 | 数字 -1 |
| 取消到 0 个 | 开始出战 (0/3)（又变灰） |

> 数字的「3」是从配置表 `cfg/team.json` 的 `maxSize` 读的，不是写死的（第 1001、1004 行）。将来改上限，这里自动跟着变。

## 四、各种状态

| 状态 | 条件 | 样子 | 能点吗 |
|---|---|---|---|
| 禁用（0 人） | 一个人都没选 | 灰掉的按钮，文字「开始出战 (0/3)」 | ❌ 不能 |
| 常态（1~3 人） | 选了至少一个 | 灰蓝底 + 2 像素金边 + 金色文字 | ✅ 能 |
| 鼠标悬停 | 鼠标在按钮上 | 系统默认一点点变化 | — |
| 按下 | 正按着 | 系统默认的按下效果 | — |
| 满员（3 人） | 选满 | 和常态一样，只是数字是 (3/3) | ✅ 能 |
| 加载中 | 已经点了、正在切场景 | **按钮已经消失**（整屏隐藏了） | — |

> **注意**：这个按钮**没有「加载中」的状态**。点下去以后整屏立刻隐藏，玩家看到的是加载画面（或黑屏），没有「正在进入战斗…」的提示。这是可以改的（见第十节第 2 题）。

## 五、声音/反馈

| 时机 | 现在 | 应该 |
|---|---|---|
| 人数变化（0→1、1→2…） | ❌ 无声 | 卡片那边已经有「叮」，这里不必重复 |
| 点下「开始出战」 | ❌ 无声 | ✅ 一声**干脆的鼓点或「出击」音**，这是玩家最有仪式感的时刻 |
| 战斗加载中 | ❌ 没有提示 | ✅ 至少一行「正在进入战斗…」 |
| 点灰按钮（0 人时） | ❌ 点不动、没反应 | 建议按钮上直接写「先选人」，不用弹框 |

> 这一屏**目前完全没有音效**。但「出战」这一下的仪式感值得单独做一个音效，这是整局游戏的发令枪。

## 六、异常情况

| 情况 | 会怎么 | 玩家看到什么 | 应该怎么处理 |
|---|---|---|---|
| 0 人时点按钮 | 禁用，点不动；函数里也有第二层保险直接返回（第 1009~1011 行） | 没反应 | ✅ 合理。建议按钮上加提示字 |
| 队伍里有英雄在配置表中被删了 | 名单里还留着这个编号，战斗加载时会找不到人 | 可能少人、可能报错 | 点按钮时校验一遍名单，剔除不存在的编号 |
| 关卡编号为空（比如直接从别处跳进这一屏） | 战斗不知道打哪关 | 可能加载出错 | 点按钮时检查：没关卡就弹「请先从选关屏选一关」 |
| 战斗场景加载失败 | 界面已隐藏、场景没出来 | 黑屏/空屏 | 加载失败要能回主城，并显示「战斗加载失败」 |
| 连点两次按钮 | 第一次已隐藏整屏，第二次点不到 | 正常 | 无问题 |
| 队伍上限改成 1（配置表被改） | 按钮写「(0/1)」，选一个就满 | 数字自动跟着变 | ✅ 合理 |
| 队伍上限配置缺失 | 读不到上限，可能拿到 0 | 按钮写「(1/0)」，永远满员选不进人 | 上限缺失时应兜底成 3 |
| 主城/结算后回来，队伍还留着上次的人 | 每次进这一屏会先清空队伍（第 746 行） | 按钮回到 (0/3) 灰态 | ✅ 已处理 |

## 七、不许干的事

| ❌ 不许 | 为什么 |
|---|---|
| 一个英雄都不选也能进战斗 | 全局是「三人同场」，一个人都没带进去就是空队，战斗没法跑 |
| 0 人时按钮看起来还能点 | 点了没反应等于骗人。必须明显变灰 |
| 点下去弹「确定要出战吗？」的二次确认 | 玩家已经选了人、按了按钮，这一步已经很明确了。多一个框只会烦 |
| 按钮上的数字写死成 3 | 上限在配置表里，将来要改，写死就得改代码 |
| 点下去以后还能反悔（停在这屏） | 已经交出去了，必须立刻进战斗；想退出在战斗里退 |
| 出战时把玩家选的顺序打乱 | **第一个是队长**，顺序有含义 |
| 点下去瞬间没有任何视觉反应 | 玩家会连点。点下后应立刻变灰或隐藏 |
| 在按钮上写「开始战斗」 | 文案统一用「开始出战」，和别处一致 |
| 加载战斗时一片黑什么都不说 | 玩家以为卡死了 | 应显示「正在进入战斗…」 |

## 八、和其他文档的约定

| 项目 | 内容 |
|---|---|
| **输入** | 当前队伍名单（1~3 人，按点击顺序）；全局状态里的「本局关卡编号」；`cfg/team.json` 的 `maxSize` |
| **输出** | 全局状态里的「队长」＝名单第一个；「队伍名单」＝完整名单；广播「队伍已确认」；切到战斗场景 |
| **依赖** | `B001-英雄卡片` 提供名单；`003-选关` 提供关卡编号 |
| **前置条件** | 队伍非空 + 关卡编号非空 |
| **和 `005-战斗` 的约定** | 战斗按名单顺序放人，第一个当队长，其余跟随；战斗不重新读队伍，只用这里交出来的名单 |
| **和 `006-结算` 的约定** | 这一屏先把屏幕状态记成「结算」，是为了战斗结束后能正常弹结算屏 |
| **和 `B004-返回选关` 的约定** | 两个按钮在同一行、左退右进。别把「返回」也做成金色，否则玩家分不清主次 |

## 十、太奶奶要定的三件事

| 问题 | 选项 |
|---|---|
| **一个人都没选时，怎么告诉玩家「先选人」？** | (A) 按钮文字直接写「先选 1~3 个英雄」　(B) 按钮旁边一行小灰字提示　(C) 什么都不写，灰着就够明显 |
| **点「开始出战」后，要不要一段过渡？** | (A) 直接切（现在这样，快）　(B) 显示「正在进入战斗…」一行字　(C) 加 2 秒「队伍已就位」的过场 |
| **带 1 个人和带 3 个人，按钮有什么不同吗？** | (A) 没不同，只改数字　(B) 带满 3 人时按钮更亮/加一句「满编」　(C) 带 1 人时提醒「人少风险高」 |

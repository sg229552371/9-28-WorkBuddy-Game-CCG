## 一、这个功能是干什么的

**一句话**：屏幕下方那块「英雄说明书」——点哪个英雄，它就告诉我这个英雄血多不多、打得狠不狠、好在哪、差在哪。

**它解决的问题**：12 个英雄，头像都是色块 + 一个字，名字也就三四个字。光看卡片，玩家根本分不清「散弹手」和「穿甲者」有什么区别。**这一块就是让玩家在 3 秒内决定「要不要带他」的地方**。

**为什么这块不能省**：全局已定——死了丢光本局捡到的东西。带错人进去，可能白打 20 分钟。所以玩家会认真看这块。信息写错了，玩家就被坑了一场。

**和整款游戏的关系**：这里显示的生命、攻击等数字，就是英雄进战斗后的**基础值**（局外等级会往上加）。所以这块不只是「参考」，是玩家判断这一趟能不能赢的依据。

| 尺寸 | 宽铺满，**最小高 190** | 第 702 行 |
| 底色 | 中灰蓝 `#252a34` | 第 704 行 |
| 圆角 | 8 | 第 705 行 |
| 内边距 | 左右 12、上下 8 | 第 706~709 行 |
| 内容超出时 | 面板内部**可以上下滚**（滚动区最小高也是 190） | 第 712~715 行 |
| 行间距 | 4 | 第 719 行 |
| 刚进这一屏时 | **空白**（没有默认展示任何英雄） | 第 739~758 行构建时没有填内容 |

> **太奶奶注意**：**刚进来那一瞬间，这块是空的**。玩家会看到一块灰蓝色的空框，得先点一个英雄才有内容。这是现在的真实状态。建议默认显示第一个能用的英雄（见第十节第 1 题）。

### 2.2 里面一共 6 行（从上到下）

| 第几行 | 里面有什么 | 字号 | 颜色 | 出处 |
|---|---|---|---|---|
| ① 名字行 | 英雄名（20 号金） + 职业标签（灰蓝底白字） + **「HOPS」**（灰蓝） + 「Lv1」 | 20 / 13 / 15 / 15 | 金 / 白 / 灰蓝 / 骨白 | 第 926~944 行 |
| ② 属性行 | 「生命 94 · 攻击 16 · 速度 306 · 防御 2 · 力量 6 · 敏捷 8 · 智力 4」 | 15 | 骨白 | 第 946~956 行 |
| ③ 优点行 | 绿底「优点」+ 若干个绿底属性标签，如「敏捷」 | 13 | 绿底浅绿字 | 第 958~963 行 |
| ④ 缺点行 | 红底「缺点」+ 若干个红底属性标签；没有缺点时显示灰底「待配置」 | 13 | 红底浅红字 | 第 964~969 行 |
| ⑤ 羁绊行 | 「羁绊：待配置」 | 15 | 灰蓝 | 第 971~982 行 |
| ⑥ 进化结晶行 | 「进化结晶：击败小怪 ✦1 / 首领 ✦60，撤离后用于局外升级」 | 15 | 灰蓝 | 第 984~994 行 |

### 2.3 属性行里到底会出现哪些属性（重要）

代码按固定顺序去英雄表里找这 8 个字段，**找到就显示，找不到就跳过**：

| 顺序 | 字段 | 中文名（来自 `cfg/statNames.json`） | 12 个英雄有吗 |
|---|---|---|---|
| 1 | `hp` | 生命 | ✅ 都有 |
| 2 | `atk` | 攻击 | ✅ 都有 |
| 3 | `spd` | 速度 | ✅ 都有 |
| 4 | `dig` | **挖掘** | ❌ **一个都没有**，所以永远不显示 |
| 5 | `def` | 防御 | ✅ 都有 |
| 6 | `str` | 力量 | ✅ 都有 |
| 7 | `agi` | 敏捷 | ✅ 都有 |
| 8 | `int` | 智力 | ✅ 都有 |

> 所以实际显示的是 **7 个属性**（生命、攻击、速度、防御、力量、敏捷、智力），「挖掘」永远不会出现。**这不是 bug，是数据里没有这个字段，代码自动跳过了**。但如果哪天补了「挖掘」，它会自动出现在「速度」后面、「防御」前面。

### 2.4 「HOPS」是什么（这是一个真笔误）

名字行里那个 **「HOPS」** 是开发时留下的占位串，因为当时想放一个「职业缩写」或者「攻击方式」之类的标签，后来没做，字串没删。**它现在真的显示在玩家屏幕上**，夹在职业标签和等级之间。

> 玩家看到的效果大致是：`猎手  [输出]  HOPS  Lv1`。前两个能看懂，中间那个英文没人看得懂。**必须删掉**（待办 T2）。

### 2.5 一屏真实的样子（以猎手为例）

```
┌────────────────────────────────────────────────────────────────┐
│ 猎手  [输出]  HOPS  Lv1                                        │ ← ① 名字行
│ 生命 94 · 攻击 16 · 速度 306 · 防御 2 · 力量 6 · 敏捷 8 · 智力 4 │ ← ② 属性行
│ [优点] [敏捷]                                                  │ ← ③ 优点（绿）
│ [缺点] [待配置]                                                │ ← ④ 缺点（红）——他没有缺点
│ 羁绊：待配置                                                   │ ← ⑤ 永远这一句
│ 进化结晶：击败小怪 ✦1 / 首领 ✦60，撤离后用于局外升级             │ ← ⑥
└────────────────────────────────────────────────────────────────┘
```

**再举一个（散弹手 H002）**：

```
┌────────────────────────────────────────────────────────────────┐
│ 散弹手  [输出]  HOPS  Lv1                                      │
│ 生命 116 · 攻击 23 · 速度 290 · 防御 2 · 力量 7 · 敏捷 5 · 智力 3 │
│ [优点] [攻击] [生命]                                            │ ← 他又猛又抗
│ [缺点] [速度] [敏捷]                                            │ ← 但他慢、笨
│ 羁绊：待配置                                                   │
│ 进化结晶：击败小怪 ✦1 / 首领 ✦60，撤离后用于局外升级             │
└────────────────────────────────────────────────────────────────┘
```

> **一对比就明白了**：散弹手攻击 23 比猎手 16 高，但速度 290 比猎手 306 低。玩家不用懂数字，只看「优点 = 攻击、生命；缺点 = 速度、敏捷」这几行标签，就知道「这是个又猛又慢的胖子」。**这就是这块面板的价值。**

## 三、点击后发生什么（什么时候换内容）

| 玩家动作 | 这块面板会怎样 | 合理吗 |
|---|---|---|
| 进这一屏，还没点任何人 | **空白** | 🟡 应该默认显示第一个能用的英雄 |
| 点一个**没选过**的英雄 | 整体清空，重画成这个英雄 | ✅ 合理 |
| 点一个**已经选中**的英雄（=取消） | **仍然重画成这个英雄** | ❌ 不合理，玩家取消了却还看到他 |
| 点一个**未解锁**的英雄 | 面板**不变**（因为点不到） | 合理，但玩家不知道原因 |
| 在主城改了英雄等级后回到这一屏 | 面板内容按新等级重画 | ✅ 合理（第 940 行每次重读等级） |
| 从结算回来再进选人 | 面板**是空的**（重建网格时不清详情，但详情框也跟着被重建屏清空） | 🟡 空着不好看 |

**重画时的内部动作**（第 918~919 行）：先把面板里现有的所有东西全删掉，再从头一行一行画出来。

| 步骤 | 耗时 |
|---|---|
| ① 删掉旧的几行 | 立刻 |
| ② 新建名字行（4 个部件） | 立刻 |
| ③ 新建属性行（拼 7 个数字） | 立刻 |
| ④ 新建优点行、缺点行（每个标签一个小框） | 立刻 |
| ⑤ 新建羁绊行、进化结晶行 | 立刻 |
| ⑥ 整块显示 | 立刻，肉眼看不到过程 |

> 所以切换英雄时**看不到「闪一下」**，是瞬间换掉。这是好事，不用加动画。

## 六、异常情况

| 情况 | 会怎么 | 玩家看到什么 | 应该怎么处理 |
|---|---|---|---|
| **名字行出现「HOPS」** | 现在就会 | 一行看不懂的英文 | 删掉（待办 T2） |
| **羁绊永远「待配置」** | 现在就会 | 每个英雄都写着「待配置」，像没做完 | 要么补数据，要么这一行先不显示（见第十节第 2 题） |
| 缺优点/缺点数据 | 显示灰底「待配置」 | 玩家看不出这个英雄强在哪 | 至少不能只写「待配置」，要写「暂未标注」 |
| 属性字段缺（比如 `dig`） | 自动跳过，不显示 | 少一项，不影响读懂 | 合理，保留 |
| 属性中文名表缺失 | 显示英文字段名 | 「hp 94 · atk 16」 | 应退成「生命」「攻击」写死兜底 |
| 属性一个都没有 | 显示「待配置」 | 一行灰字 | 只在配置全坏时出现，可接受 |
| 内容太高（某英雄标签特别多） | 面板内可滚 | 出现滚动条 | 合理 |
| 未解锁英雄被点 | 面板不变 | 玩家以为点没反应 | 应该弹「还没解锁」 |
| 面板被重建（进屏时） | 内容清空 | 空框 | 默认填第一个英雄 |

## 七、不许干的事

| ❌ 不许 | 为什么 |
|---|---|
| **在界面上留「HOPS」这种看不懂的英文占位** | 玩家会以为游戏没做完，信任直接掉 |
| **羁绊行永远写「待配置」** | 12 个英雄都写这四个字，等于告诉玩家「这块没做」 |
| 取消选择后详情还显示被取消的人 | 玩家会怀疑「我到底取消了没」 |
| 详情里显示战斗里看不到的数字 | 这里的生命/攻击就是进战斗后的基础值，不许写「参考值」之类 |
| 一进屏就是空框 | 玩家会以为详情坏了 |
| 把 99 个属性的原始英文键名露出来 | 玩家看不懂，必须转中文 |
| 详情面板超高但不给滚 | 内容会被切掉，玩家看不到下半截 |
| 用「优点/缺点」以外的颜色 | 绿=好、红=差，是玩家已经在别的游戏里学会的常识，别创新 |

## 八、和其他文档的约定

| 项目 | 内容 |
|---|---|
| **输入** | 被点击的英雄那一条完整数据（名字、职业、属性、优点、缺点）；存档里的「局外等级」；`cfg/statNames.json` 的属性中文名；`cfg/heroRoles.json` 的职业名；`cfg/outLevel.json` 的结晶数（小怪 1、首领 60） |
| **输出** | 只读，不产生任何数据 |
| **依赖** | `B001-英雄卡片` 的点击事件 |
| **和 `B001-英雄卡片` 的约定** | 卡片负责「谁被点了」，这块负责「这个人怎么样」。卡片取消选择时**不该**再通知这块刷新 |
| **和 `005-战斗` 的约定** | 战斗里的英雄基础值必须和这里显示的一致 |
| **和 `006-结算` 的约定** | 「进化结晶：击败小怪 ✦1 / 首领 ✦60」这句是**承诺**，结算必须按这个给，不能少给 |
| **和 `001-主菜单` 图鉴的约定** | 图鉴里的「英雄详情」应该是同一套内容，别两处写得不一样 |

## 十、太奶奶要定的三件事

| 问题 | 选项 |
|---|---|
| **刚进选人屏时，下方这块显示什么？** | (A) 显示第一个能用的英雄（推荐）　(B) 显示「点上面任意英雄看详情」一行提示　(C) 就空着，反正玩家会点 |
| **「羁绊：待配置」怎么办？** | (A) 先整行藏起来，做好了再放出来（推荐）　(B) 补上羁绊数据，真的显示　(C) 保持现状，写「待配置」 |
| **取消选择后，下方详情怎么处理？** | (A) 保持显示这个人（现状）　(B) 退回「点上面任意英雄看详情」的空状态（推荐）　(C) 显示队伍里剩下的第一个人 |

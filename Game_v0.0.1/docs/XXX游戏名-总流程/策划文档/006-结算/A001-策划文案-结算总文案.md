## 一、这一屏是干什么的

**一句话**：一局打完了，告诉玩家「你活着出来了」还是「你死在里面了」，把这局杀了多少、用了多久、赚了多少结晶摆出来，然后让他回城。

**太奶奶怎么理解这一屏**：这就是矿工下井回来，在井口过秤的地方。人活着上来，捡到的矿称一称，登记进账；人埋在下面了，只能捞回一点点。

**四条设计底线**

| 底线 | 具体做法 | 现实情况 |
|---|---|---|
| 一句话看懂输赢 | 最上面一行大字，「撤离成功！」或「不幸阵亡…」，32 号金色 | ✅ 已有，但只会在全局结算屏上出现，玩家**通常先看到的是另一块写着「阵亡」的板子**（见第五节 ❌） |
| 钱要算得明白 | 收益单独一行金色：「结晶收益 ◆12」 | 🟡 数字是真的，但算法叫「结晶」的其实是金币（见第六节） |
| 不准糊弄玩家 | 拾了什么就列什么 | ❌ 现在是「（战利品清单占位：待战斗侧接入）」八个字 |
| 点两下之内回城 | 大按钮「返回主城」 | ✅ 已有，但要连按两次（见第五节） |

**已经定死、不许再改的三条**（太奶奶定的，`005-战斗` 总纲定-1/定-2 已记录）

| 编号 | 结论 | 一句话解释 |
|---|---|---|
| 定-1 | **打死 Boss 就算赢** | 打穿本关的大怪，这一局就算成功 |
| 定-2 | **死了丢光本局捡到的所有东西**（局外等级保住） | 背着的东西全没，人「升的级」留着 |
| 定-3 | 三人同场，局内满级 46 级 | 结算里不区分是谁杀的，整队算一份 |

### 5.1 玩家实际会经历的完整顺序（这是本屏最要命的地方）

```

        │  ┌──────────────── 同时有两个人接这个事件 ────────────────┐
```

## 六、和其他文档的约定

| 约定 | 内容 | 依据 |
|---|---|---|
| 谁发结算 | `combat.gd` 发 `EventBus.run_settled`，字段 `winner`（`"extract"` / `"dead"`）、`shards`、`kills`、`time`、`level_id` | `combat.gd` 第 365~371 行 |
| 字段名两种写法都收 | `winner` 或 `reason`；`time` 或 `elapsed`；`shards` 或 `crystals` | `flow_root.gd` 第 106~117 行 |
| 谁是入账唯一真源 | `_apply_settle_to_meta()`，**只有这一处动存档里的结晶和星级** | 第 166~186 行 |
| 赢了给多少结晶 | 取结算里的 `crystals`；没给就用击杀数；**但绝不能超过击杀数**（第 171 行 `get("crystals", kills)` 的兜底口径） | 第 171 行 |
| 赢了给几星 | 取结算里的 `stars`，不给就 1 星 | 第 174 行 |
| 赢了解锁到第几关 | 当前关序号 **+2**（序号从 0 算，所以是「解锁下一关」） | 第 172~176 行 |
| 输了给多少结晶 | `击杀数 × deathRatio`，`deathRatio` 从 `cfg/outLevel.json` 读，缺省 0.3，取整时**直接抹掉小数** | 第 177~182 行、`cfg/outLevel.json` 第 44 行 |
| 什么时候落档 | `GameState.meta.commit()`，在发结算屏之前就已经存好 | 第 183~186 行 |

### 6.1 两个必须点出来的大冲突

**冲突一：怎样算赢**

| 说法 | 出处 |
|---|---|
| 打死 Boss 就算赢 | 太奶奶定的（`005-战斗` 总纲 定-1） |
| 打完 Boss 出撤离点，站圈读条 8 秒才算赢 | `combat.gd` 第 326~328 行 `extract_point.update()` 成功才 `_settle("extract")`；`cfg/extract.json` `channel=8` |
| 死亡时撤离点雕像消散 | `cfg/extract.json` 第 4 行 `note` |

**三处口径里，代码走的是第二条。** 建议（写在 `B001` 第十节也提一次）：**保留代码这条（打 Boss 出点、站 8 秒），但把「赢」改成两段说法** —— 打死 Boss 那一刻在屏幕上写「首领已倒下，撤离点已开启」，读条完成才算「撤离成功」。这样既满足太奶奶「打死 Boss 就算打赢了」的成就感，又保住「舍不得走」的紧张感。不要改成「打 Boss 立刻结算」，否则 `cfg/extract.json` 里那一整套压力波、护盾、雕像守卫（`shieldMax=2000`、`siegeDpsMul=1.5`）全白做。

**冲突二：死了丢多少**

| 说法 | 出处 | 说的是什么 |
|---|---|---|
| 丢光本局捡到的所有东西，局外等级保住 | 太奶奶定的（`005-战斗` 总纲 定-1） | 说的是**局内的装备、宝箱、材料** |
| 死亡保留 30% 结晶 | `flow_root.gd` 第 177~182 行、`cfg/outLevel.json` 第 44 行 | 说的是**结晶这个局外货币** |

**这两件事根本不是一回事，能同时成立。** 关键是别让玩家看糊涂：

| 东西 | 死了以后 | 为什么 |
|---|---|---|
| 本局捡的装备 / 宝箱 / 材料（局内收获） | **全丢，一件不留** | 太奶奶定的，这是「舍不得走」的动力来源 |
| 局外等级、已解锁关卡、已存进仓库的东西 | **全部保住** | 太奶奶定的，不能让玩家白玩 |
| 本局赚到的结晶 | **按 30% 折，算进局外账** | 代码口径。理由：结晶是「杀怪的辛苦钱」，不是「捡到的东西」，杀都杀了，给三成安慰奖 |

**必须改的是文案**：现在屏幕上写「结晶收益 ◆8（死亡仅保留 30%%）」—— 太奶奶看了会以为「我捡的东西保住了三成」，实际是全丢。建议改成两行：

- 第一行（金色）：`本局收获：全部丢失`
- 第二行（灰字）：`击杀辛苦钱 ◆8 已入账（按 30% 折算）`

`cfg/outLevel.json` 里 `deathLossValue=0` 和 `deathRatio=0.3` 打架的问题，交给 `B003` 第十节让太奶奶拍板。

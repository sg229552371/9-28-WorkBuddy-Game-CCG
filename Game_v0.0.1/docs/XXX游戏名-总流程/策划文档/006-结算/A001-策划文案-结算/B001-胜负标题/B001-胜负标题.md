# B001-胜负标题

> 父级：`006-结算`　｜　版本 v1.0　｜　2026-10-26
> 对应代码：`flow_root.gd` `_build_settle()` 第 1021~1028 行（面板标题 + 胜负大字）、`_show_settle()` 第 1065~1071 行（填文字）
> 另一套：`battle.gd` `_show_death_settlement()` 第 259~262 行（**标题写死「战斗结算（阵亡）」**）

---

## 一、这个功能是干什么的

**一句话**：一局打完，屏幕最上面几个大字，第一时间告诉玩家「你活着出来了」还是「你死里面了」。

**为什么要做得这么显眼**：玩家打完一局，心跳还在，眼睛第一眼找的就是「我成了没」。这一行字如果含糊，下面写得再细他都看不进去。**这一行是整屏的门面。**

**太奶奶怎么理解**：就像医院的诊断书，第一行大字写「已康复」还是「需留院」，别的都在后面。

## 三、点击后发生什么

标题本身不能点，但它是「一局结束后玩家看到的第一样东西」，所以把整条路径写清楚。

| 步 | 发生什么 | 耗时 |
|---|---|---|
| ① | 玩家血量归零，或撤离读条到 8 秒（`cfg/extract.json` `channel=8`） | 瞬间 |
| ② | `combat.gd` 第 361~371 行发一次结算事件（有闸门，只发一次） | 同一帧 |
| ③ | `battle.gd` 第 146~154 行接住 → 弹出**小板**，标题「战斗结算（阵亡）」 | 同一帧，立即出现 |
| ④ | `flow_root.gd` 第 97~102 行也接住 → 先算账、再切到**大屏**，标题「战斗结算」+ 大字「撤离成功！」 | 同一帧，被小板挡在后面 |
| ⑤ | 玩家看到的是小板。点「返回主城」→ 切主城场景 | 点一下 |
| ⑥ | 主城上还压着大屏（层级 100），标题又出现一遍 | — |
| ⑦ | 再点「返回主城」，才真的进主城 | 再点一下 |

**没有动画、没有淡入、没有延迟**。两行字是「啪」地直接出现的，中间也没有「结算中」的过场。

> **说明**：板子甲只对「撤离成功」弹（`battle.gd` 第 148 行只处理 `extract`）。**阵亡**的时候甲不弹，只有大屏。所以玩家会碰到两种完全不同的体验：赢了看两块板，输了只看一块 —— 这本身也不合理。

## 四、各种状态

| 状态 | 应该长什么样 | 现在实际 |
|---|---|---|
| 撤离成功（常态） | 大字「撤离成功！」绿色或金色，底下有淡淡的胜利感 | 金色字，正确文字 ✅，但只可能在大屏上看到 |
| 阵亡（常态） | 大字「不幸阵亡…」红色或灰，气氛沉 | 金色字，正确文字 ✅，在大屏上 |
| 小板-撤离成功（错） | 不该存在，或应写「撤离成功！」 | **写「战斗结算（阵亡）」** ❌ |
| 小板-阵亡 | 写「战斗结算（阵亡）」 | 此路径根本不触发（第 148 行只处理 extract）❌ |
| 悬停 | 标题不可点，无悬停 | 无 |
| 按下 | 同上 | 无 |
| 禁用 | 不适用 | 无 |
| 结算数据缺字段 | 应按「输了」或「未知」兜底，不能崩 | `won` 默认 `false`（第 1065 行），会显示成阵亡，不崩 ✅ |

## 五、声音/反馈

| 时机 | 应该有 | 现在 |
|---|---|---|
| 大字出现（赢） | 一声上扬的短音，或者鼓点收尾 | ❌ 没有 |
| 大字出现（输） | 一声低沉的下坠音 | ❌ 没有 |
| 字出现的方式 | 从 90% 放大到 100%，0.2 秒 | ❌ 直接出现 |

> 一局打完了却一声不响，像关了音效玩游戏。建议至少加两个短音效（各 0.5 秒以内）。

**另外有一个容易引起误会的地方**：现在「撤离成功！」和「不幸阵亡…」**颜色一模一样**，都是金色。如果玩家一眼扫过去只看颜色，会以为两局是同一个结果。建议见第十节。

## 六、异常情况

| 情况 | 应该 | 现在 |
|---|---|---|
| 结算数据没带 `winner` 也没带 `reason` | 不能崩，按「未知」显示 | 第 107 行取空字符串 → 第 109 行 `won = false` → 显示「不幸阵亡…」，不崩 ✅ 但会**冤枉玩家** |
| 结算数据里 `winner` 是没见过的值（比如 `"escape"`） | 兜底成「阵亡」并记一条日志 | 同上，静默按输处理 🟡 |
| 玩家在两块板之间反复切屏 | 不能出现第三块板 | `_build_settle()` 只建一次（第 210 行），`_show_settle()` 只复用 ✅ |
| 中文字体缺失 | 不能变成方块 | Godot 默认字体带中文，正常 ✅ |
| 一行太长顶到屏幕右边 | 自动换行 | 大字**没有**设自动换行（第 1024~1028 行没设 `autowrap_mode`），但「撤离成功！」「不幸阵亡…」都短，暂时无事 🟡 以后换长句子就会溢出 |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 赢了写「阵亡」 | 玩家辛辛苦苦打赢，屏幕上写着死，第一反应是「游戏坏了」，成就感直接归零。这是现在 `battle.gd` 第 260 行的真实状态 |
| 赢和输用同一个颜色、同一个图标 | 扫一眼分不出来，等于没做 |
| 用「恭喜通关」「挑战失败」这类词 | 太正式。本游戏是「下矿撤离」的调子，要说「撤离成功」「阵亡」 |
| 在标题里写数字（比如「击杀 37 撤离成功」） | 标题只负责说输赢，数字归 `B002`，混在一起就没人看了 |
| 做两块板、两个标题 | 一次结算只该有一个结论。现在两块板都带标题，是重复 |
| 标题里放「阵亡」两个字做装饰表情 | 玩家情绪最敏感的地方，别耍花招 |
| 输的时候把大字做成灰到看不见 | 「输了」也要看清，灰到看不见等于逃避 |

## 八、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 输入 1 | 结算数据里的 `won`（布尔值，真=赢） |
| 输入 2 | 结算数据里的 `winner` / `reason`，值只能是 `"extract"` 或 `"dead"`（`combat.gd` 第 366 行） |
| 输出 | 只改文字，不改任何数据 |
| 谁给结论 | `flow_root.gd` 第 106~109 行归一化出的 `won`，`_apply_settle_to_meta()` 第 167 行也会重算一次，两处口径一致（都是 `winner == "extract"`）|
| 依赖 | 无（不依赖存档、不依赖网络） |
| 前置 | 战斗必须已经发出结算事件，否则这一屏根本不会出现 |
| 下游 | `B002-本局数据` 紧接在下面，间距 10 像素 |
| 和 `001-主菜单` 的关系 | 无。主菜单没有胜负概念 |
| 和 `005-战斗` 的关系 | 战斗屏总纲第 176 行、第八节 T1 已记录「赢了不能写阵亡」，本文件是它的落地规格 |
| 和 `007-退出` 的关系 | 无 |

## 十、太奶奶要定的事

| 问题 | 选项 |
|---|---|
| **一、赢和输要不要一眼分色？** | (A) **要**：赢绿字、输红字（最清楚）　(B) 不要，都金色，靠字面分（贵气，但容易看错）　(C) 赢金色、输灰色（低调，但输了看着像坏了） |
| **二、打赢了以后，第一句话该说什么？** 现在代码说「撤离成功！」 | (A) 保持「撤离成功！」（和撤离点玩法一致）　(B) 改成「凯旋！」（更响亮）　(C) 改成「你活着回来了」（更有代入感） |
| **三、标题要不要有个大图标？** | (A) **要**：赢一个金色印章/旗帜，输一个灰烛台（好认，但要美术画）　(B) 不要，纯文字（省事）　(C) 先用色块占位，以后换图 |

## 一、这个功能是干什么的

**一句话**：让玩家从结算屏离开，去下一个地方。主路只有一个：回主城。

**为什么这里最容易出事**：结算屏是「一局结束」的终点，也是「下一局开始」的起点。如果这里点完去到不该去的地方，玩家会以为自己掉档了、卡住了。**这一屏的两个按钮，决定玩家再玩不玩下一局。**

**太奶奶怎么理解**：就像饭店买单以后，服务员把你送到门口。送错了门（送到后厨），客人就懵了。

## 二、界面长什么样

这一屏有 **3 个**「返回主城」按钮（两套面板各一个，大屏还多一个「回主菜单」），必须分开说。

### 2.1 大屏的两个按钮（`flow_root.gd` 第 1047~1057 行）

| 项目 | 主按钮 | 次按钮 |
|---|---|---|
| 文字 | 「返回主城」（第 1047 行） | 「回主菜单」（第 1053 行） |
| 是主按钮吗 | 是（`true`） | 不是（`false`） |
| 尺寸 | 320 × 52 | 320 × 52 |
| 字号 | 20 号 | 20 号 |
| 文字色 | 金色 `#e8b33c` | 骨白 `#e2e6ee` |
| 底色 | 卡片中灰蓝 `#252a34` | 同左 |
| 描边 | 金色 2 像素 | 无 |
| 圆角 | 8 像素 | 8 像素 |
| 位置 | 竖排在下，靠左 | 在「返回主城」下面 10 像素 |
| 代码来源 | `_make_button()` 第 252~265 行 | 同左 |

> **共同点（也是问题）**：两个按钮**都是中灰底**，主按钮只是多了一圈金字金边。从这个屏上看，两个按钮的「分量」差不多，玩家容易点错。

### 2.2 小板的一个按钮（`battle.gd` 第 276~281 行）

| 项目 | 规格 |
|---|---|
| 文字 | 「返回主城」（第 277 行） |
| 尺寸 | 宽不设（撑满），高 56（第 278 行） |
| 字号 | 24 号（第 279 行） |
| 颜色 | 没指定，默认 |
| 描边 / 圆角 | 没有（用的是 Godot 默认按钮样式） |
| 位置 | 面板 `x=240, y=140` ~ `x=1040, y=620` 内的最下面 |

> 小板这个按钮**和大屏那个长得完全不一样**（尺寸、字号、样式全不同）。玩家点完小板回主城，再被大屏挡住，看到的又是另一种样式的「返回主城」，会觉得是两件事。

## 三、点击后发生什么

### 3.1 点「返回主城」（大屏）

| 步 | 发生什么 | 耗时 | 代码 |
|---|---|---|---|
| ① | 把整个流程 UI 隐藏（`visible = false`） | 立即 | 第 1049 行 |
| ② | 内部记的「当前屏」改成主菜单 | 立即 | 第 1050 行 |
| ③ | 加载主城场景 `city.tscn` | 一次性加载，通常几十毫秒 | 第 1051 行 |
| ④ | 玩家看到主城 | — | 第 41 行常量 `FLOW_SCENE_CITY` |

### 3.2 点「回主菜单」（大屏）

| 步 | 发生什么 | 耗时 | 代码 |
|---|---|---|---|
| ① | 把整个流程 UI **显示出来**（`visible = true`） | 立即 | 第 1055 行 |
| ② | 切到主菜单屏 | 立即 | 第 1056 行 |
| ③ | 玩家看到主菜单 | — | — |

> **这里有个关键点**：结算屏属于「已经脱离开场景」的那层 UI（第 72~85 行把它挂到了最上层的 `FlowLayer`，层级 100）。点「返回主城」时只是把这层**隐藏**了，**没有销毁**。所以它能从主城上面再冒出来。

### 3.3 点「返回主城」（小板）

| 步 | 发生什么 | 代码 |
|---|---|---|
| ① | 直接切到主城场景 | `battle.gd` 第 284~285 行 |
| ② | 大屏那层 UI **仍然存在且仍然显示着结算内容**（因为它挂在最上层，切场景不影响它） | `flow_root.gd` 第 72~85 行 |
| ③ | 玩家看到：主城 + 上面压着一块大结算屏 | — |

### 3.4 完整的「点几次」实测推演

| 情形 | 玩家看到 | 要点几次才真正玩上主城 |
|---|---|---|
| **撤离成功**（甲、乙都弹） | 先小板「阵亡」，点掉 → 主城 + 大屏「撤离成功！」→ 再点掉 → 主城 | **2 次** |
| **阵亡**（只有乙弹，甲只在 `extract` 时触发，见 `battle.gd` 第 148 行） | 直接是主城？不 —— 大屏盖在战斗画面上，玩家点「返回主城」→ 主城 | **1 次** |

> **荒谬之处**：赢了要点两次，输了只需一次。**赢了的人反而更麻烦**，这是现在最刺眼的一处。

## 四、各种状态

| 状态 | 主按钮「返回主城」 | 次按钮「回主菜单」 |
|---|---|---|
| 常态 | 中灰底 + 金色描边 2px + 金字 | 中灰底 + 无描边 + 白字 |
| 悬停 | **没有任何变化**（`_make_button()` 只设了 `normal` 样式，第 264 行） | 同上，没变化 |
| 按下 | **没有任何变化**（没设 `pressed` / `hover` 样式） | 同上 |
| 禁用 | 从来没被禁用过 | 从来不 |
| 键盘 | **没设焦点，Tab 键可能能切到，但没有任何视觉提示** | 同上 |
| 鼠标指针 | 系统默认箭头（没设手指） | 同上 |

> **三条必须说清的实话**：
> 1. 按钮**悬停不变色**，玩家鼠标移上去分不清自己停在哪；
> 2. 按钮**按下没反馈**，点下去不知道有没有点上；
> 3. 两个按钮**都没有键盘快捷键**。

## 六、异常情况

| 情况 | 应该 | 现在 |
|---|---|---|
| 主城场景文件丢失 / 加载失败 | 不能黑屏卡死，要提示「主城加载失败，请重启」 | ❌ 没处理 |
| 玩家连点两下「返回主城」 | 只切一次场景 | 🟡 会连发两次 `change_scene_to_file`，第二次可能覆盖，通常不出事，但没保护 |
| 玩家点「返回主城」后再点「回主菜单」 | 不可能（已经换屏了） | ✅ |
| 玩家点「回主菜单」，再从主菜单点「开始游戏」 | 进主城，但「这局已经结束」的状态还在 | 🟡 **能进，但玩家会以为自己开了新的一局**。主城上的「上局战绩」还会显示刚才那局的数据 |
| 玩家点「回主菜单」后回到选关再打 | 可以，数据和结算已经落档 | ✅ 数据不会重复加（加钱发生在弹屏前，第 183 行） |
| 结算屏数据还没准备好就点了按钮 | 不应该发生（按钮和内容是同时出现的） | ✅ |
| 玩家在小板上点「返回主城」时，大屏还没建好 | 不应该发生（`_build_all_screens()` 在第 61 行一次性建完） | ✅ |
| 手柄 / 键盘玩家 | 应该能用方向键 + 回车选 | ❌ 没做 |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 让玩家点两次才回主城 | 现在真的要点两次（赢了的情况）。玩家会以为游戏卡了 |
| 在结算屏上同时给「返回主城」和「回主菜单」两个平级选择 | 玩家不知道该点哪个，会犹豫。结算完的路只有一条：回城 |
| 「回主菜单」点了以后直接进游戏 | 会跳过主城，玩家没地方看仓库、没地方升级 |
| 结算屏回主菜单以后，主城从来没被进过 | 流程上绕圈。玩家点了「开始游戏」，却不知道自己接的是新一局还是上一局 |
| 两个按钮长得一样重 | 现在就是这样：都中灰底。主按钮只有一圈金边 |
| 按钮悬停无反馈 | 玩家鼠标移过去不知道点没点上 |
| 返回主城时把结算数据清掉 | 主城要显示「上局战绩」，清了就没了 |
| 返回主城时重新算一遍钱 | 会重复加结晶。钱已经在第 183 行加过了 |
| 点按钮时播放长动画（超过 1.5 秒） | 玩家已经想玩下一局了，别拖 |
| 结算屏关了就把存档写一遍 | 存档已经在第 186 行 `commit` 过了，再写一次是浪费，还可能出错 |

## 八、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 输入 | 无（不依赖任何数据） |
| 输出 1 | 主城场景 `res://mods/jes-engine-core/scenes/city.tscn`（第 41 行常量） |
| 输出 2 | 主菜单屏 `screen-main`（第 1056 行） |
| 依赖 | 主城场景必须存在 |
| 前置 | 必须在结算屏上（`current_screen` 是 `screen-settle`） |
| 合法去向 | 流转表第 24 行：`"screen-settle": ["city", "screen-main"]` —— 只允许去这两个地方 |
| 和 `002-主城` 的关系 | 主城要接住「上局战绩」（`GameState.last_settlement`，`battle.gd` 第 243~246 行写入），显示在上局战绩区 |
| 和 `001-主菜单` 的关系 | 点「回主菜单」就等于绕回起点。**主城是必经的一环**（`001-主菜单` 总纲第五节写了「直接跳去选关不允许，必须经过主城」），而这里刚好开了个后门 |
| 和 `003-选关` 的关系 | 回主城后才能从传送门进选关。结算屏**不能**直接跳选关（流转表里没有） |
| 和 `005-战斗` 的关系 | 小板上的按钮归这里管，样式要统一 |
| 和 `007-退出` 的关系 | **在结算屏上直接退出游戏是安全的**：结晶已入账（第 186 行）、星级已写、关卡已解锁。`007` 的「关闭方式」要写清这一点 |
| 和存档的关系 | 本按钮**不写存档**，存档在更早的 `_apply_settle_to_meta()` 里已经写完 |

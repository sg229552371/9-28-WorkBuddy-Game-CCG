# B002-本局数据

> 父级：`006-结算`　｜　版本 v1.0　｜　2026-10-26
> 对应代码：`flow_root.gd` `_build_settle()` 第 1029~1033 行（数据行控件）、`_show_settle()` 第 1072~1077 行（填内容）
> 另一套：`battle.gd` `_show_death_settlement()` 第 263~275 行（六行数据）

---

## 一、这个功能是干什么的

**一句话**：把这局「杀了多少怪、花了多长时间、捡了几件东西」三件事并排摆出来，让玩家一眼看完就有数。

**为什么要摆出来**：玩家打完一局，心里有三个疑问 ——「我打得够不够狠」「我耗了多久」「我这趟有没有白跑」。这三个数一行说完，他接着看下面的钱和东西。

**太奶奶怎么理解**：就是体检报告上那三行数字：身高、体重、血压。不用看懂，看一眼心里有底。

**现在的问题一句话**：这行数字里，**「拾取 0 件」永远是 0**，因为战斗那边从来没告诉过结算屏捡了几件。

## 二、界面长什么样

### 2.1 大屏（`flow_root.gd`）

| 项目 | 规格 | 代码依据 |
|---|---|---|
| 元素名 | `SettleStats` | 第 1030 行 |
| 字号 | **没有单独设**，随全局默认（面板标题 30 号是单独设的，这行不是） | 第 1029~1033 行 |
| 颜色 | 正文骨白 `#e2e6ee` | 第 1031 行 |
| 换行 | 自动换行，按「词」断，智能模式 | 第 1032 行 `AUTOWRAP_WORD_SMART` |
| 对齐 | 靠左 | 竖排容器默认 |
| 一行文字格式 | `击杀 %d · 用时 %02d:%02d · 拾取 %d 件` | 第 1076~1077 行 |
| 分隔符 | 中间点「·」两边各一个空格 | 同上 |

**「%02d」是什么意思（大白话）**：数字不够两位就前面补 0。`6 分 42 秒` 写成 `06:42`，看起来整齐。太奶奶可以理解成「工整对齐」。

## 三、点击后发生什么

这一行不能点，但内容是被算出来的，把算的过程写清（时间单位是「同一帧」，实际耗时 < 1 毫秒）。

| 步 | 发生什么 | 在哪 |
|---|---|---|
| ① | 战斗侧 `_settle()` 把 `kills`、`time` 打进结算数据发出 | `combat.gd` 第 365~371 行 |
| ② | 结算屏接住，`_normalize_settle_payload()` 把 `time` 复制一份改名 `elapsed`（第 110~112 行），**原来的 `time` 还留着** | `flow_root.gd` 第 106~117 行 |
| ③ | `_show_settle()` 取 `elapsed` 秒数 | 第 1072 行 |
| ④ | 除以 60 取整得「分」（`floori`，向下取整），`int(elapsed) % 60` 得「秒」 | 第 1073~1074 行 |
| ⑤ | 取 `kills`、`pickups`，三个数拼成一行 | 第 1076~1077 行 |
| ⑥ | 贴到屏幕 | 同一帧 |

**没有动画、没有数字滚动、没有「叮」一下的音效。** 数字是直接出现的。

### 用时的例子（含边界）

| 实际用时 | 显示 | 好不好 |
|---|---|---|
| 0 秒 | `00:00` | ✅ |
| 42 秒 | `00:42` | ✅ |
| 6 分 42 秒 | `06:42` | ✅ |
| 59 分 59 秒 | `59:59` | ✅ |
| 1 小时 01 分 05 秒（3665 秒） | `61:05` | ❌ 应该显示 `1:01:05`，现在像个 61 分钟的超长局 |
| 负数（数据异常） | `-1:-1` 之类 | ❌ 没做保护 |
| 极大数（比如挂机 10 小时） | `600:00` | ❌ 一行会撑出去 |

> **太奶奶注意**：本关限时在 `cfg/levels.json` 里配了（第 1 关 180 秒），正常打不会超过一小时。但「无尽模式」`cfg/endless.json` 可以打很久，**一小时以上的情况是真会出现的**。

## 六、异常情况

| 情况 | 应该 | 现在 |
|---|---|---|
| `kills` 是负数或超大 | 夹到 0 ~ 合理上限 | ❌ 原样显示 |
| `elapsed` 是字符串（比如 `"123"`） | 能转换就转换 | ✅ `float()` 能转 |
| `elapsed` 不是数字（比如 `"abc"`） | 不能崩，按 0 处理 | 🟡 `float("abc")` 得 0.0，实际不崩，但**没日志**，出问题查不到 |
| 用时超过 1 小时 | 显示 `1:01:05` | ❌ 显示 `61:05` |
| 一行太长顶到右边 | 自动换行 | ✅ 已设自动换行（第 1032 行） |
| 拾取件数没数据 | 应该**不显示这一项**，而不是显示「拾取 0 件」骗人 | ❌ 永远显示 0 |
| 玩家看不懂「·」 | 分隔符要大一点、颜色淡一点 | 🟡 和文字同色同大小 |

> **「显示 0 件」和「没有这一项」是两回事**。玩家看到「拾取 0 件」会以为「我这局什么都没捡到」，实际可能是「系统不知道」。**宁可不说，也不能说错。**

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 数据没有就写 0 | 玩家会以为自己白捡了。宁可整项不显示 |
| 用时超过 60 分还写 `61:05` | 一眼看不出多长，像数字出错了 |
| 把小板的「波次 / 金币 / 经验 / 暴击 / 技能」和大屏的「用时 / 拾取」混成一行 | 一行塞七个数据，太奶奶根本读不完 |
| 显示内部编号（`SK001`、`H002`、`L003`） | 玩家不认识，要写中文名 |
| 用「:」以外的分隔（比如 `|` 或 `->`） | 「·」是中文阅读里最不打断的停顿符号，别的都硌眼 |
| 数字带小数（比如 `128.0`） | 本屏所有数字都是整数，带小数点显得是半成品 |
| 把击杀数写成「K/D」这种游戏黑话 | 太奶奶不看懂 |
| 用时做倒计时（`还剩 02:18`） | 结算屏是「已经结束」，不该再有倒计时 |

## 八、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 输入 1 | `kills`（整数）—— `combat.gd` 第 368 行 |
| 输入 2 | `time`（秒，浮点）—— `combat.gd` 第 369 行 |
| 输入 3 | `pickups`（整数）—— **当前无人提供，待战斗侧补** |
| 输出 | 无（纯展示，不改数据） |
| 依赖 | 结算数据的字段名兼容：`time` 和 `elapsed` 都认（第 110~112 行） |
| 前置 | 必须已经打完一局 |
| 下游 | `B003-结晶收益` 紧接下面，间距 10 像素 |
| 和 `005-战斗` 的关系 | 战斗 HUD 的「击杀进度」「波次」和这里说的**是同一批数**。战斗屏的计数要保证和结算屏对得上，不能一边说 37 一边说 35 |
| 和 `B004-战利品` 的关系 | 「拾取 5 件」是**数量**，「战利品」是**名字清单**。两者必须对得上：写 5 件就必须列 5 个名字 |
| 和 `003-选关` 的关系 | 关卡限时在 `cfg/levels.json` 的 `timeLimit` 里。以后如果想显示「限时 180 秒 / 用了 402 秒」，数据从那张表取 |
| 和 `007-退出` 的关系 | 无 |

| 问题 | 选项 |

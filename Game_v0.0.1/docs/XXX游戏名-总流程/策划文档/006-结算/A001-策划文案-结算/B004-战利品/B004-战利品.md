# B004-战利品

> 父级：`006-结算`　｜　版本 v1.0　｜　2026-10-26
> 对应代码：`flow_root.gd` `_build_settle()` 第 1038~1046 行（小标题 + 清单控件）、`_show_settle()` 第 1087~1095 行（填内容）

## 一、这个功能是干什么的

**一句话**：把这一局捡到的东西一件件列出来，让玩家确认「我这趟带回来了什么」。

**为什么要列出来**：这是玩家最在意的一块。结晶是个数字，看多了没感觉；「破损的铁盔」是实物，会让他想起「哦，这件是我在 B3 那个宝箱里翻出来的」。**清单是这一局的纪念品。**

**太奶奶怎么理解**：就像出门旅游回来，摊开行李给大家看：买了什么、带了几件。空着手回来也要说「什么都没带」。

**现在的问题一句话**：这块显示的是一句内部备注 ——「（战利品清单占位：待战斗侧接入）」。**玩家打开结算屏会看到一句写给程序员看的话。**

### 2.4 代码里那句占位文字长什么样

原文（第 1095 行）：

```
（战利品清单占位：待战斗侧接入）
```

| 问题 | 说明 |
|---|---|
| 全角括号 | 看起来像「备注」不像「内容」 |
| 「占位」两个字 | 这是内部行话，意思是「先放个假的」，玩家不该看到 |
| 「战斗侧」 | 指程序员那一侧，玩家完全不懂 |
| 「接入」 | 同上 |

> 这句话等于在游戏里贴了一张「此处未完成」的便条。**玩家看到会觉得游戏没做完。**

## 三、点击后发生什么

清单本身不能点（只能看），但玩家从看到清单到「东西进背包」这条线，得说清楚 —— 因为**现在这条线是断的**。

### 3.1 现在的真实情况

| 步 | 应该发生 | 实际发生 |
|---|---|---|
| ① | 战斗里捡到宝箱，东西进背包 | ✅ 装备进临时背包（`battle.gd` 第 121~122 行注释提到「宝箱拾取 → 装备入临时背包」） |
| ② | 结束时，战斗侧把这些东西整理成清单，发进结算数据 | ❌ **没做**，`combat.gd` 第 365~371 行只有五个字段 |
| ③ | 结算屏列出清单 | ❌ 显示占位文字 |
| ④ | 玩家点「返回主城」 | ✅ 切场景 |
| ⑤ | 东西存入主城仓库 | 🟡 存档 `_save_on_death()`（`battle.gd` 第 221~234 行）只存了英雄、技能水晶、金币、经验、最佳波次 —— **没有存装备** |

> **最严重的一条在 ⑤**：即使清单做出来了，存档里也没有「装备」这一项。也就是说，**这一局捡的装备，现在根本没有地方存**。清单做得再漂亮，回主城也找不到。

### 3.2 赢了和输了的差别（太奶奶定的口径）

| 结局 | 本局捡的东西 | 依据 |
|---|---|---|
| 撤离成功 | **全部带回，进主城仓库** | 太奶奶定的 |
| 阵亡 | **全部丢失，一件不留** | 太奶奶定的（`005-战斗` 总纲 定-1） |

> 所以这一块在赢和输的时候，**说的应该是完全相反的话**：

| 结局 | 「战利品」这一块应该写 |
|---|---|
| 赢了 | 列表 + 每件的名字（真实清单） |
| 输了 | 一行红字「本局捡到的 5 件全部丢失」+ 也许用灰字划掉清单（让人心疼） |

**现在的代码只做了一种情况**（列表或占位），输了也照样显示同一块，**没有任何「全丢了」的提示**。

## 六、异常情况

| 情况 | 应该 | 现在 |
|---|---|---|
| `loot` 是空数组 | 显示「这趟什么都没带回来」，**不能说占位** | ❌ 占位 |
| `loot` 里有空字符串 | 跳过空的 | ❌ 会连出两个「· ·」 |
| `loot` 里是字典（比如 `{name: "铁盔", quality: 3}`）而不是字符串 | 按 `str()` 转，会显示成一坨花括号 | ❌ 第 1092 行直接 `str(item)`，字典会显示成 `{ "name": "铁盔" }` 这样的机器话 |
| 清单有 100 件 | 不能无限往下长，要截断 + 「等 100 件」 | ❌ 有多少列多少，按钮会被顶出屏幕外（外面套的是可滚动容器，但玩家不会想到去滚） |
| 名字里有「·」 | 会和分隔符混在一起，看起来多了一件 | ❌ 没处理 |
| 名字超长（50 字） | 自动换行 | ✅ 已有 |
| 中文字体缺字 | 显示方块 | 🟡 依赖系统字体 |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 给玩家看「占位」「待接入」「TODO」这类内部词 | 等于在游戏里贴「没做完」。这是现在第 1095 行的真实状态 |
| 阵亡时还照常列清单，不说明东西没了 | 玩家会以为东西带回来了，回主城找不到再发火 |
| 只剩一句「战利品」却不列任何东西 | 空标题比没标题更让人困惑 |
| 用竖排长列表把所有东西列完 | 20 件东西竖着排会把按钮挤出屏幕，玩家找不到「返回主城」 |
| 每件前面加「-」或者编号 | 这不是报表，是纪念品清单 |
| 把数量写成「铁盔 ×1」 | 一件就是一件，写 ×1 显得像库存管理 |
| 用英文或者拼音写装备名 | 太奶奶看不懂 |
| 把战利品和结晶收益混成一行 | 一个是钱（会入账），一个是东西（要存仓库），两件事 |
| 打赢的清单里出现「金币」「经验」 | 那不是战利品，是资源，归 `B002`/`B003` |
| 清单里东西品质不同却全用同一个灰 | 玩家看不出哪件是宝 |

## 八、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 输入 1 | `loot`（数组）—— **当前无人提供** |
| 输入 2 | `won`（布尔）—— 赢了列清单，输了说明全丢 |
| 输出 | 无（纯展示） |
| 依赖 | 需要战斗侧把「本局拾取到的装备/物品」整理成字符串数组 |
| 前置 | 必须打完一局 |
| 下游 | `B005-返回主城` 的按钮紧跟后面，间距 10 像素 |
| 和 `B002-本局数据` 的关系 | `B002` 的「拾取 N 件」是**数量**，这里是**名字**。两边必须是同一批东西，数量必须对得上 |
| 和 `005-战斗` 的关系 | 战斗里 Tab 键背包（`bag_ui.gd`）装的是**临时背包**，本局的收获就在那里面。结算清单应该直接来自那个背包的内容 |
| 和 `002-主城` 的关系 | 赢了以后这些东西要进主城仓库。**存档里目前没有装备这一项**（`battle.gd` 第 225~234 行只存了英雄/技能/金币/经验/波次），这是要把这条线打通的最大障碍 |
| 和 `cfg/itemQualities.json` 的关系 | 物品品质颜色应该从这张表读，不要自己定色 |
| 和 `007-退出` 的关系 | 无 |

| 项目 | 状态 | 说明 |

| 实际内容 | ❌ 空壳 | 永远显示「（战利品清单占位：待战斗侧接入）」 |
| 战斗侧发 `loot` | ❌ 没有 | `combat.gd` 第 365~371 行没这个字段 |
| 阵亡「全丢」提示 | ❌ 没有 | 赢了输了显示一模一样 |
| 装备进仓库 | ❌ 没有 | 存档结构里没有装备项 |
| 品质分色 | ❌ 没有 | 全灰 |
| 清单过长截断 | ❌ 没有 | 有多少列多少 |
| 空清单文案 | ❌ 没有 | 走的是占位分支 |

**要补的（这是个链条，缺一环都不行）**

1. 战斗侧把临时背包的东西整理成名字数组，塞进结算数据的 `loot`；
2. 结算屏在**输了**的时候把这块换成「全部丢失」；
3. 存档结构里加一项「仓库里的装备」；
4. 清单太长时截断，加「等 N 件」；
5. 名字按品质分色。

> 第 3 条是根本。**仓库不打通，前两条做了也白做** —— 玩家在结算屏看到 5 件东西，回主城一件都找不到，比看到占位文字更让人失望。

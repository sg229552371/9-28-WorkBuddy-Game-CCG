## 一、这个功能是干什么的

**一句话**：告诉玩家「这一局赚了多少结晶」，这是他去局外升级的唯一收入。

**为什么要做好**：结晶是玩家重复玩这个游戏的唯一理由。一局打完，他要知道「再打多少局能变强」。这个数如果算错、说明不清，玩家会觉得「打了白打」，然后就不玩了。

**太奶奶怎么理解**：就是打工一天挣多少钱。挣的钱能拿去升装备（局外等级），局外等级最高 10 级（`cfg/outLevel.json` 第 2 行 `maxLevel=10`），升一级从 50 结晶起步（第 3 行 `costBase=50`），越往后越贵（第 4 行 `costStep=40`）。

**现在的问题一句话**：屏幕显示的是「结晶收益」，实际数的是**金币**（`combat.gd` 第 367 行注释原文 `PLACEHOLDER：结晶折算口径待 settleConvert 接入，暂用金币`）。而且输了以后那句「死亡仅保留 30%」，和太奶奶定的「死了丢光本局收获」是两回事，写在屏幕上会让人读错。

### 2.2 撤离成功时候的文字

统一格式（第 1084 行）：

```
本关评级 ★★☆ · 结晶收益 ◆37
```

| 部分 | 说明 |
|---|---|
| 「本关评级」 | 固定 4 个字 |
| 三颗星 | 1、2、3 颗星，实心按星级填，剩下空心的（第 1081~1083 行） |
| 「·」 | 分隔 |
| 「结晶收益」 | 固定 4 个字 |
| 「◆37」 | 结晶符号 + 数字 |

**星级怎么来的（真实情况）**

| 第  | 代码做什么 |
|---|---|
| 1 | 从结算数据里取 `stars`，没有就取 1（第 174 行 `get("stars", 1)`） |
| 2 | 显示时再夹一次，范围 0~3（第 1080 行 `clampi(..., 0, 3)`） |
| 3 | **谁都没有往结算数据里塞过 `stars`** —— `combat.gd` 第 365~371 行发的五个字段里没有它 |

> **结论：星级永远是 ★☆☆（1 星）。** 赢了是 1 星，打得再漂亮也是 1 星。这不是「待优化」，这是**空的**。

**三个星级长什么样**

| 星级 | 显示 | 现在的触发条件 |
|---|---|---|
| 0 星 | `☆☆☆` | 只有数据里写 0 才会出现，现在不可能 |
| 1 星 | `★☆☆` | **永远是这一档** |
| 2 星 | `★★☆` | 现在不可能 |
| 3 星 | `★★★` | 现在不可能 |

### 2.3 阵亡时候的文字

统一格式（第 1086 行）：

```
结晶收益 ◆6（死亡仅保留 30%%）
```

| 部分 | 说明 |
|---|---|
| 「结晶收益 ◆6」 | 和上面同格式 |
| 「（死亡仅保留 30%%）」 | 括号里一句解释。**注意代码里写的是两个百分号 `30%%`**，这是 Godot 字符串格式的转义写法，屏幕上会正常显示成 `30%`，只有一个 |
| **没有星级** | 输了就不评星级（第 1078 行 `if won:` 分支） |

**30% 是怎么算的**

| 步 | 代码 | 说明 |
|---|---|---|
| ① | 从 `cfg/outLevel.json` 读 `deathRatio`，缺省 0.3 | 第 178~181 行 |
| ② | 结晶 = 击杀数 × 0.3，**抹掉小数** | 第 182 行 |
| ③ | 加进存档，`commit` | 第 183~186 行 |

| 击杀数 | 算式 | 显示 |
|---|---|---|
| 0 | 0 × 0.3 = 0 | `◆0` |
| 3 | 0.9 → 抹掉小数 | `◆0` |
| 10 | 3.0 | `◆3` |
| 21 | 6.3 → 抹掉小数 | `◆6` |
| 37 | 11.1 → 抹掉小数 | `◆11` |

> **注意「抹掉小数」这条**：杀 3 只怪，写 `◆0`。玩家杀了几只怪却一分钱没拿到，会觉得系统吞了钱。见第十节第一个问题。

## 三、点击后发生什么

这一行不能点，但数字是**真的进了存档**的。完整顺序（同一帧内完成，实际 < 1 毫秒）：

| 步 | 发生什么 | 代码位置 |
|---|---|---|
| ① | 战斗侧发结算数据：`winner`、`shards`（金币）、`kills`、`time`、`level_id` | `combat.gd` 第 365~371 行 |
| ② | 结算屏复制一份数据存档用 | `flow_root.gd` 第 98 行 |
| ③ | 归一化：`shards` 改名成 `crystals`（如果本来没 `crystals`），**数值不动** | 第 113~114 行 |
| ④ | **赢了**：`crystal_gain` = 结算里的 `crystals`，没有就用击杀数 | 第 171 行 |
| ⑤ | **输了**：`crystal_gain` = `击杀数 × 0.3` 抹小数 | 第 177~182 行 |
| ⑥ | 调 `GameState.meta.add_crystals(结晶数)` | 第 183 行 |
| ⑦ | 把真数写回结算数据 `crystalGain`，标记 `won` | 第 184~185 行 |
| ⑧ | `GameState.meta.commit()` **立刻落档** | 第 186 行 |
| ⑨ | 切换到结算屏（这时候钱已经进账了，屏幕只是显示） | 第 101~102 行 |
| ⑩ | 屏幕读 `crystalGain` 拼字显示 | 第 1084、1086 行 |

> **关键理解**：屏幕上的数字是**「已经入账之后」的回顾**。即使玩家看到数字就立刻退出游戏，钱也已经存好了（第 186 行在显示之前）。这点是好的，不用改。

### 赢的时候还有两颗「隐形收益」

| 收益 | 代码 | 玩家看得见吗 |
|---|---|---|
| 星级写进存档 | 第 175 行 `set_level_stars()` | 看得见（就是那三颗星） |
| 解锁下一关 | 第 176 行 `unlock_level_to(level_index + 2)` | **看不见**。结算屏上完全没有「已解锁第 N 关」这句话 |

> 「解锁下一关」是打赢的最大奖励，玩家却要回到选关屏才知道。建议见第十节。

## 六、异常情况

| 情况 | 应该 | 现在 |
|---|---|---|
| `cfg/outLevel.json` 读不到或坏了 | 用缺省 0.3 继续 | ✅ 第 178~181 行已兜底 |
| `deathRatio` 被配成 0 | 死了给 0 结晶 | ✅ 会显示 `◆0`，不崩 |
| `deathRatio` 被配成 1 或更大 | 死了也和赢一样给钱，玩法就废了 | 🟡 代码不拦，谁改配置谁负责 |
| `deathRatio` 是负数 | 结晶变成负数，扣玩家的钱 | ❌ **没拦**。`add_crystals(-5)` 会把玩家存款扣掉，可能扣成负数 |
| 击杀数是浮点（比如 21.7） | 先取整再乘 | ✅ 第 182 行 `int(float(kills) * ratio)` 最后取整 |
| 赢了但 `crystals` 是负数 | 不能扣钱 | ❌ 没拦 |
| 赢了但 `crystals` 比击杀数大很多（比如 ◆99999） | 应有个上限，防作弊/防算错 | 🟡 **文件头注释说「若大于击杀数就用击杀数」，但第 171 行实际代码没有做这个比较**（只有 `get()` 的默认值），上限不存在 |

| 玩家在结算屏连点两下「返回主城」 | 不能加两次钱 | ✅ 加钱发生在弹屏之前，且结算事件有闸门（`combat.gd` 第 362 行） |

## 七、不许干的事

| ❌ | 为什么 |
|---|---|
| 显示「结晶收益」，实际给金币 | 名不副实。玩家以后发现「我明明 ◆500 多，怎么升不了一级」，就不信任这个游戏了。**这是现在最硬的一条隐患** |
| 死亡写「仅保留 30%」却让人以为捡到的东西保住三成 | 太奶奶定的是「本局收获全丢」。装备全丢、结晶给三成，是两件事，不能一句「保留 30%」糊在一起 |
| 输了也显示星级 | 输了就该没有评级，给星等于鼓励送死 |
| 星级永远 1 星还显示三颗星 | 玩家会琢磨「怎么才能 3 星」，结果发现怎么都上不去，更气 |
| 结晶数是负数还照扣 | 死了还能倒扣玩家的存款，玩家会骂街 |
| 数字带小数（`◆6.3`） | 结晶是不带零钱的整数金币 |
| 用 `$`、`￥` 之类货币符号 | 本游戏统一用 `◆` |
| 结算屏改成「+37」这种加号写法 | 要写「结晶收益 ◆37」，玩家才明白是「这一局赚的」，不是「总共有 37」 |
| 把总存款写在这行 | 这行只讲这一局。总共多少去主城看 |
| 赢了不给「解锁了下一关」的提示 | 这是最大的奖励，藏起来等于白菜价 |

## 八、和其他文档的约定

| 约定 | 内容 |
|---|---|
| 输入 1 | `won`（布尔）—— 决定走赢分支还是输分支（第 167 行） |
| 输入 2 | `kills`（整数）—— 输的时候算钱，赢的时候当兜底（第 168 行） |
| 输入 3 | `crystals`（整数，来源于 `shards`）—— 赢的时候直接拿来用（第 113~114、171 行） |
| 输入 4 | `stars`（整数 0~3）—— **当前无人提供** |
| 输出 | `crystalGain`（写回结算数据，第 184 行）+ 存档里的结晶总数 |
| 依赖配置 | `cfg/outLevel.json` 的 `deathRatio`；未来应该再加 `crystalKill`、`crystalBoss` |
| 前置 | 必须打完一局 |
| 下游 | `B004-战利品` 紧接下面，间距 10 像素 |
| 和 `combat.gd` 的关系 | 结算数据里 `shards` 这个字段名**语义是错的**（实际是金币）。要么改字段名，要么真按配置算结晶，两者选一个 |
| 和 `002-主城` 的关系 | 主城显示的是**总结晶数**。结算屏加多少，主城就该涨多少。两个数必须对得上 |
| 和 `003-选关` 的关系 | 赢了会解锁下一关（第 176 行）。选关屏的锁图标应该跟着打开 |
| 和 `005-战斗` 的关系 | 战斗 HUD 右上角显示「✦金币」，结算屏却把它叫「结晶」。**同一个数两个名字**，玩家会以为是两种钱 |
| 和 `007-退出` 的关系 | 结晶在弹屏之前就已经落档（第 186 行），**所以结算屏上直接退出不丢钱**。这点要在 `007` 里说清 |

## 十、太奶奶要定的事

| 问题 | 选项 |
|---|---|
| **一、杀得少的时候，要不要给个零头？** 现在杀 3 只怪，30% 算下来 `◆0`，一分不给 | (A) **不给就不给**，杀得太少本来就没资格拿钱（规则清楚）　(B) 至少给 1 颗，让玩家觉得没白杀（和气）　(C) 改成四舍五入，0.9 算 1 颗（公平，但数学上不严谨） |
| **二、星级按什么给？** 现在永远是 1 星 | (A) **按用时**：限时内完成 3 星，超一点 2 星，勉强过 1 星（好懂，玩家会想刷）　(B) 按挨打次数：一滴血没掉 3 星（硬核，割草玩家受苦）　(C) 按击杀数达标：杀够了就给（简单，但会鼓励刷怪不撤离）　(D) 暂时不给星，先在屏幕上留个空 |
| **三、死了到底丢多少？** 现在屏幕上写「保留 30%」，但太奶奶定的是「丢光本局收获」 | (A) **东西全丢、结晶给 30%**（现在代码这样，但文案要拆成两句说清）　(B) 东西全丢、结晶**一颗不给**（最狠，最符合「丢光」）　(C) 东西全丢、结晶给 50%（不那么心疼，但重复玩 15~25 局的节奏要重算） |

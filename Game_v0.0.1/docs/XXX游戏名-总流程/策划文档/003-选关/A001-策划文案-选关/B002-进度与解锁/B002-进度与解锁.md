## 一、这个功能是干什么的

**一句话**：管「99 个关卡怎么排、谁先能打、我打到哪了」——让玩家看明白自己是**爬楼梯爬到第几级**。

**为什么单独开一份**：卡片（B001）是「每一级台阶长什么样」，这一份是「整条楼梯怎么排、哪几级已经开放」。两者拆开，将来改「开放规则」（比如改成每 5 关解锁一次）只动这一份，不用碰卡片。

**对玩家的意义**：这类游戏最容易劝退的一件事，是玩家进来看到 99 关，全灰，不知道自己该干嘛。所以这一屏的第一任务不是「好看」，是**让玩家一眼找到那一张金边的卡**。

**和整款游戏的关系**：打死 Boss 算赢 → 赢了就解锁下一关 → 回主城 → 再从传送门进来。这一屏就是那个循环的「起点」。解锁规则错了，整条循环就断了。

## 三、点击后发生什么

这一份管的是「整屏怎么排、谁能点」，所以流程分两段写。

### 3.1 从主城进来（每次打开都要走一遍）

| 步骤 | 发生什么 | 玩家看到什么 | 耗时 |
|---|---|---|---|
| ① | 主城传送门站满 2 秒，通知「打开选关」 | 主城画面 | 2 秒（主城那边的事） |
| ② | 检查「是不是已经在选关/选人」——是的话直接放弃（第 150~151 行） | 没变化 | 0 |
| ③ | **清空上一次选好的队伍**（第 153 行） | 没变化（看不到） | 0 |
| ④ | 把整个界面显示出来 | 画面出现 | 立刻 |
| ⑤ | **重建 99 张关卡卡片**（先全删，再全建） | 卡片一张张出现，低配机器会顿一下 | 有明显卡顿风险 |
| ⑥ | 停在选关屏 | 看到「选择出发关卡」 | — |

### 3.2 判断「哪张卡是金的」

| 步骤 | 规则 |
|---|---|
| ① | 从存档拿「已解锁关卡数」，**没有记录时当作 1** |
| ② | 拿这个数跟 1 比，取大的那个（`max(1, 已解锁数)`，第 161 行） |
| ③ | 卡片在列表里的**序号从 0 开始数**，只要 **序号 < 这个数**，就是金色能打 |
| ④ | 其余全是灰的 |

**举例**（假设已解锁数是 3）：

| 卡片 | 序号 | 能不能打 |
|---|---|---|
| 第 1 关 | 0 | ✅ 能（0 < 3） |
| 第 2 关 | 1 | ✅ 能（1 < 3） |
| 第 3 关 | 2 | ✅ 能（2 < 3） |
| 第 4 关 | 3 | ❌ 不能（3 不小于 3） |

> **结论**：已解锁数 = 3，就是「第 1、2、3 关能打」。这个数**一次也没超过**当前能打的数量，绝不会出现「跳过第 3 关直接开第 4 关」。

### 3.3 滚动

| 步骤 | 发生什么 |
|---|---|
| ① | 手指/滚轮往上推 |
| ② | 滚动区内容向上挪，露出下面一排卡片 |
| ③ | 一直滚到第 33 排（最后一排只有 99 关的收尾），到底停下 |

99 关 ÷ 3 列 = **33 排整**。每排 96 高 + 间距 10 = 106，33 排大约 3400 像素高，而可视区只有 560 左右——**要滑很长的路**。

## 四、各种状态

### 4.1 解锁状态

| 状态 | 条件 | 卡片样子 |
|---|---|---|
| 刚开局 | 已解锁数 = 1（默认） | 只有第 1 关金边，后 98 张全灰 |
| 打通第 3 关 | 已解锁数 = 4 | 第 1~4 关金边 |
| 打通全部 | 已解锁数 ≥ 99 | 99 张全金边 |
| 存档数是 0 或坏的 | 代码按 1 算 | 第 1 关永远能打，不会全灰锁死 |

### 4.2 滚动条状态

| 状态 | 样子 |
|---|---|
| 内容一屏装得下 | 理论上滚动条不出现；但这里最小高 560、内容有 3400，所以**一定出现** |
| 拖到顶 | 显示第 1~15 关左右 |
| 拖到底 | 显示最后几关（第 99 关「神罚之眼 9」） |
| 滚动中 | 每张卡片都在内存里，滑到哪都立刻显示 |

### 4.3 「面板超屏」状态（现在的真实情况）

| 情况 | 结果 |
|---|---|
| 屏幕 720 高 | 面板要 760，多出 40，上下各切一截 |
| 玩家想找「返回主城」 | 按钮在面板最底下，可能在屏幕外，**找不到** |
| 玩家想找标题 | 标题在面板最上，可能被切掉一截 |

## 六、异常情况

| 情况 | 会怎么 | 玩家看到什么 | 应该怎么处理 |
|---|---|---|---|
| 关卡配置表读不到 | 打一句警告，一张卡都不建 | 空白滚动区，看着像坏了 | 显示「关卡数据读取失败」+ 一个「返回主城」按钮 |
| 配置表只有 0 条 | 同上，空白 | 空白 | 同上 |
| 存档里已解锁数被改成 999 | 99 张全解锁 | 全金边 | 不用管，不影响玩 |
| 存档里已解锁数是 -5 | 按 1 算 | 只有第 1 关能打 | 符合预期 |
| 面板高过屏幕 | **现在真的会发生** | 底部按钮被切 | 必须改成「面板最高不超过屏幕高」 |
| 99 张卡一次全建导致卡顿 | 打开瞬间顿一下 | 画面卡 0.2~1 秒（低配更久） | 改了分批建，或只建可见的一屏 |
| 玩家反复进出选关 | 每次都重建 99 张卡 | 每次顿一下 | 建议记住已建好的卡片，只在解锁数变了才重建 |
| 玩家在选关屏时，从别处又触发一次「打开选关」 | 第 150~151 行挡住，不重复弹 | 没变化 | ✅ 已经防住了 |

## 七、不许干的事

| ❌ 不许 | 为什么 |
|---|---|
| 面板高度超过屏幕（现在就是 760 > 720） | 底部按钮被切到屏幕外面，玩家退不出去，等于卡死 |
| 让玩家能跳过中间的关卡去打后面的 | 顺序解锁是整条循环的骨架，跳关会让「打死 Boss 才解锁下一关」的成就感全没 |
| 一进来就是灰色一片、一张能打的都没有 | 至少要保证第 1 关永远能打（代码已用 `max(1, …)` 兜底） |
| 打开时默认停在最上面 | 打到第 60 关的玩家每次都要滑半天，应该自动滚到「当前能打的那一关」附近 |
| 每次进出都重新建 99 张卡 | 关卡只会增加，越建越慢 |
| 副标题里写「星级」「奖励」但卡片上不给 | 承诺不兑现，玩家会觉得做得半截 |
| 左右也能滚动 | 3 列正好排满面板宽度，左右滚会让画面乱晃（代码已禁掉横向滚动，第 575 行） |

## 八、和其他文档的约定

| 项目 | 内容 |
|---|---|
| **输入** | 存档里的「已解锁关卡数」（没记录时按 1）；关卡配置表 `cfg/levels.json` 的 99 条 |
| **输出** | 屏幕当前显示的是「选关」；已解锁数只读，**选关屏自己不修改它** |
| **谁修改已解锁数** | `006-结算`：赢了才把已解锁数 +1（结算屏负责写存档） |
| **依赖** | 卡片（B001）按这里算出的「能不能打」上色 |
| **被谁依赖** | `004-选人` 不关心解锁，只关心「选了哪关」 |
| **和 `002-主城` 的约定** | 主城只负责叫这一屏出来，不传解锁信息 |
| **和 `005-战斗` 的约定** | 战斗不信「已解锁数」，它只按选中的关卡编号加载 |
| **和 `A002-UI层-SVG文档-选关` 的约定** | 面板 680×760 这个尺寸改了几何图都要重画 |

## 十、太奶奶要定的三件事

| 问题 | 选项 |
|---|---|
| **打开选关时，画面停在哪儿？** | (A) 永远从第 1 关开始　(B) 自动跳到「当前能打的最难关」附近（推荐）　(C) 记住玩家上次停在哪里 |
| **99 关怎么露出来？** | (A) 全露，滑到底（现在这样）　(B) 只露已解锁 + 后面 5 关，更远显示「???」　(C) 分章节，每 10 关一页 |

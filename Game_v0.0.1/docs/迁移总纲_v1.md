## 一、总原则（三条铁律）

1. **原型冻结，单向搬运**：HTML 版不再加新玩法，只修 bug；Godot 侧发现设计问题 → 回 decision_log 登记后再两边同步。
2. **数据先行**：先迁数据表（CFG → JSON），再迁逻辑；Godot 逻辑里禁止硬编码数值（沿用铁律 1）。
3. **每阶段门禁**：Godot 侧自建 headless 测试基线（对齐 `run_tests.sh` 口径：exit=0 且 bad=0），每阶段全绿才进下一阶段。

## 六、已知风险

1. **js 动态性 → GDScript 静态**：`vm.runInContext` 式动态装载、monkey-patch（rewards.js 包装结算）在 Godot 无等价物 → 改为信号/钩子模式，迁移时逐个登记改法。
2. **CFG 索引契约**：`CFG.heroes[i]` 物理序是全库隐性契约 → JSON 导出必须保序（数组不转字典键）。
3. **Canvas 渲染语义**：render.js 的绘制顺序/裁剪/降档逻辑是表现层，行为对齐但不逐行搬——验收以「同输入同画面要素」为准，不追求像素级一致。
4. **Web 导出限制**：Godot Web 导出包体与首屏加载大于 HTML 版；试玩链接策略（托管站 vs itch/Pages）待 P5 前拍板。

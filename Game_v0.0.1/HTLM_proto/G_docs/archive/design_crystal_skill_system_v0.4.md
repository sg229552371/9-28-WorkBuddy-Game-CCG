## 1. 确认规则

- 英雄初始一个自动技能，无额外普攻；局内可通过雕像获得一个稀有技能，玩家主要操作为走位。
- 两个技能属于一个共享辅助组；英雄四个共享水晶槽，开局全开。技能自身不占水晶槽。
- 水晶装入后本局不可卸载或替换。同定义重复获得升级，不新增槽。
- 每颗水晶对组内每个技能独立进行条件判定；两个技能都符合时，同时受益。
- 获取池只决定候选来源，不决定辅助归属。
- 槽满后排除所有未装新水晶，只出现可升级的已装水晶与其他合法奖励。
- 默认主效果触发事件水晶，派生效果不再触发；配置可明确开放有界联动，禁止无边界递归。
- 标签与摘要可以简化，但实际收益、代价、适用条件、互斥和限制必须在详情可查。
- 槽位及装配顺序不影响最终效果；每个技能只能拥有一种主运动形态。

## 2. 本版纠正的旧口径

删除“水晶只强化所属技能”。改为共享组内逐技能判定。

四槽限制内容数量，不保证输出和性能不会膨胀，多发、重复命中、派生数量仍需测试。

外部 Increased 同区加算不天然鼓励分散来源。按来源划分水晶 More 与外部 Increased 是本项目的简化约定，不应称为 POE 全部机制的精确复制。

品质是本项目稀有度和机制定位，不直接等同 POE 宝石 quality。

已有机制积木可用配置组合出新水晶；新底层能力仍需要新增通用执行器，禁止按具体水晶 ID 特判。

等级统一采用连续数组，等级上限等于数组长度；不混用表长与最大键。

## 3. 核心对象

技能定义描述自动施放、目标选择、主效果与参数。技能实例保存当前等级。
水晶定义描述适用条件、操作、成长、冲突与展示；实例保存定义 ID 和等级。
辅助组连接技能实例与四个水晶实例。获取池独立描述奖励来源和权重。
效果节点分别表示直击弹、小火球、爆炸、火场等，独立拥有标签和结算规则。

### 3.1 共享辅助示例

贯穿要求可贯穿的碰撞投射物：可辅助火球，不辅助没有该能力的雷链。
通用魔法强化匹配魔法伤害节点：火球与雷链均符合时，同一颗水晶同时强化两个技能。
扩域匹配范围半径节点：火球装爆破后形成爆炸节点，扩域可以辅助爆炸，但不扩大飞行火球碰撞体积。

### 3.2 满槽后获得稀有技能

新技能加入辅助组，已装水晶逐一重新判定。符合条件的水晶辅助新技能之后的施放；全部不符合时，新技能仍使用基础行为自动施放，不需要空水晶槽，也不增加第五槽。

## 4. 辅助编译与解释契约

标签负责语义分类，能力负责可执行性，不能仅凭“投射物”标签推断可贯穿、追踪或分裂。

构建阶段：
1. 创建技能基础效果图。
2. 应用主形态、数量等结构操作，创建派生节点。
3. 对完整效果图匹配范围、持续与伤害修改器。
4. 校验冲突、事件路由、深度、预算、重复命中和重叠规则。
5. 生成施放配置与辅助解释矩阵。

结构操作必须声明依赖阶段；禁止循环依赖和依赖自身添加的标签通过前置条件。同阶段数值操作使用明确的合并算子，不按槽位执行。

每颗水晶对每个技能输出：applied（至少一个合法操作）、inactive（无匹配对象）、conflict（互斥），同时给出实际节点、收益、失效操作及原因码。部分操作生效也必须逐项解释。

### 4.1 形态互斥

追踪与环绕竞争每技能的主运动形态，不能同时作用于同一技能。互斥默认按技能作用域判断，不默认全英雄互斥。

为防不可卸载后获得新技能制造冲突，建议装配时检查本局可获得技能集合的潜在形态冲突，发现即拒绝并解释；这是本版工程建议，须在实现前验证对构筑自由度的影响，不冒充已确认玩法。不得到获得技能时暗中关闭一颗水晶。

## 5. 装配、升级与快照

新水晶合法条件：有空槽；至少一个已拥有技能能受益；无互斥；配置有效。零收益组合不应作为可装奖励。

装配弹窗：
> 装配「贯穿」？装入后本局不可卸下或替换，只能升级。
> 当前适用：火球。当前不适用：雷链（缺少贯穿投射物能力）。
> 占用一个共享槽。【装配】【取消】

取消返回原奖励列表，不消耗奖励、不刷新随机结果。

同名合并以 crystalId 为准，不按显示名称判断。等级数组每项是该级完整状态，不默认累计增量。满级排除升级候选。升级可改变机制，但不得制造不可拆的新冲突。

一次施放锁定技能构建、施放者进攻数值与后续派生配置。升级只影响未来施放。敌方防御与受伤状态默认在命中时读取。已生成的火球和火场不被中途改写。

## 6. 合法奖励算法

合并已拥有技能获取池 → 按 crystalId 去重 → 区分新装/升级/满级 → 校验槽位、条件、冲突 → 按权重无放回抽取 → 用其他合法奖励补足 → 提交时再次校验。

槽满排除全部未装水晶。满级水晶不出现。所有已装水晶满级且没有合法新装路径时，水晶类别转为属性奖励等，不要求整个技能池所有水晶满级。

不足四个合法选项时优先补合法奖励；确实不足则显示实际数量，不伪造不可选项。权重合并策略与类别占比进入配置；重复出现于两个池的水晶不自动双倍权重。

水晶只来自升级选择，不进商店/宝箱。雕像获得稀有技能的概率、交互、选项数量仍待配置。英雄最多一个稀有技能，不用替换技能绕过水晶承诺。

## 7. 派生与有界联动

主效果：施放直接生成的效果，扇射每枚主火球都算主效果。
派生效果：命中或消失事件生成的小火球、爆炸、火场，属于原技能和原施放，不算新施法。

默认示例：主火球首次命中分裂，消失爆炸并留火场；小火球只造成自身伤害，不再分裂、爆破或留火场。直接适用的贯穿、范围和伤害强化仍可辅助相应派生节点。

有限联动示例：配置允许分裂小火球消失触发爆破，但不触发分裂或余焰；爆炸不再派生。必须声明来源白名单、接收操作白名单、最大深度、每事件次数、每施放预算、伤害基准与结束条件。不能用一个 allowDerived=true 无条件开启。

配置加载拒绝无终止条件的联动图，运行时预算兜底并记录诊断。火球八颗试点默认不开放有限联动，能力预留给后续明确等级配置。

事件包含 castId、effectInstanceId、parentId、originOperationId、目标、深度和消失原因。首次命中按每实例去重；消失每实例只触发一次。离局、场景清理与强制回收不触发战斗派生。

## 8. 数值与标签

基础伤害只有物理、魔法。火焰视觉不自动意味着火焰伤害类型；元素转换不在本版。

每个效果独立拥有标签：主火球/小火球=魔法、投射物；爆炸=魔法、范围；火场=魔法、范围、持续。技能面板汇总标签不能拿来给所有效果统一加成。

节点伤害 = 基准 × 声明的形态系数 × (1+匹配的外部 Increased 总和) × 适用水晶独立 More 乘数 × 暴击 × 命中时敌方修正。

水晶未声明伤害乘数时为1；数量、半径、速度和持续时间不自动进入伤害乘区。一个水晶的同一伤害规则不得在同节点重复计算。

派生从声明的基础节点取伤害基准，乘继承比例与明确继承的形态系数，再按自身标签应用一次加成；禁止复制已结算的主效果最终伤害再二次强化。

普通飞行弹每实例每敌人命中一次。环绕节点须配置每目标受伤间隔。直击与爆炸独立结算，爆炸可再次伤害直击目标。

持续区域按固定模拟间隔结算。建议同英雄同技能同类火场对每目标只保留最高一份有效持续伤害，区域独立计时；跨英雄/技能重叠作用域须显式配置，不隐含全局合并。

## 9. 火球八颗水晶机制定义

以下未拍板的细节为明确标注的试点建议；参数值待平衡表填入。
基础火球向有效敌人自动发射碰撞投射物，命中造成魔法直击后消失；贯穿可延后消失。无目标保持就绪。寿命/距离耗尽结束。

### 9.1 贯穿
条件：支持贯穿计数的碰撞投射物。
对象：主飞行火球及小火球，不影响范围节点。
时机：命中伤害后检查剩余额外贯穿次数。
参数：extraPierceCount，指首个敌人之外可继续命中的敌人数。
结束：贯穿耗尽后命中消失，或寿命/距离耗尽。
环绕主节点不使用贯穿；若分裂产生飞行小火球，贯穿仍对小火球生效。只有环绕且无适用派生时属于零收益，应过滤或拒绝该装配。
文案：可额外贯穿{extraPierceCount}名敌人；同一枚飞行火球不会重复命中同一敌人。

### 9.2 扇射
条件：主投射物生成器支持多发分布。
对象：只增加主效果数量，不增加每次分裂子体数。
时机：施放生成。
参数：mainCount、spreadAngle、mainDamageFactor。
建议：飞行形态按目标方向扇形分布；环绕形态通过配置适配为均匀环形分布。每枚主火球独立触发首次命中与消失事件。
结束：每枚按自身形态规则。
文案：每次产生{mainCount}枚主火球，单枚伤害系数为{mainDamageFactor}。

### 9.3 追踪
条件：可转向的飞行主投射物。
对象：主火球，小火球不默认追踪。
时机：移动更新。
参数：turnRate、retargetRadius、targetLostPolicy。
建议：目标失效时范围内重选，无目标沿当前方向飞行。
结束：贯穿耗尽、寿命/距离耗尽，不无限延长寿命。
互斥：环绕。
文案：主火球转向追踪目标，目标失效时尝试重新索敌。

### 9.4 分裂
条件：能发出合法首次命中事件的主投射物。
时机：每枚主火球首次命中伤害结算后。
对象：生成派生飞行小火球。
参数：childCount、spreadAngle、childSpeed、childLifetime、damageRatio。
建议：按父体命中前方向展开；环绕按接触点切线展开。子体预先记录生成处被击目标，避免出生即重复击中它。
父体是否继续由贯穿/形态决定。子体默认不触发事件水晶，可受贯穿。
结束：子体命中耗尽或寿命/距离耗尽。
文案：首次命中生成{childCount}枚小火球，小火球不会再次触发事件型水晶。

### 9.5 爆破
条件：主投射物支持带位置的消失事件。
时机：命中耗尽、寿命或距离结束，不含清理。
对象：派生圆形瞬时范围伤害。
参数：radius、damageRatio。
每爆炸对范围内每目标结算一次，允许再次伤害直击目标。
结束：结算完成。
文案：主火球消失时爆炸，对周围敌人造成魔法范围伤害。

### 9.6 余焰
条件与来源：同爆破。
对象：派生持续范围区域。
参数：radius、duration、tickInterval、damagePerTickRatio、stackPolicy。
建议：生成后经过一个完整伤害间隔首次结算，不额外添加瞬时伤害；同技能同类火场最高一份。
结束：时长耗尽或清理。
文案：主火球消失时留下火场，每{tickInterval}造成伤害，同类重叠不叠加。

### 9.7 扩域
条件：完整效果图存在可修改半径的范围节点。
对象：爆炸、火场，不修改碰撞体、扇角、环绕半径或索敌距离。
时机：效果图构建后修改参数，生成实例时读取快照。
参数：radiusMultiplier或radiusIncrease，必须选定算子。
无范围节点时不适用，不可当作基础火球的合法新装奖励。
结束：随对应节点结束，无独立实体。
文案：扩大本技能爆炸与火场的范围，不改变火球碰撞体积。

### 9.8 环绕
条件：主投射物生成器支持环绕运动适配。
对象：主火球，改为围绕施放者运动的接触攻击实体。
时机：施放创建后按环绕轨迹更新。
参数：orbitRadius、angularSpeed、duration、perTargetHitInterval、activeBatchPolicy。
建议：跟随施放者移动，固定存续时间；同技能只保留最新一批环绕主实体。替换旧批属于回收，不触发爆破/余焰；自然到期在当时位置可触发。此策略必须在详情说明，需试玩确认。
分裂仅每主实体首次合法接触触发一次。贯穿不改其接触间隔。追踪互斥。
结束：自然到期、明确批次替换或清理。
文案：主火球围绕角色运动，每个目标按独立间隔受伤；新一批替换旧批。

## 10. 组合例与边界

- 贯穿+扇射+分裂+追踪：多枚追踪主弹穿行，各首次命中分裂；子弹可贯穿但不追踪、不再分裂。
- 扇射+爆破+余焰+扩域：每主弹消失产生爆炸和火场，范围增强，重叠火场不简单叠加。
- 环绕+扇射+分裂+爆破：多枚环绕体接触攻击并各分裂一次，自然到期爆炸；替换回收不爆炸。
- 追踪+环绕：对同技能互斥，奖励生成时排除冲突。
- 扇射不等于范围伤害；“攻击多个目标”不自动追加范围标签。
- 同施放多枚弹能否集中击中同一目标须配置 hitPolicy；试点建议不同实例各可命中一次，需按单体输出验证。

## 11. 数据表与执行器契约

建议配置分表：skillDefs、effectTemplates、crystalDefs、qualityDefs、rewardPools、rewardPolicies、supportGroupRules、eventPolicies、migrationMaps、localization。

水晶不再使用单一 pool 或一个 effect 覆盖全部行为；使用条件+操作列表。

```js
{
  id: 'CR_PIERCE', nameKey: 'crystal.pierce', qualityId: 'Q_COMMON',
  eligibility: { requiredCapabilities: ['collisionProjectile'] },
  operations: [{
    operationId: 'pierceOp', executor: 'modifyPierce', phase: 'nodeModify',
    selector: { capabilitiesAll: ['pierceCounter'] },
    parameterRef: 'extraPierceCount', merge: 'add'
  }],
  levels: [
    { parameters: { extraPierceCount: 2 } },
    { parameters: { extraPierceCount: 3 } }
  ],
  presentation: { summaryTagVisibility: 'compact', detailsVisible: true }
}
```

示例数值仅说明结构，不是平衡定案。levels每项是完整等级参数；如需复用模板，加载时展开并验证。

操作字段必须包含：执行器、阶段、作用对象、参数引用、合并方式；事件操作还需事件名、来源、触发作用域、派生模板、基准引用和路由策略。

执行器注册表只认识 modifyPierce、spawnOnEvent、modifyRadius、setMotion 等通用能力，不认识具体技能/水晶名字。配置不能塞任意可执行脚本绕过校验。

参数统一单位：时间秒、角度度、距离项目世界单位、概率0~1、数量非负整数、倍率1为无变化。持续间隔必须大于0；数量与倍率范围由 schema 校验。

技能标签与效果标签分层；隐藏只影响展示。互斥用资源组和作用域，weakWith只是解释提示，不能替代真正适用校验。

### 11.1 数据校验

校验引用、重复ID、连续等级、必填参数、合法范围、未知执行器、操作依赖环、形态冲突、无界派生、模板占位符、品质引用与奖励可达性。

制作工具应提供辅助矩阵、合成效果预览、伤害来源树和事件追踪。新增组合无需修改测试框架，测试案例也可由表描述。

## 12. 品质、UI和文案

品质定义表管理名称、颜色、排序与权重；档数不限但UI必须有可读设计。水晶自身颜色语义与品质颜色分开，不靠颜色独自辨认内容。

高品质偏机制独特、条件明确，不等于无条件更强。低品质保留用途。

详情顺序：技能名称与基础描述 → 两技能辅助矩阵 → 四槽与等级 → 当前行为摘要 → 各效果节点标签/参数 → 触发与结束 → 冲突、无效和低收益解释。

水晶文案采用“作用对象+时机+变化+限制”。共享水晶列出每技能实际收益。隐藏不得遮蔽负面系数、零收益、互斥和递归限制。

文案尽量从配置参数与解释器结果生成，避免说明文字与运行逻辑两套规则。不得宣传不存在的联动。

## 13. 迁移与存档

moduleDefs迁移为crystalDefs；旧模块ID通过显式映射转为水晶ID。品质映射到品质表，槽数量维持四个，旧套装继续废弃。

存档保存schemaVersion、configVersion、技能实例、水晶实例、等级、奖励随机状态与必要运行状态，不保存无法恢复的代码对象。

旧9级不能直接映射到短等级表而丢失资产：需专门迁移规则或保留对应等级。缺失ID、冲突组合、超上限等级均输出迁移报告，不静默删除。运行中是否允许跨版本恢复需单独决定，不能默认热改已开始的局。

## 14. 验收清单

1. 一水晶同时辅助两个符合技能，只占一槽；不符合技能显示原因。
2. 水晶获取池归属不限制辅助；两池重复ID不重复抽取。
3. 槽满绝不出现未装新水晶；满级不出现升级。
4. 取消确认不消耗奖励或重抽；重复提交不能重复发奖。
5. 两技能无水晶仍可自动施放；满槽获得稀有技能正常生效。
6. 所有槽位排列与装配顺序输出相同效果图与数值。
7. 爆破创建节点后扩域可生效，未创建范围节点时扩域不装。
8. 子弹默认不再触发事件水晶；允许联动严格受白名单、深度和预算限制。
9. 首次命中与消失不重复触发，场景清理不爆炸。
10. 派生伤害不二次继承外部加成，投射物强化不误加爆炸。
11. 环绕受伤间隔、火场重叠与固定tick在不同帧率一致。
12. 升级不改已有对象；共享水晶更新两个技能的未来施放。
13. 隐藏不影响计算，详情能查所有收益、代价和限制。
14. 旧存档迁移有报告且不静默丢资产。
15. 测试单体、群体、贴身走位和最坏派生数量，记录对象数、事件数、帧耗时与实际输出。

## 15. 待填写与待试玩事项

数值待填：技能基准、冷却、八颗水晶完整等级参数、品质和奖励权重、雕像概率、预算与性能目标。

表现待补：颜色语义、图标、轨迹、爆炸与火场识别度。

明确需要试玩确认的建议：环绕批次替换规则、分裂出生目标排除、扇射同目标多实例命中、环绕扇射适配、前瞻形态冲突校验。上述建议不更改用户已确认的共享辅助、四槽不可卸载和有界联动铁律。

下一步应先对这些建议做少量样例验证，再填完整等级表与可执行配置，不先用大量硬编码技能分支实现。

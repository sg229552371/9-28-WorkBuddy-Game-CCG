## 1. 问题与取舍（回放 = 重新演算，不是录像）

14.9 承诺单机同输入、同种子逐次一致，却未给出可保存、可加载的回放格式。本补丁只补记录与验证协议，不修改运行时结算规则。

**回放是“重新演算”，不是“录像”：保存不可推导的初始条件与输入，其他状态由固定步长重算，以免重复保存造成体积膨胀。**

| 存什么 | 为什么必须存 |
|---|---|
| 格式版本、引擎规则版本、配置内容摘要 | 分别识别字段语义、执行规则、实际使用内容 |
| 逻辑 RNG 种子、固定步长、总 tick 数 | 重建随机流与逻辑时间轴 |
| 开局条件及逐 tick 逻辑输入 | 同一种子并不能推导玩家选择、局外属性与操作 |
| 终局校验和；可选周期校验点 | 校验结果、缩小偏离区间，不用于恢复运行状态 |
| 可选检索元数据 | 方便找回一局，但不决定重算结果 |

不存渲染帧、音视频、每 tick 全量快照、逐次 RNG 抽取结果或整局中间实例状态。检查点只存 tick 和摘要，不是可恢复存档。表现 RNG 的种子、状态、抽取序列均不进回放，也不进逻辑校验和；继续使用 14.6 的独立表现 RNG，服务 D-09 的确定性要求，不扩写 D-09 原文。

最小可重建集合必须闭合：除了用户指定的种子、输入、配置版本、引擎规则版本，还需一次性的开局条件。18.9 已要求局外固化“角色属性包”；只留角色名、当前等级或今日配置路径不够。回放保存当局固化包及实际开局选择，不重新读取今天的成长系统或云存档。由种子、配置确定性生成的场景和实例不重复保存。

## 2. 回放文件字段表

以下为独立的 Replay 容器，〔推荐默认〕采用 UTF-8 JSON；**不是技能 CFG**，不改 `_shared/10_冻结接口约定.md` 的七个 CFG 顶层键。表中“必填”只约束本草案格式，不表示已经冻结。

| 字段名 | 类型 | 单位/取值 | 必填 | 说明 |
|---|---|---|---|---|
| `schema_version` | string | 本草案 `"0.1"` | 是 | 回放 Schema 版本，不是 CFG Schema，也不是书稿版本 |
| `rules_version` | string | 不可变规则版本标识 | 是 | 指向本局实际采用的逻辑实现与规则集合；含 RNG 算法/种子解释、输入语义、初始化、步进与数值处理规则 |
| `config_digest` | string | `sha256:` + 64 位小写十六进制 | 是 | 本局完整逻辑配置闭包的内容摘要，覆盖技能、关卡、敌人、碰撞数据及影响逻辑的预算/开关等；不能只哈希技能表 |
| `config_version` | string | 人读版本标签 | 否 | 配置版本辅助定位；不能替代内容摘要，标签相同仍须验摘要 |
| `config_bundle` | object | 完整逻辑配置闭包 | 条件 | 无法保证按摘要取得原始配置时必须内嵌；可省略的前提是原始包按摘要不可变保存且可取回 |
| `seed` | string | 无符号十进制整数文本 | 是 | 逻辑 RNG 初始种子；字符串避免大整数精度损失，位宽及合法范围由规则版本约定；表现 RNG 不记录 |
| `ticks` | object | 时间轴描述 | 是 | 包含以下两个子字段 |
| `ticks.total` | integer | ≥0，推进次数 N | 是 | 执行输入 tick 为 `[0,N)`，最终边界为 N；不是渲染帧数 |
| `ticks.step_seconds` | object | `{numerator, denominator}`，均为正整数 | 是 | 固定逻辑步长的最简有理数，单位秒/tick；如 `1/60` 仅是示例，不在此冻结频率；必须与原规则/配置匹配 |
| `initial_context` | object | 第 0 tick 前的开局输入 | 是 | 只保存不可从 seed 与配置重建的开局条件，不保存已运行后的实例集合 |
| `initial_context.role_id` | string | 配置内角色标识 | 是 | 决定重建角色，不从检索元数据读取 |
| `initial_context.level_id` | string | 配置内关卡标识 | 是 | 决定重建关卡，不从检索元数据读取 |
| `initial_context.character_package` | object | 18.9 固化属性包 | 是 | 按上游正式字段/单位保存当局值；不自创等级公式，不把 L3 混进出手 `snapshot` |
| `initial_context.setup` | object | 经规则版本校验的开局选择 | 是 | 技能栏、已装备修饰器及其他不可推导开局条件；无额外选择时为 `{}`。初始 L2 效果与 L3 修饰器按各自来源保存并重建 |
| `inputs` | array<object> | 可为空 | 是 | 被逻辑入口接收的外部命令，不是执行结果；闭环拒绝/缓冲等结果仍由重算决定 |
| `inputs[].tick` | integer | `0 ≤ tick < N` | 是 | 在该 tick 的输入入口注入，早于闭环推进；不是操作发生的墙钟时间 |
| `inputs[].order` | integer | 同 tick 从 0 连续递增 | 是 | 明确同 tick 多条命令的接收顺序，与实例 `seq` 不混用 |
| `inputs[].actor_id` | string | 稳定逻辑实体标识 | 是 | 命令接收者；系统级命令的接收者由规则版本登记，不用内存地址 |
| `inputs[].op` | string | 规则版本支持的操作类型 | 是 | 例如移动方向变更、施放请求、局内升级选择、装备替换；这些仅是示意，不在此冻结操作枚举 |
| `inputs[].payload` | object | 按 op 校验 | 是 | 例如目标 `target_id`、逻辑方向/坐标、技能或选项标识；坐标系、单位、按下/释放及持续语义由该规则版本给定；无载荷为 `{}` |
| `checkpoints` | array<object> | 边界 tick 严格升序 | 否 | 周期校验点；可省略或为空，间隔由录制方选择，不冻结周期 |
| `checkpoints[].tick` | integer | `0 ≤ tick ≤ N` | 是（存在项时） | 表示已完成 tick 数；0 为初始化完成，k 为执行输入 tick `k-1` 并完成回收之后 |
| `checkpoints[].digest` | string | `sha256:` + 64 位小写十六进制 | 是（存在项时） | 截至该边界的逻辑累计校验和，算法见第3节；不是状态快照 |
| `final_digest` | string | 同上 | 是 | 边界 N 的累计校验和；若检查点含 N，两者必须一致；N=0 时校验初始化 |
| `metadata` | object | 检索信息 | 否 | 整块不参与初始化、输入解释或逻辑哈希 |
| `metadata.recorded_at` | string | ISO 8601，含时区 | 否 | 录制时间，不作为逻辑时间源 |
| `metadata.role` | string | 展示名称/标签 | 否 | 只作检索；与 `initial_context.role_id` 职责不同 |
| `metadata.level` | string | 展示名称/标签 | 否 | 只作检索；不能决定加载关卡 |

**版本三元组不可合并：** Schema 变了，字段语义可能变；规则版本变了，同配置也可能算出不同结果；配置摘要变了，输入的内容已经变。三者分别校验，书稿版本或一个“游戏版本号”不能替代。

输入按 `(tick, order)` 严格递增保存；拒绝重复顺序、越界 tick、未知 op 及不合法载荷，不静默丢弃。持有方向只记录变更还是每 tick 记录，必须遵守所绑定 op 的语义，不能由播放器猜。自动索敌、命中、派生、死亡是运算结果，不当作输入再注入。任何运行时无法从既有条件推导的外部逻辑变化，都须成为有 tick 的输入；墙钟时间、实时局外属性、表现层回调不能成为隐含输入。

## 3. 校验和定义

### 3.1 逻辑状态投影与采样边界

在初始化完成的边界 0，以及每 tick 全部逻辑处理与回收完成后的边界取样。按适用的既有运行时规则推进，不在本补丁重排内部阶段。

| 纳入逻辑状态投影 | 排除 |
|---|---|
| 角色/目标稳定标识、位置、速度、生命、护盾、死亡/免疫标记、层数与状态截止时间 | 渲染插值位置、动画帧、粒子、拖尾、音频、镜头、伤害数字、UI |
| 活动实例及待参与判定的派生实例；身份、`seq`、来源、宿主、位置、剩余寿命、`snapshot`、有效 `params`、命中规则与计数 | 对象地址、渲染节点 ID、无语义的容器遍历顺序 |
| 闭环相位、冷却/定时器、输入缓冲、逻辑输入保持状态、尚待处理的队列与游标 | 墙钟、录制时间、渲染帧率、调试输出文本 |
| 逻辑 RNG 当前状态、下一创建序号/ID 分配器、候选接触与重命中登记、家族登记、被动冷却及预算占用 | 表现 RNG、纯统计缓存、可从上述字段无损推导且不影响未来的缓存 |
| 逻辑结算累计计数、终局结果及后续逻辑仍会读取的结算记录/消费位置 | 已消费且无逻辑作用的完整历史日志 |

原则是覆盖“会影响后续逻辑或最终结果的状态”，而不是只取几个方便读取的字段。具体投影字段须随规则版本登记；漏掉 RNG 状态、队列或接触登记，可能把尚未显现的偏离误判为一致。投影只用于即时算摘要，不逐 tick 写入回放文件。

### 3.2 规范化与哈希

〔推荐默认〕本回放 Schema 使用 SHA-256。先对逻辑投影做规范化：

1. 无序的目标集合按稳定 `target_id` 排序，实例集合按数值 `seq` 排序；登记表按其完整稳定复合键排序。标识的类型及比较规则由绑定版本规定，不以加载顺序重新分配标识。
2. 对象字段按键名排序；集合与映射转为稳定键序列。**有语义的数组不可随意排序**：FIFO 保留出队顺序，`parts[]` 保留 `part_index` 顺序。若队列以其他容器存放，按其稳定入队顺序号还原后再编码。
3. 规范字节编码使用带类型与长度的值编码：字符串为 UTF-8，整数为规范十进制文本，布尔/null 为固定标记，数组记录长度；浮点用固定字节序的 binary64 位串表示，统一负零为正零，拒绝 NaN/无穷。字段缺失与 null 不等价。编码方案属于回放 Schema，不靠宿主语言默认 JSON 打印格式计算摘要。
4. 配置摘要对完整逻辑配置闭包使用同一规范编码后哈希；资源引用须绑定内容摘要，不能仅用可被覆盖的文件路径。元数据、纯表现配置不入摘要；影响碰撞等逻辑的资源仍须纳入。

为避免“中途偏离后状态重新汇合”漏检，〔推荐默认〕校验点存**累计逻辑链摘要**，而不只存采样时瞬时状态：

```text
S_k = 边界 k 的规范化逻辑状态字节
H_0 = SHA256(encode(["R6.logic.initial.v1", 0, S_0]))
H_k = SHA256(encode(["R6.logic.step.v1", k, H_(k-1), S_k]))，k ≥ 1
checkpoints[i].digest = H_(checkpoints[i].tick)
final_digest = H_N
```

哈希链只覆盖逻辑投影、逻辑 tick 和前项摘要，不加入渲染字段或检索信息。每 tick 可流式计算后丢弃投影，文件仅保留选定校验点及终局摘要。摘要不是防篡改签名；一致性判断沿用常规哈希碰撞可忽略的工程前提。

### 3.3 偏离定位与二分的限制

先比较已保存的 `checkpoints[]`，用二分查找找出首个不一致的检查点 C 及前一个一致检查点 P；若运行尚未生成被测摘要，就从 0 重算到相应边界，不能把检查点当存档恢复。累计链使中途偏离不会因后来状态相同而消失，支持该前缀比较。

**稀疏检查点只能把首个偏离缩小到 `(P,C]`，不能凭两个哈希推出区间内的期望状态。** 若没有检查点，用已验证初态与 N 形成粗区间；初始化也无法核对时，报告区间包含边界 0。

若可取得录制时的可信参考运行环境及原始输入/配置，参考端和被测端从 0 重算，在区间中点比较累计摘要，反复二分至相邻边界，才可报告首个偏离边界 k（对应首个偏离输入 tick `k-1`；初始化偏离为边界 0）。不能把被测实现重算出的摘要当作“期望值”。无可信参考时，只报告“首次发现偏离的检查点”和可能区间，不谎称精确定位。

此处精确哈希仅作同受支持执行环境的诊断。14.9 的位置比较容差与平局定序仍在逻辑中生效；不得为了哈希擅自给全部浮点量化、修改判定容差，亦不得据跨平台哈希差异直接判定逻辑 bug。

## 4. 重放流程

1. **加载**：解析回放，检查必填字段、数值范围、输入顺序、校验点范围及摘要格式；读取元数据只能用于检索展示。
2. **校验版本三元组**：确认支持该回放 `schema_version`；选择完全匹配的 `rules_version`；取得原始配置闭包并重算 `config_digest`。同时核对固定步长和开局载荷。任一不满足则停止比较，不以当前配置补空缺。
3. **重建边界 0**：以 `seed` 初始化逻辑 RNG，使用原配置与 `initial_context` 创建初态；只读固化角色属性包，按 18.9 分层还原初始修饰器/状态，不读取实时局外数据。计算 H₀，有边界 0 检查点时立即比对。
4. **逐 tick 注入**：对 t=0…N−1，按 `order` 注入该 tick 的全部 inputs，再交给原有闭环及输入缓冲处理。无命令的 tick 也必须推进，不伪造重复输入。
5. **推进完整逻辑步**：按原规则版本执行完整 tick，不受播放快慢或渲染帧率影响；在回收后的边界 t+1 计算 H，并比对该边界检查点。
6. **完成比对**：到边界 N 比对 `final_digest`。无任何不一致时报告“版本与配置匹配，已记录的逻辑校验通过”；这不是视频画面一致承诺。
7. **报告偏离**：发生摘要不一致时保存检查点边界 tick、期望值、实际值、三元组及前一个一致边界，按3.3定位。报告必须区分“首个偏离已定位”与“仅定位区间”；取得可信参考后再补精确 tick。版本/依赖不兼容是另一类报告，不冒充执行偏离。

## 5. 版本兼容与三个边界

### 5.1 版本不匹配怎么办

- `rules_version` 不一致时禁止静默重放，必须显式报告：**“规则已变更，结果不可比”**。只有拿到匹配规则实现后才进入正式比较；不得把不能比较称作回放失败的 bug。
- 不支持的 `schema_version` 拒绝解释。不在此定义隐式迁移；将来若提供迁移，须明确其支持范围与来源，不能把改过的字段直接沿用旧终局摘要。
- `config_digest` 不匹配或原始包缺失，报告“原配置不匹配/不可取得，结果不可比”。不能套用34.1中普通运行时的 CFG 降级策略去替换旧回放配置，因为那不再是同一输入条件。
- 规则版本与配置相同仍不承诺跨平台位级一致。变更执行环境须先确认比较资格；本草案不额外冻结平台清单。

### 5.2 中途读档怎么办

基线回放始终从第 0 tick 起算；用户在局中读取存档，不等于可以截掉此前输入后仍称作完整重建。**本 v0.1 不提供从中途快照起播的编码格式**，避免把可选优化变成必做项。

若后续允许快照起播，须另行评审可选扩展：快照声明所属回放、版本三元组、边界 tick、快照自身的内容校验和，且 **快照不含输入序列**；输入仍来自完整回放文件。恢复所需逻辑状态必须完整，包含 RNG、计时器、稳定标识分配器、队列和计数。还须验证快照与可信原回放该边界状态一致；仅“文件哈希正确”不证明它属于正确时间线。继续累计校验需要可信 H_k，不能从快照内容伪造此前链历史。

这里的恢复快照不是18.9的出手属性 `snapshot`：后者仅为实例取值结构，不能恢复一局。若实际读档会改变原时间线，读档分支的记录方式列为未决，本版不声称支持该完整局型。

### 5.3 回放与联机的关系

本格式只服务14.9的**单机回放、自动测试、复盘**。不提供联机同步，不定义锁步、回滚、网络输入交换或观战协议；不得把本地稳定 tick、输入序列、校验和解释为支持联机。

## 6. 不做什么

- 不定义录像编码或压缩算法，不保存画面/音频。
- 不定义 UI 回放控件、播放手感、观战功能或性能验收指标。
- 不定义网络同步设计，不扩张14.9边界。
- 不承诺跨平台位级一致，不改14.9的容差与稳定标识定序口径。
- 不重新设计 RNG 算法、技能操作枚举、角色成长公式或局外属性来源。
- 不新增或改动 AC；现有83条保持不动。本草案流程与诊断说明不另行编号为 AC。
- 不修改14条已确认决策，不改 `events: [hit, vanish]`、`carriers: [none, self, independent, attached]` 或其他已冻结词表。

# 对外接口定义与使用说明（v1.0，2026-10-18 第四轮）

> **性质变更（2026-10-18 用户指示）**：本文件原为《跨系统接口清单》（列"对方必须补什么"），现改为**只站在技能系统一方**的对外接口定义与使用说明——**我们给出接口、契约、错误码与用法，对方系统自行适配；我们不关心对方内部实现，也不为对方的适配负责**。
> **文件名保留** `跨系统接口清单_v0.3.md` 仅为维持主书稿既有引用（D-92 等），内容以本版为准。
> **约定**：所有接口以"调用方 → 技能系统"或"技能系统 → 调用方"标注方向；字段名与主书稿 36.4/附录 B 一致；`tick` 为绝对 tick（固定步长，D-09）。

## 0. 责任边界（先说清什么不归我们管）

| 事项 | 归属 |
|---|---|
| 接口定义、字段语义、错误码、调用时机、幂等性、示例 | **技能系统（本文件）** |
| 何时调用、数据从哪来、失败后怎么提示玩家、UI 怎么排布 | 调用方 |
| 局外成长/背包/装配的数值与规则 | 调用方 |
| 技能系统内部如何用这些数据（合并、快照、预算） | 技能系统（主书稿） |

**一句话**：我们只接受符合本文件契约的输入；不符合的输入一律拒绝并返回错误码，不做"猜你想要什么"的兼容。

## IF-1　修饰器集合装载（load / replace / unload）

**方向**：调用方 → 技能系统

| 项 | 内容 |
|---|---|
| 用途 | 把"这个持有者当前生效的修饰器集合"交给技能系统；技能系统据此计算技能字段的当前值 |
| 输入 | `holder_id`（必填）、`set_id`（必填，调用方生成，唯一）、`modifiers[]`（必填，可为空数组=卸载全部） |
| `modifiers[]` 每项 | `modifier_id`、`permission`（`mutate_number`/`add_behavior`/`mutate_live_instance`）、`scope`、`inheritable`、`targets[]`、`stack_rule`、`params{}` |
| 输出 | 成功：`{ok:true, applied_tick, effective_set_id}`；失败：`{ok:false, errors:[{code, modifier_id, field, detail}]}`（**整批拒绝，不做部分应用**） |
| 调用时机 | 任意 tick 的**边界**（该 tick 任何出手之前）；同一 tick 多次调用以最后一次为准 |
| 幂等性 | 以 `set_id` 幂等：同一 `set_id` 重复提交直接返回上次结果，不重复计算 |
| 生效范围 | 只影响**之后生成**的实例；已生成实例与已结算内容不变（D-91/D-105） |
| 我们不做 | 不校验物品是否存在、不读背包、不判断该不该给；只校验字段白名单与权限矩阵 |

**错误码**：`E_FIELD_NOT_WHITELISTED`（字段不在设计卡暴露声明内）、`E_PERMISSION`（权限档不允许该操作）、`E_NOT_LIVE`（对非 live 字段做实时修改）、`E_UNKNOWN_MODIFIER`、`E_STACK_RULE`

**示例**
```json
// 请求
{"holder_id":"p1","set_id":"eq_20261018_01","modifiers":[
  {"modifier_id":"crystal_flame","permission":"mutate_number","scope":"own_skill",
   "inheritable":false,"targets":["bolt.damage"],"stack_rule":"add","params":{"value":8}}]}
// 响应（成功）
{"ok":true,"applied_tick":1200,"effective_set_id":"eq_20261018_01"}
// 响应（失败，整批拒绝）
{"ok":false,"errors":[{"code":"E_FIELD_NOT_WHITELISTED","modifier_id":"crystal_flame","field":"bolt.max_chain_depth"}]}
```

## IF-2　装配操作请求（战斗中换水晶/遗物）

**方向**：调用方 → 技能系统

| 项 | 内容 |
|---|---|
| 用途 | 请求卸下/替换某个装配槽；技能系统负责**公共冷却**与生效边界 |
| 输入 | `holder_id`、`slot`（`crystal`/`relic`/未来新槽）、`op`（`unequip`/`replace`）、`item_id`（replace 时必填） |
| 输出 | 成功：`{ok:true, applied_tick, cooldown_until_tick}`；拒绝：`{ok:false, code, remaining_ticks}` |
| 公共冷却 | 任一槽操作成功后，**所有装配槽**进入同一公共冷却（D-105）；冷却期内的请求一律拒绝，不排队 |
| 冷却时长 | 由 CFG 给（`assembly_cooldown_ticks`），数值待手感调试 |
| 生效范围 | 同 IF-1：旧修饰器对之后生成的实例失效；已生成实例与已结算不变 |
| 我们不做 | 不判断玩家是否拥有该物品、不做背包 UI、不决定"能不能在战斗外换"（战斗外调用同样走本接口，冷却可配置为 0） |

**错误码**：`E_ASSEMBLY_COOLDOWN`、`E_UNKNOWN_SLOT`、`E_NO_ITEM`、`E_SLOT_LOCKED`（该槽在本次战斗中已锁定，如 Boss 机制）

**示例**
```json
{"holder_id":"p1","slot":"relic","op":"replace","item_id":"relic_soul_burst"}
// → {"ok":false,"code":"E_ASSEMBLY_COOLDOWN","remaining_ticks":84}
```

## IF-3　角色属性包注入（战斗开始）

**方向**：调用方 → 技能系统

| 项 | 内容 |
|---|---|
| 用途 | 战斗开始时固化"这个角色此刻的属性"，作为 `snapshot` 的 L0–L2 来源（D-92/18.9） |
| 输入 | `holder_id`、`attribute_bundle{ fields... }`、`bundle_id` |
| 字段 | 见主书稿 18.9 与附录 B `snapshot_fields`（攻击、暴击、暴击伤害、治疗强度、冷却缩减、范围加成…）；**未列字段一律拒绝** |
| 输出 | `{ok:true, bundle_id, accepted_fields[]}` 或 `{ok:false, code, field}` |
| 调用时机 | 战斗初始化阶段，**首次出手之前**；战斗中不可再次注入（保证 D-09 确定性） |
| 我们不做 | 不计算等级曲线、不读存档、不管局外加成怎么来；只要最终数字 |

**错误码**：`E_BUNDLE_TOO_LATE`（战斗已开始）、`E_FIELD_UNKNOWN`

## IF-4　输入序列递交（按键 → 施放）

**方向**：调用方 → 技能系统

| 项 | 内容 |
|---|---|
| 用途 | 把玩家的施放意图按 tick 递交；**缓冲由调用方（输入层）负责**，技能系统不持有队列（D-93） |
| 输入 | `{tick, actor_id, action, target_hint?}`，每 tick 可多条，按递交顺序处理 |
| 输出 | 无返回值（fire-and-forget）；是否真的进入索敌/前摇属于技能系统内部结果，调用方可从 `cast_started` 结算记录观察 |
| 时机要求 | `tick` 必须是当前 tick 或下一 tick；**迟到 tick 一律丢弃**（不补帧、不插队） |
| 缓冲约定 | 位移/眩晕/沉默期间的按键由输入层缓冲（推荐 10–15 tick），窗口内状态恢复后**在恢复的那个 tick 递交一次**；过期丢弃 |
| 我们不做 | 不做输入缓冲、不做按键映射、不做"手感补偿" |

**错误码**：`E_STALE_INPUT`（tick 过期，静默丢弃，只日志）

## IF-5　表现流（只读订阅）

**方向**：技能系统 → 调用方

| 项 | 内容 |
|---|---|
| 可订阅 | `hit`（事件）、`hit_settled`（结算记录）；两者均为只读快照，订阅方**不得回写** |
| 不可订阅 | `debug_record`（`budget_drop`/`proc_blocked`/`gen_limit`）——**正式 UI 与任何游戏逻辑层禁用**，仅调试面板/性能工具可读（D-94） |
| `hit` 载荷 | 来源实例、目标、`parts[]{part_index,type,evaded,final_amount}`、`crit_flag`、`origin_skill`、`chain_depth` |
| `hit_settled` 载荷 | 同上份级 `parts[]`（6.4/21.2 已补）+ `total`、`killed`；`total` 为**吸收前**伤害（D-96） |
| 数字合并 | 合并只作用于显示，结算不变；同目标同类型窗口 3 tick（示例）；P4 数字可丢但**合计显示必须保留**（15.7） |
| 我们不做 | 不做飘字动画、不做 UI 排布、不做音效触发规则 |

**错误码**：`E_READONLY`（订阅方试图写回）

---

## IF-6　只读查询（供 HUD / 调试面板）

**方向**：调用方 → 技能系统

| 查询 | 返回 |
|---|---|
| `get_instance_stats()` | 当前各分级实例数（P0–P4）、预算状态（正常/紧张/丢弃中） |
| `get_cooldown(holder_id, skill_id)` | 剩余 tick、起算点（末次实际出手） |
| `get_effective_fields(holder_id, skill_id)` | 合并后的当前字段值与来源（基准/修饰器/角色属性） |

**约定**：查询**纯只读、无副作用**、不改变 RNG、不影响结算；可在任意 tick 调用。**错误码**：`E_UNKNOWN_ACTOR`

---

## IF-7　确定性与回放（种子 + 输入序列）

| 项 | 内容 |
|---|---|
| 输入 | 战斗初始化：`seed`（必填）、`tick_rate`（默认 60）；回放：`seed` + 逐 tick 输入序列 |
| 保证 | **同平台、同种子、同输入序列** → 逐次一致（D-09）；跨平台浮点不保证 |
| 输出 | 可选 `state_hash(tick)`，用于自动比对 |
| 我们不做 | 不做联网同步、不做服务器校验 |

## 附录：错误码总表

| 码 | 含义 | 调用方可做的处理 |
|---|---|---|
| `E_FIELD_NOT_WHITELISTED` | 字段不在设计卡暴露声明内 | 修数据，不要重试 |
| `E_PERMISSION` | 权限档不允许该操作 | 修数据 |
| `E_NOT_LIVE` | 对非 live 字段做实时修改 | 改为非实时路径 |
| `E_UNKNOWN_MODIFIER` / `E_UNKNOWN_SLOT` / `E_NO_ITEM` | 标识不存在 | 修数据或提示玩家 |
| `E_ASSEMBLY_COOLDOWN` | 装配公共冷却中 | 读 `remaining_ticks` 后提示，**不要自动重试** |
| `E_SLOT_LOCKED` | 该槽被机制锁定 | 提示玩家 |
| `E_BUNDLE_TOO_LATE` | 属性包注入过晚 | 修流程（初始化阶段注入） |
| `E_FIELD_UNKNOWN` | 属性包含未登记字段 | 修数据 |
| `E_STALE_INPUT` | 输入 tick 过期 | 静默丢弃，记日志 |
| `E_READONLY` | 订阅方写回表现流 | 修实现 |
| `E_UNKNOWN_ACTOR` | 查询了不存在的持有者 | 修数据 |

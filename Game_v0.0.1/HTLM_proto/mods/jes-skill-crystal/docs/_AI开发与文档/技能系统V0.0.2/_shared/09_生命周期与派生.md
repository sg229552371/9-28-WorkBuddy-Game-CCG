# 第5章　效果体生命周期

> **一句话结论**：每个实例独立走"生成 → 存活／运动 → hit 0..N → 终止 → vanish（带原因码）→ 派生 → 回收"；它不是一条每步只发生一次的线；瞬时实例的寿命为 0，在同一 tick 内完成 hit 与 vanish（`instant_end`）。〔D-01 已确认〕

## 5.1 效果体是容器

效果体是承载一段战斗行为的容器，不是某一个事件。一个炮弹实例可以：生成后飞行、飞行中命中、命中后继续穿透、再命中两次、飞行距离耗尽后终止并发出 `vanish`、由 `vanish` 派生火区、最后回收；也可以全程零命中，到终点正常结束。

## 5.2 生命周期总览

| 步 | 名称 | 是事件吗 | 次数 | 说明 |
|---|---|---|---|---|
| 1 | 生成 | 否 | 恰好 1 | 实例开始存在，分配 `instance_id`、`seq`，记录 `spawn_tick`；一次出手可生成 0 到 N 个实例 |
| 2 | 存活／运动 | 否 | 持续 | 飞行、静止、环绕、回旋、追踪、波前扩张、沿路径移动、等待开始等；"计时到点""波前到位"是内部状态，**不是事件** |
| 3 | hit | **是** | 0 到 N | 一次接触中至少一份未被闪避（含非伤害份，见 22.2/33A）时成立，且只发一条〔2026-10-18 终审修正〕（词表见第6章） |
| 4 | 终止 | 否 | 至多 1 | 状态进入 `terminating`，并确定原因码 |
| 5 | vanish | **是** | 0 或 1 | 自然终止必发，带原因码；`purge` 不发〔D-01 已确认〕 |
| 6 | 派生 | 否（由 hit 或 vanish 驱动） | 0 到 N | 创建子实例，`parent_ref` 指向本实例 |
| 7 | 回收 | 否 | 恰好 1 | 状态变为 `gone`，释放预算 |

不是"每一步只发生一次"的线：

- hit 可以发生零次，也可以发生多次；
- hit 发生在终止之前，且可派生子实例而父实例继续存活；
- 终止不一定发 vanish（`purge`）；vanish 也不保证有派生；
- 回收不是事件。

## 5.3 状态机

`state` 只有三个值：`live`、`terminating`、`gone`。

| 转换 | 触发 | 在此期间允许 | 状态 |
|---|---|---|---|
| 创建 → `live` | 出手或派生 | 运动、产生 hit | — |
| `live` → `terminating` | 自然终止（任一非 purge 原因码） | **只**处理 vanish 发出与派生；不再产生新 hit，不再运动 | 〔D-15 推荐默认〕 |
| `terminating` → `gone` | vanish 派生处理完毕 | 释放预算 | 〔D-15 推荐默认〕 |
| `live` → `gone` | `purge` | 无；不发 vanish、不派生、不补 hit | 〔D-01 已确认〕 |

规则：

1. **每个实例至多发出一条 vanish**；`terminating` 状态下不会再次进入终止。〔D-15 推荐默认〕
2. 需要读取父实例信息的派生，必须在 `gone` 之前完成（"先派生后回收"）。〔D-15 推荐默认〕
3. `terminating` 状态的实例不再被命中检测选中，也不再产生 hit。〔D-15 推荐默认〕

## 5.4 instance 字段表

下表字段即契约词表，不得另造字段名。示例数值仅为说明。

| 字段 | 取值／类型 | 确定时机 | 含义 | 运行中是否可变 |
|---|---|---|---|---|
| `instance_id` | 唯一标识 | 生成 | 实例唯一编号 | 否 |
| `seq` | 创建序号 | 生成 | 全局创建先后；同 tick 内排队与 FIFO 的依据（第14章） | 否 |
| `skill_id` | 技能编号 | 生成 | 所属技能 | 否 |
| `carrier` | `none` ／ `self` ／ `independent` ／ `attached` | 生成 | 载体类型；`none` 即瞬时实例（第8章）；`attached` 见 8.5A〔2026-10-18 终审修正〕 | 否 |
| `caster_id` | 施法者编号 | 生成 | 谁施放（召唤物独立闭环，其 `caster_id` 为召唤物自身，见第22章） | 否 |
| `generation` | 整数，根为 0 | 生成 | 派生代数 | 否 |
| `parent_ref` | 实例引用或空 | 生成 | 指向父实例；根实例为空 | 否 |
| `origin` | 来源链标记 | 生成 | 含 `origin_skill`、`origin_cast_id`、`chain_depth`、`proc_mask`；细则第20章 | 否（派生时按第20章规则继承） |
| `spawn_tick` | tick 编号 | 生成 | 生成发生的 tick | 否 |
| `lifetime_ticks` | 整数 | 生成 | 预定寿命；**瞬时实例为 0**；无限期实例用技能声明的上限（见第15章预算） | 默认否；修改走第18章 |
| `snapshot` | 属性快照 | 出手瞬间 | 出手时施法者属性的快照；语义细则第18章 | 否 |
| `params` | 参数集 | 生成 | 生成时确定的实例级参数（半径、速度、数量等；示例） | 视权限；第17、18章 |
| `hit_policy` | 见下 | 生成 | 重复命中规则 | 默认否 |
| `state` | `live` ／ `terminating` ／ `gone` | 随生命周期 | 当前状态 | 由系统转换 |

`hit_policy` 子字段：`per_target_limit`（默认 1）、`rehit_interval_ticks`（可选）、`max_hits`（可选）。默认每实例每目标 1 次，火区、环绕、穿透必须显式声明。（计次按候选接触，细则见第14章；此处只引用冻结词表）

补充规则：

1. 位移状态本身不是实例；它的**跟随判定体**才是实例（`carrier = self`）。位移状态是施法者的运动状态，不占 `instance_id`。〔D-18 推荐默认〕
2. `generation` 只数派生（根为 0）。`chain_depth` 另见第20章：每次派生与被动触发各 +1，故 `chain_depth ≥ generation`。〔D-17a 推荐默认〕

## 5.5 瞬时实例：寿命为 0

瞬时实例是寿命为 0 的效果体：它在被创建的那个 tick 内，依次完成"生成 → hit 0..N → 终止 → vanish（`instant_end`）→ 派生 → 回收"，没有跨 tick 的存活期。〔D-01 已确认〕

| 规则 | 内容 | 状态 |
|---|---|---|
| 5.5-1 | `lifetime_ticks = 0`，`carrier = none` | 〔D-01 已确认〕 |
| 5.5-2 | 同一 tick 内，先对范围内目标逐个产生 hit（每目标至多一条，沿用 `per_target_limit` 默认 1），**然后**发 `vanish`，原因码 `instant_end` | 〔D-01 已确认；先 hit 后 vanish 的次序为 D-16a 推荐默认〕 |
| 5.5-3 | 瞬时扇形、瞬时圆形爆炸、瞬时射线都是瞬时实例，**不是"没有实例的特例"** | 〔D-01 已确认〕 |
| 5.5-4 | 零命中的瞬时实例（范围内没有目标，或所有份被闪避）仍发 `vanish(instant_end)` | 〔D-16a 推荐默认〕 |
| 5.5-5 | 瞬时实例的 `instant_end` 默认**允许** vanish 派生（"挥砍结束后生成残影爆炸"是合法写法） | 〔契约表：是〕 |
| 5.5-6 | 瞬时实例派生出的子实例是**新实例**，进入本 tick 的创建队列，按 `seq` 先后处理；是否在同一 tick 内完成由其寿命决定，派生代数与预算仍受第20章限制 | 〔D-16a 推荐默认〕 |
| 5.5-7 | 瞬时实例不能被"打断"：它没有可被打断的存活期（打断只作用于出手之前的前摇） | 〔D-16a 推荐默认〕 |

> 对照（外部事实 E4，Unreal GAS 的 Gameplay Effects）：Instant 类效果称为 Executed，不进入"激活容器"；本书的瞬时实例与之类似——创建即结算，不长期驻留。仅作类比，不是实现依据。

## 5.6 存活与运动

存活与运动可以是：飞行、等待开始、静止滞留、环绕、回旋、追踪、波前扩张、半径变化、沿路径移动、等待某个时间后进入可命中状态。"运动"不意味着向前飞；静止火区同样是独立载体的存活过程。

规则：

1. 存活期间的内部状态变化（计时到点、波前到位、延迟结束）**不是事件**，不能被其他规则订阅；它们要么改变实例自身行为，要么触发终止并发出 `vanish`。〔D-01 已确认〕
2. 运动方式属于判定维度还是表现维度，见第9章；本章只规定"存活"与"终止"的语义。

## 5.7 hit 与寿命的关系

命中是瞬时的 `hit`，发生在生命周期内部。命中后可能：结束当前实例（`hit_end`）、继续运动、修改当前实例目标、由 `hit` 派生新实例、以后对同一目标再次命中。这些都必须由技能声明，不得仅凭"命中"二字自动推导。〔D-14b 推荐默认〕

## 5.8 常见误写 → 正确写法

| 常见误写 | 正确写法 |
|---|---|
| "瞬时扇形没有实例，直接结算" | 瞬时扇形是寿命为 0 的瞬时实例，同 tick 内 hit 后发 `vanish(instant_end)`〔D-01〕 |
| "炮弹命中后消失，所以必须命中才能产生火区" | 火区由 `vanish` 派生，可挂 `landed` 或 `hit_end`；零命中落地也可以派生〔第7章〕 |
| "实例终止后再发 hit 补一次" | 终止后不再产生 hit〔D-15〕 |
| "清场时给所有实例补一个 vanish" | `purge` 不发 vanish、不派生、不补 hit〔D-01〕 |
| "冲刺的位移状态也是一个实例" | 位移状态不是实例；只有它的跟随判定体是实例〔D-18〕 |

# 第11章　一次命中的逐份结算

> 一句话结论：先对每一份逐份判闪避，未闪避的份再逐份算减免；全部闪避则没有 hit，任一份未闪避则恰好一条 hit，减免到 0 仍是 hit。无敌等于“伤害份视为闪避”（非伤害份见 11.4/D-104），免疫某类型等于“该份减免到 0”。暴击、格挡与数字叠加顺序在本章只设入口，细节见第26章候选。

## 11.1 结算顺序

对一次候选接触（某实例 × 某目标 × 某 tick）的每一份伤害，按以下顺序处理〔D-24 推荐默认；沿用 v0.1 既定顺序〕：

```text
候选接触 → 读取伤害份列表（来自实例 params / snapshot）
  步骤 1　目标是否无敌？是 → 所有份 evaded=true（见 11.4）
  步骤 2　逐份判闪避（使用注入 RNG，见 14.6）：evaded = true / false
  步骤 3　对每个 evaded=false 的份：计算 final_amount（含适用减免，见 11.5 入口）
  步骤 4　汇总
      ├─ 所有份 evaded=true  → 本次未命中，不产生 hit
      └─ 至少一份 evaded=false → 产生恰好一条 hit
```

步骤 2 与步骤 3 的顺序固定：先判闪避、再算减免，不能反过来（反过来会浪费计算，并让“闪避后仍扣减”之类歧义出现）。

## 11.2 hit 与载荷

hit 成立时载荷字段（契约冻结）：

| 字段 | 含义 |
|---|---|
| `source_instance` | 产生接触的实例 |
| `target_id` | 被命中目标 |
| `parts[]` | 每份：`part_index`、`evaded`、`type`、`final_amount` |
| `any_reduced_to_zero` | 是否存在未闪避但 `final_amount` 为 0 的份（2026-10-18 第二轮，U-2/D-96：`final_amount` 是步骤 3 减免后的值；护盾吸收发生在其后，**不**使其变为 0，因此护盾吸收到 0 不算 `reduced`，不置位本字段） |
| `killed` | 本 hit 结算后目标是否死亡 |
| `tick`、`seq` | 发生的 tick 与事件序号（14.3） |

被闪避的份保留在 `parts[]` 中且 `evaded=true`、`final_amount=0`，供表现层显示“闪避”字样，不影响“只一条 hit”。

## 11.3 部分闪避案例

一次接触含三份：

| 伤害份 | 闪避结果 | 处理 | 本次结果 |
|---|---|---|---|
| A | 闪避 | 跳过，`final_amount=0` | 不单独产生 hit |
| B | 未闪避 | 算伤害与减免 | 同一条 hit |
| C | 未闪避 | 算伤害与减免 | 同一条 hit |

结论：一条 hit，不是两条。若 A、B、C 全闪避：没有 hit，不执行由该 hit 驱动的派生，但记录 `evaded_all`（结算记录，非事件，见第6章）。

## 11.4 无敌与免疫（D-05 已确认）

| 情形 | 规则 | hit 是否成立 | 编号 |
|---|---|---|---|
| 目标无敌 | **伤害份**视为闪避（`evaded=true`），无需调用 RNG；非伤害份照常，除非带对应免疫标记（11.4/D-104） | 否；记录 `evaded_all`（仅当所有份都被闪避） | 〔D-05 已确认；2026-10-18 第四轮加限定〕 |
| 目标免疫某伤害类型 | 该类型的份**不是**闪避；减免到 0，`final_amount=0` | 是（只要有一份未闪避）；`any_reduced_to_zero=true` | 〔D-05 已确认〕 |
| 全部份都是被免疫类型 | 全部未闪避、全部减到 0 | 是，仍是一条 hit，驱动命中规则 | 〔D-05 已确认〕 |

由此得到的直接后果（保持一致、供验收用）〔D-25 推荐默认〕：

1. 无敌目标不会触发“命中才生效”的派生；免疫目标会。
2. 无敌时逐份闪避不消耗 RNG 抽取（具体抽取顺序见 14.6）。无敌目标的这次接触仍是一次**候选接触**（14.7），同样计入 `per_target_limit` 与 rehit 计时；因此无敌/全闪避之后，同一实例不会在下一 tick 对同一目标重新判定。这是防止“逐 tick 重掷闪避直到打中”的关键，见 14.6、14.7。〔D-25/R2 推荐默认〕
3. 无敌是目标状态，在步骤 1 读取一次；同一 tick 内状态变化不回溯已结算的 hit（见 14.3 FIFO）。

**无敌不豁免有益效果（2026-10-18 第二轮，D-90 已确认用户拍板；以交叉引用方式补充 D-05，D-05 原文不变）：** 上表“全部份视为闪避”只作用于**伤害份**（D-05 的语义：无敌 = 伤害被闪避）。治疗份、增益、有益修饰器对无敌目标**照常生效**，不因无敌被闪避。“不可选取”是**独立标记**，只有它阻止指向性效果（索敌与指向性施放）；无敌本身不带“不可选取”。有害的非伤害份（控制、击退、减益等）对无敌目标**照常生效，除非目标带有该份类型对应的免疫标记**（2026-10-18 第三轮，D-104 已确认：份级免疫是数据驱动配置，无敌不隐含任何非伤害免疫，策划在技能/状态配置里勾选什么免疫标记就有什么效果）；免疫标记=该份减免为 0（D-05 口径），hit 是否成立按各份定义；见 22.7、22.10，字段名 `immune_flags` 建议随下次小修补入 18.9 snapshot 词表。外部佐证见附录 D 的 E9、E8。

## 11.5 暴击、格挡与数字叠加：只设入口

下列机制尚未拍板，**本章不决定**，只规定它们在流程中的位置，细节见第26章候选方案：

| 机制 | 入口位置 | 状态 |
|---|---|---|
| 暴击 | 步骤 3 内部（未闪避份之后） | 按份还是按整条 hit：见第26章候选 |
| 格挡 | 步骤 3 内部 | 同上 |
| 百分比减免叠加顺序 | 步骤 3 内部 | 见第26章候选 |
| 护甲/吸血参与顺序 | 步骤 3 之后 | 见第26章候选 |
| 护盾吸收（2026-10-18 第二轮，D-96 推荐默认） | 减免之后、扣血之前，是结算链的一步 | 吸收不改变 hit 成立、`final_amount`、`any_reduced_to_zero`；`hit_settled.total` 为吸收前，`damage_taken.total` 为吸收后实际扣血（与 22.4 同口径） |
| 内部精度与显示取整 | 步骤 3 输出 | 见第26章候选 |
| 伤害数字显示合计还是分份 | 表现层 | 见第26章候选；合并显示的预算口径见 15.6 |

后续 AI 不得因“闪避已逐份”就推出暴击、格挡也必须逐份〔D-26 推荐默认〕。

## 11.6 命中规则不随份数复制

一条 hit 内有三份，不代表命中分裂三次、施加状态三次、播放音效三次、派生子弹三批。由“一条 hit”驱动的规则**执行一次**；一条规则内部可声明生成多个子实例，但不得因伤害份数自动复制规则〔D-23 推荐默认〕。

## 11.7 同 tick 多条接触的顺序

同一目标在同一 tick 被多个实例接触，逐条按 `seq`（实例创建序号）稳定排序结算，详见 14.3；已死亡目标不再产生后续 hit（14.5）。

## 常见误写→正确写法

| 常见误写 | 正确写法 |
|---|---|
| "闪避了两份，所以有两条 hit" | 闪避份不产生 hit；其余未闪避份合成一条 |
| "被免疫了就等于没打中" | 免疫=减免到 0，hit 仍成立（D-05）；想要“免疫则不触发”须在派生条件里写 `any_reduced_to_zero` 判断（第26章前不拍板具体条件） |
| "无敌=伤害为 0 的 hit" | 无敌=**伤害份**视为闪避，无伤害 hit；非伤害份（控制/击退/减益）照常生效，除非目标带对应免疫标记（D-05、D-104；2026-10-18 第四轮修正旧写法"全部份视为闪避"） |
| "三份伤害触发三次吸血" | 一条 hit，吸血规则按其归属执行一次，具体口径见第26章 |

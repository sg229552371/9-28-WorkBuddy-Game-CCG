# 10　冻结接口约定（跨章接线，WorkBuddy 冻结，执笔不得更改格式）

> **为什么有这份文件**：多个章节由不同执笔并行写作，但第 4/5/9/13 章之间存在依赖。
> 为让它们能真正并行，WorkBuddy 在此**预先冻结各章产出的登记格式与命名规范**。
> 执笔**必须**用本文件给定的字段名与结构书写，使下游章节无需等待上游即可开工。
> 若你认为某格式确实不合理：照此写，并在章节末尾「未决问题」提出，由评审裁决。

## 一、积木登记格式（第 4 章产出 → 第 5 章、T1 表消费）

第 4 章每一块积木**必须**用以下 12 行登记卡，一块一卡，不得增删字段：

```yaml
brick_id:        # 字符串，snake_case，全局唯一，如 projectile_bolt
name:            # 中文名，如「直线飞弹」
tagline:         # 一句话（≤30字）说明它做什么
carrier:         # 四类载体之一：none | self | independent | attached
                # 〔评审裁决 C04-01，2026-10-18〕以主书稿 8.1 终审修正表为准。
                # 注意："instant"（瞬时实例）是 none 载体的语义描述词，不是枚举值。
                # 四类分别对应：none=寿命0瞬时实例 / self=位移状态+跟随判定体 /
                #               independent=独立运行实例 / attached=附着宿主的有寿命效果体
summary:         # 3-5 句说明：它产生什么效果体、如何命中、典型用法
default_cfg:     # 默认 CFG 片段（YAML 块），可直接被运行时读取
author_params:   # 作者可填参数列表（字段名 → 见下方「参数登记格式」）
locked_params:   # 锁死参数列表（字段名 + 锁死理由），作者不可改
relic_params:    # 水晶/遗物可改参数（字段名 → 权限档位：可改|可加|禁止）
presentation:    # 表现层需求（引用第 9 章表现配置段的 key，见第三节）
player_text:     # 玩家文字三句（见主书稿 23.2）
status:          # 已登记 | 候选 | 预留
```

**积木候选来源**（执笔须逐一评估，能归的归类，归不下的登记为 `候选` 并说明缺什么载体能力）：

| 来源 | 内容 |
|---|---|
| 主书稿第 8 章 | 四类载体与其建模方式 |
| 主书稿 22.x | 治疗 / 护盾 / 增益 / 减益 / 召唤 / 击退 / 控制 七类非伤害模板 |
| 主书稿案例章 | 重型火炮(27)、双脉冲射击(28)、突进冲刺(29)、裂变长矛(30)、扇形斩(31)、大地回响(32)、亡魂连爆(33)、庇护祷言(33A)、震地冲击(33B) |
| 上游设计文档 | `02_上游设计文档/hero_roster_design_v1.md`（12 角色技能线索） |

**红线**：积木数量**不固定**，不得写死"共 N 块"。新增走登记流程，章节末尾必须给出「积木扩展登记流程」。

## 二、参数登记格式（第 5 章产出 → T3 表消费）

第 5 章每个参数**必须**登记以下 9 列（对应需求文档 24.2 八栏 + 单位）：

| 列 | 说明 |
|---|---|
| 字段名 | snake_case，与 CFG Schema 路径一致 |
| 类型 | int / float / bool / enum / string / ref / array |
| 默认值 | 具体值或 `—`（无默认） |
| 取值范围 | 闭区间 / 枚举集合 / 引用目标 |
| 单位 | tick / 秒 / 像素 / 百分比 / 无量纲 / — |
| 必填 | 是 / 否 |
| 分级 | 新手 / 进阶 / 专家（新手默认可见，专家需展开） |
| 所属积木 | 该参数属于哪块积木（`*` 表示通用） |
| Schema 路径 | 该字段在 CFG Schema 中的完整路径，供 T3 表直接引用 |

## 三、表现层配置段格式（第 9 章产出 → 第 10 章、T2 表消费）

第 9 章必须给出表现配置的**七类**分节，每类一个配置段，段名固定：

| 段名 key | 覆盖范围 | 完成判定硬指标 |
|---|---|---|
| `fx` | 特效（生成/持续/消失，绑定效果体生命周期） | 必须能挂到 effect body 的 spawn / tick / vanish 三个时点 |
| `sfx` | 音效（触发时点、优先级、并发上限） | 必须给出并发上限字段 |
| `anim` | 动画（施法者动作、出手帧对齐） | 必须给出「逻辑出手 tick ↔ 动画帧」对齐字段 |
| `trail` | 拖尾（跟随载体、寿命、淡出） | 必须区分 independent / self / none 三类载体（见裁决 C04-01） |
| `camera` | 镜头（震屏/推拉，仅表现，不得影响逻辑） | 必须显式声明不影响逻辑 |
| `damage_number` | 伤害数字（合并规则、闪避/免疫/击杀显示） | 必须对齐主书稿 15.7 合并规则 |
| `status_icon` | 状态图标（增益/减益/控制的显示与堆叠） | 必须对齐主书稿 22.5 / 22.8 |

**硬约束**：表现配置**只读** `hit` / `hit_settled`，不得反向影响逻辑（铁律 8）。

## 四、技能 ID 命名规范（第 13 章产出 → 全书统一使用）

```
<role>_<category>_<name>[_<variant>]
```
- `role`：角色标识，如 `pyro`；通用/非角色技能用 `common`
- `category`：`active`（技能石=主动技能）/ `passive` / `crystal` / `relic`
- `name`：snake_case 短名
- `variant`：可选，变体序号或标签

示例：`pyro_active_flame_lance`、`common_crystal_split`、`relic_soul_chain`

**组织维度**（第 13 章必须能支撑）：12 角色 × 每角色多技能 × 水晶池的索引与检索。

## 七、CFG 结构骨架（第 16 章 / Schema 任务共同遵守）

顶层键**固定为这 7 个**，不得增删：

```yaml
schema_version:   # 字符串，当前 "0.1"
skill_id:         # 见第四节命名规范
meta:             # 归属、标签、版本、作者
bricks:           # 积木列表，每项是第一节的登记卡实例
params:           # 参数填值，覆盖 default_cfg
presentation:     # 表现配置，见第三节七段
runtime_hints:    # 给运行时的非功能性提示（预算档位、分桶建议等）
```

### 3.5 曲线生成规则（`js/config.js` 的 `skillLevels()`）

```
幂曲线：value_i = base × (target/base)^(i/(n-1))      // 浮点，两位小数
阶梯曲线：value_i = round(base + (target-base)×i/(n-1)) // 整数（数量类）
L1 恒等于 base（不走曲线计算），保证迁移基准绝不漂移
```

| 类型 | 用途 | 曲线形态 |
|---|---|---|
| 系数 / 倍率 / 半径 / 速度 | 伤害与形态成长 | 幂曲线 递增 |
| 冷却 / `lessMult` | 节奏成长 | 幂曲线 递减 |
| 数量（弹数 / 贯穿 / 环绕 / 链长） | 数量成长 | 阶梯整数，上限 10 |

> 🔑 **结构契约不变**：`levels` 仍是数组 `[{ cooldown, castTime, parameters }, ...]`，
> 编译器 `_levelRow` / 调度器 `cooldownFor` / 运行时**零改动** —— 只是数组变长。

## 6. 平衡流程（照抄执行，6 步）

```
① 固定基准   读当前英雄有效伤害/冷却（迁移基准，见 §2）
② 建基线     无水晶下测：单体 DPS / 群体清场时间 / 贴身场景
③ 填表       按 §3~§5 逐项填「目标值」，替换占位
④ 组合穷举   每颗水晶 + 全部合法四槽组合（v0.5 §14 第 11 条）
⑤ 调参       调输出 / 覆盖 / 对象数至基线预期
⑥ 归档       填满本表 + 标注实测环境（设备/帧率/对象数）
```

## 7. C 类：待实测项（必须真机 + 多帧率，**不能凭空宣称达标**）

| 项 | 测法 | 通过判据 |
|---|---|---|
| 最坏对象数 | 主实体数 × 每主实体派生数 × 可并存批次 × 持续区域时长 | 不超 `budgets`，帧率稳 |
| 帧率一致性 | 30 / 60 / 120 FPS 同场景 | 持续伤害累计**一致**（`skill_fps_test` 已锁部分） |
| 真机性能 | 目标机型实机 | 无卡顿、无明显掉帧 |
| 四槽组合 | 全合法组合穷举 | 均有可定位解释，无静默失效 |
| 近战/远程手感 | 人工试玩 | 符合 8.2.2 手感取向 |

> ⚠️ **禁止**在没有实测数据时写"性能达标"。v0.5 §10 明文：「具体预算与目标设备帧耗根据真实测试填入，不凭空宣称性能达标」。

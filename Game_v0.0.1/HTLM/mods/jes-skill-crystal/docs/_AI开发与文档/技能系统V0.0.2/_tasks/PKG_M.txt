## 四、必须写清的内容（判定标准，不是凑数量）

### 1. 回放文件存什么、不存什么

- **存**：足以重建整局的最小集合（种子、输入序列、配置版本、引擎规则版本）。
- **不存**：渲染帧、中间实例状态、每 tick 全量快照——体积会爆，且与"重算"重复。
- 用一句话说清取舍理由：**回放是"重新演算"，不是"录像"**。

### 2. 字段表

每个字段给出：字段名｜类型｜单位/取值｜必填｜说明。至少覆盖：
- 版本三元组：`schema_version` / `rules_version` / `config_digest`（**说明为什么三者都要**：Schema 变了字段语义变；规则版本变了同配置结果变；配置摘要变了内容变）
- `seed`（逻辑 RNG 种子；**必须声明表现 RNG 不进回放**，对齐 D-09 的分离要求）
- `ticks`（总 tick 数、固定步长）
- `inputs[]`（输入序列：`tick` + 操作类型 + 目标/方向等载荷）
- `checkpoints[]`（可选：周期性终局校验和，用于定位首个偏离 tick）
- `final_digest`（终局校验和）
- 元数据（录制时间、角色、关卡——**只作检索用，不参与重算**）

### 3. 校验和怎么算

- 必须**只覆盖逻辑状态**（实例集合、位置、剩余寿命、层数、结算计数等），**不得包含渲染字段**。
- 必须**与遍历顺序解耦**：按稳定标识（`target_id` / `seq`）排序后再哈希，否则同状态不同顺序会算出不同校验和。
- 说明背离时怎么用 `checkpoints[]` 二分定位首个偏离 tick。

### 4. 重放流程

写成有序步骤：加载 → 校验版本三元组 → 用 seed 重建初始状态 → 逐 tick 注入该 tick 的 inputs → 推进 → 比对 checkpoints/final_digest → 报告首个偏离点（含 tick、期望值、实际值）。

### 5. 三个必须回答的边界

1. **版本不匹配怎么办**：`rules_version` 不一致时**禁止静默重放**，必须显式报告"规则已变更，结果不可比"，不得宣称回放失败是 bug。
2. **中途读档怎么办**：回放从第 0 tick 起算；若允许从中途快照起播，必须声明该快照本身的校验和，且**快照不含输入序列**。
3. **回放与联机的关系**：14.9 已定"不做联网锁步/回滚"，本格式**只服务单机**，不得暗示支持联机同步。

### 6. 明确不做什么（边界声明）

不定义录像压缩算法、不定义 UI 回放控件、不定义观战、不承诺跨平台位级一致（沿用 14.9 容差口径）。

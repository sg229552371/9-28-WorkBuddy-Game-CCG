# 第6章　暴露部位

## 6.1 部位是什么，不是什么

〔2026-10-18 第1轮〕

暴露部位是单个技能向玩家开放的一组自定义入口，不是积木类别，不是运行时处理阶段，也不是技能栏多槽中的装配槽。默认创建“伤害、冷却、范围、数量”四个自定义点；可以删减为三个，也可以增加为六个或其他数量。四个只是新建向导的预设，不是保存条件、数组长度或全局上限。

| 概念 | 编辑器里的含义 | 不得混用的含义 |
|---|---|---|
| 暴露部位 | 组织可修改字段与可添加能力的玩家入口 | 不等于必须放一个物品的装备格 |
| 暴露字段 | 部位实际开放的最小接口 | 中文“范围”不自动代表所有距离 |
| 积木 | 有名字的能力预设，按注册表扩展 | 不以部位数决定积木数 |
| 技能石 | 主动技能 | 不作为修饰器权限名称 |
| 辅助石 | 武器模块 | 不因挂在某位置就取得额外权限 |
| 技能栏多槽 | 局内武器栏 | 不由本章制定装配数量 |

〔推荐默认〕新建技能时显示四张待确认的部位卡。选择积木后，只有已有参数、合法范围与权限均齐全的卡才能启用。治疗技能可以把“伤害”替换为“治疗量”，纯辅助技能可以不开放伤害；没有生成数量参数时，不凭空添加一个可调数字来凑四点。空卡必须显示“未绑定字段”，不能给玩家呈现为可用入口。

部位数量与每个部位包含的字段数量分别可扩展。新增部位只是组织接口，不得因此注册新事件、改变四类载体或增加结算步骤。载体名称统一使用 `independent`、`instant`、`attached`、`none`；旧地基里的载体旧写法不复制进本规格。

## 6.2 部位卡与字段白名单

〔2026-10-18 第1轮〕

〔推荐默认〕部位卡分为名称区、绑定区、边界区、预览区。名称区面向策划，绑定区使用字段标识；玩家可以看到“范围”，但策划必须看见究竟绑定判定半径、射程还是波前距离。一个部位可以组织多个字段，不能把它们暗中作为同一个数值修改。

| 卡片内容 | 必须回答的问题 | 未填写的处理 |
|---|---|---|
| 名称与用途 | 玩家通过这个入口改变什么体验 | 草稿提示；启用前补齐 |
| 绑定目标 | 属于哪个积木实例，改哪一个字段 | 阻止启用，不能按同名猜目标 |
| 字段来源 | 来自基础积木，还是已登记的行为模板 | 来源不存在则报缺失引用 |
| 权限 | 可改数字、可加行为、禁止分别覆盖什么 | 未声明即禁止 |
| 上下限与单位 | 最终允许到哪里，数值表示什么 | 数字接口不允许无边界发布 |
| live 与继承 | 是否影响场上效果，是否影响派生体 | 默认不开放，不自动继承 |
| 当前用途 | 已被哪些物品与文案引用 | 删除前展示受影响引用 |

主书稿17.2的字段暴露表继续保留“字段名、默认值、可被哪档权限改、上下限、是否 live 可改、派生体是否沿用”六项。编辑器部位卡只是它的组织视图，不新建一份相互独立的权限真相。`author_params` 表示技能作者能填写什么，`relic_params` 表示外部修饰器能动什么，`locked_params` 表示锁定什么；作者可填不等于玩家可改。

〔推荐默认〕接线草案放在 `params.exposure_points[]`：每项以 `point_id` 稳定标识部位，以 `name` 保存展示名，以 `targets[]` 引用暴露字段。此处只提出组织关系，不替代修饰器的 `targets[]`。字段必须通过第5章登记的“字段名”解析到唯一“Schema 路径”；多个积木使用同一字段名且不能唯一解析时，阻止挂载并交 Schema 任务补足绑定方式，不能自造带点号的字段别名蒙混通过。

## 6.3 默认部位能挂什么

〔2026-10-18 第1轮〕

| 默认部位 | 可以开放的内容 | 不能挂的内容 | 必须明确的边界 |
|---|---|---|---|
| 伤害 | 已暴露的伤害字段及相应数值修饰 | 直接扣目标生命、回改已结算结果 | 单次还是逐份；字段是否真的暴露 |
| 冷却 | 已暴露的冷却时间、缩减量 | 改内部起算工序、借动画回调出手 | 改数值不代表改冷却起点 |
| 范围 | 已暴露的判定半径、长度、射程 | 放大特效后反推命中范围 | 每个距离的定义、单位分别登记 |
| 数量 | 已有出手数、生成数或已配置行为的数量 | 用数字从无到有创造分裂行为 | 连发、齐发、份数不能互相代替 |

同一张“数量”卡可以并列显示连发次数与齐发数量，但每个控件有独立目标；修改其中一个，不应顺手改变另一个。增加伤害份数也不等于新增效果体，更不等于多触发一次技能自身的 hit 派生。编辑器用说明文字解释区别，不让玩家文字决定内部语义。

〔推荐默认〕可登记的扩展示例包括“飞行”“持续”“治疗”“护盾”“控制”。飞行可以开放速度，持续可以开放寿命，治疗可以开放治疗量；这些名称只是组织建议，不是新增封闭枚举。护盾额度、控制时长、召唤上限等仍需各自模板与字段登记；某技能采用了对应积木，才有可绑定的目标。

**数量为零不等于没有行为。** 如果模板已经具有分裂行为，只是当前分裂数量为零，是否允许将数量改成正数，必须由模板声明零值语义并暴露该字段；没有分裂模板时不存在这条数字通道。不能用一个名为“数量”的空字段绕开 `add_behavior`。

## 6.4 多字段、共享字段与可见性

〔2026-10-18 第1轮〕

〔推荐默认〕同一个字段可以被多个部位导航引用，但只能有一份有效的暴露声明。一处改动后其他入口同步显示；不重复装载同一修饰器，不重复合并数值。若确需让一个物品同时改多个字段，展开它的目标列表逐项检查权限；一次挂载是一个完整操作，任一目标不合法则整条修饰器不生效。

| 场景 | 编辑器处理 | 不允许的隐式结果 |
|---|---|---|
| “范围”和“持续区域”都引用半径 | 显示共享字段标记及其他入口 | 两次计算同一份加成 |
| 同部位开放基础飞弹和派生爆炸 | 分两行显示所属积木与继承状态 | 改飞弹半径自动放大爆炸 |
| 部位没有当前兼容物品 | 显示可开放但暂无兼容修饰器 | 自动放宽权限填满列表 |
| 字段有作者默认值但禁止修饰 | 显示锁定及理由 | 把灰色控件误当成未实现 |
| 字段由未启用行为提供 | 显示依赖，数字修饰不能先激活 | 用挂数字的顺序补行为 |

新手视图突出部位用途、当前值、能否挂载；进阶视图展开单位、目标与来源；专家视图显示完整白名单、live 和继承约束。折叠不是权限隔离：隐藏字段仍接受同样的校验；专家模式也无权修改锁定内容。

## 6.5 增删部位与扩展登记

〔2026-10-18 第1轮〕

〔推荐默认〕新增流程为“选择用途→选择已登记字段或行为入口→确认权限与上下限→检查文案和继承→预览→登记”。能用现有字段表达就不增加积木；必须有新能力时，只提交候选说明，由第4章登记流程处理，本章不擅自给出新的已登记积木。

删除部位先区分“删除导航入口”和“撤销字段暴露”。仅删除导航时，共享字段仍可由其他入口访问；撤销暴露时，必须列出引用它的修饰器、被动产出和文案绑定。存在有效引用则阻止发布，不将引用静默转移到另一个同名字段。重命名只改展示名，稳定标识不随卡片排序变化。

配置容量若需要限制，应由项目配置及 Schema 声明可接受的资源边界，编辑器读取后给出提示，不能在本文写成技能永远只支持固定数量的点。容量不足不能通过删除玩家配置来自动修复。本章不定义性能验收指标。

# 第7章　修饰器挂点

## 7.1 三档权限的策划语义

〔2026-10-18 第1轮〕

编辑器不要求新手先理解三档英文权限，但必须完整保存其差异。“可改、可加、禁止”描述当前挂点允许的操作；live 是额外的生效对象提示，不是比“可加”更高的万能权限。

| 策划看到的标签 | 对应契约 | 可以做什么 | 不能暗含什么 |
|---|---|---|---|
| 可改·后续 | `mutate_number` | 修改技能已暴露的数字 | 不能修改旧实例、不能加新行为 |
| 可加·后续 | `add_behavior` | 装入已登记行为及其默认参数 | 不自动获得修改其他数字的权力 |
| 可改·场上 live | `mutate_live_instance` | 从现在起改已暴露 live 数字 | 不改快照、过去、身份、行为结构 |
| 禁止 | 不发放对应权限 | 显示锁定原因 | 不是付出更多成本即可解锁 |

同一个挂点可以同时展示“可加”和“可改”，但导出的每条修饰器只能有一个 `permission`。一件遗物既增加穿透又修改速度时，应拆成两条修饰器，各自有稳定标识、作用域与目标。编辑器可以把它们折叠为一个物品卡，不能合成一条含多档权限的数据。

`relic_params` 继续使用冻结的“可改｜可加｜禁止”。live 的细节来自字段暴露声明与独立的权限值，不给该枚举增加第四项。水晶、遗物是物品来源，不是两套修改系统，也不能根据物品名称推断权限。

## 7.2 挂载表单与六项契约

〔2026-10-18 第1轮〕

| 冻结字段 | 控件与中文说明 | 编辑器必须检查 |
|---|---|---|
| `modifier_id` | 修饰器标识，物品内每条效果独立显示 | 不因拖动排序重命名，不与已有标识冲突 |
| `permission` | 本次操作：改数字／加行为／改场上数字 | 必须且只能选一档 |
| `scope` | 本技能／指定标签技能 | 默认 `own_skill`；跨技能用 `tagged` |
| `inheritable` | 派生体沿用这条修饰 | 默认关闭，不跟随物品品质自动打开 |
| `targets[]` | 从已暴露字段中多选 | 不接受自由描述，不接受未解析目标 |
| `stack_rule` | 按该字段登记的合并类别展示 | 不允许拖拽修改合并工序 |

〔推荐默认〕修饰器实例列表使用 `params.modifiers[]` 作为待冻结接线位置，六项字段原样保留。数值操作数、标签过滤和行为模板引用必须由 Schema 任务在该结构内正式登记；本章只规定其必需语义，不伪造一份可执行导出。引用没有完整登记时，状态为候选，不能假称已登记可运行。

`own_skill` 显示具体技能；`tagged` 显示选定标签和命中技能列表。标签不存在时提示缺少声明，不能把空列表理解成全部技能。跨技能数值预览逐技能使用各自上下限，不用一个总值替代不同技能的实际结果。

## 7.3 来源权限与挂点兼容矩阵

〔2026-10-18 第1轮〕

| 来源或挂点 | 改已有数字 | 加原本没有的行为 | 修改场上实例 |
|---|---|---|---|
| 技能水晶 | 有白名单则可改 | 默认禁止 | 默认禁止 |
| 遗物 | 有白名单则可改 | 有登记入口则可加 | 默认关闭，物品申请和字段声明均满足才开放 |
| 冷却数字挂点 | 按登记规则可改 | 不把改数字当成新增闭环 | 不借此重排已确定的出手 |
| 效果体参数挂点 | 速度、半径、寿命等已声明数字可改 | 行为模板经兼容检查后可加 | 仅标 live 的数字 |
| 行为参数挂点 | 行为已存在且数字已暴露时可改 | 先通过行为入口添加 | 不能让旧实例获得新行为 |
| 身份和结算内部字段 | 禁止 | 禁止 | 禁止 |

〔推荐默认〕兼容列表同时考虑权限、载体能力、目标字段与依赖，不按名称模糊匹配。例如“到期爆炸”需要合法终止原因和派生配置；只有瞬时寿命的模板不能因为名称含“爆炸”就接受持续时间延长。兼容失败须说明缺少什么，不直接隐藏全部失败项，让策划无法区分未登记与不支持。

内部结算工序固定不可配；命中、逐份闪避、减免等先后不出现在挂点拖拽列表。行为组合的既有约束同样不能被“自由编排”覆盖：主书稿20.7的一次碰撞一种行为、家族登记与优先级口径由只读说明呈现，不能给物品私自修改。

## 7.4 live 标记和双向声明

〔2026-10-18 第1轮〕

〔推荐默认〕每个 live 字段旁固定显示“影响场上／从现在起／下一次重算生效”，同时显示上下限和当前实例适用性。不能仅用颜色或闪电图标表达，因为颜色无法说明是修改新生成参数还是场上参数。

| 物品申请实时权限 | 技能声明 live | 结果与提示 |
|---|---|---|
| 否 | 否 | 普通后续数值修改，不出现实时承诺 |
| 是 | 否 | 拒绝实时挂载，定位字段暴露声明 |
| 否 | 是 | 字段可实时修改，但本物品未获权限 |
| 是 | 是 | 检查字段档位、范围与实例类型后启用 |

还须核对字段“可被哪档权限改”确实包含实时权限。地基17.2的速度示例存在“live 为是，但权限列只写数字权限”的歧义，编辑器不能替作者补齐权限；本稿将此类记录视为待修复声明，在未决问题登记，不修改地基。

对 `snapshot`、`origin`、`generation`、`instance_id`、`seq`、`state` 一律显示不可修改。对寿命为零的瞬时实例显示“实时修改不适用”；运行时沿用主书稿18.6的忽略口径，编辑器预先提示，不能宣传已生效。对剩余寿命只开放声明允许的延长及上限，不能每次重算都把总寿命重新加一遍。

〔推荐默认〕实时预览采用“旧实例参数／拟生效参数／不受影响内容”三栏。范围变化只影响未来接触，不补发过去漏掉的命中；速度变化不回画已经走过的轨迹；修改重复接触间隔也不能绕过既有候选接触额度。复杂字段没有完整重算语义时保持关闭，不能因它是数字就授予实时能力。

## 7.5 同字段多修饰器的合并提示

〔2026-10-18 第1轮〕

数值来源抽屉按固定顺序展示“基准→覆盖→相加→比例→夹取→当前值”。移除修饰器后重新计算，不对现值做反向乘除。挂载顺序只在多个覆盖规则竞争时有意义，不能使同类加法、比例加成产生拾取顺序差异。

| 类别 | 展示内容 | 冲突或边界提示 |
|---|---|---|
| `set` | 当前胜出的覆盖来源，其他覆盖来源折叠可查 | 多个覆盖取最后挂载者，必须提示覆盖冲突 |
| `add` | 每个有效来源及同类合计 | 不把负数自动认成比例减免 |
| `mul` | 该字段适用的比例规则与贡献列表 | 一般同类比例先相加后乘；减免按 D-67 |
| `clamp` | 作者声明的下限、上限与夹取前后值 | 达上限时说明新增来源已计入但收益受限 |

示例：基准100，覆盖为80，固定加20，再有同类增加20%和50%，夹取上限150。顺序得到100、170、150，属性区显示150，明细显示被上限截去20。不能把两条同类增加算成连续乘1.2再乘1.5。减免字段若为20%和30%两项，按减免规则得到保留比例0.8×0.7，而不是复用增伤的加法示例；这些数字均为演算示例。

〔推荐默认〕多个 `set` 来源显示“当前生效”和“被覆盖”两个状态。纯粹拖动卡片以整理界面不算重新挂载，不改变胜出者；预览工具若提供模拟挂载顺序，应另设明确操作并显示顺序。移除最后挂载的覆盖来源后，恢复前一个仍有效的覆盖来源，而不是直接回到基准值。

## 7.6 行为添加、依赖与继承

〔2026-10-18 第1轮〕

〔推荐默认〕添加行为前先展示差异清单：将新增什么行为、带来哪些字段、哪些字段允许后续数值修饰、作用于哪些新实例。行为默认参数并不自动开放；模板预先声明的暴露字段仍要经过技能侧适配与上下限检查。

| 操作 | 对之后生成的实例 | 对已生成的实例 |
|---|---|---|
| 装入新增穿透行为的遗物 | 获得登记后的穿透行为 | 保留原行为 |
| 再装穿透额度数值修饰 | 已有行为且额度暴露时可修改 | 非 live 额度保持原值 |
| 移除提供行为的修饰器 | 该行为不再提供 | 旧行为不被撤销 |
| 保留依赖已移除行为的数值修饰 | 显示依赖失效，不凭空恢复行为 | 不迁移到其他字段 |
| 开启显式继承 | 按声明影响派生体的有效修饰 | 不重写已采样快照 |

〔推荐默认〕编辑配置时依赖失效阻止发布；战斗预览中因合法卸装造成依赖暂失，保留装配信息并显示该条当前无有效目标，不让它进入数值合并。依赖恢复后从基准重算，不补算缺失期间的效果。此运行中失效策略须在 Schema 和运行时接线时共同确认，不能把编辑错误与战斗中合法替换混为一谈。

继承预览以根实例和派生体分列，逐条说明 `inheritable`。父体的最终值不是一份新的修饰器，不能先复制最终值再重复叠加同一来源。`origin` 是因果与预算身份，不受继承开关修改；不继承数值修饰不等于重开施放预算。

## 7.7 战斗中替换与生效时间

〔2026-10-18 第1轮〕

装配预览沿用 D-91、D-105：水晶和遗物战斗中可卸下或替换，替换为空也是替换；替换在 tick 开始、任何出手之前整批原子应用。装配公共冷却期间所有装配槽操作被拒绝，时长来自 CFG，本稿不给最终值。

〔推荐默认〕提交替换后显示“待边界应用”，实际应用后更新为“后续生成使用新配置”。旧实例卡保留原参数、行为与快照，不显示为配置同步失败。不能用卸装操作自动回滚曾对旧实例施加的实时数值结果；D-91的旧实例不变边界与实时重算的关系尚需专门规则时，在末尾登记，暂不提供隐式撤销。

装配公共冷却、技能冷却和被动内置冷却必须分别命名、分别显示。一个倒计时结束不意味着另外两项也结束。战斗中替换不修改技能设计资产，变动的是有效装配与运行时副本。

# 第8章　被动挂点

## 8.1 入口与订阅白名单

〔2026-10-18 第1轮〕

被动挂点属于设计卡第八栏，默认不挂被动。它读取已经完成的结算记录，再生成效果体或挂修饰器，不代替施法者闭环。界面标题使用“结算后触发”，避免把它画成插入命中结算中间的回调槽。

| `on` 可选值 | 中文入口 | 需要查看的载荷 | 不能据此宣称 |
|---|---|---|---|
| `hit_settled` | 命中结算后 | 来源、目标、合计、击杀标记、份类型 | 一定扣了生命，或一定是伤害 |
| `evaded_all` | 接触全部闪避后 | 来源与目标 | 任意一份闪避都触发 |
| `damage_taken` | 实际承受伤害后 | 目标、实际承受量、来源链 | 护盾完全吸收也等于实际扣血 |
| `cast_started` | 开始施放后 | 施法者、技能、施放标识 | 每次出手或每个效果体都写一条 |

白名单来自主书稿21.2，不是用户可输入任意字符串的下拉框。`hit`、`vanish` 留在技能内部派生规则，不进入被动订阅列表；`debug_record` 禁止订阅，不能通过专家模式、导入配置或手写文本打开。

〔推荐默认〕技能级允许订阅声明与被动规则共同检查：记录类型合法但技能未开放时，显示“该技能未开放此挂点”，不扩大成全局订阅。受击侧记录的归属需显示目标是否为持有者；跨技能标签筛选与持有者筛选不能混为同一条件。

## 8.2 触发表单与冻结字段

〔2026-10-18 第1轮〕

| 字段 | 策划需要填写或确认什么 | 控件要求 |
|---|---|---|
| `trigger_id` | 这条触发的稳定标识 | 进入来源链标记，不按列表序号生成身份 |
| `allow_self_chain` | 是否显式允许同链再次触发自己 | 默认关闭，开启显示高风险提示 |
| `on` | 订阅哪种结算记录 | 仅四种白名单 |
| `condition` | 满足哪些记录载荷条件 | 按记录类型提供合法字段 |
| `chance` | 触发概率 | 显示最终有效概率及来源 |
| `internal_cooldown_ticks` | 持有者这条触发的内置冷却 | 以 tick 存储，秒为辅助显示 |
| `max_chain_depth` | 允许的最大因果链深度 | 与派生代数分栏展示 |
| `produces` | 生成效果体还是挂修饰器 | 引用已有模板或合法修饰器 |
| `strength_coeff` | 若采用强度缩放，使用哪个固定系数 | 作者固定，不向外部修饰器暴露 |

〔推荐默认〕规则列表接线位置为 `params.passive_triggers[]`，其中各项保留以上字段名。条件表达式的具体序列化由 Schema 任务登记；本章不设计任意脚本输入口。条件必须可静态检查字段存在、类型适配和引用有效，不能用文案解析代替条件数据。

## 8.3 过滤语义与触发粒度

〔2026-10-18 第1轮〕

“命中”“造成伤害”“击杀”“承受伤害”是不同条件预设，不是四个新增事件。选择预设后，策划仍能展开其真实记录类型与过滤条件。

| 意图 | 推荐条件解释 | 必须防止的误用 |
|---|---|---|
| 命中时 | 合法的命中结算记录，按需要限定份类型 | 把未扣血误判成没有命中 |
| 击杀时 | 读取 `killed`，并限定合法来源 | 建立独立击杀事件 |
| 治疗命中时 | 成立份中存在治疗类型 | 用总量判断它一定是伤害 |
| 承受生命伤害时 | 受击侧实际承受记录，目标为持有者 | 用吸收前合计代替实际扣血 |
| 全部闪避时 | 读取全闪避记录，确认持有者归属 | 订阅普通命中后再推测闪避 |

〔推荐默认〕份过滤采用“存在至少一份满足条件”的记录级判断，同一记录同一触发规则最多进行一次触发机会判定；不因三份伤害把该规则复制三次。需要逐份触发的设计属于新增语义，本轮不开放。命中派生与被动触发各自遵守自己的规则，不能用玩家描述中的“多段”决定触发次数。

主书稿冻结载荷明确提供份索引与类型，但没有在本章输入中完整定义“指定伤害类型的实际伤害合计”。因此混合治疗与伤害的记录不能用全记录 `total` 判断某一类份实际大于零。〔推荐默认〕此类过滤在缺少份级金额接口时显示“不支持该精确条件”，只允许已能表达的类型存在、击杀或受击侧条件；需要扩展载荷的事项登记未决，不猜算金额。

## 8.4 两种产出及不可绕过的管线

〔2026-10-18 第1轮〕

| 产出模式 | 必须展示 | 禁止项 |
|---|---|---|
| 生成效果体 | 模板、生成位置规则、合法目标、来源链、预算归属 | 直接扣血、直接调用伤害结果、跳过份结算 |
| 挂修饰器 | 目标技能或持有者、有效期、权限、暴露字段 | 回改结算记录、越权改快照、改来源链 |

“击杀后周围爆炸”应显示将生成的范围效果体，伤害继续经过接触与结算；“闪避后冷却缩短”应显示将挂的数值修饰器，而不是修改已经结算的那次施放。没有合法目标时如何处理，沿用所引用模板，不在被动卡上偷偷增加一次重新索敌。

被动产出不产生 `cast_started`，不能触发一次新的施法者闭环。位移期间允许合法被动产出，但不得借被动开启新的位移状态。派生或被动生成物参与接触的时点遵守主书稿14.4；状态型派生体创建 tick 可挂载但不可据此提前接触判定，两者应在预览中分别显示。

## 8.5 循环保护的三层 UI

〔2026-10-18 第1轮〕

〔推荐默认〕触发卡底部固定显示三枚带文字的保护状态，不允许折叠后完全看不见。“来源链保护”“链深度上限”“持有者内置冷却”同时有效，不提供三选一按钮。

| 保护层 | 静态配置提示 | 运行预览提示 |
|---|---|---|
| 来源链标记 | 默认同链不得重复触发自己；产出继承父链 | 显示本链已包含哪些触发标识，当前是否被拦截 |
| 链深度 | 显示当前深度与允许深度，区分派生代数 | 生成请求使链超过上限时，不执行产出 |
| 内置冷却 | 按持有者和触发标识计，不按目标分别刷新 | 显示可再次触发的 tick 与本次被拦原因 |

`allow_self_chain=true` 只放开本触发重复自身的限制，不清空已有链标记，也不关闭深度与冷却。默认内置冷却不能为零；确需零冷却，必须显式填写理由、最坏情况和预算兜底。不能通过把同一个触发拆成随机标识规避内置冷却。

〔推荐默认〕概率判定预览使用可注入种子 RNG，显示种子和最终有效概率。安全检查、冷却和概率的详细求值与抽取顺序由运行时契约统一固定，编辑器不可配置。本章不擅自规定失败尝试是否消耗随机数；在没有冻结求值顺序前，统计图只能标为条件概率展示，不能宣称是确定性触发序列。

## 8.6 链、代数与预算的辅助视图

〔2026-10-18 第1轮〕

来源链视图把根、派生、被动产出画成因果树，节点只用于解释，不是可任意重排的执行图。根实例代数为零；派生增加代数和链深度，被动生成也增加链深度。不能把 `max_generation` 当作全部被动链的上限，也不能把链深度误写成效果体数量。

〔推荐默认〕每个节点展示最初技能、最初施放、链深度、派生代数与预算归属。产出继承原 `origin_cast_id`，不能新开编号逃避同次施放预算。确非某次施放引发的受击触发，才按主书稿21.5开独立短链预算，预算值来自 CFG，不在本章写死。

预算是三层循环保护之外的生成边界，不替代其中任何一层。预览可以显示某请求因预算未生成，但不得让正式技能逻辑根据这一提示再生成补偿效果。编辑器诊断面板与玩家正式界面必须分开；诊断可以只读调试记录，正式 UI 不读取它。

## 8.7 错误定位与验收例子

〔2026-10-18 第1轮〕

〔推荐默认〕非法订阅定位到具体规则的 `on`；危险自循环定位到该规则的允许自链开关；缺少预算或冷却说明定位相应字段。列表以稳定标识定位，删除其他规则不能导致报错跳到另一条。报错内容交第15章统一登记，不在本章抢占编号。

| 输入与操作 | 预期结果 | 验证点 |
|---|---|---|
| 导入订阅 `debug_record` 的被动 | 拒绝并定位订阅字段 | 导入不能绕过白名单 |
| 一条结算记录有三份匹配伤害类型 | 本规则只得到一次触发机会 | 记录级而非份级复制 |
| 治疗记录被“伤害类型存在”过滤 | 不匹配，不触发 | 非伤害记录不误入伤害条件 |
| A触发B，B再指向已在链中的A | 默认来源链保护拦截A | 标识必须沿链传播 |
| 开启允许自链但链深度已达上限 | 后续产出仍被拦截 | 自链开关不是总开关 |
| 同持有者同一 tick 多次满足条件 | 内置冷却约束仍有效 | 不按不同目标重新开冷却 |
| 被动生成效果体 | 不写新的开始施放记录 | 不递归启动闭环 |
| 诊断出现预算丢弃记录 | 只在调试视图可查，不触发补偿 | 调试数据不反馈逻辑 |

# 第11章　数值成长

## 11.1 双层等级与来源分层

〔2026-10-18 第1轮〕

本章新增的是编辑器的成长配置与预览，不重做角色成长系统。局内等级每局从 LV1 起，局外角色等级随角色档案保留；两者不能相加成一个不明来源的“总等级”。角色基础与等级加成属于 L0，永久成长或天赋属于 L1，局内临时增益属于 L2，水晶与遗物修饰器属于 L3。

| 来源 | 编辑器解释 | 进入技能结算的路线 |
|---|---|---|
| L0 基础与等级 | 基础属性、局外角色等级贡献、局内等级贡献 | 合成角色属性，出手时采样 |
| L1 局外永久加成 | 非角色等级的永久成长、天赋等 | 开局固化后参与角色属性合成 |
| L2 局内临时增益 | 战斗内实际有效的增益或状态 | 在对应出手时读入快照 |
| L3 修饰器 | 水晶、遗物对技能字段的作用 | 不进快照，走技能字段合并 |

〔推荐默认〕两种角色等级的数值贡献都在 L0 内分列，不把“局外”等同于 L1。某永久系统如果本身属于天赋，应在 L1 登记；同一个来源只能登记一次，不同时作为等级加成和永久天赋重复累加。编辑器展示来源说明与唯一引用，遇到重复引用先报冲突，不由名称猜归属。

开局固化的是本局外部输入，不意味着局内等级永远不能变化。角色档案、局外等级、永久天赋在本局内不重新读取外部实时数据；局内等级及 L2 有效状态是本局受控输入，在 tick 边界或各自契约指定时点推进。

## 11.2 成长面板与配置边界

〔2026-10-18 第1轮〕

〔推荐默认〕成长面板分“引用来源”“曲线定义”“字段规则”“预览”四区。技能编辑器可以引用角色成长配置并创建技能字段自身的等级曲线，但不负责发放经验、决定升级门槛、售卖永久成长或修改角色存档。

| 面板项 | 需要提供的内容 | 边界 |
|---|---|---|
| 双等级输入 | 局内等级与局外角色等级独立输入 | 局内开局为1，最高等级读取配置 |
| 属性来源引用 | L0、L1、L2的合法来源 | 战斗预览不实时读取外部档案变化 |
| 曲线目标 | 角色贡献还是技能字段基准 | 不允许同一贡献同时走两条路线 |
| 取值规则 | 定义域、单位、插值、取整、上下限 | 不用图形曲线代替明确数据 |
| 生效说明 | 下次出手、新生成、继承或实时 | 升级不是通用 live 权限 |

〔推荐默认〕技能成长配置接线草案放在 `params.growth`。其下 `source_refs` 引用角色成长来源，`field_curves[]` 登记技能字段曲线。每条曲线以 `curve_id` 标识，以 `target_field` 指向已登记字段，以 `level_axis` 区分局内或局外轴，以 `points[]` 提供等级和值，以 `interpolation` 声明插值。取整规则直接引用该参数登记，不另造一套互相冲突的精度。

这些是新建议的子结构，必须经第5章参数登记与第16章 Schema 接线后才能导出；不增加顶层 `growth`，不把成长数值塞入 `runtime_hints`。角色属性的正式字段词表沿用主书稿18.9与 IF-3；攻击、暴击率等中文标签在本稿中只是语义名称，不冒充已冻结的英文键。

## 11.3 曲线类型与确定性求值

〔2026-10-18 第1轮〕

〔推荐默认〕首版支持常量、逐级表、分段线性三种受控曲线。没有配置成长时使用常量，不把“缺数据”当成“按上一级自动增长”。需要更多曲线类型时走登记，不在编辑器写死只有三种的永久边界；未登记类型不能运行。

| 类型 | 编辑方式 | 求值约束与适用场景 |
|---|---|---|
| 常量 | 一个确定值 | 未成长字段、教学基础配置 |
| 逐级表 | 整数等级对应一个值 | 每级可审核，适合离散数量和非线性调节 |
| 分段线性 | 有序等级锚点与数值 | 在相邻锚点间线性求值，适合连续属性 |

〔推荐默认〕锚点等级必须唯一且严格递增，覆盖声明的合法等级域。逐级表缺级时报错，不插入作者未确认的数值。输入等级超出域时拒绝该预览或导出，不静默外推；角色最高等级调整后必须重新验证覆盖范围。常量也必须有合法域，便于发现引用了错误的等级体系。

首版不开放任意表达式执行、不接受随机曲线、不使用当前时间或联网数据作为函数输入。分段线性只在合法整数等级上求最终值；图上等级之间的连线用于阅读，不意味着运行时存在半级角色。对于数量、tick等整数目标，先求曲线，再按字段规则取整；禁止先对每个来源分别取整后累加而不声明。

**已核验外部事实。** Godot 官方 Curve 文档说明：`sample` 根据横坐标返回纵坐标，曲线具有定义域，切线可使中间值超过点值范围。原文地址：https://docs.godotengine.org/en/stable/classes/class_curve.html ，2026-10-18 已通过带浏览器 UA 的 curl 抓取原文。由此采用的项目建议是“显式定义域、可复算插值、结果检查”，不是照搬引擎资产格式，更不能由此推断其他游戏的升级快照行为。

## 11.4 两条等级轴如何合成

〔2026-10-18 第1轮〕

〔推荐默认〕角色属性的最小成长形式采用“基础值＋局外等级贡献＋局内等级贡献”，两条贡献曲线在各自起始等级默认贡献零。永久加成和临时增益再按它们已登记的属性规则进入 L1、L2；百分比来源的分类与合并规则必须来自属性接口，不能由本章凭空定义全部属性的算式。

示例：基础攻击100，局外等级贡献20，局内等级贡献从0升至10；没有其他来源时，角色最终攻击由120变为130。如果技能存在一条合法的20%伤害字段修饰，L3单独显示该项。为了验算，本例假设技能伤害基数直接取攻击且目标无减免，则新出手预估伤害从144变为156；这不是所有技能通用的伤害公式。

| 合成问题 | 默认处理 | 编辑器说明 |
|---|---|---|
| 两个轴都增加攻击 | 在 L0 内分列贡献后合成 | 不相乘两个“等级总倍率” |
| 局外永久天赋也加攻击 | 单独进入 L1 | 不再计入局外等级曲线 |
| 两条轴都驱动同一技能字段 | 必须登记合成方式与来源，缺失则阻止启用 | 不默认后写者覆盖前写者 |
| L3修改技能伤害 | 在技能字段或伤害层按既有规则合并 | 不回填角色攻击或快照 |
| 降低冷却的成长 | 按该字段语义判定增益方向 | 数字更小也可能更强 |

〔推荐默认〕技能字段自身的成长输出作为该字段当前等级下的基准值，然后走主书稿16.4的修饰器合并。它与角色攻击成长是两种独立贡献，若同时开启，预览必须明确告知“双重成长”，不能把两者隐藏成一条等级倍率。该接线是本稿新增建议，不将它伪称为 D-92 已确认内容。

## 11.5 数值成长与行为解锁分开

〔2026-10-18 第1轮〕

曲线只改变已存在字段的值。等级到达某级后首次获得分裂、追踪或新的被动，属于行为或内容解锁，不属于纯数字成长。首版成长曲线不能把任意字段从空变为结构，也不能因为某个数量超过零就自动装入模板。

〔推荐默认〕允许离散数量的逐级变化，但模板必须声明该数量控制的是已有行为。预览将断点标为“已有行为数量变化”，并显示它改变连发、齐发、重复接触还是份数。每个离散变化都附对应的验收例子，不能用连续折线掩盖突然多一发的语义。

| 目标 | 成长允许的方向 | 必须保留的保护 |
|---|---|---|
| 伤害、治疗量 | 已登记数值随等级变化 | 类型、单位与上限 |
| 半径、寿命 | 改新实例的参数基准 | 判定与表现分离、寿命有限 |
| 控制时长 | 改已存在控制的数值 | 免疫与控制类型注册不变 |
| 召唤上限 | 有对应模板并开放时可成长 | 召唤约束与归属不变 |
| 派生代数、来源身份 | 不作为玩家数值成长目标 | 不能用等级绕开组合安全 |
| 强度系数 | 作者固定，首版不作为外部成长可改项 | 不削弱被动触发安全边界 |

非伤害模板使用同一套来源与预览规则。治疗量提高不改变敌友过滤，护盾额度提高不改变吸收顺序，控制时长成长不意味着改写目标免疫。成长图只说明输入值变化，不宣称每个目标都能实际获得满额结果。

## 11.6 升级瞬间与已生成实例

〔2026-10-18 第1轮〕

**〔推荐默认〕编辑器采用“升级提交到下一合法 tick 边界，影响之后出手；已生成实例不因升级自动重算”的展示与预览规则。** 核心时点已有主书稿18.9原文支持，不再当成可以自由翻转的空白。新增建议只补边界呈现和测试：升级请求若在本 tick 处理中产生，不插进本 tick 已进行的出手或结算，下一 tick 开始出手前统一应用。

| 升级时对象状态 | 是否自动更新 | 解释 |
|---|---|---|
| 尚未出手 | 边界应用后，新出手采样新角色属性 | 采样单位是出手，不是打开技能界面 |
| 同次出手的多个实例 | 共用该次出手快照 | 不出现一半旧等级、一半新等级 |
| 已飞行的飞弹 | 不更新参数和快照 | 未命中也不代表尚未生成 |
| 已存在的持续区域 | 各跳仍用原快照，参数保持原值 | 目标侧状态仍按每跳时刻读取 |
| 升级后才出现的旧链派生体 | 复制父快照，不重新取角色等级 | 出生较晚不等于新的一次出手 |
| 已完成的命中 | 永远不补算、不回写 | 过去不可修改 |
| 已配置 live 的场上字段 | 升级本身不授权修改 | 另有合法实时修饰时才按实时契约执行 |

例如旧飞弹在 tick 20 出手，tick 22 结算后达到升级条件，tick 23 边界应用新等级。旧飞弹 tick 24 命中仍使用旧快照；tick 23的新出手使用新快照；旧飞弹命中后派生出的子体仍复制旧快照。不能因子体在升级后创建就让它突然获得新攻击。

不选择“升级立刻刷新全场”，因为那会改写已冻结参数与快照；不选择“每次命中读当前等级”，因为它会破坏持续区域与派生链的一致性。live仅是已经允许的未来数值修改通道，不是升级追溯全场的例外许可。相关材料残存的快照 live 歧义在未决问题登记，未裁决前不开放快照覆盖。

## 11.7 已排时间表、刷新与召唤的边界

〔2026-10-18 第1轮〕

〔推荐默认〕升级改变角色属性，不重排已确定的施放时间表，不补发出手、不补扣冷却。已经进行的前摇或冷却不因为预览上的新数值突然归零。尚未出手点的角色属性仍按真正出手时采样；时间表冻结与属性采样是两件事，应在预览中分开解释。

| 复杂情形 | 本稿采用的边界 | 是否需要额外接线 |
|---|---|---|
| 连发中间升级 | 之后实际出手采样新属性，既定出手点不重排 | 时间字段读取点需由闭环规格确认 |
| 升级后重新施放持续技能 | 新施放按新值，实例关系服从 `restack_rule` | 不因成长自动触发重施放 |
| 刷新单例 | 允许按模板刷新寿命与声明的参数 | 旧快照是否替换的残存歧义须评审 |
| 既有召唤物 | 不因主人升级自动刷新冻结属性与修饰集合 | 召唤模板若需特殊继承必须登记 |
| 新召唤物 | 按新生成时有效配置创建 | 自身闭环与归属沿用召唤规则 |
| 已采样的召唤物攻击 | 使用该攻击的快照 | 不因主人或召唤物随后变化回写 |

〔推荐默认〕刷新单例时先沿用主书稿明确允许的寿命与 `params` 更新，旧 `snapshot` 保留；如果设计确需换成新出手快照，必须由主书稿明确刷新专属规则后才开放。这个保守默认不是宣布主书稿已裁决全部刷新细节。预览应显示“参数已刷新／快照仍为原出手”，避免把两者合并成一个“等级已更新”图标。

## 11.8 成长预览：二维、差值与来源

〔2026-10-18 第1轮〕

〔推荐默认〕提供局内等级横轴、局外角色等级选择器，以及二维等级表。拖动任一轴只改变预览输入，不编辑曲线；预览与改稿按钮分开，避免策划把观察某等级误操作成写入默认等级。

| 预览区 | 必须展示 | 不允许省略 |
|---|---|---|
| 当前／下一级 | 字段当前值、下一等级值、差值 | 哪条等级轴发生了变化 |
| 来源明细 | 基础、两级别贡献、永久、临时、修饰器 | L3与快照来源的分界 |
| 二维表 | 选定等级组合的最终字段值 | 各轴定义域与当前选区 |
| 上限提示 | 夹取前值、夹取后值、触顶位置 | “升级无显示增长”的原因 |
| 时间预览 | 新出手、旧实例、旧链派生体 | 不能只展示升级后的理想值 |
| 目标条件 | 无目标预估或固定测试目标 | 实际减免、免疫、护盾等假设 |

预览冷却时同时给出 tick 与换算秒数，暂停或慢动作不改逻辑 tick 值；预览半径时区分判定尺寸与特效尺寸。预览“单次伤害”时明确是单份、一次命中合计还是整轮理论值，不能乘齐发数就宣称单目标必定承受总量。

〔推荐默认〕颜色只辅助说明变强、变弱或无变化，并附文字原因。冷却从长变短用“缩短”，持续时间缩短不自动标为更强；字段未登记收益方向时只显示数值差，不猜好坏。达到上限后升级仍可发生，但该字段提示“已达上限”，不得显示假增长。

## 11.9 校验与验收例子

〔2026-10-18 第1轮〕

〔推荐默认〕保存草稿允许缺少曲线引用，但明确标注未完成；启用或导出要求引用齐全、定义域完整、单位可转换、取整规则明确。出现非有限值、重复等级锚点、越界曲线值、缺级或重复来源时，定位具体曲线和目标字段。曲线编辑器不能自动删除坏点后声称校验通过。

| 输入与操作 | 预期结果 | 验证点 |
|---|---|---|
| 新开一局，局外角色已成长 | 局内仍为LV1，保留固化的局外等级贡献 | 双层等级分离 |
| 战斗中外部角色档案变化 | 本局属性包不变，下局才重新固化 | 不实时读局外数据 |
| 分段线性端点为等级1值10、等级3值14 | 等级2为12；不存在半级运行输入 | 可复算的插值 |
| 逐级表缺少等级2 | 报缺级，不猜插值 | 表与曲线类型有区别 |
| 等级1基础100，局外加20，局内下级加10 | 无其他来源时120变130 | 两条等级贡献不重复 |
| 添加伤害修饰后查看来源 | L3独立列出，快照角色属性不被改写 | D-92边界 |
| 升级时旧火区仍有后续跳 | 旧跳快照不变，新火区用新快照 | 已生成实例不刷新 |
| 旧飞弹升级后命中并派生 | 子体沿用父快照 | 按因果来源，不按出生时等级 |
| 同次出手齐发期间应用等级 | 不允许拆开同次出手采样 | 原子边界 |
| 曲线令值超过参数上限 | 预览清楚显示夹取，非法配置按字段规则处理 | 无隐藏收益 |
| 升级缩短了冷却基准 | 已在计时的冷却不被隐式清零 | 时间表与属性分开 |
| 等级数量曲线引用不存在行为 | 阻止启用 | 数值成长不创造结构 |

## 与运行时契约的引用关系

〔2026-10-18 第1轮〕

# 第12章　文案

## 12.1 两种文字，三层玩家界面

〔2026-10-18 第1轮〕

玩家文字回答“会发生什么”，设计文字回答“规则怎样成立”。玩家界面分正文、属性区、详情层；设计文字另在策划区完整展示，不能拿一句易读描述替代字段暴露、终止原因或被动条件。

| 区域 | 读者与内容 | 数据来源 | 禁止做法 |
|---|---|---|---|
| 效果正文 | 玩家，最多三句可见结果 | 审核过的 `player_text` | 手写冷却和伤害等易变数字 |
| 属性区 | 玩家，可比较的当前数值 | 当前生效配置与所选预览上下文 | 复制正文里的旧数字 |
| 玩家详情层 | 玩家，条件限制、来源说明、行为补充 | 已确认规则的易读表达 | 直接展示内部标识与调试丢弃记录 |
| 设计文字区 | 策划、程序、评审，完整规则 | 八栏设计卡与已登记配置 | 为了三句限制而省略内部规则 |

正式 UI 对战斗结果只读 `hit` 与 `hit_settled`；静态技能说明和成长比较读取已批准配置及当前数值投影，不读取调试记录。此区分不扩大正式 UI 的战斗记录白名单。工具里的调试详情与玩家详情必须分栏，不能因主书稿23.3曾并称“详情／调试层”就把调试数据直接交给玩家。

## 12.2 三句写法与四项覆盖

〔2026-10-18 第1轮〕

四项信息是生成什么、怎么运动、打中怎样、结束怎样，不要求四句。新建模板按技能类型组合前三项与结束信息；没有特殊结束结果时允许两句，不为了凑三句编出不存在的爆炸、治疗或消失触发。

| 技能类型 | 第一句 | 第二句 | 第三句 |
|---|---|---|---|
| 飞行或抛射 | 生成物与运动方式 | 命中可见结果 | 未命中或自然结束的可见结果 |
| 瞬时范围 | 形状、位置与动作 | 影响对象与可见结果 | 有额外后果才填写 |
| 持续区域 | 生成的区域及其位置 | 区域内持续或周期效果 | 自然结束的可见结果 |
| 位移 | 自身如何移动 | 沿途或终点作用 | 有必要才说明结束限制 |
| 护盾或增益 | 给谁提供什么 | 可见收益或保护 | 必要的结束条件 |

〔推荐默认〕编辑器提供三行句子输入，空行可省。每个动词旁可在设计区关联对应的行为依据，供核对，不把这些内部引用导出给玩家。自动草拟文案只是建议，不反向创建配置。写下“追踪”但没有追踪运动时，报文案与设计不符，不自动把飞弹改成追踪。

正文不出现权限名、原因码、实例、派生代数等内部词。数字大小移入属性区；“一片”“一枚”如果用于叙述形态，必须与实际配置核对。数量可成长或可修饰时优先写“射出飞弹”，避免正文锁定为一枚而属性区已经显示多枚。

## 12.3 属性区与正文分开的判定表

〔2026-10-18 第1轮〕

| 待写内容 | 默认归属 | 原因与例外 |
|---|---|---|
| 落地后留下燃烧区域 | 正文 | 玩家可见的行为结果 |
| 冷却、持续时间、周期间隔 | 属性区 | 数字会随成长或修饰变化 |
| 射程、判定半径、扇形角度 | 属性区 | 要比较的精确尺度；正文只说范围形态 |
| 单次伤害区间、治疗量、护盾额度 | 属性区 | 来自当前值，不写死于描述 |
| 连发次数、齐发数量 | 属性区并分别命名 | 两种数量不能用“发数”混称 |
| 多次接触还是一次接触多份 | 详情层 | 正文可用易读描述，但不暗示触发次数 |
| 不可被闪避 | 正文或详情层 | 影响玩家决策时可提升到正文，必须真实适用 |
| 会被护盾吸收 | 详情层 | 规则明细，不挤占主要行为说明 |
| 击杀后发生爆炸 | 正文或附加行为区 | 必须写出击杀条件，不能简写成命中爆炸 |
| 某字段已经达到上限 | 属性区状态提示 | 解释数字不再增长，不改变技能正文 |
| 无敌不等于所有控制免疫 | 详情层 | 按份类型解释，不能承诺全部失效 |
| 内部来源链、预算丢弃记录 | 设计或调试区 | 不能以调试记录驱动正式提示 |

〔推荐默认〕一个信息既含行为又含数值时拆写：正文“区域周期灼烧敌人”，属性区“作用间隔、持续时间、每次伤害”。不要写两份数字，也不要正文说“持续伤害”而属性区只给一次性总伤害，令玩家误以为每次都获得总量。

## 12.4 属性绑定与成长、修饰联动

〔2026-10-18 第1轮〕

〔推荐默认〕属性行使用已登记字段或明确的只读派生显示值，显示名称、值、单位、数值口径、来源入口。具体绑定结构交 Schema 任务登记，不在 `player_text` 内嵌入执行表达式。数值为空或引用失效时阻止发布，不把缺失值显示成零。

| 变化 | 正文 | 属性区 | 详情层 |
|---|---|---|---|
| 等级提高伤害 | 不变 | 显示新出手对应的新值 | 展示等级来源与旧实例边界 |
| 数值修饰增大半径 | 不变 | 更新判定半径 | 显示该修饰器来源及夹取 |
| 新增行为 | 原技能正文不改 | 新行为数值在独立属性组 | 展示附加行为说明 |
| 卸下数值修饰 | 不变 | 重新合并后的当前值 | 来源列表移除该项 |
| 达到上限 | 不变 | 显示最终值及达上限 | 明细解释未产生的额外收益 |

默认属性区表示“当前配置下的新出手”，不能让玩家误读为所有场上效果已同时更新。选中旧实例的工具预览要显式切换为“该次出手快照”；玩家界面如需解释，只写“已释放的效果不随升级改变”等易读规则，不暴露内部快照字段。

伤害预估不能伪称实际扣血。没有目标时显示基础或条件范围，并标明不含目标防御与护盾影响；有测试目标时注明目标条件。治疗显示潜在量与实际量的区别，满生命造成零实际治疗不说明技能失效。护盾吸收前的伤害合计与实际承受量分别命名，不能都叫“伤害”。

## 12.5 新增行为文案与三句约束

〔2026-10-18 第1轮〕

主书稿要求新增行为的说明来自修饰器自己的玩家文字，不能修改原技能正文。〔推荐默认〕基础正文保持最多三句，附加行为采用独立来源卡，紧邻正文显示摘要并可进入详情；附加卡不是悄悄拼进原字段的第四句。

| 情形 | 编辑器策略 | 玩家可见结果 |
|---|---|---|
| 修饰器只改数字 | 不要求额外行为句 | 属性变化即可 |
| 修饰器增加穿透 | 要求行为说明及数值属性 | 基础正文不变，附加卡说明获得穿透 |
| 多个修饰器提供同类数值 | 不重复生成同一句行为 | 来源在详情展开 |
| 新行为附带触发条件 | 条件必须出现在说明中 | 不能把有条件效果写成必然发生 |
| 移除行为来源 | 删除对应附加卡 | 不保留已经失效的承诺 |

〔推荐默认〕正文与附加卡同时预览，检查首屏是否容易误解。若某行为与基础描述构成矛盾，不靠把说明藏进详情解决；应标为文案冲突，要求作者修订该配置下的展示组合。原技能正文仍不被修饰器回写。附加卡布局数量随有效来源变化，不写死最多几个来源；具体排版交表现章节处理。

## 12.6 设计文字的核对清单

〔2026-10-18 第1轮〕

设计文字保留完整八栏，可引用已登记内容，但引用必须唯一有效。编辑器在文案侧提供核对关系，不重新定义闭环、效果体或份结算的结构。

| 玩家动词或承诺 | 设计文字必须有的依据 | 缺失时处理 |
|---|---|---|
| 射出、连射 | 出手安排、生成数量及运动规则 | 报行为无依据 |
| 穿透、分裂 | 已有行为或合法新增行为来源 | 不自动赋予能力 |
| 爆炸、留下区域 | 生成条件、原因过滤、效果体模板 | 不省略是否必须落地或击杀 |
| 治疗、护盾、控制 | 对应份类型、目标过滤和模板 | 不从名称猜效果类型 |
| 持续、周期 | 寿命与重复接触间隔 | 无间隔时不承诺持续跳伤 |
| 结束消散 | 合法终止条件及可见表现 | 不将所有终止都写成派生触发 |

“零伤害仍命中”“全部闪避无命中”“无敌与非伤害份分别处理”等内部差异放在设计文字和必要的玩家详情中。不能为了简单，把免疫造成的零值写成闪避，也不能把一次命中里的多份写成必定多次触发遗物。内部规则与玩家简化表达之间必须有可核对映射。

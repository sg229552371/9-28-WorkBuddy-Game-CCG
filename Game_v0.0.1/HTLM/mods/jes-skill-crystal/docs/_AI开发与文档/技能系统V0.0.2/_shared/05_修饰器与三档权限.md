# 第16章　水晶与遗物是同一套修饰器

> 一句话结论：水晶和遗物不是两套机制，而是同一种"修饰器"；差异只来自两条轴——**拿到什么权限**、**作用到哪个技能**。

## 16.1 两种物品，一套机制

1. 水晶和遗物不再是"水晶改某一段、遗物改另一段"的固定关系（取代 v0.1 的层一/层二分工）。
2. 二者共用同一份修饰器接口（见 16.3），引擎只实现一遍修饰器管线。〔D-40 推荐默认〕
3. "水晶还是遗物"是**物品属性**（来源、获取方式、是否可拆装），不是修饰器字段；修饰器本身只认 `permission` 与 `scope`。

## 16.2 默认权限矩阵

| 修饰器来源 | `mutate_number` | `add_behavior` | `mutate_live_instance` |
|---|---|---|---|
| 技能水晶 | 开 | 关 | 关 |
| 遗物 | 开 | 开 | 默认关；仅当物品显式声明且技能暴露了 live 字段时开 |

- 水晶、遗物的前两列沿用 v0.1 的当前口径；第三列 v0.1 为"未指定"，本书给出推荐默认：**默认关，需双向声明**（物品声明申请该权限，技能设计卡声明哪些字段允许被实时改，两边都声明才生效）。〔D-41 推荐默认〕
- "双向声明"的理由：避免一件遗物悄悄改动所有技能的场上实例，也避免技能作者没意识到某字段可被实时改。

## 16.3 修饰器接口（冻结词表）

| 字段 | 含义 | 默认 |
|---|---|---|
| `modifier_id` | 修饰器唯一标识 | 必填 |
| `permission` | `mutate_number` / `add_behavior` / `mutate_live_instance` 之一 | 必填 |
| `scope` | 作用域：`own_skill`（只作用于所挂技能）或 `tagged`（作用于带指定标签的技能） | `own_skill` |
| `inheritable` | 派生体是否继承该修饰 | `false` |
| `targets[]` | 要改的暴露字段名列表（必须是技能设计卡"字段暴露声明"里已列出的字段，见第17章） | 必填 |
| `stack_rule` | 同一字段上多个修饰器的叠加规则 | 见 16.4 |

一件物品含多个效果时，拆成多个修饰器，每个修饰器只带**一档**权限。〔D-40 推荐默认〕

## 16.4 同字段多修饰器如何合并

从基准值重算，而不是按拾取顺序反复乘除（保留 v0.1 精神）：

```text
基准值（技能设计卡）→ 收集当前有效且作用域匹配的修饰器 → 按 stack_rule 类别合并 → 得到该字段的当前值
```

| `stack_rule` 类别 | 含义 | 示例（仅示意） |
|---|---|---|
| `add` | 同类相加 | 半径 +1，+2 → +3 |
| `mul` | 相加后乘：同类百分比先相加再乘；百分比减免相乘（见 26.9 / D-67） | ×1.2，×1.5 |
| `set` | 覆盖；同字段多个 `set` 取最后挂载者，须在设计卡写明 | 将持续时间设为 3 |
| `clamp` | 技能设计卡给出的上下限，合并结果最后夹取 | 速度不低于 1 |

- 合并顺序固定：`set` → `add` → `mul` → `clamp`。〔D-43 推荐默认〕
- 修饰器移除或失效后，下次重算自动还原，不需要"反向撤销"。
- 数值系统最终形态（曲线、软上限）不在本书，本章只定接口与顺序。

## 16.5 水晶与遗物的典型分工（说明，不是强制）

| 场景 | 更适合 | 原因 |
|---|---|---|
| "这个技能半径 +20%" | 水晶，`mutate_number` | 只改已有数字，影响面小 |
| "所有火系技能冷却缩短" | 遗物，`tagged` 作用域 | 跨技能，需要显式标签 |
| "飞弹获得穿透" | 遗物，`add_behavior` | 创造原本没有的行为 |
| "命中时额外生成一枚追踪弹" | 遗物，走第21章被动触发层 | 属于新增触发，不是改技能本身 |

## 16.6 常见误写→正确写法

| 常见误写 | 正确写法 |
|---|---|
| "水晶改前摇，遗物改飞弹" | 二者都是修饰器，按 `permission` 与 `targets[]` 区分，不按物品种类分层 |
| "分裂数量 +1"（技能本无分裂） | 技能本无分裂时是 `add_behavior`，且遗物才有该权限；水晶只能改已配置的分裂数量 |
| 一个修饰器同时写改数字与加行为 | 拆成两个修饰器，各带一档权限 |
| "遗物可以改场上所有实例" | `mutate_live_instance` 默认关，需物品与技能双向声明 |
| 修饰器写"层一速度 +10%" | 写 `targets=[projectile_speed]`，不使用"层一/层二"说法 |

## 16.7 战斗中卸下与替换（2026-10-18 第二轮，D-91 已确认）

| 项 | 规则 |
|---|---|
| 语义 | 战斗中允许卸下/替换水晶；严格语义是**替换**（卸下后槽位被另一水晶占用，或槽位置空视为替换为“空”）。获得新遗物即装载，沿用 18.5 |
| 对之后生成的实例 | 旧修饰器**立即失效**：卸下 tick 之后生成的实例，不再应用旧修饰器；新修饰器按 16.4 从基准值重算后对之后生成的实例生效 |
| 对已生成的实例 | 已生成实例的 `params`、行为、`snapshot` 不变；已结算内容不变（D-44/D-45 口径、18.4）。持续区域已冻结的参数不回滚（18.3） |
| 应用点 | 替换在 tick 开始、该 tick 任何出手之前统一应用，整批原子替换，中间态不可见（《跨系统接口清单》IF-2 G2/G3）〔2026-10-18 终审修正〕 |
| 遗物（D-105） | 战斗中可卸下/替换，与水晶同口径（旧修饰器对之后生成的实例失效）；卸下或替换任一装配槽触发**装配公共冷却 CD**（时长入 CFG，推荐默认数值待手感调试），冷却期间所有装配槽操作被拒绝（2026-10-18 第三轮） |

# 第17章　三档权限与字段暴露声明

> 一句话结论：修饰器分三档权限；**没有声明的字段就不是接口**，技能设计卡必须列出"哪些字段可被改"，其余一律不可改。

## 17.1 三档权限

| 权限 | 能做 | 不能做 | 生效时机 |
|---|---|---|---|
| `mutate_number` | 改技能设计卡已暴露的数字（前摇、冷却、速度、半径、波前速度、已配置的分裂数量、已配置的持续时间） | 凭空发明技能没有的字段 | 技能被施放时读取（影响之后的施放） |
| `add_behavior` | 给技能增加原本没有的行为（穿透、分裂、到期爆炸等），并带来该行为的新字段 | 影响已在场上的旧实例（见 18.5） | 影响之后生成的实例 |
| `mutate_live_instance` | 改场上实例上已暴露为 live 的数字（如剩余持续时间、环绕半径） | 改已发生的 hit；让旧实例获得新行为；改轨迹与命中的过去 | 下一次重算起生效（见 18.6） |

规则：

1. 三档权限互相**不包含**：拥有 `add_behavior` 不等于拥有 `mutate_number`。〔D-40 推荐默认〕
2. 行为被 `add_behavior` 添加后，行为里出现的数字，仍须在设计卡的暴露声明里（或在该行为模板里预先声明）才可被 `mutate_number` 修改。
3. 过去不能改写：已结算的伤害、已发生的 hit、已选过的目标、已走过的路径，任何权限都不可回头改。

## 17.2 字段暴露声明（设计卡里的一栏）

技能设计卡（见第24章）里固定有一栏"字段暴露声明"。写法：

| 字段名 | 默认值（示例） | 可被哪档权限改 | 上下限（示例） | 是否 live 可改 | 派生体是否沿用 |
|---|---|---|---|---|---|
| `windup_ticks` | 18 | `mutate_number` | 6–30 | 否 | 不适用 |
| `projectile_speed` | 6 | `mutate_number` | 3–12 | 是 | 随 `inheritable` |
| `hit_radius` | 1.0 | `mutate_number` | 0.5–3 | 否（实例级参数，生成时定） | 随 `inheritable` |
| `lifetime_ticks` | 120 | `mutate_number` / `mutate_live_instance` | 30–300 | 是（仅延长剩余） | 否 |
| `hit_damage_base` | 20 | **不暴露** | — | — | — |

- 未列入表中的字段，一律**不可被任何修饰器修改**（白名单制）。〔D-42 推荐默认〕
- 上下限由技能作者写，管线合并后统一夹取，防止数值失控。
- "不暴露"也要显式写出，让评审者看到作者是有意为之。

## 17.3 暴露策略候选

| 候选 | 规则 | 体验 | 优点 | 代价 | 典型案例 | 与已确认规则兼容性 |
|---|---|---|---|---|---|---|
| A 白名单 | 设计卡列出的才可改，其余不可改 | 玩家可预期，构筑边界清晰 | 组合安全最强；与 D-04 一致 | 作者要多写一栏；新修饰器需回头开字段 | 本书推荐 | 兼容 D-04 |
| B 黑名单 | 默认全部可改，设计卡列出不可改的 | 构筑自由度最高 | 作者省事 | 新字段默认暴露，易产生意外组合 | 开放式模组环境 | 与 D-04"从严"相冲突 |
| C 分类默认 | 按字段类别（时间/几何/数量/伤害）给默认开关，设计卡可覆盖 | 折中 | 减少重复书写 | 类别边界需维护；伤害类默认值易吵 | 大批量技能库 | 兼容，但需先定类别表 |

推荐：**A 白名单**，理由是 D-04 已确认"高自由度拼装→组合安全从严"，白名单让"哪些能被乘出爆炸"在设计卡里一眼可查。推荐不是确认。〔D-42 推荐默认〕

## 17.4 外部做法参考（只作参考，不整套移植）

| 外部做法 | 事实 | 对本书的启发 | 采纳候选 |
|---|---|---|---|
| E3 RoR2 Proc Coefficient | 系数是缩放因子，同时乘到触发概率和持续时间；技能系数不可被修饰 | "触发强度系数"这个量**不暴露**，作者固定；只有技能作者能改 | 采纳：设计卡里"强度系数"类字段默认不暴露〔D-42 推荐默认〕 |
| E2 Noita Trigger | 载荷与外部修饰隔离；冷却/充能类属性是例外 | 派生体（载荷）默认与外部修饰隔离，继承需显式；"冷却/充能"类可作为例外 | 采纳其精神：派生体默认不继承，仅 `inheritable` 修饰例外；是否把"冷却"设为通用例外**待用户确认** |

> 说明：E2/E3 仅是外部做法；本书规则以本书各章为准，二者不是本书规则来源。

## 17.5 暴露字段的"live"标记

- 字段若允许 `mutate_live_instance`，必须在暴露声明里标注 live，并说明改动后"从现在起"还是"重算全程"（默认**从现在起**，见 18.6）。
- 不标 live 的字段，`mutate_live_instance` 对其无效；管线应在装载时报错而不是静默忽略。〔D-42 推荐默认〕

## 17.6 常见误写→正确写法

| 常见误写 | 正确写法 |
|---|---|
| "遗物让技能伤害 +50%"（设计卡未暴露 `hit_damage_base`） | 先在设计卡暴露该字段，或改为遗物走被动触发层生成额外效果体 |
| "遗物可以随便改技能的任何数字" | 只能改设计卡"字段暴露声明"里列出的字段 |
| `mutate_live_instance` 用来让旧飞弹分裂 | 不可行；旧实例不能获得新行为，见 18.5 |
| 修饰器 `targets` 写成自由文本描述 | `targets[]` 只能是暴露字段名 |
| 不写上下限 | 每个可改字段都写上下限（示例亦可），管线统一夹取 |

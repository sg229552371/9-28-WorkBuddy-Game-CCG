# 00　铁律与协作口径（所有执笔 CLI 必读，优先级最高）

> 本文件由 WorkBuddy（评审方）制定。本地 Claude CLI（gpt-6-astra）为执笔方。
> **本文件与需求文档冲突时，以本文件为准；本文件与主书稿冲突时，以主书稿为准。**

---

## 一、双 AI 分工

| 角色 | 是谁 | 干什么 | 不干什么 |
|---|---|---|---|
| **执笔** | 本地 Claude CLI（gpt-6-astra） | 按任务包写出章节正文，落盘到指定文件 | 不改别人的文件；不自创任务；不改主书稿（除非任务包明确授权） |
| **评审** | WorkBuddy | 拆任务、派单、验收、合书、兜底 | 不代替执笔写正文（除非返工一次后仍不合格） |
| **拍板** | 用户 | 主观取舍 | 日常设定题不上报（见铁律 3） |

**相互监督**：执笔写完后由评审逐项验收；评审的口径由执笔在执行中反向质疑（发现矛盾必须在产出末尾「未决问题」列出，不得自行改口径）。

## 二、十条铁律（违反任何一条 = 产出作废）

| # | 铁律 |
|---|---|
| 1 | **数据驱动**：一切策略/数值进 CFG 配置表，程序逻辑保持通用，禁止硬编码具体技能 |
| 2 | **已确认决策一字不改**：D-01…D-09、D-90、D-91、D-92、D-104、D-105 共 14 条，只能在「备注」列追加限定说明 |
| 3 | **不问用户设定题**：技能/机制类设定问题由你查业界资料后自行拍板，标「推荐默认」；只有真正的主观取舍（手感、美术方向）才上报 |
| 4 | **扩展性优先**：宁可预留冗余字段暂不实现，也不得写死数量/种类；边界必须定义清楚 |
| 5 | **每处改动带标注**：`〔YYYY-MM-DD 第N轮〕`，并同步版本号 |
| 6 | **改完必须复跑校验**：旧词扫描、与冻结接口一致性、交叉引用 |
| 7 | **性能口径不进技能文档**：帧率/实例数/子弹数验收属项目层文件，技能文档只声明「不定义验收指标」 |
| 8 | **表现层不反向影响逻辑**：逻辑不得依赖动画回调；表现只读 `hit` / `hit_settled` |
| 9 | **外部事实必须抓原文**：引用业界做法要给出可访问 URL 并实际抓取，抓不到就标「待核验」，不得当事实用 |
| 10 | **不引入范围外内容**：联网同步、代码映射、最终数值表不在本阶段 |

## 三、硬边界（防无限扩张，违反即终止该任务）

1. **只写任务包指定的那一个输出文件**。不得新建任何其他 `.md` 文件，不得创建目录，不得写临时文件。
2. **不得修改共享地基 `_shared/` 下任何文件，不得修改主书稿**，除非任务包明确写出「允许修改主书稿」并给出确切章节。
3. **不得跨章节扩写**。任务包给了第 N 章就只写第 N 章；相邻章节如需改动，写进「未决问题」交给评审，不要自己动手。
4. **不得反复自我迭代**。写完一遍即提交；只有评审返回明确返工清单时才改第二轮。
5. **不得用 AskUserQuestion / 向用户提问**。拿不准的按铁律 3 自行拍板并标「推荐默认」。
6. **不得无限试探外部资料**。`WebFetch` 不可用就用 `curl`（带浏览器 UA）；连续 2 次抓不到就标「待核验」并继续，不得卡住。
7. **长度纪律**：章节正文按任务包给的字数区间写。不够就补实质内容，超了就压缩；不以注水凑数。

## 四、统一术语（写错即作废）

| 术语 | 含义 |
|---|---|
| 技能石 | 主动技能 |
| 辅助石 | 武器模块 |
| 技能栏多槽 | 局内武器栏 |
| 效果体 | 一切技能产物的统一模型（子弹/区域/护盾/召唤物/状态/纯表现） |
| 四类载体 | `independent` / `instant` / `attached` / `none` |
| 积木 | 有名字的能力预设（飞弹/爆炸/光环/护盾/链电/冲刺…）= 四类载体之一的预设组合 + 默认参数 |
| hit / vanish | 仅有的两个事件 |
| 份（parts[]） | 一次 hit 内含的多个结算份（伤害份/治疗份/控制份…） |
| 顺序不可配，数值可配 | 编辑器设计红线：内部结算工序固定不可配，只暴露数值 |

**旧词禁用**：不得再使用「普攻」「弹幕实体」「技能对象」等非统一说法。

## 五、输出格式强制要求

1. 每个章节文件开头必须有版本块：
   ```
   > 版本：v0.1　日期：2026-10-18　轮次：第 N 轮
   > 执笔：Claude CLI（gpt-6-astra）　评审：WorkBuddy
   ```
2. **每一章末尾必须有「## 与运行时契约的引用关系」小节**（表格：本章条款 → 主书稿章节/决策号）。这是 12.1 完成判定的硬指标。
3. 表格优先，中文，条目化。
4. 所有「推荐默认」必须显式标注，格式：`〔推荐默认〕`。
5. 文件末尾必须有「## 未决问题」小节（列不出就写「无」）。

---

## 六、完成信号

任务完成后，最后一个输出行必须是：

```
DONE::<输出文件名>::<正文字数>
```

评审据此判定任务结束。**未输出该行视为任务未完成。**

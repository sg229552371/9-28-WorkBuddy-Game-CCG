## 一、冲突内容

| 来源 | 四类载体枚举 |
|---|---|
| 主书稿第 8 章 8.1「四类载体总表〔2026-10-18 终审修正〕」 | `none` / `self` / `independent` / `attached` |
| 需求文档 2.4 / 2.5 节（交接版 v1.0） | `independent` / `instant` / `attached` / `none` |
| 本流水线 `_shared/10_冻结接口约定.md` 初版 | 沿用需求文档写法（含 `instant`，漏 `self`） |

**差异**：`instant` ↔ `self`。二者不是同义词，而是两个不同的载体。

---

## 二、裁决

**以主书稿 8.1 为准。四类载体枚举为：`none` / `self` / `independent` / `attached`。**

### 依据

1. **权威层级**：主书稿《全新技能系统设计书 v0.2.6》是运行时契约本身，第 8 章带「2026-10-18 终审修正」标记，是全书最新、且经过 6 轮双 AI 交叉评审的口径。需求文档 2.4/2.5 是对主书稿的**摘要转述**，摘要出错时以原典为准。
   - **决定性证据**：主书稿**附录 B 机器可读摘要**（3863 行起，第 3893 行）以 YAML 形式写死——
     ```yaml
     carriers: [none, self, independent, attached]  # 〔2026-10-18 终审修正〕
     ```
     附录 B 是「供程序与 AI 解析」的冻结接口机器形式，且带终审修正标记。四值中**无 `instant`、有 `self`**，冲突当场可结。
2. **语义自洽**：主书稿 8.2 明确定义 `none` = 寿命为 0 的瞬时实例。也就是说，"瞬时"这一语义**已经由 `none` 承担**，不需要也不应该再有第二个 `instant` 枚举。
3. **能力不重合**：`self`（位移状态 + 跟随判定体，见主书稿 8.3、8.4）描述的是冲刺/跳跃这类「施法者自身位移且路径可命中」的能力。这套能力在 `none`/`independent`/`attached` 三者中**无处安放**——若按需求文档的枚举，冲刺类积木将没有合法载体，这正是第 4 章执笔把位移卡判为「候选并阻止导出」的原因。

### 结论：需求文档该处为转述笔误

需求文档在汇总时，把 `none` 的语义名「瞬时实例」误当成了枚举名写进四值表，同时遗漏了 `self`。

## 三、术语使用规范

| 词 | 性质 | 用法 |
|---|---|---|
| `none` | **枚举值** | 载体字段的合法取值，意为「无载体 = 寿命 0 的瞬时实例」 |
| `self` | **枚举值** | 载体字段的合法取值，意为「自身载体 = 位移状态 + 跟随判定体」 |
| `independent` | **枚举值** | 独立运行实例 |
| `attached` | **枚举值** | 附着宿主的有寿命效果体 |
| 瞬时实例 / instant | **描述词** | 可用于行文描述 `none` 载体的语义，**不得作为 carrier 字段的取值** |

**判定规则**：凡出现在 `carrier:` 字段、Schema 枚举约束、参数取值范围中的，必须是四值之一；行文中的"瞬时"描述不受此限。

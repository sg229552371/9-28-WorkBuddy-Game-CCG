# 技能与辅助水晶系统 v0.5

> 🔤 **命名（2026-10-12 统一）**：本系统正式名称 = **能量水晶系统**（作用**单个角色「武器中」的技能**）。
> 本文里的「水晶 / 辅助水晶」是旧稿用词，**同义**，不改写本文以保留原貌。命名规范见 `skill_system_master_v1.md` §0.5。
> 另：**遗迹秘宝**（旧称「芯片」）= 另一个系统（作用**全队**），与本系统**并存**，勿混。

日期：2026-10-11。状态：开发规格与首轮验证方案；尚未实现、尚未平衡验收。
本文件作为新系统设计入口，替代 v0.4 中相冲突的建议；保留旧稿。下列新增决策是本轮设计方案，不冒充用户此前确认。

## 1. 玩家规则

- **技能来源 = 武器绑定初始主动技能**：每英雄的武器绑定其**唯一一个初始主动技能**。在技能系统一侧的数据真源是 `CFG.skillSystem.initialSkillBindings[heroId]`（`weaponId` 仅作与 `CFG.weapons` 的溯源对应，`skillId` 为新路径技能定义 id）；武器不可丢弃、不可更换。
- **无普攻**：普攻已退役（`CFG.basicAttack.removed = true`）——英雄的默认输出手段就是这一个初始主动技能，不存在独立的普通攻击条目。
- **稀有技能**：局内通过雕像**最多获得一个**（池见 `CFG.skillSystem.rareSkillPool`，授予策略见 `CFG.skillSystem.rewardPolicies.RP_STATUE`）。已获得后再次触发雕像 → 转为配置的其他奖励，不重复授予；授予前按 §3 试编译过滤，与已装水晶形态冲突（如互斥运动资源）则候选不作数。
- 每英雄独立辅助组：**两个技能（初始 + 稀有）共享四颗水晶**，四槽开局全开；不向其他英雄共享水晶效果。
- 每颗水晶分别判断两个技能，符合的都强化；获取池不限制辅助对象。
- 水晶装配后本局不可卸载、替换；同 crystalId 重复获得升一级，不新增槽。不同名称或品质不能绕过 ID 合并规则。
- 等级上限由完整等级数组长度决定。品质由定义固定，重复获取不随机改变品质；品质档数由表决定。
- 水晶来自升级选择；商店、宝箱不出水晶。雕像提供稀有技能，已拥有稀有技能后转为配置的其他奖励。
- 满槽只出已装且未满级的合法升级，其他位置补属性奖励。没有合法水晶时不生成废选项。
- 装配前显示两技能实际收益、代价、限制，并明确不可拆卸；取消不消耗奖励、不重抽。

## 2. 技能如何运行

技能定义自动施放条件、索敌、冷却、效果图；技能实例记录等级与冷却。两技能独立计时，彼此不阻塞。

默认寻找范围内最近有效敌人；距离相同按稳定目标 ID 决定。无目标保持就绪，不消耗冷却。有目标则施放并进入冷却。初始技能与稀有技能同时就绪时按稳定技能 ID 执行。

环绕类改为无目标也可施放。默认只保留一批主环绕实体：有效施放间隔取冷却与环绕持续时间的较大值，持续时间结束先处理自然到期，再生成新批，避免冷却缩短令旧批永远无法自然结束。强制替换、清场与对象回收不触发消失派生。

一次施放锁定技能构建、角色进攻属性、水晶等级及派生配置。装配、升级影响后续施放；敌方防御、易伤等在命中时读取。

## 3. 适用、冲突与不可拆保护

标签说明“是什么”，能力说明“能做什么”。投射物标签不自动代表能贯穿、追踪或分裂。

装配或升级先模拟完整新组合，并满足：
1. 新水晶至少对一个已有技能产生实际收益。
2. 每颗已装水晶仍至少对一个已有技能产生实际收益，可通过派生节点或第二技能保留用途。
3. 同一技能没有互斥操作，没有无界事件链，参数和预算合法。

保护按完整已拥有技能组判断，不按单个节点判断。部分操作失效允许，但确认页必须展示失效项目；全部失效则禁止该候选。

互斥使用“资源组＋技能作用域”。首批追踪与环绕争用主运动资源，不能作用于同一技能；允许分别强化不同技能。

获得稀有技能时模拟现有四颗水晶对候选技能的作用；存在冲突则不提供该技能，不关闭已装水晶。未来技能无需提前限制当前装配；雕像候选不足则使用其他合法奖励，并提示原因。稀有技能池制作时必须检查常见构筑的可获取率。

## 4. 固定构建流程

基础图 → 主形态 → 数量与分布 → 派生模板展开 → 节点参数与伤害修正 → 校验 → 冻结构建。

- 前置条件读取基础能力；结构操作读取已完成阶段的图；数值修改读取最终图。
- 禁止操作依靠自己新增的能力满足自己的前置条件。依赖必须指向更早阶段，禁止循环。
- 同阶段同字段只能使用已声明的合并算子：add、multiply、min、max、exclusive。
- exclusive 存在多来源即冲突，不允许后装覆盖前装；不同合并算子竞争同字段必须在字段定义中给出运算次序。
- 先按稳定操作 ID 规范排序再归并，浮点数也按同一顺序计算，确保槽位排列不改变结果。
- 结构变化后重新生成效果图，不增量叠加旧构建。
- 解释器逐水晶逐技能输出 applied / inactive / conflict、命中节点、参数前后值和原因；奖励与界面共用该结果。

## 5. 伤害与命中

本版伤害类型只有物理、魔法；火焰与雷电先作为表现主题。直击、爆炸、持续区域分别持有自己的结算标签。

伤害 = 原始基准 × 形态系数 × 派生比例 × (1＋匹配外部 Increased 总和) × 各独立水晶 More × 暴击倍率 × 敌方修正。

每个修改器对同一节点只应用一次。派生引用未经外部加成的原始基准，明确继承哪些形态系数，不复制父节点最终伤害。持续伤害默认不能暴击；瞬时命中每次合法结算独立暴击。防御公式沿用现有项目，接入前核对，禁止另加一层重复减伤。

本项目首轮明确采用：
- 同一施放的主飞行弹对同一敌人共享一次直击额度；扇射提升覆盖，不默认多弹集中叠伤。
- 分裂子弹使用独立的一次直击额度，同一施放同模板对子弹目标去重；生成处被击目标加入排除集合。
- 爆炸同一施放同模板对同一敌人最多一次，可与直击各结算一次。属于项目规则，不声称与 POE 火球一致。
- 环绕接触按“施放者＋技能＋接触模板＋目标”共享受伤间隔，多枚环绕体不绕过间隔。
- 同英雄、同技能、同区域模板的持续区域重叠取最高有效 DPS；不同英雄或技能可叠加。
- 持续伤害按独立于渲染帧的模拟时间积分，以 DPS × 有效时间结算；同组区域共享结算时钟，不能通过错开出生时间额外叠 tick。固定 tick 只决定结算批次；结束时补齐最后不足一个 tick 的有效时间。

以上规则均写入 hitPolicies 与 stackPolicies，可在明确平衡实验后调整。未命中额度的飞行弹仍处理碰撞与贯穿，但不发出“伤害命中”事件，不制造额外分裂。

## 6. 事件与派生

主效果由施放直接创建，扇射产生的全部主弹都属主效果。命中或自然消失产生的实体是派生，不算新施法。

默认只有主效果触发事件水晶；派生仍接受符合条件的贯穿、范围、伤害等直接修正。首批不开放二层事件联动。

事件统一包含 castId、ownerId、skillId、effectId、parentId、templateId、operationId、targetId、depth、simulationTime、endReason。

处理顺序：合法伤害结算 → 首次伤害命中事件 → 贯穿与结束判断 → 消失事件。事件队列按稳定序号消费；死亡目标仍可提供本次已锁定的碰撞位置。

自然命中结束、寿命结束、距离结束可派生；批次替换、场景清理、离局、强制回收不可派生。每实例首次伤害命中和消失各只发一次。

未来有界联动必须同时配置来源白名单、允许操作、最大深度、次数、每施放实体预算、终止条件。禁止仅用 allowDerived 开关放开全部递归。

## 7. 首批通用辅助机制：用火球验证

这八颗是首批内容，不是总数上限，也不是火球专属库。

| 水晶 | 改变 | 适用对象与限制 |
|---|---|---|
| 贯穿 | 增加额外贯穿目标数 | 具备贯穿计数的主/派生飞行弹；不改变环绕接触 |
| 扇射 | 增加主效果数量，降低单体基准系数 | 支持数量分布的主生成器；飞行扇形、环绕均匀分布；不增加分裂数量 |
| 追踪 | 主飞行弹持续转向索敌 | 支持转向的主飞行弹；失去目标重选，无目标沿原方向；与环绕互斥 |
| 分裂 | 首次伤害命中产生小弹 | 主投射物；父体继续与否由贯穿/形态决定；小弹不再触发事件水晶 |
| 爆破 | 主实体自然消失产生瞬时范围伤害 | 有位置的消失事件；不由清理触发 |
| 余焰 | 主实体自然消失产生持续区域 | 不另加瞬时伤害；重叠按最高 DPS |
| 扩域 | 扩大最终图中的伤害范围半径 | 爆炸、火场；不改弹体、扇角、索敌或环绕距离 |
| 环绕 | 主弹改为围绕英雄的接触实体 | 可环绕适配的生成器；一批实体、共享目标间隔；与追踪互斥 |

分裂沿父弹命中前方向展开，环绕沿接触点切线展开。扩域采用半径 multiply 算子，范围面积随半径平方变化，必须在平衡测试中记录。

## 8. 获取和升级

流程：合并获取池 → 按 ID 去重 → 新装/升级分类 → 完整组合模拟 → 权重抽取 → 属性兜底 → 确认并原子提交。

- 两池同 ID 权重默认取 max，不自动相加；权重合并策略可配置。
- 升级候选取定义下一等级完整参数，重新检查冲突、已装水晶用途和预算。
- 奖励生成时保存候选与随机状态；取消不改变结果。提交再次检查版本与当前状态，rewardId 只能兑现一次。
- 升级不占新槽；满级移出候选。非法新装不以灰色废选项占位。
- 若不足配置选项数，补合法属性奖励；仍不足则显示实际数量。
- 品质控制定义定位与出现权重，不单独再乘伤害，避免重复品质加成。

## 9. 配置与通用程序

配置表：skillDefs、effectTemplates、crystalDefs、qualityDefs、rewardPools、rewardPolicies、supportGroupRules、hitPolicies、stackPolicies、eventPolicies、budgetPolicies、migrationMaps、localization。

程序职责：配置校验器、辅助编译器、自动施放器、通用效果执行器、伤害结算器、事件路由器、奖励事务、说明生成器、存档迁移器。

已有能力内新增技能/水晶只改配置。新底层机制可以增加通用执行器；禁止判断具体技能/水晶 ID 或名称来决定战斗行为，配置不允许嵌入任意脚本。

最小数据契约：
```js
// 示例仅表示结构，不是最终数值。
{
  id: 'CR_PIERCE', qualityId: 'Q_COMMON',
  eligibility: { read: 'base', capabilitiesAny: ['flightProjectile'] },
  operations: [{
    id: 'pierce.count', executor: 'modifyParameter', phase: 'nodeModify',
    selector: { read: 'final', capabilitiesAll: ['pierceCounter'] },
    field: 'extraPierceCount', parameter: 'count', merge: 'add'
  }],
  levels: [{ parameters: { count: 1 } }, { parameters: { count: 2 } }],
  presentation: { nameKey: 'crystal.pierce', detailKey: 'crystal.pierce.detail' }
}
```

技能必填：id、levels、targetPolicy、castPolicy、baseGraph、rewardPoolIds。节点必填：nodeId、templateId、role、tags、capabilities、parameters、damageBasis、hitPolicyId。事件操作另填 event、sourceSelector、spawnTemplateId、damageBasisRef、inheritFactors、routePolicyId。

单位：秒、角度度、世界距离单位、概率 0~1、数量整数、倍率 1 为原值；无上限必须用明确枚举，不能把 0 同时解释为无效和无限。持续 tick > 0、冷却 > 0；数组每级为完整状态。

加载校验重复 ID、未知字段/执行器、引用、参数范围、等级连续性、阶段依赖环、资源冲突、事件终止、预算上界、文案占位符及奖励可达性。开发环境拒绝非法配置并定位到定义/操作/字段；正式环境禁用错误定义，奖励兜底并记录诊断，不半应用错误组合。

## 10. 首轮测试内容与数值处理

验证技能：火球（碰撞飞行弹）＋震荡波（瞬时魔法范围技能）。通用魔法增幅同时辅助两者；贯穿只辅助火球；扩域辅助震荡波及火球派生范围。震荡波先作为验证配置，不代表已确定正式雕像内容。

八颗机制水晶之外增加一个通用魔法增幅测试定义，用于证明跨能力共享，不扩大首轮正式内容承诺。

数值流程：读取当前英雄有效伤害/冷却作为迁移基准 → 建立无水晶单体与群体基线 → 填首轮参数表 → 测每颗及全部合法四槽组合 → 调整输出、覆盖与对象数。不得把结构示例数值当上线平衡表。

最坏预算按主实体数、每主实体派生数、可并存施放批次、持续区域时长计算；每施放与每英雄运行预算均进表。超限配置优先加载拒绝；运行兜底按稳定创建顺序截断新派生并记录，不随机删已有伤害实体。具体预算与目标设备帧耗根据真实测试填入，不凭空宣称性能达标。

## 11. 界面与表现

技能面板展示两个技能、四槽、等级、实际辅助矩阵；详情列出作用节点、收益代价、事件限制、冲突与不适用原因。汇总标签仅展示，结算使用节点标签。

文案从配置和解释结果生成。火球、小弹、爆炸、火场需易区分；品质颜色与伤害主题分开，图标不能只靠颜色辨识。装配升级时预览变化，确认后同步刷新两个技能。

## 12. 现有代码迁移

实读确认：game.js 的玩家战斗已停用普攻，按冷却自动施放；不能再声称当前仍执行普攻。items.js 仍返回 basic/skill 兼容字段，config.js/moduleDefs 与 recomputeWeapon 仍存在全队模块语义，需要迁移。

- 配置新增新表，旧模块只经明确映射进入新实例。
- run 中建立每英雄 supportGroup；解析与缓存不再把所有英雄水晶聚合为全队修正。
- Player 与队友调用统一自动施放入口，新增稀有技能独立冷却。
- 保留短期旧字段适配层，但不得与新路径同时伤害/加成。
- 奖励、UI、召唤/陷阱兼容接入逐项验证。首轮先验证投射物与范围；召唤/陷阱需各自专用能力契约后再迁移，不用投射物字段硬套。
- 遵守 AGENTS.md：通用新增逻辑独立区块，原入口插单行调用，数值进入 CFG，不变更英雄物理索引；真正修改 JS 后更新版本并执行门禁。

## 14. 开发验收

1. 两技能自动施放；同一水晶可同时强化两技能，只占一槽。
2. 每英雄水晶独立；池归属不决定效果归属。
3. 满槽、满级、取消、重复提交与奖励兜底正确。
4. 所有槽位排列得到相同构建、参数与解释。
5. 爆破生成范围节点后扩域生效；装配不能令已有水晶全部无效。
6. 新稀有技能冲突被候选过滤，不暗中停用已装水晶。
7. 主弹/子弹/爆炸命中额度、环绕间隔与火场重叠符合本版规则。
8. 派生不复制最终伤害；默认不递归；清理不派生。
9. 升级不改已有实体；不同帧率累计持续伤害一致。
10. 非法配置、旧存档与预算超限都有可定位报告。
11. 测全部合法四槽组合、单体/群体/贴身场景与最坏对象数；数值及性能报告通过后扩内容。

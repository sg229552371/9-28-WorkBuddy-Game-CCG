# 技能系统开发合同与任务拆分 v1.0

> 🔤 **命名（2026-10-12 统一）**：本文的「水晶 / 技能系统」= **能量水晶系统**（代码 `CFG.skillSystem` / `CR_*`）；
> **遗迹秘宝**（旧称「芯片」，代码 `CFG.chips`）是**并存**的另一系统（作用全队），**不在本合同范围**。
> 命名规范见 `skill_system_master_v1.md` §0.5。

日期：2026-10-11。
用途：交给后续 AI 开发者执行的工程合同。本文优先于 design_crystal_skill_system_v0.5.md 的技术建议；用户已确认玩法不得由开发者自行改动。
状态：前期设计，未实现。不能据此宣称测试通过或已经上线。

## 1. 开发目标与边界

构建每英雄独立、两个自动技能共享四槽辅助水晶的数据驱动系统。新增已有能力范围内的技能与水晶，必须只修改配置；新增底层机制允许增加通用执行器。

第一交付范围：基础自动施放、两个技能、四槽与升级、辅助编译、投射物/瞬时范围/持续范围、八颗试点水晶、获取与解释 UI、存档兼容、组合测试。用火球与震荡波验证不同能力；通用魔法增幅作为共享辅助测试定义。

第一交付不扩展：元素转换、异常状态、完整 POE 规则、无限事件联动、召唤物 AI 重做、陷阱体系重做、大量新技能。现有召唤/陷阱功能必须维持旧路径可用，不能因第一交付覆盖不全而删除。

本文的设计选择需要实现和验证；具体平衡参数未定案。开发者不得把示例参数、占位值或建议当成已验证上线数值。

## 2. 规则优先级

用户明确确认的铁律 > 本文合同 > v0.5 补充说明 > 旧设计与代码注释。
项目 AGENTS.md 的文件组织、测试与版本要求适用于实现过程。用户本次授权是规划文档，不包含提交、推送或部署游戏。

### 已确认玩法

- 初始一个自动技能，无独立普攻；局内最多增加一个稀有技能。
- 每英雄四个共享辅助槽，开局全开；两技能分别判断每颗水晶。
- 水晶本局不可卸载、替换；同定义重复获取升级，不占新槽。
- 获取池只控制候选来源与权重，不控制辅助对象。
- 满槽排除未装水晶，满级排除升级，无合法水晶用其他奖励兜底。
- 默认派生不能再次触发事件水晶；有限联动必须有明确边界。
- 槽位与装配顺序不改变组合；已发起施放及派生使用快照。
- 节点标签参与结算，汇总标签只展示；派生加成只计算一次。
- 装配前可查实际收益、代价、条件、互斥、触发限制。

### 本轮明确提出的项目方案

采用 v0.5 的不可拆用途保护、稀有技能冲突过滤、同施放命中额度、最高 DPS 火场重叠及环绕批次规则。它们不是用户历史拍板，也不是 POE 事实。开发者应实现为可配置策略并提供验收场景；不得自行换成相反规则。

## 4. 模块边界

建议独立文件 js/skill-system.js，内部按职责分区。最终文件位置须遵守 AGENTS.md，不引入打包器、ES 模块或外部运行库。新文件加载在 combat.js 之后、首次运行初始化之前；须实读 index.html 确认。CFG 数据仍收口到 config.js 的独立新增区块。

| 模块 | 输入 → 输出 | 禁止承担 |
|---|---|---|
| SkillConfig | 原始表 → 校验后的定义索引 | 操作世界或 UI |
| SupportCompiler | 技能定义、等级、水晶实例 → BuildResult | 随机、碰撞、改 run |
| SkillScheduler | 英雄状态、模拟时间 → 施放请求 | 直接结算伤害 |
| EffectRuntime | 快照、世界 → 效果实例与事件 | 自行识别水晶 ID |
| DamageResolver | 节点伤害、目标状态 → 伤害结果 | 生成奖励 |
| SkillEventRouter | 合法事件、路由策略 → 派生请求 | 无界递归调用 |
| SkillRewardService | 实例、池、随机源 → 候选与事务 | 修改已飞出的效果 |
| SkillPresenter | 编译解释、配置文案 → UI 数据 | 再计算一套适用规则 |
| SkillSaveAdapter | 存档版本 → 可恢复状态与报告 | 静默丢弃资产 |

依赖方向：配置 → 编译 → 施放/运行 → 结算与事件。奖励和展示调用编译器；编译器不反向依赖奖励或 UI。

## 5. ID、实例与数据所有权

定义 ID：稳定字符串，发布后不可随意重用。显示名称可变，不能用于逻辑判断。
实例 ID：本局递增稳定 ID。castId、effectId、rewardId 不可在回收后重复用于仍存活的去重键。

- Definition：配置所有，加载后只读。
- HeroSkillState：本英雄所有，包含技能实例、水晶实例、辅助组版本与冷却。
- BuildResult：编译器所有，创建后只读，可按配置版本与组签名缓存。
- CastSnapshot：一次施放所有，运行实体仅引用，不原地修改。
- EffectInstance：世界所有，可变位置、寿命和状态；回收时清空所有运行字段。
- RewardTransaction：奖励服务所有，生成后固定候选，提交只生效一次。

辅助组缓存键包含 configVersion、英雄必要基础差异、技能 ID/等级、水晶 ID/等级、编译策略版本；水晶先按 ID 规范排序。若外部属性不进入构建，只在施放快照读取，不使每帧重新编译。

## 6. 数据字段合同

### 技能定义

必填：id、nameKey、levels、baseGraph、targetPolicyId、castPolicyId、rewardPoolIds。
levels 是连续数组，每项完整参数；level 从 1 开始，对应数组下标 level-1。技能等级成长来源沿用项目实际路径，先审查，不额外发明第二套升级经济。
baseGraph 包含节点数组与显式事件边；不能在描述字符串中藏战斗规则。

### 效果节点

必填：nodeId、templateId、role、tags、capabilities、parameters、damageBasis、hitPolicyId。
role 取 primary / derived；不是依靠命名猜测。
模板类型首批：flightProjectile、orbitContact、instantArea、persistentArea。
damageBasis 明确 baseRef、coefficient、inheritFactorKeys；baseRef 引用原始伤害源，不能引用已结算结果。
节点标签分开描述伤害类型、作用方式与可加成分类；碰撞半径与伤害范围半径是不同字段。

### 水晶定义

必填：id、nameKey、qualityId、eligibility、operations、levels、presentation。
eligibility 指明 readStage 和条件表达式；表达式只允许 all / any / not / 标签 / 能力 / 声明参数比较。
operations 每项必填 id、executor、phase、selector、参数引用和合并算子。事件操作另填 event、sourceSelector、spawnTemplateId、damageBasisRef、inheritFactors、routePolicyId。
禁止配置携带函数、eval 字符串、任意 JS 表达式或文件路径执行命令。

### 策略表

每个策略有稳定 ID、明确作用域、上限和默认值。不得把缺失值默认为无限。必需字段缺失应报错；可选字段的默认值统一由 schema 定义，不能散落在执行器中。

时间秒、角度度、距离世界单位、概率 0~1、数量非负整数、倍率 1 为无变化。负数仅在字段 schema 明确允许时合法。禁止 NaN、Infinity 和隐式字符串转数值。

## 7. 通用 API 合同

名称可根据现有项目调整，但职责与返回信息不得丢失。

```js
validateSkillConfig(rawConfig) // { ok, definitions, diagnostics }
compileSupportGroup(input)    // { ok, builds, explanations, diagnostics, signature }
previewCrystalChange(state, change) // { legal, nextGroup, result, reasonCodes }
createCastSnapshot(hero, build, stats, castId) // 只读快照
updateHeroSkills(world, hero, dt) // 统一自动施放入口
spawnEffect(world, snapshot, nodeId, spawnContext) // { accepted, effectId, reason }
resolveSkillDamage(world, damageRequest) // { applied, amount, killed, reason }
enqueueSkillEvent(world, event) // 入队，不同步递归派生
buildSkillRewards(state, source, rng) // 固定候选事务
commitSkillReward(state, rewardId, optionId) // { committed, nextState, reason }
serializeHeroSkills(state) // 可序列化对象
migrateHeroSkills(saved, definitions) // { state, report, preservedOriginal }
```

返回结构稳定，业务不可依赖中文错误文案判断分支。原因码例如 NO_COMPATIBLE_NODE、SLOTS_FULL、MAX_LEVEL、MOTION_CONFLICT、EXISTING_CRYSTAL_INACTIVE、INVALID_REFERENCE、EVENT_BUDGET_EXCEEDED、ALREADY_COMMITTED。

## 8. 编译算法

1. 校验实例引用、等级与四槽限制。
2. 展开两个技能的基础效果图。
3. 读取基础能力，筛选结构操作。
4. 按主形态、数量分布、派生模板三个阶段构建完整图。
5. 在最终图匹配参数、范围、伤害等修改器。
6. 按字段的固定算子顺序归并；来源按稳定操作 ID 排序。
7. 校验资源互斥、事件终止、伤害基准、命中策略与预算。
8. 生成每颗水晶对每个技能的逐操作解释。
9. 检查新装有实际收益，且已有水晶至少在一个已有技能保留收益。
10. 输出只读构建或完整失败报告；不发布半成品构建。

收益包括合法行为改变和有效参数改变。乘数 1、数量 +0、没有节点匹配不算收益；负面代价不能单独被认定为适用收益。

结构操作不得靠自己添加的能力通过前置检查。操作只读取本阶段以前已完成的结构；无固定点反复试算，不无限直到“稳定”。

## 9. 运行时顺序

沿用现有世界更新主流程，插入点由审查确定，避免重跑移动/碰撞。技能内部固定顺序：

到期处理 → 自动施放请求 → 实体生成 → 运动与碰撞 → 合法伤害 → 首次命中事件 → 贯穿/结束 → 消失事件 → 事件队列派生 → 回收。

队列消费必须有限。新派生可在本步创建，但首次运动/碰撞从下一模拟步开始，防止出生即在同一步递归碰撞。暂停不推进模拟时间；界面动画不得推进战斗计时。

同一步多个碰撞按碰撞发生时间、距离、目标稳定 ID 排序。高速飞行弹使用扫掠碰撞或现有等效可靠机制，不能只检查终点而穿过敌人。对象池回收必须在本步已引用事件完成后进行，事件保存必要标量，不能引用已回收后会变内容的实体对象。

## 10. 命中与伤害合同

- 主飞行弹：castId＋主直击组＋targetId 共享一次伤害额度。
- 分裂飞行弹：castId＋派生模板组＋targetId 共享一次额度，出生目标被排除。
- 爆炸：castId＋爆炸模板组＋targetId 共享一次额度；可与直击各伤害一次。
- 环绕：ownerId＋skillId＋接触模板组＋targetId 共享 nextAllowedHitTime。
- 持续区域：ownerId＋skillId＋区域模板组取该目标有效最高 DPS，按共同模拟时间结算。

去重键不是永久全局集合。按施放生命周期或区域生命周期释放；目标死亡/回收需要稳定目标 ID，避免对象池复用误认旧目标。

碰撞无伤害额度时不发伤害命中事件，但仍按节点碰撞策略处理贯穿与消失。爆炸等消失派生仍受自身目标额度限制。

伤害基准只含原始数值及明确形态系数；匹配外部加成与水晶倍率在当前节点一次应用。采用项目现有防御和取整规则时先记录实际公式。持续伤害默认不暴击；输出展示和日志必须能追溯来源。

火场重叠按时间段计算有效区域的最高 DPS；区域进入、退出、出生、消失是变化边界，不能把采样瞬间最高 DPS 当成整段一直有效。首轮允许采用固定模拟步近似，但必须声明误差目标并通过帧率一致性测试。

## 11. 自动施放与环绕

每技能独立冷却。没有目标不消耗普通技能冷却；环绕允许无目标。

环绕有效周期 = max(冷却, 持续时间)。同一英雄同技能只一批主环绕实体，自然结束可触发爆破/余焰；强制替换不触发。扇射改变环绕数量与分布，不绕过共享受伤间隔。

冷却缩减下限、持续上限、索敌范围均为配置。冷却降低不自动提高移动速度或伤害。角色死亡、失活、离局停止施放并按清理原因回收。

## 12. 奖励事务与雕像

奖励生成与提交分离。生成时锁定 rewardId、候选、randomState、groupVersion。取消保留该事务。提交校验事务未兑现、选项有效、组版本和完整新组合。

单线程也须防重复点击：先标记提交处理中，原子更新技能组和事务状态，再发 UI 通知。失败不消耗奖励、不重复随机。已有候选因合法状态变化失效，保留事务记录并生成明确替代流程，不偷偷改玩家已选收益。

稀有技能候选加入当前组试编译；与已装形态冲突则过滤。候选不足其他奖励兜底。雕像概率、交互条件、选项数量、重复雕像处理都属于 rewardPolicies 参数，不硬编码在场景对象。

## 13. UI 合同

UI 仅消费解释结果。不得通过水晶名字再次判断“是否能用”。

装配页必须展示：不可卸载、占槽、两技能收益、失效操作、负面系数与冲突。升级页展示该级到下一等级的参数变化。四槽界面显示定义、等级、品质、实际辅助对象。

详情与战斗使用同一参数版本；隐藏汇总标签不隐藏代价。取消不刷新随机列表。按钮状态反映事务状态，错误提示使用原因码映射的中文文案。

遵守竖屏与三处 CSS 同步要求；开发验收覆盖 390×844 及横屏，不仅检查桌面截图。

## 14. 兼容与迁移

新旧战斗路径必须明确分流，不能同一技能两路施放或两路增伤。适配层只翻译数据与调用，不再次乘数。

新增系统以配置开关接入首批英雄；未迁移英雄继续旧路径，记录覆盖范围。最终扩展前验证召唤/陷阱各自能力，不假装全部已支持。

存档迁移必须备份原始有效存档，按版本执行一次。未知 ID、旧九级超过新等级、冲突旧组合不能静默删掉；输出报告并保留原始数据。映射表需要逐项审核，不能按名称相似自动匹配。

运行中恢复若项目已有则保持兼容；若未有，本次不顺便承诺跨版本恢复。configVersion 不匹配不得把新表直接套到旧实体快照。

## 15. 性能与失败策略

定义每施放实体/事件预算、每英雄活动实体上限、队列消费上限和深度上限，全部进配置。预算包括并存施放批次，不只统计一次分裂。

加载阶段能算出的超限组合直接拒绝。运行超限拒绝新的派生请求并记录原因；不随机删旧实体、不降低碰撞或改伤害作为画质优化。画质降档只能裁减视觉效果，不改变命中、持续伤害与事件。

对象池 reset 必须清空来源、快照、去重、计时、死亡状态与上一目标。开发环境追踪重复回收、重复消失、孤立引用。诊断设开关与容量上限，禁止每帧无限日志。

| E 内容 | 八颗机制及增幅测试定义 | 完整等级表、文案、组合报告 | 无具体内容 ID 特判 |
| F 获取/UI | 四槽、升级、事务、雕像、详情 | 玩家完整操作链 | 满槽与取消等边界正确 |
| G 迁移 | 每英雄组、新旧适配、存档映射 | 迁移报告及回退说明 | 资产无静默损失 |
| H 验收 | 门禁、浏览器、帧率、性能、平衡 | 证据报告、文档更新 | 满足本合同后才准备代码交付 |

B 依赖 A；C 依赖 B；D 依赖 C；E 依赖 D；F 可在 C 后按固定 API 并行，但集成验收依赖 E；G 设计在 A 开始，实施依赖稳定数据版本；H 最后执行。

多 AI 并行必须先约定文件所有权。config.js 和 skill-system.js 由唯一集成者写入；其他 AI 可提供独立配置草稿或测试文件，不能同时编辑同一文件。接口改变先更新合同再通知依赖任务。

## 17. 测试合同

测试输入固定随机种子与模拟时间；测试工具不依赖真实 DOM 除非验证 UI。

必要案例：
- 两技能共享一颗增幅；贯穿对范围技能 inactive；每英雄不串效果。
- 空槽装配、同 ID 升级、满槽、满级、无候选兜底、重复提交、取消保持随机。
- 爆破加扩域的两种获取顺序、所有槽位排列、升级不重复叠加。
- 贯穿后环绕导致唯一用途消失被拒；有适用派生或第二技能时允许。
- 追踪与环绕同技能冲突；未来稀有技能冲突被过滤。
- 主弹同目标额度、子弹出生排除、爆炸独立一次、环绕共享间隔。
- 火场出生错位、重叠、进入退出、到期残余时间，不获得额外 tick。
- 死亡/清理/回收不派生，自然消失只一次；子弹默认不递归。
- 已飞出对象升级前后伤害不变，新施放读取新等级。
- 未知执行器、坏引用、循环依赖、NaN、零 tick、无界路由和超预算拒绝。
- 对象池复用后无旧目标、旧命中额度或旧快照污染。
- 旧存档迁移可追溯且可重复运行而不重复补偿。

组合枚举：所有装配数 0~4 的定义组合、合法等级组合或明确覆盖的边界等级。首批定义少，优先穷举结构组合；等级全组合过大则记录覆盖策略，不能只测一套“最强配置”。排列测试与属性测试检查不变量，不能简单复制实现公式作为独立正确性证明。

帧率测试至少覆盖固定 30/60/120 FPS 和抖动 dt；统计累计伤害、事件数、实体数和结束状态。随机数、暴击种子及目标运动相同，记录允许的离散模拟误差。

运行项目现有 quick 和全量门禁，报告实际 suite 数与断言数；每项 exit=0 且 bad=0。不能沿用旧文档数量宣称本轮通过。

## 18. 开发者禁止事项

- 按火球/水晶名字或 ID 写战斗特殊分支。
- 用槽位顺序、装配时间决定修改器覆盖。
- 直接修改只读定义、缓存构建或旧施放快照。
- 派生复制最终伤害再套加成。
- 全队汇总新水晶、从池来源推断辅助对象。
- 事件处理同步递归到没有深度/次数/预算限制。
- 只改文案而保留相反运行规则。
- 因已有字段不方便而降低不可卸载、共享辅助等铁律。
- 测试未运行却写通过，UI 可见就宣称系统完成。
- 顺便重构无关系统或引入新的构建工具链。

## 19. 交付报告模板

每阶段报告：实现范围、修改文件及入口、配置变化、兼容路径、真实测试命令与结果、未通过项、尚未覆盖项、下一阶段依赖。
最终报告另附：所有规则到实现/测试的对应表、组合测试摘要、伤害来源示例、最坏预算与帧耗、存档迁移样例、已知限制及回退操作。提交推送与独立托管发布按届时用户授权执行，不能把文档生成当成发布完成。

## 20. 需要后续证据闭合的内容

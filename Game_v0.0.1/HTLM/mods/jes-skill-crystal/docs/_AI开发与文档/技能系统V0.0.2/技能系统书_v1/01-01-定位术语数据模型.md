# 第 1 章　定位与边界

## 1.1 核心定义与唯一理由

**定义「一个技能在数据上是什么」——把策划脑子里的技能，变成一份合法、可预览、可保存、能被运行时 100% 还原的 CFG。**

编辑器存在的唯一理由，是让不会写代码的人通过「选积木 + 填参数」造出技能，且造出来的东西运行时一定跑得起来、结果就是预览里看到的样子。作者不需要理解引擎内部工序，不需要填写运行时实例编号，也不需要为每个技能编写专用逻辑。作者必须能够说明想做什么，选择承载该能力的积木，在允许范围内填写参数，并看到配置所对应的行为与表现。

这里的「合法」不是文件能够解析，而是所选能力已登记、字段有定义、引用可解析、参数符合范围、组合没有违反运行时契约。「可预览」不是播放一段相似的演示动画，而是用该份配置驱动约定的运行时能力。「可保存」不是把任意表单状态写进文件，而是形成能再次打开、恢复语义的正式 CFG。「100% 还原」约束的是配置语义完整性，不能靠预览专用补丁或运行时猜测来弥补遗漏。

一致性比较须固定运行时版本、初始场景、种子、操作序列及相关资源版本；运行时确定性承诺沿用主书稿的同平台口径，不扩大成跨平台逐像素一致。换了目标属性、种子或输入，不属于同一实验。表现资源未指定或尚不可用时，预览必须明确显示缺项，不能用占位表现冒充最终效果通过验收。

## 1.2 读者、责任与完成含义

| 角色 | 在本规格中得到什么 | 不应被要求承担什么 |
|---|---|---|
| 技能作者 | 能力选择、参数含义、默认值、错误定位、预览结果 | 手写结算算法、理解调度队列、猜测隐含规则 |
| 编辑器实现者 | 稳定数据边界、登记格式、字段来源、交付条件 | 自行创造一套与主书稿不同的技能语义 |
| 运行时实现者 | 唯一 CFG 入口、已冻结字段、可追溯能力声明 | 从中文名称推断逻辑，容忍不明确的默认值 |
| WorkBuddy | 可逐项评审的条款、来源、冲突与验收例子 | 把推荐默认自动升级成用户已确认 |
| 用户 | 对方向与主观效果的最终决定权 | 回答每一处日常字段设定题 |

本文件属于新系统规格阶段的分章交付，不涉及实现代码。文中的验收例子是后续测试依据，不等于测试已经执行。读完本章应能分清作者是在配置能力还是在改写引擎；读完第 2 章应能用同一套词解释一次预览；读完第 3 章应能认出 CFG 七个顶层键及其责任，而不会把运行时状态写回技能资产。

本章不声明完整编辑器已经可用。完成本章只意味着定位、边界和数据责任已形成可评审文本；完整能力登记、参数目录、表现配置和 Schema 仍由后续章节交付。依赖未完成时必须显示为未完成，不能以「默认已有实现」消除问题。

## 1.3 第一根柱子：积木体系

积木是有名字的能力预设，等于一种载体的预设组合加默认参数。作者看到的是「直线飞弹」「瞬时爆炸」「护盾」等能力名称，而不是被迫从一张巨型参数表猜出组合方法。一个名字必须对应可追溯的登记卡；同名描述不能在预览和正式运行中各指一种行为。名字可以方便理解，不能成为运行时选择专用算法的暗号。

| 积木必须回答的问题 | 登记入口 | 对作者的意义 |
|---|---|---|
| 这是什么、能做什么 | `brick_id`、`name`、`tagline`、`summary` | 先选能力，避免先面对底层术语 |
| 默认就能做出什么 | `carrier`、`default_cfg` | 默认片段有明确语义，不是空壳 |
| 我可以调什么 | `author_params` | 表单只展示已开放的参数 |
| 为什么有些项不能调 | `locked_params` | 锁定有原因，不伪装成失效输入框 |
| 水晶或遗物能改什么 | `relic_params` | 作者权限与修饰权限分别声明 |
| 如何呈现、如何描述 | `presentation`、`player_text` | 表现与玩家说明能追溯到能力 |
| 是否可以正式使用 | `status` | 区分已登记、候选和预留 |

积木数量不固定，也不把当前角色数量当成能力数量上限。扩展时先确认现有能力是否足以表达，再决定登记新预设还是申请新增运行时能力。仅仅换颜色、换名称或换合法数值，不自动构成新的底层能力。反之，缺少一种运行时行为时，不能通过把说明文字写得更长、把参数取到极端来冒充实现。

〔推荐默认〕作者浏览时允许看到候选与预留项及其缺失说明，但正式 CFG 只接受已登记且依赖完整的积木。此默认是可用性约束，不给第 4 章预先规定积木数量。第 4 章负责逐块登记和扩展流程；本章只要求每块有身份、默认能力、开放边界与使用状态。

积木组合表达能力关系，不提供内部工序编排。作者可以在已登记模板允许的范围内选择效果与派生目标；不能拖动一个名为「结算」的节点来改变引擎阶段。模板没有开放的连接不能靠数组位置或任意字符串偷偷接通。

## 1.4 第二根柱子：表单与校验

表单是 CFG 的受控入口，不是另一个数据模型。每个可编辑控件都应能追溯到具体字段路径；相同含义不能在不同页面保存成不同字段。填写前能看到类型、单位与默认值，填写后能知道是否有效，错误发生时能定位到实际输入位置，而不只是得到「技能配置错误」的总提示。

| 层面 | 本规格要求 | 不允许的替代做法 |
|---|---|---|
| 单字段 | 检查类型、必填、范围、枚举与引用目标 | 让运行时把任意字符串强制转换后继续 |
| 跨字段 | 按契约检查载体、寿命、权限等组合约束 | 每个字段单独合法就视为整份配置合法 |
| 跨积木 | 检查引用是否存在、关系是否有登记依据 | 用显示名称猜引用目标 |
| 输出前 | 检查默认展开后的有效配置 | 只检查作者改动过的字段 |
| 错误定位 | 对应具体 Schema 路径和文案登记 | 让作者自己排查整份 YAML |

参数登记严格使用字段名、类型、默认值、取值范围、单位、必填、分级、所属积木、Schema 路径九列。新手、进阶、专家是展示层级，不是三套规则。隐藏高级项不能删除它的值；展开专家项不能获得修改锁死参数的权限。无默认值须显式登记为无默认，不能把空值、零和未填写混为一谈。

校验由运行时契约反推。瞬时实例寿命为零、附着效果需要宿主与终止依据、未暴露字段不能被修饰，均有上游语义依据；本章不另造战斗规则。第 14 章负责 `V-###` 规则，第 15 章负责 `E-####` 文案。本章验收编号只用于规格评审，不抢占这两套编号空间。

〔推荐默认〕不合格工作状态可保留在编辑会话中，但不得以正式可运行 CFG 的身份导出或替换已有合格版本。是否提供草稿恢复及其存储形式留给组织与存档章节，不新增第八个 CFG 顶层键。警告和提示不应被一概升级为阻止保存，也不能把阻止保存降格成可忽略提示。

## 1.5 第三根柱子：表现层配置

表现层是交付核心，不是逻辑完成之后可随意略去的装饰。作者必须能为技能选定视觉、声音和反馈方式，预览时能辨认出手、持续、命中与结束。表现缺失会使作者无法判断配置表达是否符合意图；但表现丰富不能弥补逻辑字段缺失，更不能决定逻辑结果。

| 固定配置段 | 作者配置的内容范围 | 与逻辑的边界 |
|---|---|---|
| `fx` | 生成、持续、消失特效 | 绑定效果体生命周期，不创建第三种事件 |
| `sfx` | 音效时点、优先级、并发上限 | 音效是否播放不决定命中是否成立 |
| `anim` | 施法者动作、逻辑出手 tick 与动画帧对齐 | 由逻辑出手驱动对齐，不等动画回调出手 |
| `trail` | 载体轨迹、拖尾寿命、淡出 | 不把拖尾长度当成逻辑判定长度 |
| `camera` | 震屏、推拉 | 不改变位置判定、目标选择或结算 |
| `damage_number` | 数字合并及结果显示 | 读实际结果，不自行重算一遍伤害 |
| `status_icon` | 增益、减益、控制的图标与堆叠显示 | 状态存在与否由逻辑确定，不由图标控制 |

正式结果表现只读 `hit` / `hit_settled`；不得订阅调试记录来决定正式反馈，也不得让特效结束、音效结束或动画帧回调修改逻辑。生命周期绑定与结果订阅属于不同用途：`fx` 的生成、持续、消失绑定要求应保留，但不能因此宣布 `spawn`、`tick` 是新增技能事件。共享约定对消失绑定与只读范围的接口表达尚需合并，见文件末尾未决问题。

表现资源可以改变外观、节奏感知与信息密度，不能改变某一份是否被闪避、是否产生派生或实例寿命。逻辑种子不应因为多播放了一次随机音效而前进；表现与逻辑随机来源的隔离直接继承运行时契约。第 9 章负责七段完整字段，本章不抢先规定资源路径格式和动画资源类型。

## 1.6 第四根柱子：组织与版本

技能必须能够被定位、复制、比较、保存和再次打开。组织层至少支撑当前十二角色、每角色多技能与水晶池的索引检索，但不把这些现状写成数组定长上限。作者应能按归属和标签找到资产，程序应通过稳定标识引用它；中文名称变化不应使既有引用失效。

| 对象 | 本章确定的责任 | 后续落点 |
|---|---|---|
| 技能身份 | 使用 `skill_id`，不拿显示名替代 | 第 13 章命名与组织 |
| 归属与检索 | 放入 `meta`，不混进战斗参数 | 第 13 章元数据定义 |
| 结构版本 | `schema_version` 当前为字符串 `"0.1"` | 第 16 章与 Schema |
| 内容版本 | 区分资产修改与结构升级 | 第 13、16 章 |
| 保存与重开 | 保持实际语义，不靠本机临时缓存补全 | 第 16 章 |
| 迁移 | 有明确版本依据，不静默猜测旧含义 | 第 16 章 |

〔推荐默认〕复制为新技能时分配新的 `skill_id`，修改同一技能时保留身份并更新内容版本；显示名允许重复，身份不允许重复。此默认不预设磁盘目录结构，也不规定最终版本号编码。结构版本回答「按照哪套字段规则解释」，内容版本回答「这是该技能的哪次内容」，二者不能互相替代。

## 1.7 明确不做什么

| 排除项 | 正确归属 | 本编辑器仍需做到的边界动作 |
|---|---|---|
| 不定义运行时怎么算 | 主书稿运行时契约 | 引用其语义并据此校验，不复制算法 |
| 不定义帧率、实例数、子弹数验收指标 | 项目层性能文件 | 仅声明不定义验收指标 |
| 不暴露内部工序顺序 | 引擎固定语义 | 不提供排序控件、隐藏开关或导入后门 |
| 不校验物品合法性 | 物品与装备系统 | 校验本 CFG 引用可解析，不判断玩家能否持有 |
| 不做输入缓冲 | 输入系统与施法入口契约 | 预览不另造一套缓冲规则 |
| 不做 UI 适配 | 项目 UI 适配系统 | 定义字段和反馈内容，不规定多端布局适配 |
| 不做联网同步 | 项目网络层 | 不把确定性承诺扩大成联网同步方案 |
| 不做代码映射与最终数值表 | 后续实现、数值工作 | 不给出脚本类名绑定或正式平衡数值 |

「不校验物品合法性」不等于不校验技能参数。引用是否存在、参数是否越界属于技能配置问题；玩家当前背包能否装备某个辅助石属于外部系统问题。「不做 UI 适配」也不等于不定义表单：字段叫什么、错误指向哪里属于本规格；分辨率布局和设备输入映射不是本章任务。

## 1.8 红线：顺序不可配，数值可配

内部结算工序由运行时契约固定。即使作者进入专家模式、直接导入文本或编辑积木组合，也不能获得重排内部工序的能力。允许配置的数值仍受登记范围和权限约束；这句话不是「任何数值都能改」，而是「已开放参数可以填值，固定语义不能被重编排」。

允许配置顺序会把能力组合变成工序排列问题：原本只需验证同一种语义下的参数边界，随后还得验证每种排列与每种能力的交叉结果。组合数迅速膨胀，验收写不完；相同界面数值可能因隐藏顺序产生不同结果，作者发现配错也难以定位，最终形成查不出来的平衡差异。因此禁止顺序编辑是保证可验证性的产品约束，不是临时缺少可视化能力。

| 请求 | 判定 | 理由 |
|---|---|---|
| 修改已开放的寿命或重复命中间隔 | 可按字段规则填写 | 改参数，不改规则 |
| 勾选已登记的派生能力预设 | 依登记权限决定 | 选能力关系，不是改工序 |
| 调整特效播放与出手的对齐参数 | 依表现登记决定 | 对齐表现，不推迟逻辑出手 |
| 重排减免与结算阶段 | 禁止 | 修改固定语义 |
| 用积木数组顺序暗示结算先后 | 禁止 | 数据排列不是调度权限 |
| 直接写入未暴露的内部字段 | 禁止 | 文本导入与表单服从同一校验 |

# 第 2 章　术语对齐

## 2.1 词表使用原则与冲突处理

本章以主书稿附录 A 为术语依据；通过共享分片读取的原文仍按主书稿章节号引用。下表保留契约含义，并补充编辑器标签与使用位置，不把界面简称升格为新类型。凡推荐默认、已确认、待用户确认的状态均沿用原有层级，冻结只表示本版接线约定，不表示用户已经拍板。

发现冲突时，不静默统一、不改共享文件，也不让运行时猜词义。本次有一处基础冲突：共享协作口径及冻结积木卡列出的四类载体为 `independent / instant / attached / none`，而主书稿第 8 章、5.4 与 36.4 为 `none / self / independent / attached`。按共享铁律的优先级，本章解释运行时语义时服从主书稿；复述冻结登记格式时原样保留它的枚举要求。两者尚不能宣称完全接通。

本章不会把 `instant` 偷换成 `none`，也不会把缺失的 `self` 塞进冻结积木卡后宣称合规。完整 CFG 示例仅使用双方共同承认的 `independent`。冲刺和瞬时能力必须等待该枚举冲突裁决，不能借中文显示名隐藏差异。

## 2.2 面向作者的基础词

| 术语 | 统一含义 | 编辑器视角补注 |
|---|---|---|
| 技能石 | 主动技能 | 面向作者显示「技能石」，技术分类对应 `active` |
| 辅助石 | 武器模块 | 作为模块来源或组合语境显示，不偷换成一种载体 |
| 技能栏多槽 | 局内武器栏 | 指外部承载和组织语境，不等于 CFG 内积木数量 |
| 积木 | 有名字的能力预设；载体预设组合加默认参数 | 能力选择区显示中文名，详情保留 `brick_id` |
| 效果体 | 一切技能产物的统一容器 | 通用说明统一使用此词，不因外观换一套模型 |
| 四类载体 | 运行时为无载体、自身载体、独立载体、附着载体 | 中文辅助理解，存储枚举冲突按 2.1 处理 |
| 份（`parts[]`） | 一次 `hit` 内的多个结算份 | 显示「结算份」，可解释为伤害份、治疗份、控制份等 |
| 设计卡 | 一页写完一个技能的标准模板 | 帮助作者组织意图，不等于替代 CFG 或积木登记卡 |

技能石、辅助石、技能栏多槽分别涉及能力身份、模块身份与外部槽位语境，三者不能互相计数。一个技能石可以使用多块积木，一个效果体也可以携带多个结算份；不能因此把积木行数显示成技能栏槽数。编辑器组织信息应注明其统计对象，避免作者把「多份」理解成「多次出手」。

## 2.3 施放、效果体与实例

| 附录 A 术语 | 契约定义 | UI 显示与作者边界 |
|---|---|---|
| 施放 | 玩家或怪物发起一次技能，从索敌到本轮结束；一次施放为一轮，对应 `cast_id` | 显示「一次施放」，不把每次命中叫一轮 |
| 施法者闭环 | 索敌、前摇、出手、冷却构成的固定闭环 | 显示阶段说明，不提供内部顺序编辑 |
| 出手 | 闭环中的一个瞬间：创建效果体或进入位移状态；X 为一轮内出手总次数 | 显示「出手次数」，不用实例数代替 |
| 实例 | 效果体的一次运行时存在，拥有唯一 `instance_id` 与 `seq` | 预览检查中只读，不是资产登记项 |
| 瞬时实例 | 寿命为零，同 tick 内完成适用的命中处理与 `vanish(instant_end)` | 显示「瞬时判定」，未命中时不伪造 `hit` |
| 位移状态 | 施法者被占用的运动状态，期间不能施放其他技能 | 说明中显示「位移状态」，本身不占实例编号 |
| 快照 | 出手时施法者属性的冻结副本，默认用于该实例全寿命 | 显示「出手快照」说明，不让作者手填实战属性副本 |
| 召唤物 | 拥有独立施法者闭环的效果体，受 `summon_cap` 约束，`bind_owner` 默认 true | 显示「召唤物」，不把任何独立载体都叫召唤物 |

「实例」强调一次实际存在，「积木」强调一种可选预设，「效果体」强调统一模型。这三个词可出现在同一个说明中，但不能互换。作者选一块飞弹积木不意味着场上永远只有一个实例；一次出手生成多个实例也不意味着多次施放。预览统计须明确计量对象，正式 CFG 则保存能力定义，而不保存某次试运行生成的编号。

## 2.4 四类载体的编辑器解释

| 主书稿枚举 | 中文显示 | 关键语义 | 典型误解的纠正 |
|---|---|---|---|
| `none` | 无载体／瞬时判定 | 瞬时实例，`lifetime_ticks=0`，有 `vanish(instant_end)` | 无载体不是无实例，也不是瞬移 |
| `self` | 自身载体 | 位移状态加跟随判定体，只有判定体是实例 | 不把位移状态本身存成效果体实例 |
| `independent` | 独立载体 | 出手后独立运行，可运动也可静止 | 静止火区仍可属于独立载体 |
| `attached` | 附着载体 | 附着目标，有寿命或明确终止条件，无空间运动 | 护盾不能用无载体配正寿命冒充 |

载体不是近战、远程的同义词。近战可以是瞬时扇形、自身载体冲刺或独立剑气；远程可以是瞬时射线或独立飞弹。作者可以使用近战、远程作为理解标签，但标签不能决定生命周期，不能自动把「远程」解释为「一定飞行」。

附着载体必须能说明依附谁以及何时结束。主书稿使用 `anchor_target_id` 表示宿主，实例一般不参与空间候选接触，模板显式声明周期跳时按对应规则工作。纯数值状态仍可能不建效果体，具体由模板选择；不能把所有状态一律强制变成附着实例，也不能因图标存在就认定存在效果体。

瞬移是零时长位移，无路径判定体，不以超大速度的冲刺代替。落点爆炸是同一次出手另生成的实例，不写成瞬移结束事件派生。上述约束属于作者选择积木时的说明边界，不要求本章重新设计瞬移合法落点算法。

## 2.5 事件、结算份与记录

| 术语 | 契约定义 | 编辑器补注 |
|---|---|---|
| `hit` | 一次候选接触中至少一份未被闪避，含非伤害份，只发一条 | 显示「命中事件」，不等于伤害数值大于零 |
| `vanish` | 效果体自然终止时发出的事件，带原因码 | 显示「终止事件」，不等于任意清理操作 |
| 原因码 | 标记自然终止原因 | 界面可显示中文解释，CFG 使用原码 |
| purge（清场） | 清场、卸载、阵亡清理或预算丢弃；不发 vanish、不派生、不补 hit | 显示「清理」，不是可订阅的第三事件或原因码 |
| 伤害份 | 一条 hit 内独立判闪避、独立算减免的单位 | 显示「伤害份」，是结算份的一类 |
| 候选接触 | 从不重叠变重叠，或重复命中间隔到点；每次只判一次逐份闪避 | 详情说明用语，不直接等于已命中 |
| 结算记录 | 非事件，只读记录：`hit_settled`、`evaded_all`、`damage_taken`、`cast_started` | 按消费方权限展示，不新增事件选项 |
| `debug_record` | 非事件、非结算记录，仅测试与调试；种类含 `budget_drop`、`proc_blocked`、`gen_limit` | 仅调试面板使用，不能作为正式逻辑或表现触发源 |

一条 `hit` 中三份伤害，不是三条 `hit`。其中一份被闪避、两份未闪避时，该命中仍只发一条，份级结果保留各自状态；全部份被闪避时不成立命中。未闪避但被减免到零与闪避不同，不能因为数字为零就在表现中假装「未命中」。非伤害份也属于同一语义，不得新增治疗事件或控制事件来绕过最小事件集。

`parts[]` 的数组下标不是一次独立出手，也不是一个效果体。结果载荷中的 `part_index` 用于识别份，`evaded`、`final_amount` 属于运行时结果，不是作者填入的预期答案。作者配置效果类型与允许的参数，运行时生成实际结果，表现读取结果；把最终数值硬填进 CFG 会破坏这一责任划分。

主书稿 36.3 的原因码包括 `hit_end`、`range_end`、`landed`、`expired`、`returned`、`interrupted`、`instant_end`。第 8.5A 另出现附着载体的 `dispelled` 与 `anchor_gone`，但未同步进冻结原因码表；本章保留差异，不擅自增加可选项。某原因允许派生并不意味着每个积木都默认配置派生，具体能力仍需显式登记。

## 2.6 组合、权限与来源

| 附录 A 术语 | 契约定义 | 编辑器补注 |
|---|---|---|
| 家族登记 | 分裂体与母体共享的候选接触登记，防二次命中 | 不与防霰弹合并成一个开关 |
| 防霰弹 | 同一次出手同时生成的独立实例对同一目标只有一个能接触 | 作为能力规则解释，不由排列顺序决定 |
| 被动触发层 | 读结算记录，只能生成效果体或挂修饰器，不能直接造成伤害 | 能力来源说明，不是表现回调 |
| 修饰器 | 水晶与遗物的统一机制，三档权限 | 显示权限说明，不能凭名称推断可改范围 |
| `mutate_number` | 改数值字段，仅限暴露字段 | 技术详情显示「改数值」 |
| `add_behavior` | 加行为，只影响之后生成的实例 | 显示「加行为」，不回写现存实例 |

# 第 3 章　数据模型总览

## 3.1 唯一契约与七个顶层键

**编辑器写入 CFG，运行时读取 CFG，CFG 是两者唯一不可变契约。**「不可变」指同一正式版本的含义不能被消费方私自改写，不是说作者以后不能修改技能。编辑修改形成新的内容版本；运行时生成的实例状态和修饰结果不反向污染原始技能资产。预览也必须消费这份契约，不能另存一份只在编辑器生效的技能定义。

| 顶层键 | 职责 | 不得装入的内容 |
|---|---|---|
| `schema_version` | 结构版本，当前字符串 `"0.1"` | 技能内容版本、程序构建号 |
| `skill_id` | 按冻结命名规则标识技能 | 实例编号、中文显示名 |
| `meta` | 归属、标签、版本、作者等组织信息 | 当前目标血量、即时来源链 |
| `bricks` | 积木列表，每项为十二字段登记卡实例 | 只有名称、缺失能力定义的占位项 |
| `params` | 作者参数填值，覆盖 `default_cfg` | 未开放参数、调度顺序、实战结果 |
| `presentation` | 七类表现配置 | 结算算法、动画回调驱动逻辑的开关 |
| `runtime_hints` | 非功能性提示，如预算档位与分桶建议 | 必需战斗规则、项目性能验收阈值 |

顶层固定为这七个，不新增 `events`、`instances` 或所谓扩展总入口绕过约束。能力扩展应在既定结构内通过正式登记与 Schema 演进承载；无法表达时提出接口变更，而不是把新功能塞进提示字段。`runtime_hints` 即使被忽略，也不能改变该技能承诺的功能语义。

## 3.2 身份、元数据与版本边界

技能 ID 使用 `<role>_<category>_<name>[_<variant>]`；角色标识为归属角色，通用技能用 `common`；分类采用 `active`、`passive`、`crystal`、`relic`；名称用 snake_case。示例使用 `common_active_training_bolt`，完整符合规则，不以中文能力名作为引用键。冻结文件中的个别示例与格式存在差异，见未决问题，本章不传播不一致示例。

〔推荐默认〕示意元数据使用 `role`、`tags`、`version`、`author`，分别表达归属、检索标签、内容版本、作者。它们是本章建议的嵌套字段，不冒充共享文件已经冻结的字段；正式命名由第 13、16 章收口。在此之前，读者应将示例看作完整结构提案，而不是已经通过最终机器 Schema 的资产。

〔推荐默认〕归属信息必须与 ID 的角色段一致，标签仅参与检索，不直接决定伤害类型或载体。任何会改变战斗行为的分类必须由能力与参数显式表达，避免把修改标签变成修改技能机制。作者署名是资产来源说明，不是运行时权限凭据。

## 3.3 积木登记卡与参数覆盖

`bricks` 的每项必须保留 `brick_id`、`name`、`tagline`、`carrier`、`summary`、`default_cfg`、`author_params`、`locked_params`、`relic_params`、`presentation`、`player_text`、`status` 十二字段。不能为了减小样例而改成仅含 `brick_id` 的引用列表。运行时无需消费全部说明文字，但不能因此把未声明的外部目录当成恢复能力的唯一依据。

`default_cfg` 是能力默认片段，`params` 是作者对已开放参数的填值，两者作用不同。锁死项不因出现在默认片段内就变成可覆盖项。修饰器的权限也不能因为作者填过某个参数而自动扩大。校验应针对实际有效值，不能只证明默认模板合法，却忽略覆盖后已违反契约。

〔推荐默认〕本章样例用 `params.<brick_id>` 承载覆盖对象；标量按路径替换，映射递归覆盖，数组整项替换，不按位置追加。未登记键直接报错，不静默丢弃。此建议使覆盖可解释，但共享骨架尚未冻结嵌套语法，必须由第 16 章确认后才能作为最终接线格式。

同种积木需要在一个技能中出现多次时，仅用 `brick_id` 定位可能不够。不能把技能内出现编号混进全局积木 ID，也不能改变十二字段登记卡。本章示例只出现一个积木，不借此规定多次使用被禁止；重复实例的定位方式列为接口未决项，由评审统合后续章节解决。

## 3.4 完整 CFG 结构样例

以下是七键齐全、十二字段齐全、表现七段齐全的 YAML 结构样例；数值仅说明寿命覆盖，不是正式平衡表。为避免把未冻结的伤害字段伪装成事实，使用不含结算份的独立效果体教学预设，展示默认寿命与作者覆盖。它不是第 4 章正式积木目录，也不声称现有运行时已经实现该预设。

〔推荐默认〕空表现段暂表示未绑定资源、无该类表现，不表示继承外部隐藏默认。七段内部语法、关闭方式以及无结算教学积木的实际可用性均待第 4、9、16 章验证。本样例能够展示完整 CFG 的组成，但不能单凭本章宣布为已验证可运行资产；这一限制不能从交付说明中省略。

```yaml
schema_version: "0.1"
skill_id: common_active_training_bolt
meta:
  role: common
  tags: [training]
  version: "0.1"
  author: design_team
bricks:
  - brick_id: training_bolt
    name: 教学独立效果体
    tagline: 展示独立效果体的寿命覆盖
    carrier: independent
    summary: >-
      创建一个独立效果体。此结构样例不声明结算份。
      默认寿命有限，作者可以修改寿命。
      仅用于说明数据边界，不作为正式能力登记。
    default_cfg:
      carrier: independent
      lifetime_ticks: 60
    author_params:
      lifetime_ticks:
        字段名: lifetime_ticks
        类型: int
        默认值: 60
        取值范围: "[1, 120]，仅示例"
        单位: tick
        必填: 是
        分级: 新手
        所属积木: training_bolt
        Schema 路径: params.training_bolt.lifetime_ticks
    locked_params:
      carrier: 独立载体为此预设的能力身份，不允许覆盖
    relic_params:
      lifetime_ticks: 禁止
    presentation: [fx, sfx, anim, trail, camera, damage_number, status_icon]
    player_text:
      - 生成一个教学独立效果体。
      - 此样例不包含伤害或其他结算份。
      - 效果体在声明寿命结束时终止。
    status: 候选
params:
  training_bolt:
    lifetime_ticks: 90
presentation:
  fx: {}
  sfx: {}
  anim: {}
  trail: {}
  camera: {}
  damage_number: {}
  status_icon: {}
runtime_hints: {}
```

| 阅读位置 | 样例表达的事实 | 不能推导出的结论 |
|---|---|---|
| `schema_version` | 当前结构草案版本为字符串 | 不表示运行时版本相同 |
| `bricks[0].carrier` | 双方枚举共同支持独立载体 | 不表示其他枚举冲突已解决 |
| `default_cfg.lifetime_ticks` 与 `params` | 默认六十，建议覆盖语法下有效值为九十 | 不表示单位可以省略或自动当秒 |
| `locked_params` | 载体不可被作者替换 | 不表示所有默认参数都锁死 |
| `relic_params` | 此样例不授权修饰寿命 | 不表示系统永久禁止寿命修饰 |
| `status` | 明确为候选教学预设 | 不得正式导出后宣称可运行 |
| 表现七段 | 配置分区完整 | 不表示七类表现已绑定完成 |
| `runtime_hints` | 未指定非功能性建议 | 不表示不存在运行时安全约束 |

样例刻意保持候选状态，是为了让结构完整与资产可发布这两个概念不再混淆。将来替换成已登记积木、补齐正式嵌套字段和资源绑定后，仍要通过同一套校验；不能只把 `status` 改成已登记就越过能力验证。可运行完整示例是最终合书的必需物，本章提供结构基础和明确缺口，不将草案包装成测试结果。

## 3.5 静态 CFG 与运行时实例的接线点

| 数据或语义 | 谁提供 | 谁生成／消费 | 是否写回正式 CFG |
|---|---|---|---|
| `skill_id`、载体、默认参数 | 编辑器登记与作者填值 | 运行时读取，生成相应效果体 | 定义保留，实例不回写 |
| `lifetime_ticks`、`hit_policy` | 已登记能力及开放覆盖 | 运行时按契约解释 | 只保存定义，不保存倒计时 |
| `caster_id`、`instance_id`、`seq` | 实际施放上下文 | 运行时生成与维护 | 否 |
| `spawn_tick`、`state` | 当前运行过程 | 运行时生成与转换 | 否 |
| `snapshot` | 出手时实际属性 | 运行时冻结 | 否 |
| `parent_ref`、`generation`、`origin` | 实际来源与派生上下文 | 运行时按继承规则生成 | 否 |
| `parts[]` 的结果字段 | 实际候选接触与结算 | 运行时产出，表现只读 | 否 |
| 表现资源及对齐配置 | 作者与表现配置段 | 表现消费者读取 | 保存配置，不保存播放游标 |

`params` 一词既出现在顶层 CFG，也出现在主书稿实例字段表。前者是作者填值，后者是实例生成时确定的参数集；相同名称不表示它们是同一个可变对象。运行时可以按契约生成实例级值并执行合法修饰，但不得把变化写回模板，使下一次预览未经编辑就换了技能。

同理，`skill_id` 可以从资产传到实例以标记所属技能，`instance_id` 却不能从资产复制为固定值。一次预览若生成多个效果体，不能让它们共用编辑器预填编号。主书稿已经确定的来源链与快照字段属于实际执行上下文，本章不重复规定生成算法。

## 3.6 接线责任与不可变边界

| 接线边界 | 提供物 | 消费方责任 | 失败时处理原则 |
|---|---|---|---|
| 能力登记到表单 | 十二字段积木卡与九列参数登记 | 生成开放项、锁定说明与帮助文本 | 缺少能力声明不能伪装成完整表单 |
| 表单到 CFG | 七键结构与合法填值 | 保存明确配置，不夹带会话状态 | 指向具体路径，不输出伪合法资产 |
| CFG 到运行时 | 相同结构版本下的能力与参数 | 按运行时契约解释，不按名称猜逻辑 | 不支持的能力明确拒绝 |
| CFG 到预览 | 与正式读取一致的配置 | 使用同样语义与受控初态 | 不用演示脚本掩盖缺失能力 |
| 运行结果到表现 | 只读 hit／hit_settled 及已约定生命周期绑定 | 显示结果，保持单向 | 表现失败不反向改战斗结果 |
| 正式配置到存档重开 | 身份、版本、定义与资源引用 | 恢复同一配置语义 | 不静默套用新版默认 |

〔推荐默认〕预览开始时固定当前配置快照；编辑表单得到的新内容在下一次明确启动的预览中生效，不偷偷改变正在核对的实验。支持热预览时也应将版本切换显式化，且不能借热更新绕开运行时 `mutate_live_instance` 权限。本章不规定热更新实现方式，只规定作者必须知道自己正在看哪个版本。

「唯一契约」不排斥外部资源存在，而是禁止另有一份隐藏技能定义决定结果。特效引用需要可解析，能力登记需要可追溯，运行时版本需要兼容；这些依赖应由正式字段及加载约定说明，而不是靠编辑器内存缓存补齐。离开原编辑会话后无法解释的 CFG 不满足保存目标。

## 3.7 扩展与失败关闭

扩展性优先不等于接受任意键。新积木通过登记增加能力入口，新参数通过九列登记增加可填范围，新表现能力在既定七段内演进。若现有结构不够，需要更新版本和迁移约定，不改变旧版本同名字段的含义。预留项可以存在于登记目录，但不能把空实现登记为正式可用。

〔推荐默认〕未知结构版本、未知字段和无法解析的必需引用采用明确拒绝，不自动删除后继续保存。拒绝时保留原输入供修正，不用「系统已优化配置」掩盖信息丢失。对于非必需表现缺项可采用何种降级，由第 9、14 章明确；在规则确认前不能把缺资源当成逻辑通过的证据。

本章不冻结完整机器 Schema，也不登记具体 `V-###` 或 `E-####`。本章确定数据责任与基础断言，后续章节补足精确嵌套路径和诊断文案；同一检查不得在不同章节被定义成相反结果。发生冲突时回到主书稿与冻结接口，而不是以哪个示例更容易实现为裁决依据。

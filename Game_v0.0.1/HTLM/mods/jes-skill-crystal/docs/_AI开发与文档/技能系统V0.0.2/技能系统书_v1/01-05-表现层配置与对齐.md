# 第 9 章　表现层配置

## 9.0 章定位与硬约束

本章把 `presentation` 中的七个固定配置段写成编辑器可以填写、校验、预览、交接的规格。表现层负责把已经确定的结果翻译成画面、声音、动作、镜头、文字和图标；它不重新计算命中，不决定目标，不产生伤害，不延长或缩短效果体寿命。

本章所有配置均属于 `presentation.fx`、`presentation.sfx`、`presentation.anim`、`presentation.trail`、`presentation.camera`、`presentation.damage_number`、`presentation.status_icon` 七个段。段名不得换成同义词，也不得把七段合并为一个自由文本字段。未配置时采用默认值；默认值是表现默认，不是逻辑默认。

> **显眼硬约束（铁律 8）**：表现配置只读 `hit` 与 `hit_settled`。表现不得反向影响逻辑；逻辑不得依赖动画回调、音效回调、粒子回调、镜头回调或数字显示完成。`hit` 是技能内部驱动表现的唯一事件输入，`hit_settled` 是结算完成后供表现读取的只读记录；`debug_record`（包括 `budget_drop`）不进入正式表现层。

这里的“绑定 spawn / tick / vanish”是效果体生命周期中的**表现挂点**，不是新增事件，也不是让表现订阅第三种事件。挂点只决定表现实例何时创建、更新或收束；逻辑仍按第 5、6、7 章运行，`vanish` 仍是既有事件，且 `purge` 不发 `vanish`。表现挂点不能写回 `state`、`params`、`hit_policy`、`parts[]` 或任何结算字段。

### 9.0.1 通用字段与公共校验

| 字段 | 类型 | 默认值 | 取值范围 | 分级 | 说明 |
|---|---|---:|---|---|---|
| `enabled` | bool | `true` | `true/false` | 新手 | 是否启用本段；关闭只关闭表现 |
| `preset_id` | string/ref | `—` | 已登记资源引用 | 新手 | 引用素材或模板，不写内嵌逻辑 |
| `layer` | enum | `world` | `world/ui/overlay/debug` | 进阶 | 显示层级；`debug` 不得进入正式 UI |
| `start_offset_ticks` | int | `0` | `≥0` | 专家 | 相对挂点的表现延迟；不改变逻辑 tick |
| `duration_ticks` | int | `—` | `0` 或正整数；`0` 表示跟随挂点 | 专家 | 仅控制表现实例 |
| `time_mode` | enum | `scaled` | `scaled/unscaled` | 专家 | `unscaled` 只能用于编辑器预览或明确登记的界面提示；战斗表现默认跟随统一时间缩放 |
| `budget_class` | enum | `P4` | `P4` | 专家 | 本章表现实例属于 P4；不得借此改变判定实例预算 |
| `fallback` | enum | `none` | `none/minimal` | 进阶 | 素材缺失时不影响结算；`minimal` 只显示最小替代表现 |
| `visibility_filter` | enum | `all` | `all/owner/team/target` | 进阶 | 只影响谁看见表现，不影响谁被命中 |

通用校验规则：资源引用不存在时阻止发布或降级为 `fallback`，不得创建逻辑替代；负的表现延迟、负寿命、未知层级和未知挂点均应指向具体 Schema 路径报错。所有以秒填写的编辑器字段必须同时换算成 tick，默认向上取整；运行时只使用 tick。

### 9.0.2 生命周期挂点总表

| 挂点 | 可以做什么 | 不可以做什么 | 典型输入 |
|---|---|---|---|
| `spawn` | 创建生成火花、初始音效、施法者起手姿态、投射物外观 | 不得让效果体因此提前可命中 | 效果体生成时的只读实例信息 |
| `tick` | 更新跟随位置、透明度、旋转、蓄力进度和持续循环 | 不得用动画帧决定移动、碰撞、寿命或伤害 | 只读 `instance_id`、`carrier`、当前表现时钟 |
| `vanish` | 收束、淡出、尾迹回收、结束音效 | `purge` 不得伪造 `vanish` 表现，不得派生新逻辑实例 | 既有终止结果与原因码的表现映射 |
| `hit` | 命中特效、受击音、闪避或击杀的即时表现 | 不得重复结算或创建新的逻辑命中 | `hit` 载荷 |
| `hit_settled` | 伤害数字、免疫文字、状态图标、击杀标记 | 不得改写 `total`、`killed` 或 `parts[]` | 结算记录及其份级信息 |

`spawn/tick/vanish` 负责与效果体“同生、同存、同收”，`hit/hit_settled` 负责与结算结果对齐。任何设计卡若写“动画播完后才出手”“音效回调后才命中”“数字显示结束后才回收”，均为错误写法。

## 9.1 `fx` 特效

`fx` 管理粒子、材质、精灵、线条、冲击波、命中特效等纯表现实例。它可以挂在效果体的 `spawn`、`tick`、`vanish` 三个生命周期时点；也可以由 `hit` / `hit_settled` 选择命中反馈。`fx` 不承载判定体，不进入接触收集，不拥有伤害份。

### 9.1.1 配置字段

| 字段名 | 类型 | 默认值 | 取值范围 | 分级 | 绑定/含义 |
|---|---|---:|---|---|---|
| `fx.spawn` | array | `[]` | 每项为 FX 引用 | 新手 | 效果体生成时创建；允许 0 到 N 项 |
| `fx.tick` | array | `[]` | 每项含更新轨道 | 进阶 | 存活期间按 tick 更新；不参与运动判定 |
| `fx.vanish` | array | `[]` | 每项含收束轨道 | 进阶 | 自然终止时收束；按原因码选择素材 |
| `fx.on_hit` | array | `[]` | `hit` 映射表 | 新手 | 每条 `hit` 最多按规则触发一次，不能按份数自动复制 |
| `fx.on_settled` | array | `[]` | `hit_settled` 映射表 | 进阶 | 需要 `total/killed/parts[]` 时使用 |
| `fx.resource_ref` | ref | `—` | 已登记 FX 资源 | 新手 | 粒子、材质、精灵或组合预制引用 |
| `fx.anchor` | enum | `instance` | `caster/instance/target/world` | 新手 | 视觉锚点；不改变载体归属 |
| `fx.follow_mode` | enum | `none` | `none/position/rotation/full` | 进阶 | 跟随显示变换；不得跟随逻辑判定之外的路径 |
| `fx.spawn_count` | int | `1` | `0..上限` | 进阶 | 表现实例数；预算紧张时可减少或拒绝 |
| `fx.loop` | bool | `false` | `true/false` | 新手 | 循环只影响表现循环 |
| `fx.duration_ticks` | int | `0` | `0` 或正整数 | 进阶 | `0` 表示跟随挂点；正数到点收束 |
| `fx.vanish_by_reason` | map | `{}` | 冻结原因码键 | 专家 | `landed/expired/interrupted/...` 的不同收束；`purge` 不伪造 |
| `fx.color_mode` | enum | `fixed` | `fixed/snapshot/team/status` | 进阶 | 颜色读取来源；不得读取实时逻辑数值来改结算 |
| `fx.random_seed_stream` | enum | `presentation` | `presentation` | 专家 | 必须与逻辑 RNG 分离，不消耗逻辑抽样 |

`fx.spawn` 适合炮口闪光、生成圆环、护盾出现；`fx.tick` 适合旋转、脉冲、火焰流动、随独立载体更新的位置；`fx.vanish` 适合消散、爆裂收束、残光淡出。若“消失时爆炸”需要伤害，必须另建由 `vanish` 派生的效果体；`fx.vanish` 本身只画爆炸，不产生伤害。

### 9.1.2 与逻辑的解耦

- `fx` 可因 P4 预算被提前结束或不创建；对应 `debug_record` 只供调试，不显示“丢特效”提示。
- 表现路径可以与判定路径不同，例如表现弧线高于判定路径；设计卡必须明确“弧线仅表现”，命中仍由逻辑形状和运动方式决定。
- `fx.on_hit` 对一条 `hit` 只播放一次；一条 `hit` 含多份，不得按 `parts[]` 数量复制命中特效，除非配置明确是同一特效内部的份级装饰。
- `fx` 不监听 `debug_record`，不因预算压力制造世界内提示，不改变预算状态。

## 9.2 `sfx` 音效

`sfx` 管理生成、命中、持续循环、终止和 UI 反馈的声音。音效是最容易在高频技能中造成堆叠的表现类别，因此必须同时配置触发时点、优先级和并发上限。并发上限是防止声音实例失控的表现预算，不是命中上限。

### 9.2.1 配置字段

| 字段名 | 类型 | 默认值 | 取值范围 | 分级 | 绑定/含义 |
|---|---|---:|---|---|---|
| `sfx.spawn` | ref/array | `—` | 0..N 个音效 | 新手 | 效果体生成时播放 |
| `sfx.tick_loop` | ref | `—` | 0 或 1 个循环 | 进阶 | 存活期间循环；跟随表现时钟 |
| `sfx.on_hit` | ref/array | `—` | `hit` 映射 | 新手 | 命中成立时播放；不按伤害份自动复制 |
| `sfx.on_settled` | ref/array | `—` | `hit_settled` 映射 | 进阶 | 需按实际结算结果区分时播放 |
| `sfx.vanish` | ref/map | `—` | 原因码映射 | 进阶 | 自然终止时播放；`purge` 不伪造 |
| `sfx.trigger_scope` | enum | `per_hit` | `per_hit/per_target/per_cast/per_tick` | 专家 | 同一音效的去重范围 |
| `sfx.priority` | int | `50` | `0..100` | 新手 | 竞争时高者优先；不影响逻辑排序 |
| `sfx.max_concurrency` | int | `8` | `0..全局上限` | 新手 | **同一音效/组的并发上限，必须填写** |
| `sfx.concurrency_group` | string | `skill_id` | 非空组名 | 进阶 | 多个音效共用上限的组 |
| `sfx.steal_mode` | enum | `oldest` | `oldest/quietest/lowest_priority/none` | 专家 | 达到上限后的表现取舍 |
| `sfx.cooldown_ticks` | int | `0` | `0..` | 进阶 | 表现去重冷却；不阻止下一次逻辑结算 |
| `sfx.volume_db` | float | `0` | `-80..24` | 新手 | 声音增益 |
| `sfx.pitch_range` | array<float> | `[1,1]` | `0.01..4` 且 min≤max | 进阶 | 表现随机；使用独立表现 RNG |
| `sfx.bus` | enum/string | `sfx` | 已登记总线 | 专家 | 输出总线；不得连接到逻辑控制 |

触发选择规则：同一 `hit` 内含伤害、控制、击退等多种份，默认一条命中音效；若需要份级声音，必须在 `sfx.on_settled` 中声明 `part_type` 过滤和组内合并规则。全部闪避不产生 `hit`，因此“命中音效”不应播放；若需要闪避声音，绑定 `evaded_all` 的**表现映射**，读取的是结算结果通道，不把 `evaded_all` 另造为技能事件。

### 9.2.2 并发与解耦

`max_concurrency` 为必填字段，缺省时由 Schema 补默认值并在编辑器显示警告。达到上限只丢或合并声音，不丢 `hit`、不丢 `hit_settled`，也不改变伤害数字。音效回调永远不能触发施法、派生、冷却或补命中。优先级只决定声音资源之间的竞争；不能与 `seq`、FIFO 或结算优先级混用。

## 9.3 `anim` 动画

`anim` 描述施法者动作、效果体外观动作和命中受击动作。核心是把“逻辑出手 tick”映射到动画轨道中的一帧，而不是把动画帧当作逻辑时钟。动画可提前、延后、快进或中断，逻辑仍按施法者时间表运行。

### 9.3.1 配置字段

| 字段名 | 类型 | 默认值 | 取值范围 | 分级 | 绑定/含义 |
|---|---|---:|---|---|---|
| `anim.cast_clip` | ref | `—` | 已登记动作 | 新手 | 施法者前摇/出手动作 |
| `anim.release_marker` | string | `release` | 非空标记名 | 新手 | 动画内的出手标记，仅用于对齐显示 |
| `anim.logic_release_tick` | int | `0` | 时间表中的合法 tick | 新手 | **逻辑出手 tick ↔ 动画帧对齐字段** |
| `anim.release_frame` | int | `0` | `≥0` 且在 clip 内 | 新手 | 对应的动画帧 |
| `anim.tick_rate` | int | `—` | 正整数 | 进阶 | clip 的逻辑换算频率 |
| `anim.frame_policy` | enum | `marker_locked` | `marker_locked/time_locked/nearest` | 进阶 | 只控制呈现如何贴合逻辑 |
| `anim.pre_roll_ticks` | int | `0` | `≥0` | 进阶 | 动画起始偏移；不改前摇 |
| `anim.on_hit` | ref/map | `—` | `hit` 映射 | 进阶 | 受击动作/闪光；按一条 hit 去重 |
| `anim.on_settled` | ref/map | `—` | `hit_settled` 映射 | 专家 | 击杀、免疫等结算反馈 |
| `anim.interrupt_policy` | enum | `recover_to_idle` | `recover_to_idle/crossfade/hold_last` | 进阶 | 被打断时收动作 |
| `anim.fast_forward_policy` | enum | `seek_release` | `seek_release/clip_end/cancel` | 专家 | 逻辑已出手而动画被快进时的显示 |
| `anim.blend_ticks` | int | `4` | `0..` | 进阶 | 纯表现混合长度 |
| `anim.callback_mode` | enum | `none` | `none/presentation_only` | 专家 | 回调不得写逻辑；建议默认不使用 |

`logic_release_tick` 必须来自施法者闭环的时间表。`release_frame` 或 `release_marker` 只是在该 tick 附近将抬手、炮口闪光等视觉对齐。若帧率变化、动作被快进或资源缺帧，运行时采用 `frame_policy` 选最近可用画面，不把出手 tick 改到新帧。

### 9.3.2 对齐与解耦

动画轨道可以作为同步实现手段，但不是新事件；不能声明 `animation_finished` 为技能事件。动画未完成时，已到达的逻辑出手仍发生；动画被打断时，未到达的出手仍按第 4 章打断规则处理。动画回调只允许通知表现控制器“切换显示状态”，不允许调用技能结算、发射效果体、改变冷却或补发 `hit`。

## 9.4 `trail` 拖尾

`trail` 是纯表现拖尾，不能命中目标。必须明确拖尾跟随哪一个载体，且必须区分 `independent` 与 `instant` 两种载体。`independent` 有跨 tick 的表现寿命，可沿效果体位置采样；`instant` 在创建 tick 内完成逻辑，拖尾只能使用短暂的显示窗口，不能假装瞬时实例仍在运动。

### 9.4.1 配置字段

| 字段名 | 类型 | 默认值 | 取值范围 | 分级 | 绑定/含义 |
|---|---|---:|---|---|---|
| `trail.carrier` | enum | `none` | `independent/instant/self/attached/none` | 新手 | **必须声明载体类型** |
| `trail.resource_ref` | ref | `—` | 拖尾资源 | 新手 | 纹理、线带或粒子引用 |
| `trail.follow_mode` | enum | `position` | `position/rotation/full/none` | 新手 | 只跟随显示变换 |
| `trail.sample_interval_ticks` | int | `1` | `1..` | 进阶 | 位置采样间隔，非判定间隔 |
| `trail.max_points` | int | `16` | `0..上限` | 进阶 | 轨迹点表现上限 |
| `trail.lifetime_ticks` | int | `6` | `0..` | 新手 | 拖尾点寿命；不改变载体寿命 |
| `trail.fade_in_ticks` | int | `0` | `0..` | 进阶 | 淡入 |
| `trail.fade_out_ticks` | int | `6` | `0..` | 新手 | 载体结束后的淡出 |
| `trail.independent_end_policy` | enum | `fade_then_free` | `fade_then_free/free_on_vanish` | 进阶 | 独立载体终止后的处理 |
| `trail.instant_end_policy` | enum | `fixed_short_fade` | `fixed_short_fade/none` | 进阶 | 瞬时载体的短淡出；不能跟随不存在的运动 |
| `trail.on_hit` | ref/map | `—` | `hit` 映射 | 进阶 | 命中时短促拉亮或断裂 |
| `trail.on_settled` | ref/map | `—` | `hit_settled` 映射 | 专家 | 结算后颜色/标记反馈 |
| `trail.opacity_curve` | ref | `linear` | 已登记曲线 | 进阶 | 纯表现透明度 |

### 9.4.2 两种载体的强制差异

| 项 | `independent` | `instant` |
|---|---|---|
| 逻辑存活 | 跨 tick，有 `live/terminating/gone` | 创建 tick 内完成 |
| 拖尾起点 | 可读取每个 tick 的效果体位置 | 只能读取创建时位置/方向 |
| 寿命 | 可按载体终止后继续淡出 | 只能使用固定短淡出，不能把淡出当作逻辑寿命 |
| 终止 | `vanish` 后收束 | 对应 `instant_end` 后收束 |
| 命中 | 拖尾不命中；判定由载体实例负责 | 拖尾不命中；瞬时判定已在逻辑中完成 |

`self` 可沿施法者位移状态的跟随判定体显示，但拖尾仍不能写位移状态；`attached` 默认不画空间拖尾，可画附着光环。载体不明或填写 `instant` 却配置移动采样时，编辑器应阻止保存，因为这会诱导把表现运动误当判定运动。

## 9.5 `camera` 镜头

`camera` 只管理震屏、推拉、轻微偏移、景深提示和镜头跟随表现。它**显式不影响逻辑**：不改变目标位置、不改变判定半径、不改变 tick、不改变时间缩放、不改变 RNG、不改变效果体的运动或命中。

### 9.5.1 配置字段

| 字段名 | 类型 | 默认值 | 取值范围 | 分级 | 绑定/含义 |
|---|---|---:|---|---|---|
| `camera.enabled` | bool | `true` | `true/false` | 新手 | 是否显示镜头反馈 |
| `camera.trigger` | enum | `hit` | `spawn/hit/hit_settled/vanish/manual_preview` | 新手 | 表现触发来源；不新增事件 |
| `camera.shake_amplitude` | float | `0` | `0..` | 新手 | 震动幅度，纯表现 |
| `camera.shake_frequency` | float | `20` | `0..240` | 进阶 | 震动频率 |
| `camera.shake_duration_ticks` | int | `0` | `0..` | 新手 | 震动持续 |
| `camera.zoom_delta` | float | `0` | `-0.9..4` | 进阶 | 推拉比例 |
| `camera.zoom_duration_ticks` | int | `0` | `0..` | 进阶 | 推拉持续 |
| `camera.blend_mode` | enum | `additive` | `additive/max/replace` | 专家 | 多个镜头请求合并方式 |
| `camera.priority` | int | `50` | `0..100` | 进阶 | 镜头请求竞争优先级 |
| `camera.max_concurrency` | int | `2` | `0..` | 专家 | 同时生效的镜头效果上限 |
| `camera.logic_impact` | enum | `none` | **仅 `none`** | 新手 | **显式声明：不影响逻辑** |
| `camera.presentation_rng` | enum | `presentation` | `presentation` | 专家 | 独立于逻辑 RNG |

`camera.logic_impact` 只能是 `none`。任何“震屏使敌人更易命中”“拉近镜头扩大判定”“慢镜头只影响技能伤害”的配置都不属于本段，编辑器应拒绝。镜头请求达到并发上限时按优先级或最旧实例丢弃，逻辑结果保持不变。

## 9.6 `damage_number` 伤害数字

伤害数字是 P4 纯表现实例，只能由 `hit` 与 `hit_settled` 的只读数据生成。它必须遵循主书稿 15.7：合并只影响显示，不合并结算；同一目标、同一类型、窗口内的显示数字可合并；闪避、暴击和普通数字不混合；目标死亡后仍显示最后合计；P4 被丢弃时，合计从结算记录恢复，不依赖数字实例仍存活。

### 9.6.1 配置字段

| 字段名 | 类型 | 默认值 | 取值范围 | 分级 | 绑定/含义 |
|---|---|---:|---|---|---|
| `damage_number.enabled` | bool | `true` | `true/false` | 新手 | 是否显示数字 |
| `damage_number.source` | enum | `hit_settled` | `hit/hit_settled` | 新手 | 数据来源；需合计时优先记录 |
| `damage_number.part_mode` | enum | `aggregate` | `aggregate/per_part/by_type` | 进阶 | 一条 hit 内份级显示方式 |
| `damage_number.merge_window_ticks` | int | `3` | `0..` | 新手 | 同目标、同类型合并窗口 |
| `damage_number.merge_key` | enum/array | `[target_id,type]` | 必含 `target_id,type` | 进阶 | 合并键；不得含位置浮点 |
| `damage_number.show_zero` | bool | `false` | `true/false` | 进阶 | 普通 `final_amount=0` 不默认显示数字 |
| `damage_number.evaded_text` | string | `闪避` | 非空 | 新手 | 全部闪避或份级闪避提示 |
| `damage_number.immune_text` | string | `免疫` | 非空 | 新手 | `any_reduced_to_zero=true` 的提示 |
| `damage_number.killed_style` | ref | `—` | 击杀样式引用 | 新手 | `killed=true` 时显示击杀表现 |
| `damage_number.crit_separation` | enum | `separate` | `separate/aggregate_same_class` | 进阶 | 暴击不与普通数字混合 |
| `damage_number.dead_target_flush` | bool | `true` | `true/false` | 进阶 | 死亡目标最后刷新合计 |
| `damage_number.pressure_policy` | enum | `merge_more` | `merge_more/drop_visual_only` | 专家 | 紧张时只改变表现 |

### 9.6.2 份级规则与最小映射

- `parts[i].evaded=true` 且 `final_amount=0`：该份属于闪避提示，不生成伤害数字；若同一条 `hit` 尚有未闪避份，仍只按该条 `hit` 的规则生成一次普通/合计数字，并可附带闪避标记，不能拆成多条命中。
- `any_reduced_to_zero=true`：显示“免疫”，与闪避区分。免疫是未闪避但减免后为 0，`hit` 仍成立；护盾在减免之后吸收，不因吸收到 0 设置该字段。
- `killed=true`：显示击杀样式；击杀不是新事件，不得额外订阅或制造“击杀事件”。
- `budget_drop`：不生成任何正式 UI、数字、音效或镜头提示；调试面板可单独显示记录。
- 防霰弹整批共用一次闪避判定：同批被抑制实例不构成候选接触；若能命中的实例全闪避，只播一次闪避表现，不按批内实例数重复。

### 9.6.3 合并算法的编辑器口径

合并键至少是 `target_id + type`，必要时加来源显示分类；合并窗口以逻辑 tick 比较，不以真实秒或渲染帧比较。合并后的显示值是参与合并的 `final_amount` 或 `hit_settled.total` 的和，不回写任何原始载荷。目标死亡时，先把尚未落屏的同键数据冲刷为最后合计，再显示击杀样式。预算紧张时可把多个数字更激进地合并，但“总伤害合计必须保留”的规则不可关闭。

## 9.7 `status_icon` 状态图标

`status_icon` 表示增益、减益和控制状态，不负责施加状态。它对齐第 22.5 与 22.8：增益/减益可为 `attached` 或独立区域；状态有寿命，默认到期 `vanish(expired)`；控制类型必须在 CFG 注册 `interrupts_cast`，图标只展示注册后的状态结果，不自行推断是否打断。

### 9.7.1 配置字段

| 字段名 | 类型 | 默认值 | 取值范围 | 分级 | 绑定/含义 |

| `status_icon.source` | enum | `hit_settled` | `hit/hit_settled` | 新手 | 读取状态结果的来源 |

| `status_icon.anchor` | enum | `target` | `target/caster/ui_list` | 新手 | 图标挂载位置 |
| `status_icon.stack_mode` | enum | `count` | `count/level/refresh_only/unique` | 进阶 | 叠层显示，不改叠加逻辑 |

### 9.7.2 堆叠与控制对齐

同类状态默认刷新单例，刷新表示重置为满寿命；若设计卡声明 `restack_rule: keep_longer`，图标显示规则应为保留一枚图标并更新剩余时间，而不是创建多枚不受控图标。有限叠层显示层数上限只限制 UI，不能吞掉逻辑层数，也不能把显示层数作为后续伤害的输入。

控制图标从 `parts[].type=control` 与已经结算的状态结果读取。`interrupts_cast` 是控制类型的 CFG 字段：眩晕、冻结、沉默、定身默认为 `false`，击退、强制位移默认为 `true`；图标可以显示“打断”标签，但该标签由逻辑结果映射而来，不由图标回调触发打断。无敌、免疫、闪避的显示必须按份级结果区分，不能把“免疫”画成“未命中”。

| 表现段 | 可读取 | 不可读取/不可写入 | 丢弃时的后果 |
|---|---|---|---|
| `fx` | 生命周期挂点、`hit`、`hit_settled` | `debug_record` 触发逻辑、写 `params` | 画面少装饰，结算不变 |

# 第 10 章　表现与逻辑对齐

## 10.1 对齐原则

表现与逻辑共享同一固定步长的时间参考，但职责不同：逻辑决定何时创建实例、何时产生 `hit`、何时终止和发出 `vanish`；表现把这些已确定的状态呈现给玩家。一个渲染帧可执行 0、1 或多个 tick，表现可以插值，不能据此创造逻辑结果。

对齐的最小单位不是“动画播完”，而是“逻辑时间表中的 tick”。同一出手的所有实例使用同一个 `logic_release_tick`；同一批音效、火光、后坐力和弹道外观都以这个 tick 为锚。逻辑出手已发生而资源尚未准备好时，使用降级表现，不回滚出手。

## 10.2 逻辑出手 tick ↔ 动画帧机制

### 10.2.1 冻结字段

| 字段 | 归属 | 用途 | 谁能写 |
|---|---|---|---|
| `cast_timeline.release_tick` | 逻辑 | 决定创建效果体/进入位移状态 | 逻辑时间表 |
| `anim.logic_release_tick` | 表现配置 | 指向同一个逻辑出手 tick | 编辑器配置 |
| `anim.release_frame` | 表现配置 | 该 tick 的显示帧 | 编辑器配置 |
| `anim.release_marker` | 表现资源 | 在 clip 中定位视觉标记 | 美术资源 |
| `hit.tick` | 逻辑结果 | 命中发生的 tick | 运行时 |
| `hit.seq` | 逻辑结果 | 同 tick 稳定排序的实例序号 | 运行时 |

编辑器保存时校验 `anim.logic_release_tick` 必须存在于时间表，并提示 `release_frame` 是否超出 clip。校验通过后运行时按以下步骤处理：

1. 施法者闭环推进到时间表的出手点。
2. 逻辑在该 tick 创建效果体，分配 `instance_id`、`seq`、`spawn_tick` 和 `snapshot`。
3. 表现控制器收到该出手的只读镜像，寻找 `release_marker` 或 `release_frame`。
4. 若渲染帧跨过该 tick，表现使用一次性采样或补帧展示火光，不把出手推迟到下一帧。
5. 效果体之后的 `hit`、`hit_settled` 按真实逻辑 tick 驱动命中特效、数字和状态图标。

### 10.2.2 连发、齐发和多个实例

连发的每个出手点各自有 `logic_release_tick`；一轮技能只有一个前摇和按规则确定的冷却，不能因动画轨道重复而增加前摇。齐发时同一出手点创建多个实例，动画只播放一套施法/出手表现，`sfx` 与 `fx` 默认按 `trigger_scope=per_cast` 或 `per_hit` 去重。默认防霰弹若使同一目标只有一个实际候选接触，其余被抑制实例不应各自播放命中特效。

命中与动画帧不是一对一关系：同一动画动作可以在不同 tick 命中多个目标，同一 tick 也可能有多个实例命中。若表现需要区分，使用 `seq`、`target_id` 和合并规则稳定排序，不用渲染帧顺序。

## 10.3 被打断时表现如何收

被打断是逻辑结果，不能由动画是否播完推断。控制类型的 `interrupts_cast` 决定是否打断施法；位移状态的跟随判定体以 `interrupted` 终止，默认不补 hit、不因动画结束补落地伤害。已生成的 `independent` 实例不因施法者之后被打断而自动消失，除非其自身规则另有终止条件。

### 10.3.1 表现收束表

| 逻辑情形 | 施法者动画 | 已生成 `independent` | `self` 跟随判定体 | 音效/特效 |
|---|---|---|---|---|
| 前摇中被打断，尚未出手 | 立即进入 `interrupt` 或交叉淡出 | 无 | 无 | 只播打断反馈，不播出手火光 |
| 前摇中被打断，已有更早出手 | 当前动作收束；更早出手照常 | 照常运行 | 若该位移本身被打断则 `vanish(interrupted)` | 不取消已成立的早先表现 |
| 位移状态被打断 | 停止路径动作，进入受击/失衡 | 独立实例不受影响 | 收到 `vanish(interrupted)` 后停止跟随与判定 | `trail` 按 `fade_out_ticks` 淡出；不得补落点爆炸 |
| 动画轨道被强制替换但逻辑未打断 | 采用 `crossfade` 或 `seek_release` | 照常运行 | 照常运行 | 保持与逻辑状态一致 |
| 纯表现 P4 被预算清除 | 当前 FX/拖尾/声音淡出或立即释放 | 判定实例不变 | 判定实例不变 | 不显示预算提示 |
| 场景清场 `purge` | 立即释放 | 按清场规则释放 | 不发 `vanish` | 不伪造 vanish 收束/派生表现 |

“被打断时表现如何收”默认推荐：施法者动画 `recover_to_idle`，正在播放的出手火光允许完成极短的视觉收束；`self` 拖尾按 `fade_out_ticks` 淡出；`vanish(interrupted)` 的表现可播放，但不得从表现反推任何新的逻辑行为。若项目需要硬切或定格，写入 `interrupt_policy`，不改变逻辑契约。

### 10.3.2 不得补发的表现

被打断后不得播放“未发生的落地命中”、不得补一个 `hit`、不得补一次伤害数字、不得把动画结束当作落地。若逻辑已经有 `hit_settled`，即使画面随后被打断，已结算的数字仍须按合并规则完成或以合计回填；视觉取消不等于撤销结算。

## 10.4 暂停与慢动作

暂停时 tick 不推进，持续时间、冷却和实例内部计数全部冻结。表现层默认 `time_mode=scaled`，因此动画、粒子、拖尾、镜头震动的逻辑表现时钟也暂停；可以保留静态画面，但不能继续消耗表现寿命并让玩家误以为逻辑继续。

慢动作或加速使用统一时间缩放因子改变每真实秒推进的 tick 数，而不是修改 `lifetime_ticks`。逻辑和表现都通过同一缩放时钟推进：60 tick 的火区在缩放 0.5 下仍需 60 个逻辑 tick 才结束，只是现实经过时间更长；动画播放速率、拖尾淡出、音效循环和镜头时长随同一缩放表现时钟变化。

### 10.4.1 暂停/慢动作显示规则

| 状态 | 逻辑 tick | 动画/FX | 音效 | 镜头 |
|---|---|---|---|---|
| 暂停 | 不推进 | 保持当前帧/粒子状态 | 默认暂停或保持已开始声音，不推进触发冷却 | 保持已应用偏移，不继续抖动 |
| 慢动作 0<scale<1 | 按缩放推进 | 按同一缩放插值 | 播放速率按表现总线策略缩放 | 按同一缩放消退 |
| 加速 scale>1 | 一帧可执行多个完整 tick | 可跨帧补表现，但不跳过结果 | 并发上限仍生效 | 可能合并多次震动 |
| 编辑器单步 | 每次推进明确 tick 数 | 可逐 tick 检查对齐 | 以表现去重规则播放 | 可选择冻结镜头或逐步应用 |

`unscaled` 只允许用于编辑器预览控制或明确登记的非战斗界面反馈；战斗七段默认不得各自引入第二个时间缩放系数。某技能想不受慢动作影响，必须走设计卡显式例外和评审，不得通过动画资源偷偷实现。

## 10.5 预览：snapshot 与 live 的显示差异

运行时实例默认在生成时确定 `params`，施法者属性在出手时写入 `snapshot`；已生成实例之后不因基准值变化而回溯。持续区域各跳默认使用生成时 `snapshot` 的施法者属性，目标侧防御/抗性取各跳时刻。只有设计卡明确标记为 `live` 的可暴露字段，才可由 `mutate_live_instance` 在之后 tick 改变。

编辑器预览需要同时支持两种模式，但必须让模式名称显眼，避免作者把预览误当运行时承诺：

| 预览模式 | 取值方式 | 适合看什么 | 不得推断 |
|---|---|---|---|
| `snapshot` | 在预览出手瞬间复制参数/施法者属性，之后保持 | 验证真实实例强度、持续效果、派生一致性 | 不得因拖动面板数值而改旧实例 |
| `live` | 每个预览 tick 读取当前编辑器值，只有标记 `live` 的字段更新 | 验证允许实时修改字段的视觉响应、教学预览 | 不代表未标 `live` 的运行时实例会实时变化 |

推荐默认是 `snapshot`。预览窗口若在效果体存活期间修改攻击力：`snapshot` 模式下当前实例的伤害显示和 `hit_settled` 模拟不变，新出手才使用新值；`live` 模式下只有明确标记的视觉字段或 `mutate_live_instance` 字段变化。两种模式都不得修改正式战斗数据，不得写回 CFG，不得消耗正式逻辑 RNG。

预览还应提供 `result_snapshot` 与 `result_live` 两层标识：前者显示本次预览开始时配置的快照，后者显示当前编辑器表单值。若只显示一套数值，作者容易把“面板当前值”误认为“场上旧实例值”。预览中的 `hit`、`hit_settled` 应带 `preview=true` 的工具上下文标记，但不能在正式契约中新增第三种技能事件；预览结果仍使用同样的载荷形状和合并规则。

## 10.6 逻辑与表现的调度边界

推荐调度顺序如下，顺序是实现对照，不开放给技能作者重排：

| 阶段 | 逻辑工作 | 表现工作 |
|---|---|---|
| ① 输入/出手 | 闭环到达出手点，创建实例 | 读取出手镜像，定位 `release_frame`，播放出手表现 |
| ② 运动 | 推进 `live` 实例和内部计数 | 更新 `fx.tick`、拖尾采样、循环音效 |
| ③ 接触收集 | 收集候选接触 | 不提前播放命中特效 |
| ④ 结算 | 逐份闪避、减免、写 `hit`/`hit_settled` | 读取结果，排队命中特效/数字/图标 |
| ⑤ 终止与派生 | 处理 `vanish`、派生子实例 | 收束旧表现；新表现下一适当挂点创建 |
| ⑥ 回收 | `terminating`→`gone`，释放预算 | 释放跟随表现；未完成淡出可独立保留 |

同一 tick 内，表现请求按逻辑结果的 `seq` 和稳定目标顺序消费；不能以线程到达顺序、渲染节点遍历顺序或声音资源加载顺序改变逻辑。表现队列阻塞时只会延后或合并表现，不阻塞逻辑 tick。

## 10.7 对齐验收例子

| 输入条件 | 预期表现 | 验证点 |
|---|---|---|
| 逻辑出手 tick=20，动画第 12 帧为 `release` | tick=20 创建效果体，画面在第 12 帧附近显示出手；动画回调是否到达不影响创建 | 出手由时间表决定 |
| 同一条 hit 含三份，其中两份闪避、一份未闪避 | 一条命中表现；普通数字只来自未闪避份；不播放三次命中音 | 份数不复制 hit 规则 |
| 所有份闪避 | 无 `hit`，显示一次“闪避”或按配置不显示；效果体仍可在后续自然 `vanish` | `evaded_all` 不冒充 hit |
| 目标免疫，未闪避份减免至 0 | 显示“免疫”，可有命中特效；`hit` 与 `hit_settled` 成立 | 免疫与闪避区分 |
| 同一次出手三枚独立实例同 tick 接触同一目标，默认防霰弹 | 只对唯一实际候选接触播一次闪避/命中表现 | 批次去重 |
| 40 条同类型 hit 在 3 tick 内命中同一目标 | 数字合并，合计等于结算总和；hit 数仍为 40 | 合并不改结算 |
| `budget_drop` 丢弃拖尾 | 没有正式提示；判定结果、伤害数字合计不变 | debug_record 隔离 |
| 前摇中被击退且 `interrupts_cast=true` | 动画收束，不补出手、不补落地伤害；未出手点作废 | 打断收束 |
| 施法者出手后攻击力增加 | 旧实例仍按 snapshot；新出手按新值 | D-44/D-62 |
| 暂停 30 个真实帧 | tick、冷却、动画表现时钟不变；解除后继续 | 14.2 统一冻结 |

## 10.8 常见误写与编辑器提示

| 误写 | 编辑器应提示的正确方向 |
|---|---|
| 动画播到第 12 帧才创建效果体 | 把逻辑 tick 填入时间表，帧只作对齐显示 |
| 音效结束后再结算伤害 | 音效是 `hit`/`hit_settled` 的消费者，不是前置条件 |
| 拖尾碰到目标造成伤害 | 拖尾是 P4 表现；需要命中必须另建有判定效果体 |
| 震屏扩大判定范围 | `camera.logic_impact` 只能为 `none` |
| 数字合并后只留一条 hit | 合并只在显示，原始 hit 和结算记录保留 |
| 预算丢弃显示“弹幕被优化” | `debug_record` 不进入正式 UI |
| 跳跃被打断，动画播完后补落地伤害 | `interrupted` 不补落地 hit；表现立即收束 |
| 预览拖动攻击力让旧火区变强 | 默认用 snapshot；只有声明 live 的字段可更新 |
| 控制图标亮起就调用打断回调 | 打断由逻辑读取 `interrupts_cast` 决定，图标只显示结果 |

## 10.9 本章落地的编辑器交接清单

1. 表单顶层固定生成七个 key，且字段路径与 `presentation.<key>...` 一致。
2. 每个 key 都能显示默认值、取值范围、分级和所属生命周期挂点。
3. 预览器可以逐 tick 暂停、单步、切换 `snapshot/live`，并显示实际读取来源。
4. T2 表五行最小集合全部可以在预览中构造：闪避、免疫、击杀、预算丢弃静默、防霰弹单次闪避。
5. 打断、暂停、慢动作和资源缺失场景均有可观察的表现降级，而不是改变逻辑结果。
6. 发布前扫描动画回调、音效回调、粒子脚本、镜头脚本是否存在逻辑写入；存在即阻止发布。
7. 预览和正式运行都不把 `debug_record` 当作表现输入；调试面板与正式 UI 的数据通道分离。

# 卷七　来源与证据

> 版本：v1　日期：2026-10-18　轮次：第 1 轮
> 本卷记录本书采用的来源、冲突裁决链、文档层校验证据与已知边界。它是证据索引，不把文档静态通过等同于运行时或编辑器已经实现。

## 7.1　来源性质与权威层级

本书有五类来源：用户拍板的铁律与范围、已确认决策、主书稿运行时正文、由正文派生的编辑器／接口／Schema 规格，以及旧稿和代码注释。冲突时按下表自上而下裁决：

| 优先级 | 来源层 | 含义与处置 |
|---:|---|---|
| 1 | **用户明确确认的铁律** | 最高约束；包括范围边界、不得改动的方向和明确排除项。 |
| 2 | **已确认决策** | D-01…D-09、D-90、D-91、D-92、D-104、D-105，共 14 条；正文、派生规格和示例均不得静默改写。 |
| 3 | **主书稿正文** | 运行时契约的主体真源；未被上层铁律或确认决策取代的细则以此为准。 |
| 4 | **派生规格** | 技能编辑器规格、交界映射表、CFG Schema 等，只能把上层口径转译为可填写、可交换或可校验的形式，不能反向扩大运行时权限。 |
| 5 | **旧稿与代码注释** | 用于追溯和发现差异，不作为覆盖已批准条款的理由。 |

**代码是实现事实。** 文档与代码不符时，必须记录差异并由有权来源裁决是否改规则；代码的现状不会自动覆盖已批准条款，文档也不会自动声称代码已经实现。实现差异、未接线能力和文档草案须分别标注。

在上层来源之间也有冲突时，不以“更近的示例”或“更容易实现”为理由猜测。例如 `instant` 与 `self` 的摘要冲突，最终采用主书稿与机器可读摘要中的 `none / self / independent / attached`；`instant` 只能作描述词，不能作 `carrier` 枚举值。这一裁决属于来源治理证据，不是新增运行时能力。

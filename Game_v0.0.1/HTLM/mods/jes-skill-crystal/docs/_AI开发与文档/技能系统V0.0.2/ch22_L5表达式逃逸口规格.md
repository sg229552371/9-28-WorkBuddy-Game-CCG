> 状态：语言与编辑器校验规格草案；不宣称已实现或已并入现有 Schema。除上述用户决策与引用的冻结契约外，本章技术选择均为〔推荐默认〕。

## 22.1 定位、边界与准入

L5 解决的是：积木、参数组合与已有修饰器仍无法表达，但能够归约为**一个布尔条件或一个数值**的低频复杂需求。它不是新积木、第五类载体或第二套战斗执行器。四类载体仍为 `none` / `self` / `independent` / `attached`；效果体生命周期和内部结算工序不变。

| 可用场景 | L5 的产物 | 原有系统继续负责 |
|---|---|---|
| 多个已授权状态组成的复杂筛选条件 | bool | 既有目标筛选或条件消费者，不能扩大其目标集合与权限 |
| 按冻结输入计算分段数值、夹取系数 | number 或 int | 已登记的输入公式槽及原有数值工序 |
| 读取当前合法命中记录中的标记，组合判断 | bool | 已有记录消费位置及其来源链、冷却、预算检查 |
| 默认参数、开关、枚举或专用模块已经能表达 | 不应使用 L5 | 返回 L0—L4，减少维护成本 |

**禁止**循环、递归、自定义函数、函数指针、动态模块加载、赋值、可变局部变量、命令序列、事件发送、延时任务和生命周期管理。三元节点只是惰性选值，不是流程控制入口；逻辑短路只影响本次求值，不产生动作。不得借 L5 补齐尚未提供的位移能力、环境交互或目标约束契约。第 21 章关于“走逃逸口”的宽泛表述，不构成 L5 写状态的许可。

配置复杂度的 L0—L6 与属性快照分层不是同一套编号。L5 不改变施法者快照、目标侧读取时点或 live 双向授权；也不将一次命中变成多次触发。首发没有 L6，无法归约为纯值的需求返回能力登记流程。

## 22.2 形态决策与保存边界

### 22.2.1 只接受 JSON AST

〔推荐默认〕唯一可执行表示是**类型化 JSON AST**，不用字符串脚本。不提供表达式字符串的隐式解析，不调用 `eval`、`exec`、动态函数构造或反射取属性。编辑器可以展示可读公式，但展示文字不是执行来源。

| 选择理由 | 必须落实的约束 |
|---|---|
| 可静态校验 | 节点形状、节点类型、运算符、函数名、字段路径分别使用封闭白名单 |
| 可比较差异 | 对象键规范排序；参数数组保留语义顺序；展示变更的实际子树 |
| 可版本化 | AST、字段目录、数值语义和限制档位均绑定已验证解释版本 |
| 无动态求值 | 固定节点处理表；作者不能注册处理函数或传入宿主可调用对象 |
| 可追踪 | 校验后建立稳定节点定位与源码位置表；不靠运行时对象地址定位 |

最小示例是一个返回布尔值的独立 AST，**不是完整技能 CFG**：

```json
{"node":"literal","type":"bool","value":true}
```

下例仅在当前消费者允许读取该命中记录字段时成立；无记录的调用位置不能使用它：

```json
{
  "node": "not",
  "arg": {"node": "field", "path": "record.hit_settled.killed"}
}
```

JSON AST 指数据模型，并不推翻现有 UTF-8 YAML 外壳；未来若由 YAML 承载，解析后也只能得到同样的普通树。重复键、别名共享节点、自定义标签、非有限数字与循环对象均拒收。

### 22.2.2 CFG 接线选择与现状声明

现有 `技能CFG_Schema_v0.1.md` 中 `params.triggers[i].condition` 是引用字符串，`params.templates[i].parts[j].amount_profile` 也是引用字符串。**本章不把它们原地改成对象联合类型，也不把表达式塞进 `meta.design_notes` 或 `runtime_hints` 执行。**

〔推荐默认〕沿用上述 profile 引用槽：由版本化的条件／公式登记资产持有 AST，技能仍引用登记项。条件资产根结果必须为 bool，数值资产根结果必须满足消费字段的类型、单位和范围。`params.passive.triggers[i].condition`、`params.parts[j].amount_profile` 如被使用，同样遵守原路径和原有互斥规则；不得同时配置 `amount` 与 `amount_profile`。

登记资产必须与 CFG 作为同一发布依赖集固定：引用解析到不可变版本及内容指纹，不解析到可悄悄更新的“最新版”。现有七键仍是 `schema_version`、`skill_id`、`meta`、`bricks`、`params`、`presentation`、`runtime_hints`；积木卡仍严格十二字段。

**接线门禁**：当前 Schema 没有定义 L5 资产格式与加载能力。语言草案可以供设计与校验器实现使用，但在登记资产的 Schema、依赖固定方式、消费者采样位置和支持版本经评审落地前，不得把本章示例认证为可运行技能。不能仅因旧槽位接受字符串便声称旧运行时支持 L5。新解释能力须走正式 Schema／加载器版本审查，不能冒用旧版解释规则。

## 22.3 语法、类型和节点白名单

### 22.3.1 结构文法

〔推荐默认〕以下 EBNF 描述 JSON 解析后的抽象树，不是另一门字符串脚本语言。对象成员顺序无语义，表内字段集合精确匹配，除规定字段外一律拒收。文法的自包含嵌套只是有限树结构，不提供表达式自引用或运行递归。

```ebnf
expr       = literal | field | arithmetic | comparison | logic | membership | select | call ;
literal    = { node:"literal", type:scalar_type, value:scalar }
           | { node:"literal", type:"array", item_type:scalar_type, value:[scalar, ...] } ;
field      = { node:"field", path:path_string } ;
arithmetic = { node:"arith", op:arith_op, args:[expr, ...] } ;
comparison = { node:"compare", op:compare_op, left:expr, right:expr } ;
logic      = { node:"and", args:[expr, expr, ...] }
           | { node:"or", args:[expr, expr, ...] }
           | { node:"not", arg:expr } ;
membership = { node:"in", item:expr, collection:expr }
           | { node:"contains", collection:expr, item:expr } ;
select     = { node:"if", test:expr, then:expr, else:expr } ;
call       = { node:"call", fn:function_name, args:[expr, ...] } ;
scalar_type = "bool" | "int" | "number" | "string" ;
arith_op    = "add" | "sub" | "mul" | "div" | "mod" | "neg" ;
compare_op  = "eq" | "ne" | "lt" | "le" | "gt" | "ge" ;
function_name = "clamp" | "min" | "max" | "round" | "lerp" | "floor" | "ceil" | "trunc" ;
```

`scalar` 必须与显式类型相符；空数组允许，但必须声明元素类型。数组只作为常量或冻结字段值，不允许嵌套数组、对象元素、数组推导、动态索引或构造表达式列表。根结果只允许 bool／int／number；字符串与数组只能作为比较和成员判断的中间值。禁止 null、隐式真值、字符串转数字和布尔转数字。

### 22.3.2 节点登记表

| 节点名 | 入参及个数 | 返回类型 | 是否允许嵌套 | 精确语义 |
|---|---|---|---|---|
| `literal` | `type,value`；数组另有 `item_type` | 声明类型 | 叶节点，可嵌入其他节点 | 数字有限，int 必须为安全整数；字符串不解释为代码 |
| `field` | 非空字面路径 `path` | 字段目录给出的类型 | 叶节点，可嵌入其他节点 | 仅查冻结字典，路径不是表达式 |
| `arith` | `op,args`；neg 一项，其余恰好两项 | 数值；div 为 number | 是 | 从左到右；无字符串拼接，无指数运算 |
| `compare` | `op,left,right` | bool | 是 | eq/ne 为同类型标量比较；数值允许 int 提升；大小比较只收数值 |
| `and` | 至少两项 bool 的 `args` | bool | 是 | 从左向右遇 false 即停止 |
| `or` | 至少两项 bool 的 `args` | bool | 是 | 从左向右遇 true 即停止 |
| `not` | 一个 bool 的 `arg` | bool | 是 | 严格布尔取反 |
| `in` | 标量 `item`，同元素类型数组 `collection` | bool | 是 | 精确成员比较，不做子串、正则或实体搜索 |
| `contains` | 数组 `collection`，标量 `item` | bool | 是 | 与 in 同义但参数阅读方向相反；不允许任意对象属性检查 |
| `if` | bool `test`，同类型 `then,else` | 两分支公共类型 | 是 | 仅求值选中的分支；数值分支可统一提升为 number |
| `call:clamp` | `args=[x,lo,hi]`，数值 | 数值公共类型 | 是 | `min(max(x,lo),hi)`；lo 大于 hi 是错误，不交换边界 |
| `call:min` / `call:max` | 至少两项数值 `args` | 数值公共类型 | 是 | 固定数组顺序归约，不从世界收集候选 |
| `call:round` | 一个数值参数 | int | 是 | 最近整数，恰好半数向远离零方向；不提供位数参数 |
| `call:lerp` | `args=[a,b,t]`，数值，t 在闭区间 [0,1] | number | 是 | 按 `a + ((b-a) * t)` 次序计算；不隐式夹取 t |
| `call:floor` | 一个数值参数 | int | 是 | 向负无穷取整 |
| `call:ceil` | 一个数值参数 | int | 是 | 向正无穷取整 |
| `call:trunc` | 一个数值参数 | int | 是 | 向零截断 |

嵌套不能超过 22.7 的限制，函数名不在表内即拒绝，没有“未知函数交给宿主执行”的后备路径。新增纯函数也须更新语言版本、类型规则、最坏成本与验收，不能由技能数据动态注册。

### 22.3.3 数值语义和全定义性

〔推荐默认〕number 使用有限 IEEE 754 binary64；禁止 NaN、正负无穷，零规范化为正零。int 限于可精确表示的安全整数范围；加减乘取模在全部参数为 int 时返回 int，溢出不自动降级为 number。除法始终返回 number，取模定义为向零截断商对应的余数，符号跟随被除数。中间结果也必须有限，不只检查根结果。

这些是数值表示语义，不是技能最终数值。编译／优化不得改变括号、重排运算、融合乘加或把整数溢出吞掉；常量折叠采用与求值器相同的数值规则。`round(-1.5)=-2`，`floor(-1.2)=-2`，`ceil(-1.2)=-1`，`trunc(-1.2)=-1` 为语义例子，不是调参默认。

静态检查必须证明所有可达计算对允许输入有定义：除数非零、夹取上下界有序、lerp 系数合法、中间结果有限、根结果符合消费槽位。字段目录提供有限区间；检查器可识别比较守卫和短路形成的区间收窄。证明不了就阻止保存，要求作者加入明确守卫或 clamp，不能以“实战应该不会出现”放行。

对结构、白名单与类型，**未选分支也必须检查**；常量除零无论是否处于永不选中分支均拒收，避免危险死代码被长期保存。对于变量除零，可在 `if` 的非零分支内证明合法；不存在“报错即返回零”的默认规则。取整和夹取仅在 AST 明写时发生，不替消费者偷偷修正输入。

## 22.4 字段路径白名单与上下文注入

### 22.4.1 两层授权

字段可读需同时满足：**全局字段目录登记**，以及**当前消费者允许的上下文集合**。下表是上下文类别和最小候选路径，不是将整个对象开放；未完成精确源字段映射的候选一律不可启用。

| 上下文 | 可登记路径示例 | 只读来源与限制 |
|---|---|---|
| 施法者 | `caster.snapshot.attack` | 出手快照中已登记攻击字段的投影；不借此读取施法者最新属性 |
| 目标 | `target.hp`、`target.max_hp` | 当前消费者原有读取时点的单个目标；不能用于扩大搜索范围 |
| 效果体 | `effect.params.lifetime_ticks` | 当前实例已有参数的冻结投影；不返回实例对象、宿主指针或行为函数 |
| 命中记录 | `record.hit_settled.killed`、`record.hit_settled.any_reduced_to_zero` | 仅已完成且实际提供该字段的当前记录，不跨记录抓取 |
| 命中记录类型投影 | `record.hit_settled.part_types` | 从当前记录 `parts[].type` 按既定顺序复制的 string 数组，不伪造逐份数额 |
| 局内状态 | `run.tick` | 当前逻辑整数 tick 的冻结副本；不是系统时间或渲染帧数 |

每条实际登记必须包含：精确路径、类型、单位、范围或字符串集合、来源字段、采样位置、消费者许可、是否保证存在、数组长度界限和解释版本。缺任一必要说明不能凭名称猜值。局内状态不开放整个世界、玩家存档、环境变量或任意关卡对象；新的局内标量也须先完成登记，不能 wildcard 放行。

**冻结是本次求值的一致性措施，不是重定义快照。** 施法者快照与目标侧读取各自保持原契约时点。消费者准备好原本有权读取的数据后，复制成普通值并冻结；同 tick 后续消费者有不同输入时可生成另一份上下文。不得为了减少复制，把多次结算前后的目标状态混成同一份全 tick 缓存。

### 22.4.2 路径解析

〔推荐默认〕路径为大小写敏感的点分标识串，分段满足 `[a-z][a-z0-9_]*`。加载时用**完整路径精确匹配**登记目录，编译为固定槽位；运行时只按该槽取普通数据，不沿对象属性链逐段寻址。

禁止下标、通配符、拼接路径、计算属性、父路径、实体 ID 跳转、原型链与反射入口。不能通过 `target.owner`、任意实体表、getter 或代理对象读取另一实体；字符串即使等于实体 ID 也只是字符串。上下文复制前拒收宿主对象、访问器和可调用值，禁止让读取字段触发代码。

`hit_settled.parts` 不提供逐份 `final_amount`，不得借字段投影制造该字段。当前没有命中记录就不能读命中上下文；全闪避无 hit 也不能补造记录供表达式使用。正式表现依然只读既定结果，不通过 L5 获取新增数据源。

### 22.4.3 缺失、空值与依赖环

首发不引入 nullable 类型和存在性探测节点。目录必须保证所需字段在授权消费者中存在；可能无目标的消费者不能使用目标路径。空字符串引用、null、未解析引用和缺失路径分别报错，不能转成零、false 或空对象。合法空数组是确定的集合：任意成员判断均返回 false。

字段不得引用其他表达式的输出，也不能回读正在计算的输入槽。资产之间不提供 AST 引用节点、不允许函数调用链。编辑器保存前及加载时检查资产依赖图和上下文投影依赖图：出现 A 依赖 B、B 依赖 A，或输出反向进入自身输入，即拒收。纯 JSON 文本不会自带环，但内存草稿、YAML 别名和资产装配都可能引入环，不能因此省略环检测。

## 22.5 纯函数、诊断与失败归属

逻辑接口可理解为 `evaluate(已验证AST, 冻结context)`：成功只返回值；失败返回无值的求值诊断。校验与诊断信息属于工具返回结果，不是游戏事件或结算记录。求值器无 I/O、无文件／网络／环境读取、无当前时间读取、无随机数，也不修改 CFG、快照、实例、世界状态或外部服务。

| 情形 | 处置与可观察性 | 不能冒用的行为 |
|---|---|---|
| 编辑器形状、类型、路径、预算证明失败 | 使用 22.6 的编辑器校验报告，阻止可执行保存 | 不为表单错误向战斗流写 debug_record |
| 加载时配置／引用不合法，或表达式无法满足消费类型和范围 | 接纳边界拒绝候选，按 34.1 的既有配置错误路径由宿主记录 `config_error` | 不执行合法半份配置，不擅自替换根结果 |
| CFG 解释版本不兼容 | 按 D-112 整份回退当前已验证兼容配置；无兼容配置则受影响功能不可用 | 不在线猜迁移，不跨版本混装 |
| 运行中发现实际配置输入违背已验证约束 | 无值返回；宿主在原有消费边界拒收该非法输入，配置／引用错误才用 `config_error` | 不把错误当条件 false、数值零或一次预算丢弃 |
| 上下文适配器漏注入保证字段、处理器异常、看门狗超时 | 属实现故障，输出开发／测试诊断，当前求值不交付；预览认证失败 | 不冒称作者配置错误，不新造 debug kind 或战斗原因码 |

最后两行不新增战斗恢复契约：若某消费者没有既有的非法输入拒收边界，**该消费者不得接入 L5**，先由原职责规格审查，而不是在本章发明“跳过伤害”“整局退出”等策略。不能回滚已成立的父 hit、返还冷却、补发事件或重掷随机数。纯函数不负责这些动作。

`debug_record{kind,detail,tick}` 外壳保持不变；配置问题的路径、节点定位、期望／实际类型和处置放入既有 `detail` 调试文本，tick 使用当前逻辑 tick，启动接纳用 tick 0。`config_error` 已由补洞后的 34.1 定义，本章只是引用，不新增枚举。`budget_drop` 是实例预算拒绝，不是表达式节点限额；`proc_blocked` 和 `gen_limit` 也不能借来表示表达式错误。

宿主先根据校验／求值结果决定接纳，再写诊断；任何逻辑和正式 UI 都不得订阅或解析 debug_record 来触发行为。诊断关闭不改变值、失败位置和 RNG 抽取次数。节点跟踪由调试器旁路保存，短路未访问子树标为 `skipped`，不为了填 trace 再执行它。

## 22.6 静态检查规则与报错文案

### 22.6.1 检查流水线与定位约定

〔推荐默认〕编辑 → JSON 解析 → Shape（形状）→ Whitelist（白名单）→ 类型／区间／依赖检查 → Limits（资源证明）→ 消费槽位复核 → 原子保存依赖集。失败全部不提交，导出和加载不得绕过。校验前先用有界解析器限制输入体积和嵌套，避免“检查深度前已耗尽调用栈”。

稳定节点 ID 由校验器根据资产身份、版本和 JSON Pointer 派生，不接受作者伪造 ID；同一版本同一路径始终相同，树结构改变后结合版本区分，不承诺任意编辑后 ID 不变。每条报告同时带 CFG 使用路径、资产引用、AST Pointer、节点 ID 与原文行列；解析失败尚无节点时，用最深可解析路径和期望 token。源码位置表属于编辑／调试侧，不增加 CFG 键。

下表保持第 14 章五列。`V-220…V-236` 与 `E-2200…E-2216` 是本章编辑器错误码／文案号，等待评审并入总表，**不是运行时原因码**。定位中的 `P` 必须展开为真实消费路径，如 `params.triggers[0].condition`；其后附资产根内 Pointer，如 `/args/1/path`。引用尚未解析时只定位 P，不能报告一个不存在的资产路径。

## 22.7 资源限制、超时与协作式让出

〔推荐默认〕限制绑定解释版本，由已验证公共配置提供，作者不能在单份技能里放宽。下列数值全部是本项目安全起点，不是外部资料数值，也不是性能验收承诺。

| 项目 | 本项目建议值 | 计数方式与理由 |
|---|---|---|
| 最大 AST 节点数 | 〔推荐默认〕128 | 所有分支一起计，包含叶节点；足以表达短条件，不鼓励大程序 |
| 最大深度 | 〔推荐默认〕16 | 根深度为 1；在解析时先限制，阻断深链与栈耗尽 |
| 单 AST 输入体积 | 〔推荐默认〕32 KiB | 按 UTF-8 字节计；防止少量节点承载巨大字面量 |
| 单字符串长度 | 〔推荐默认〕128 个 Unicode 标量 | 限定标签／枚举判断成本；不用于长文本处理 |
| 单数组长度 | 〔推荐默认〕32 项 | 常量和上下文字段均适用；超过不能静默截断 |
| 单次最坏工作预算 | 〔推荐默认〕8192 工作单位 | 节点访问每个计 1；成员检查每项另计 1；字符串比较每个被检查的标量另计 1，保证集合操作非免费 |
| 协作检查间隔 | 〔推荐默认〕每 64 工作单位 | 有界解析、校验及离线批量预览检查取消；不能依赖浏览器帧率 |
| 工具侧超时看门狗 | 〔推荐默认〕50 ms／单次独立求值任务 | 仅发现卡死／实现异常，不决定战斗值或技能降级 |
| 成本预警比例 | 〔推荐默认〕上限的 75% | 提前提示维护风险，非拒收阈值 |

工作量证明按全部潜在分支、目录最大字符串／数组长度计算保守上界；实际短路可以少执行，但不能借短路藏超限树。每个允许操作均有有界成本，内存只保留有界 AST、冻结输入、求值栈与结果，不创建任意规模容器。多次调用的项目总负载另归项目层评估，不通过这里的单表达式上限证明整局性能。

**确定性超时是工作预算耗尽，不是毫秒到点。** 正式逻辑求值使用确定的工作计数，不读墙钟、不按机器快慢返回不同结果。工具看门狗位于沙盒外，触发后该次预览为未完成／实现故障，没有可提交值，不能以 false 或零继续运行并声称结果确定。

协作式让出对编辑器长批次、验证与诊断是必要的，避免不可取消任务占住界面；但不能照搬成“过一帧继续结算”。单次 L5 在固定 tick 的既有消费者位置完成，求值期间不能让其他世界逻辑前进。若实现选择内部让出，必须冻结同一上下文并在该逻辑屏障恢复，不能跨 tick 改写结果提交次序；首发推荐以有界同步求值完成战斗调用，协作取消只服务工具批次。工具取消返回未完成，不产生战斗值，不计作验收通过。

## 22.8 与确定性铁律的关系

**同种子、同输入、同定义与解释版本下，L5 每次返回的值或确定性拒收位置必须逐次一致。** L5 自身甚至不读取种子：种子只影响外部合法运行时形成的输入，表达式不新增 RNG 抽取。

| 确定性来源 | 必须固定的条件 |
|---|---|
| 数据依赖 | 仅依赖注入的冻结上下文；无隐藏全局值，无墙钟、网络或随机 |
| 数值解释 | 相同精度、取整、求值顺序与溢出规则；不按宿主默认舍入猜测 |
| 逻辑顺序 | 参数从左到右；and/or/if 按规定短路；不并行竞速取结果 |
| 字段时点 | 在既有消费者位置采样；施法者快照和目标侧当前值不混淆 |
| 版本固定 | CFG、AST、目录、限制档位及解释器版本一致；热更新不污染旧实例 |
| 限制与诊断 | 工作预算决定成功边界；trace 开关和机器速度不进入值计算 |
| 回放比较 | 逐次比较值、节点定位、逻辑 tick 与调用顺序，不只比较最终合计 |

注入 `run.tick` 是读取已知逻辑输入，不是当前时间查询。暂停不推进 tick，慢动作只改变现实中推进频率；渲染频率变化不改变 AST 结果。浮点规则遵守本项目既有单机确定性边界，本章不扩成跨平台位级一致或联网同步保证。

## 22.9 使用登记、批准和版本化

〔推荐默认〕每个使用点先提交 L0—L4 无法表达的反例，由技能设计负责人说明用途、WorkBuddy 审核边界，运行时／工具实现负责人核对消费者许可与验证证据；这些角色职责不能以 AI 自动生成替代人工验收。只有新增副作用、载体、事件或开放 L6 等范围变更才重新交用户拍板，本章不授权此类变更。

| 登记项 | 内容要求 |
|---|---|
| 身份 | 技能 ID、技能版本、消费 CFG 路径、条件／公式资产引用和不可变版本 |
| 必要性 | 低层替代尝试、失败例子、为何仍属于短条件／纯数值 |
| 输入 | 精确字段白名单、源字段、采样位置、范围和单位 |
| 输出 | bool／int／number、消费槽位、范围、失败拒收边界 |
| 安全证据 | 节点／深度／工作量、环检查、全定义证明与恶意输入负例 |
| 确定性证据 | 固定依赖、初态、种子与输入的逐次结果对比，表现关闭对照 |
| 审批 | 设计审核、技术审核、WorkBuddy 验收结果及日期 |

登记说明可通过已有 `meta.design_notes` 记录审批凭据引用，但说明文字不参与执行，不承载 AST；机器有效性由版本化资产与加载器验证。AST 常量、字段、结构或引用改变均计入 CFG 依赖版本化，递增技能 `meta.version` 并使旧预览证据过期。解释方式改变须评审 Schema／语言版本和迁移链，禁止改同一资产版本内容。

新版本只按既有装配、生成与 live 规则生效；本章不允许通过更新资产指针给旧效果体追加行为。复制技能必须重新核对使用点许可，不能只复制批准文字。多处复用的通用需求应回提 L4 能力登记，而不是把 L5 堆成完整脚本系统。
